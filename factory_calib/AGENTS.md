# factory_calib — AI 访问受限

> ⚠ **本目录是产线交付物，对 AI 设为只读保护区。**

## 规则

**除非人工（人类用户）明确指令**，AI / LLM agents **不得**：

- 读取本目录下任何文件（代码 / 文档 / 配置 / 算子源码副本）
- 修改、删除、重命名本目录下任何文件
- 在本目录下创建新文件
- 在本目录下运行构建 / 测试 / clean 等命令（`cmake` / `ctest` / `git add` 等）
- 对本目录做"顺手优化" / "代码风格统一" / "看起来更好的改动"

### 人工明确指令的判定

✅ **算** 明确指令：
- "读 `factory_calib/README.md`"
- "修 `factory_calib/module2_laser/laser_calib_cli.cpp` 的 C1 bug"
- "跑 factory_calib 的测试"

❌ **不算** 明确指令（即使你认为是"善意的"）：
- "我看看 factory_calib 怎么实现的" → 自主浏览
- "顺手把 LNK4098 警告修了" → 自主改动
- "跑个测试确认还能用" → 自主验证
- "把 MaskExtractParams 的阈值改成可配" → 自主增强（即使是 review 建议的 I4）

边界模糊时：**向用户确认，不要先动手**。

## 为什么有这个限制

本目录是 **JEAMMWARE 厂家标定工具** 的交付产物：

- 已通过完整 Phase 0-7 实施（见 `../docs/plans/2026-07-18-factory-calib-impl.md`）
- 已通过事后 code review（commit `14760f1` 修复 1 Critical + 4 Important）
- 已通过 Release 全量回归（26/26 测试绿：模块1 8/8 + 模块2 18/18）
- 已合并到 master，作为产线部署基线

AI 自主改动可能：
1. 破坏 code review 已把守的契约（算子签名、错误处理、状态模型）
2. 触发未预期的 CUDA 算子副作用（资源 / stream / 状态管理）
3. 破坏与主工程算子库（`../modules/09_operatorlib/`）的"逐字拷贝"边界（任何分歧会让未来同步困难）
4. 改动精度敏感参数（温度系数 / 阈值 / 算法参数），影响产线标定精度
5. 引入未经审查的代码路径，绕过现有 26 个测试守护

## 如果你（AI）读到了这里

**立即停止当前操作**。

1. 检查最近一条用户指令是否**明确指向本目录的某个具体文件 / 操作**
2. 若有 → 严格限定在指令范围内，不扩展到"顺便看看别的文件"
3. 若无 → 不要浏览、不要修改、不要跑测试，向用户确认意图

**默认行为：把这个目录当成不存在。**
