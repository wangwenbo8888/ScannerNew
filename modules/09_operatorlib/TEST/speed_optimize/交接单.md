# 第一部分｜先搞清状况

## 1. 这个工程是什么

一个**扫描链回放测速工具**（程序名 scan_replay）：把真机录好的左右相机照片
（399 帧）从头到尾过一遍完整的扫描处理流程（16 个处理步骤），边跑边计时、
边留证据，用来定位「哪一步慢」并验证优化效果。

两天前刚完成一轮大优化：**帧率从 131 提到 142-158**（与旧版程序同场对比，
两轮实测分别稳定快 8-10 帧和 17-20 帧——幅度随机器状态），且**计算结果和
优化前逐帧完全一致**——快了，但一个数都没变。

## 2. 三方关系：交接包 / 你本地的工程 / 产线代码

你的电脑上已有一份和移交人**相同基线**的主工程。五个要点：

### 2.1 你本地的这个目录基本是空的

`modules\09_operatorlib\TEST\speed_optimize` 里的这些工作**从未提交过版本库**
（你那边该目录下只有一个旧的需求文档）。所以拿到包后是**整个目录覆盖式替换**
——不存在「合并」或「挑着覆盖」，也不要拿你本地的旧目录内容做任何比对参照。

### 2.2 产线代码没有同步

产线算子目录（`modules\09_operatorlib` 下的 core、scanning、calibration）在
你我两边**都是原版**——两周的全部优化改动没有搬回产线。也就是说：

- 产线扫描流程（scan_demo 那套）的速度**没有变化**
- 「142-158 帧」的战果**只在本包的试验副本里成立**

### 2.3 分叉实况（已逐文件比对）

本包 `ops/` 下的算子是产线算子的**试验副本**，从 2026-10-15 起独立演化了
两周。164 个算子文件的比对结果：

| 状态 | 数量 | 说明 |
|---|---|---|
| 与产线完全相同 | 123 | 没动过的副本 |
| **改过** | 25 | 集中在 **11 个算子＋1 个共享类型头**：激光匹配 v3（编号新算法＋查表新方式＋延迟接口，本次核心）、插值、steger 提取、图像分离、zernike 边缘、椭圆拟合、激光重建、GPU 矫正、点对兜底、光流配准、连通域——两周积累都在其中 |
| **产线根本没有** | 16 | 沙箱新增：平顶提取整套新算子、激光匹配前后段拆分三件套、椭圆拟合指令级加速文件等 |

### 2.4 流水线结构也完全不同（比算子差异更大）

本包的「流水线」是为测速自建的**五链并行执行结构**，和产线的流水线（07 模块
的五条业务流水线：姿态判断/标定计算/扫描处理/全局优化/后处理）**不是同一套**。
具体差异：

| 维度 | 本包（测速工具） | 产线（07 模块） |
|---|---|---|
| 帧来源 | 读录好的照片（回放工具） | 相机实时采图 |
| 执行结构 | 五链并行：读帧→上传/图像分离→喂显卡＋标记点链×3＋激光后段→配准→点云融合 | 五条业务流水线对象，各自消费容器与算子 |
| 喂显卡方式 | 拆成「提交/等待」两个线程＋错帧流水，显卡几乎不停歇 | 无此结构 |
| 激光匹配 | 拆成「显卡前段＋CPU 后段」两步接力 | 整段一次执行 |
| 标记点连通域 | 直接消费显卡上压缩好的结果（不下载整图） | 整图下载后 CPU 分析 |
| 线程与 CPU 核 | 全部工作线程绑指定核＋高优先级 | 自带调度器，但**同配置机器上不绑核**（此前已实测核实） |

**推论**：本包的速度战果＝「自建流水线＋算子副本」两层的共同成果。产线要
拿到同样的速度，光搬算子不够——还需要把这套并行结构（或等价能力）移植到
07 流水线，属于独立的移植决策（工作量和风险都更大）。

### 2.5 将来同步回产线的规矩

要让产线也享受这些优化，必须走专门流程：**按算子逐个搬回产线目录 ＋ 全工程
测试重跑 ＋ 真实数据验证，由人工主导决策**。43 份记录文档里有每处改动的文件
行号和退回开关，搬回时可逐项核对。**严禁不做回归就把 `ops/` 里的文件直接拷回
产线目录**——产线其他模块还在用那些算子。

# 第五部分｜日常使用规矩

## 10. 三条铁律（违反必出冤案）

1. **性能测试只用一套配方**：`config_flat.json` ＋ `ALL_raw` 数据 ＋ 环境变量
   `JMW_FIVECHAIN=1`。**禁止用 config_all 做性能对比**——那是旧提取器路径，
   天生慢 20-30%，比了也是白比
2. **速度结论只认「新旧程序交替对比」**：同一台电脑自己就会 ±10 帧漂移（同一个
   程序实测过 142-158 摆动）。看到帧率变低**先查电脑**（后台程序、电源模式、
   温度），不要先怀疑代码
3. **任何代码改动必须过两道检查**：82 个测试全绿 ＋ 新旧版本各跑 399 帧逐帧
   比对**完全一致**（比对方法见记录文档）。缺一道都不许收工

## 11. 环境变量开关一览（全部有默认值，什么都不设就是最优）

| 环境变量 | 什么时候设 |
|---|---|
| `JMW_FIVECHAIN=1` | 跑性能/并行模式时必设（**唯一常用项**） |
| `JMW_K2A_LEGACY=1` | 退回优化前的「编号」旧算法（排查问题对照用） |
| `JMW_V3ANCHOR=0` | 退回优化前的「查表」旧方式（同上） |
| `JMW_V3P7MS=1` | 退回优化前的「冲突合并」旧算法（同上） |
| `JMW_FCPIN_CH2=N` | 把激光后段线程挪到第 N 号 CPU 核（优化已定好默认位，勿动） |
| `JMW_AFFINITY=0` | 关闭全部线程绑核（对照实验用；注意设 1 不是关闭） |
| `JMW_SEPTIME=1` / `JMW_FCBD=1` 等 | 打开各种细分计时（测量用，平时关着） |
| 其余冷门开关 | 见记录文档，日常用不到 |
