## 五、参考方案（可调整）

### 方案 A：CCL 改 CPU 单线程

- 新增 CPU 路径：下载掩膜到内存（2.36MB）→ 逐行扫描（8 字节整块跳全黑段）→ 并查集连通块合并 → 算面积/边框/中心
- 原 GPU 代码保留不删，加开关（如 `cclPath=cpu|gpu`），默认 CPU
- 预估 CPU 版 0.4-1.2ms（当前 GPU 版 3.9-5.1ms 且含三次全设备同步拖累全链 6.8ms）
- 注意：沙箱 harness 中 CCL 当前由 gpu_stress 调用——改为 CPU 后需调整调用方

### 方案 B：预解压数据

- 把 `date_in/laser-mark1688-1006/ALL/`（399 帧×left/right）PNG 一次性转为 `.bin`（无头原始灰度，1688×1400 字节/帧/眼）
- 输出到 `date_in/laser-mark1688-1006/ALL_raw/`（保持 left/right 结构）
- 回放工具改为直接读 raw＋`cudaMemcpy` 上传，免去每帧 PNG 解码 ~50ms

### 方案 C：GPU 2 条跨帧流水线

- 2 个 CUDA stream，帧 N 在流 1 跑激光链、帧 N+1 在流 2 跑激光链
- 每条流一套算子实例（09 算子非线程安全，不能共享实例）
- 同理配准 prevState 用原子快照
- ⚠️ 此前实验发现 WDDM 下双流掩膜分离劣化 15%、双流 steger 劣化 4×——需先验证当前算子组合下双流是否可行，不可行则改为「双眼相位交错」（Execute 拆 Submit/Finish）

### 方案 D：CPU 3 条跨帧流水线

- 3 个工作线程（可绑 P 核），每线程处理一帧的完整标记点链（CCL→…→配准）
- 帧间无依赖（配准用 prevState 快照）
- 每线程一套算子实例
- 需帧分发器（round-robin 或队列）

### 吞吐量预估

| 方案组合 | GPU 有效耗时/帧 | CPU 有效耗时/帧 | 瓶颈 | 预估吞吐 |
|---|---|---|---|---|
| 现状串行 | 10.7ms | 14.4ms | CPU | ~69 FPS |
| +A（CCL→CPU） | 6.8ms | 15.2ms | CPU | ~66 FPS |
| +A+C（GPU×2） | 3.4ms | 15.2ms | CPU | ~66 FPS |

| +A+C+D 稳态重叠 | — | — | GPU/CPU 重叠 | **≥150 FPS ✓** |

## 八、关键教训（前序会话踩坑，勿重复）

1. **每次测试前必须 `nvidia-smi` 确认 GPU 时钟**（本会话犯两次锁频丢失）
2. GpuMat 行距陷阱：D2D 裸 memcpy 压扁布局，须 `copyTo`
3. ctest 假绿：只重链 exe 不重链 test → 跑旧库，需全量 build
4. 千级串行走链对 GPU 天然不友好——先量负载形状再搬家
5. 跨环境对比必须对齐时钟状态（600 vs 1815 差 3 倍）
6. 同态图捕获前必须排空流（WDDM 驱动崩溃）
7. 测量口径（CUDA 事件 vs 墙钟）必须标注
