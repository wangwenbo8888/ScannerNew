# 全链速度优化：需求文档（供新会话执行）

> 创建于 2026-10-15。工作目录：`modules/09_operatorlib/TEST/speed_optimize/`。

## 一、目标

把整条扫描链（从读照片到输出全局三维点云）的**单帧处理时间从目前的约 1250 毫秒压到 10 毫秒以内**，同时**精度一点不能降**。

## 二、具体要求（10 条）

| # | 要求 | 说明 |

| 1 | **复制一份再改** | 在 `modules/09_operatorlib/TEST/speed_optimize/` 下复制 `steger_dedup_replay` 的完整功能（src/＋tests/＋config.json＋CMakeLists.txt），在副本上调——不动原目录 |

## 四、优化方向提示（按预期收益排序）

### 第一优先：laser_match_scan_v3（1204ms → 目标 <5ms）

这是全链成败关键。可能的方向：
- **温表查表瓶颈**：当前每帧要查 873 万条温表条目（26 条激光线 × 33 万行/线）。考虑：
  - 表预过滤：只加载当前帧涉及的行范围（用视差中位数预判）
  - GPU 常驻：温表整体放显存（当前 ~1.4GB bin 文件，可能需压缩或分档）
  - 二分/哈希替代线性扫描
  - 帧间增量：相邻帧行位置变化小，可从上帧命中位置附近搜索
- **段级投票＋冲突双弃**的计算量：26 条线 × ~50 段/线 × 投票窗口，是否可 GPU 并行化投票
- 读算子源码：`modules/09_operatorlib/scanning/laser/laser_match_scan_v3/laser_match_scan_v3_cuda_impl.cu`（~1400 行）
- 读温表结构：`modules/09_operatorlib/scanning/laser/laser_match_scan_v3/` 相关头文件

### 第二优先：步骤 1 掩膜分离（46ms → 目标 <10ms）

- 当前每次左右目各执行一次，串行。改双流并行可省一半（~23ms）
- 内部 step4（腐蚀/膨胀级联）占 ~15ms/次——GPU 已在做但可能有大核优化空间
- 读算子：`modules/09_operatorlib/scanning/preprocess/mask_separation/laser_markingpoint_mask_separation_cuda_impl.cu`

### 第三优先：标记点链与激光链并行（省 ~13ms CPU 时间）

标记点链步骤 3~10 全在 CPU（合计 ~13ms），激光链步骤 11~15 全在 GPU。
两条链互不依赖（各吃各的掩膜输出）。
可行方案：
- 方案 A：标记点链放 CPU 线程，激光链放 GPU 流，同时执行（CPU 仍单线程——只有一条 CPU 工作线程）
- 方案 B：全放 GPU——标记点链的 CPU 步骤全部 GPU 化（工作量大但收益确定性高）
- 注意：步骤 1（掩膜分离）和步骤 2（连通域）是两条链共用的前置

### 第四优先：其他 GPU 步骤双流并行

步骤 11~13 左右目各跑一次串行排队（steger 9ms×2、undistort 0.4ms×2、interp 3.5ms×2）。改双流可省 ~7ms。

### 第五优先：accumulateGlobalLaser 搬 GPU

当前 CPU 逐点矩阵乘。改 GPU：R/T 传 GpuMat，fused multiply-add kernel 一次完成全部点的变换＋追加。

## 五、精度验证标准

优化完成后，在相同数据集（sparse_30 全 14 帧 + ALL 前 10 帧）上对比：
- 配对数（matched）逐帧一致
- R/T 误差 <0.01° / <0.01mm（与优化前结果对比）
- rmse 逐帧一致
- 全局标记点地图 PLY 坐标一致
- 全局激光点云 PLY 可视化无重影/错位
