## 二、现行逻辑流程图

> 定稿档：`v3算子逻辑流程图-2026-10-30.md`（依据 impl.cu 步骤注释＋内核名逐一对齐绘制）。

### 2.1 全景数据流（Step1-10）

```
【输入】                                   【外部上下文】
 左目插值点 d_interpPoints (x,y) ─┐        CMTT 温表（按管号×温度档选表，
 左目段ID   d_line_ids  (track) ──┤         cmtt_table_loader 装载 → SetTempTable，
 右目插值点 (x,y) ────────────────┤         左点(uL,row,lid) → 预测 uR）
 右目行桶ID ──────────────────────┘        名义温度 SetCurrentTemperature
         │
         ▼
Step 1-4【右目建行索引】(仅右目)
  genKeys(行,x打包32bit键) → CUB RadixSort → Scatter有序点
  → kernelBuildCSRV3：行号 → 该行右点列表(CSR)
Step 5【发卡＝一级粗匹配】kernelIssueCardsV3
  对每个左点 × 每个 lid(1..25)：查 CMTT 表得 uR_pred(uL,row,lid)
  在该行桶右点中找 |uR − uR_pred| ≤ match_threshold 的点
  → 产出"卡片"(lid, hitRx, 残差)；一卡一票        ★歧义源头之一
Step 6+7【段级投票】（V3 核心：把"点对点"变成"段对线"）
  kernelSegVoteV3    按（段track, lid）累计票数直方图
  kernelSegWinnerV3  每段 argmax → winner lid（平票取小 lid）
  kernelConflictMarkV3 同段/行冲突 → 双弃（atomicCAS）
  ★根因①位点：相邻线预测曲线收敛区，winner 可整段投错线号
   （错配对视差偏 ~3.9 线距 → 重建 +120~170mm 鬼影）
         │
         ▼  conflict_reelect=true 时先走 host 求解层
host 求解层【P5/P6b/P7 实验性冲突消解】（基线 on/on/on）
  P5 conflict_reelect：撞车输方重选次优（票≥max(2,30%×最优)）
  P6b segment_split：串线吞并段按卡归属拆分
  P7 cascade_elim：友军合并→门槛级联→事后拼偶/间距安全检查
Step 8【收集】kernelGatherV3：按各段 winner 收卡片
  → (左点,右点,lid,track) 四元组；无 winner 卡点记 noWinnerCard（不输出）
Step 9【紧缩】CUB DeviceSelect ×4（left/right/lid/track 平行筛）
Step 10【统计归约+唯一宿主同步】kernelStep10ReduceV3
  → matchedCount、no-card/no-map/空段等诊断计数（一次 D2H）
         │
         ▼
【输出】d_matched_left/right/line_ids/track_ids + matchedCount
        + 诊断计数 + 每点 status（ping-pong 双缓冲）
         │
         ▼  （算子边界到此；宿主侧）
★【根因①修复·宿主视差门】（harness 串行 / fc_executor 五链分体）
  |对视差 − 帧鲁棒中位| > disp_gate_px(60) → 丢弃
         │
         ▼
   laser_reconstruct 三维重建 → 融合
```

### 2.2 分体 CPU 后段（split_cpu.cpp，A→G 主流程）

```
A【预处理】ptRow 复算（y/rowStep 远离零取整，不 clamp＝同 GPU 口径）
   └─ 顺带折出 noMap(-1)/noCard(0) 计数
B【投票构建】单遍扫全部左点：segPts/segRows(行位图)/segVotes(段×26 票仓)
C【选举】winner=argmax(平票取小lid)＋second          ★鬼影病灶位
D【冲突消解】按参数走三分支：
   ├─ conflict_reelect=true
   │   ├─ D1 P6b 段分裂（≤3轮）：双峰三门槛（次名票≥max(30,30%W) ∧
   │   │     持S不持W点≥max(30,30%W) ∧ S点行块连续）→ 原段留W、裂新段判S
   │   ├─ D2a P7 级联：①友军合并(union-find，共享行≥minrows 且横向
   │   │     均距≤xpx) ②门槛级联(票≥gate_h ∧ 占比≥share ∧ W/S≥margin，
   │     最高票单元先判线号→从行重叠未定段票仓抹除→递进)
   │   │     ③事后安全检查(撞号＋拼偶：相邻lid横向间距≈spacing_px±tol；
   │   │     违规整组禁赛重跑)
   │   └─ D2b P5 冲突重选（≤10轮）：两段争同一(row,lid)格，胜方留线号；
   │        输方重选次优（票≥max(2,30%×W)且≠争议lid）；无合格次优→整段弃
   └─ conflict_reelect=false → D3 默认：同行同线双弃
        cellOwner[row×26+lid] 首占者留名；后到异段→两段同弃
E【Step8 收集】段无效/已弃/winner<1→跳过；有 winner 卡→输出四元组；
   无卡→noWinnerCard++（静默丢弃口径）
F【Step9 紧缩】CPU 原序追加＝天然连续
G【Step10 统计】droppedSegs/emptySegs；matchedCount；excludedRight
         ▼
【宿主视差门】→ LaserReconstructCpu::ReconstructInto 三维重建
```

**关键数据结构（三件套贯穿 B→G）**：`segVotes`（段×26 int 票仓）｜`segRows`（段×8192bit 行位图）｜`segPts`（段→点下标列表）。

### 2.3 通俗版三原则（人工口径，2026-10-30 确认）

1. **多数票**：上游把相邻点串成段（报团），段内每点给"我像哪条激光线"投票，得票最多的线号当选，整段按它配对（平票取线号小的）。
2. **消元**（＝P7 级联判定 cascade_elim，基线默认开）：有把握的段（票数足/占比高/领先明显）先判线号，判定完就把这个线号从**与它共享行的、还没定的段**的候选票仓里抹掉，递进循环——像排除法：确定的先划掉，剩下的选择面变窄。级联关时的保底语义＝"一格一主/撞车双弃"（同行×同线只能一个段占，两段争则双弃）。
3. **宁缺毋滥**：段无胜者/投票后拿不到对应配对→静默丢弃；重选无靠谱次优→整段弃；末尾视差门把与全帧明显不一致的配对丢弃；待做"歧义弃权"（两线票数分不清→整段弃）同为此思路加强版。

一句话：**先报团投票定线号，有把握的先定并消元，拿不准的一律不要。**

**本质理解（2026-10-30 人工确认）**：本算法＝"统计证据＋确定性规则"混合体，非严格概率模型。多数票隐含假设"段内大多数证据正确（错误零散）"；全部约束（查表预测窗、行对齐、一格一主、线距 36.9px、线连续性、帧内视差一致）都来自激光线真实物理/几何特性——每条约束砍一刀假设空间，正确答案票仓占比升高＝赌赢概率升高。失效模式也由此预言：约束失去分辨力处（曲线收敛区，两线预测间距<2×验卡窗）错误变系统性（整段一致错），多数票反放大错误——鬼影根因①即此；待办"歧义弃权"＝检测该前提破缺并弃权。

### 2.4 确定性规则清单（现行全量 16 条，按流程分组）

**① 输入前提（启动校验＋上游契约）**

| # | 规则 | 物理依据 |
|---|---|---|
| 1 | 温表行距必须＝插值行距（或整数倍），否则启动报错 | 两套几何不能打架 |
| 2 | 段＝上游插值算子串好的连续点串 | 同段＝同一条线的连续轨迹（投票成立前提） |
| 3 | 温表按 管号×温度档 选表，奇偶帧自动切管 | 两支激光管标定参数不同 |

**② GPU 前段·发卡（谁能当候选）**

| # | 规则 | 物理依据 |
|---|---|---|
| 4 | 同行桶才可比（行对齐） | 极线几何：左右对应点必在同一行 |
| 5 | 验卡窗 match_threshold=7px：右点须落在查表预测位置 ±7px 内 | 标定表预测位置 |
| 6 | 每条线最多一卡（取最近） | 一点一线一票 |
| 7 | 左点查表容差 vL_tolerance=0.6px | 表栅格插值精度 |

**③ 投票与消解（host 求解）**

| # | 规则 | 物理依据 |
|---|---|---|
| 8 | 多数票当选，平票取小线号 | 正确证据应占多数 |
| 9 | 一格一主：同行×同线只许一段占，撞车双弃（级联关时保底语义） | 一个位置只有一条线 |
| 10 | 重选门槛（P5）：输方次优票 ≥ max(2, 30%×最优)，否则整段弃 | 次优太弱＝不可信 |
| 11 | 段分裂三门槛（P6b）：双峰＋次线点独占＋行块连续才拆 | 串线吞并段特征 |
| 12 | 消元资格（P7 基线值）：票 ≥30 ∧ 占比 ≥0.40 ∧ 领先 ≥1.3 倍才先判；判完线号从未定段票仓抹除递进 | 有把握的才配当裁判 |
| 13 | 友军合并（P7）：共享行 ≥3 且横向均距 ≤15px 并成一单元 | 线在图上连续 |
| 14 | 拼偶/间距检查（P7）：相邻线横向间距 ≈36.9px±容差；撞号检查；违规整组禁赛重跑 | 标定线距 |

**④ 收集输出＋宿主兜底**

| # | 规则 | 物理依据 |
|---|---|---|
| 15 | 只认当选线号：配不上当选线的点静默丢弃；右点一次性消费不重复配 | 段判决覆盖每点 |
| 16 | 帧内视差一致门 disp_gate=60px：与全帧中位差超限丢弃（仅近平面板开）；丢弃占比>40% 告警 | 同帧同面视差应一致 |

> 观察：规则 1-7 属"物理硬约束"，8-14 属"判决策略"，15-16 属"输出护栏"；
> 优化方向＝往 ①② 加物理特性约束（分辨力）比往 ③ 调策略门槛更治本（歧义弃权即此思路）。

## 四、问题 · 数据 · 方案总表（按主题）

### 4.1 【正确性·已修复】离面鬼影片——段级投票整段错投线号（根因①）

| 项 | 内容 |
|---|---|
| 现象 | 融合激光点云出现主平面前 111~173mm 两张鬼影薄片（串行累计 210 万点中 14,416 点 >50mm；golden 前 10 帧为 0） |
| 根因 | v3 段级投票在 **CMTT 曲线收敛区**（相邻线预测曲线间距<2×验卡窗）整段一致投错线号：错配对视差偏 −145px（≈3.9 线距）→ 重建深度 +120~170mm |
| 证据链 | ①鬼影集中于 7 帧（{101,133,139,143}flow＋{181,182,189}fuse），同帧 80% 点在平面→排除配准；②相机系 Z 直方图双峰→问题在激光链；③视差双峰 500-515 vs 345-374px→系统性错配；④88-98% 鬼影对在正确视差处存在右目候选（偏 0.3-1.9px）→**匹配器选错而非数据缺失**；⑤鬼影全落 7 个"纯鬼影"段（lid 单一 16-21）；f100→f101 同物理段 lid 19→20 翻转→段级投票不稳定；⑥A/B：cascade_elim 关→139/143 净化但 101/133 恶化（级联只治更底层错投） |

### 4.6 【性能·1b 链】高占用归因与等待姿势三连审

- **归因**：1b 占用大头＝排水自旋等 GPU（~3.9ms/帧，75%），非计算；衰减态占用塌到 28% 反证。
- **BLOCKSYNC**（进程级阻塞同步）：ABBA 中位 **−20.0**，NO-GO；**BSONLY**（仅 1b 睡觉）：中位 **−16.1**，NO-GO——1b＝关键路径，自旋是"最快应答 GPU 完成"的姿势，任何粒度改姿势都负收益。
- **PSPIN**（PAUSE 批轮询，省力空转）：帧率中性（中位 −0.77），**默认开**（`JMW_PSPIN=0` 回退）；功耗收益待 LHM 实测。
- 正道＝消灭等待本体：②拆线程/③缩 GPU 链/④边算边收/⑤S4 设备化消费。
- **预热证伪**：LaserOps 首帧 Warmup 引入跨测试内存污染（fivechain 语境）→已回退；残留 0.63 malloc/帧＝启动分配摊薄假象，**稳态零分配**，无缺陷可修。

### 4.7 【性能·回归案】B2 隐形节拍器（kernelIssueCardsV3 撞车）

- **现象**：帧率回归 −21，拆解＝批 B＋图族各扛一半；B2 臂 `kernelIssueCardsV3` 中位 456→475µs（未被改动却变慢＝撞车指纹）。
- **机理**（nsys 双时间线钉死）：M0 的 1.8ms 阻塞式回读是意外节拍器，使融合内核落 GPU 空闲窗（重叠 3.6%）；B2 改"快且滞后一帧"后融合提交撞上 1b 匹配链头（重叠 82.3%，撞车对象 `kernelTightenCardsSplitV3` 占 77%）→SM 争抢两边拉长 → −7~8fps。
- **处置**：低优先级融合流 `JMW_FUSELOWPRIO`（默认开）＝硬件自觉版节拍器，ABBA 中性；0.5mm 新融合参数把撞车窗口缩小 4×，残余仅 ~2fps；**B2 维持不撤销**，批 B 闭环。

### 4.8 【性能·基线】2026-10-29 基线定版

- 基线＝commit f9c95fa＋标签 `baseline-20261029`＋`configs/config_baseline.json`（单一事实源，纯 JSON 驱动零 env）；形态＝图族默认开＋PSPIN＋低优先级融合流＋融合 0.5mm/5000 万槽/步长 2000 万/饱和 3。
- 基准：逐帧间隔中位健康带 **163.25-166.55**；100 遍 39,897 帧**零衰减**；ctest **104/104 绿**（~80s）。⚠（2026-10-30 离面收官档口径为 96 用例 100% 绿——两档时点不同，引用时注意对账。）
- 已知残留（裁定在案）：图族开 −5.88 接受；B2 残余 ~2fps；钳制态倒挂风险（产线双态复测待）；融合预估分配否决。
- 测量纪律：**只认同窗配对差值**（run_abba.ps1），跨窗/跨日绝对值不可引用；跑前体检（~165 健康）。

### 4.9 【性能·实验臂】fullGpu 整体版 vs 分体版

- 五链链2 切整体版 GPU 匹配（`JMW_FC_FULLGPU=1`）：正确性对拍逐位一致（gtest 全绿）；**吞吐分体仍更优**（热机稳态 80-85 vs 67-73——分体的 CPU 后段是免费并行度，整体版把工作串行化到 GPU）。
- fullGpu 臂 ×图捕获存在既有崩溃雷（加任意 GPU 工作即触发）——默认关，启用前先排。
- 数据：`归档/实测数据/fps_{FG_a1,SP_b1,FG_a2,SP_b2}`。

### 4.10 【稳定性】图化崩溃史翻案与红线

- v3 五连发图 1/8 间歇崩溃旧案：10-27 复审翻案——当年实为 1a 分离图 Global 捕获窗竞态（案件二，已修）的时序扰动，v3 图自身 ThreadLocal＋签名恒定设计已规避两已知崩溃形态；B4 长跑 0/20 零崩实证。
