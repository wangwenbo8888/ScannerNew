# 1b 高占用归因：自旋等 GPU（2026-10-29 中午·含衰减态对照实证）

> 问题：1b（激光前段喂料线程，核2-LP0）为何 CPU 占用全机最高（健康态 82.9%、
> 5.17ms/帧）？承接 `逐核负载画像-四臂对比-2026-10-29.md` §四。

## 一、1b 每帧到底做什么（代码事实，fc_executor.cpp chain1bLoop :1238）

```
① 等上游闸门（cv 阻塞，等 1a 交棒）——挂起，零 CPU
② 提交段：flat→undistort→interp→v3前段（HDon=2次大图发射；串行版=逐发小提交）
③ evSlot 事件记录＋水位推进（零碎）
④ ★排水：gS2_.waitForCompletion()——等整条激光前段 GPU 链算完才放行
⑤ finishLaserFront 宿主收尾（统计解包等，~0.1-0.2ms）
⑥ fcV3Front：v3 匹配前段（内部自带 sync#1/#2 两处同步——S4 未做之代价）
⑦ RLE 拷出（pinned 读＋vector assign，~0.2ms）
```

## 二、归因：占用大头＝④的自旋空转，不是计算

**证据链（三组独立实证）：**

1. **健康态画像**：1b 利用率 82.9% × 帧周期 6.24ms ＝ 5.17ms「CPU 忙」，而
   1b 的真活（⑤⑦＋③）合计 ≤0.5ms、HDon 提交段②≈2 次图发射（census 稳态
   ~5-6 API/帧）——**剩下 ~4ms 只能是等待**；等待期间线程仍 100% 烧核＝
   CUDA 同步默认策略 Spin（cudaDeviceScheduleAuto 在多核机上选自旋）的
   标准行为。健康态 GPU 链（flat+undistort+interp+v3前段）恰好 ~4ms，与
   自旋时长吻合。
2. **衰减态对照（今日中午新实证）**：机器衰减（fps 117-132，CPU 受限态）下
   1b 利用率**塌到 23.7-31.5%**——瓶颈移到 CPU 侧链（标记×3/ch2 变慢拉长
   帧周期），1b 反过来等上游（①的 cv 挂起＝零 CPU）。**同一程序、同一数据，
   1b 占用从 83%→28% 的摆动只能用「等待结构」解释，用「计算量」解释不通。**
3. **wall 锚定**：wall1b≈wall1a≈e2e（6.34-6.47≈6.24-6.26ms）——1b 墙钟被帧
   节拍锚满＝它是关键路径线程，墙钟里绝大部分在等 GPU 完成。

**量化拆解（健康态 HDon，5.17ms/帧）：**

| 段 | 估计 | 依据 |
|---|---|---|
| ④排水自旋（等 GPU 链） | **~3.9ms（75%）** | GPU 前段链时长；②⑤⑦反推 |
| ⑥v3前段内部 sync＋零碎等待 | ~0.5ms | 代码内两处同步 |
| ②提交税（2 图发射 WDDM 开销） | ~0.3-0.6ms | HDon census 稳态 API 数 |
| ⑤⑦③真活 | ~0.4ms | 代码量级 |

（串行版 M0/B5 提交税更高：~64 API/帧 → 税 ~1ms 级，被 ④ 自旋部分吸收，
总占用反而略低——与画像表 M0 3.74ms < HDon 5.17ms 的差＝图发射后 GPU 链
变长＋单次同步等更久相符。）

## 三、含义

1. **「1b 占用高」本身不是坏事**——它是关键路径线程的「等 GPU 哨兵」，占用高
   说明 GPU 是瓶颈、CPU 在站岗。真正的坏处是：a) 烧掉一个核的预算（钳制态
   下雪上加霜，功耗翻转机理）；b) 阻塞式同步/拆线程等优化都在改这个等待的
   「姿势」而不是消灭等待。
2. **消灭等待本体＝缩短 GPU 前段链或异步化**（S4 设备化消费/缩串行链/前段
   异步流水）——与已登记减负选项③④同源。
3. **阻塞式同步实验（选项①）——健康窗判决（2026-10-29 下午补测）**：机器
   回 165 平台（体检 166.35 三遍极稳）后正式复测：
   - **ABBA**：B 臂（JMW_BLOCKSYNC=1）配对 **−22.1/−15.9/−21.6/−20.0（4/4，
     中位 −20.0）**——A 158-166 vs B 141-144，唤醒代价 ≈1ms/帧，比衰减态
     初测（−13）更重；
   - **逐核**：1b（LP4）**95-98% → 21-22%**（省 ~0.75 核；标记×3 不受影响）
     ——自旋假设铁证（等待结构决定占用）；
   - **判决：整进程一刀切阻塞同步＝帧率优化 NO-GO**（省核 −20fps 不划算）。
     残余价值：钳制态降级开关候补（省功耗预算场景），及「拆线程/异步等待」
     （只对 1b 局部改姿势、避开全进程唤醒税）仍开放——方向②/④优先级相应上调。

## 三.5、【追加判决】JMW_BSONLY——只让 1b 睡觉，同样 NO-GO

- **实现**：诊断臂 JMW_BSONLY=1（默认关）——只在 1b 的 3 处等待点
  （fc_executor 排水 + finishFront 防御 sync + 主批 sync#2）改用
  cudaEventBlockingSync 事件挂起，**其余线程/其余同步零改动**
  （split_front.cu bsonlyStreamSync()＋fc_executor 排水臂）；
- **ABBA（4/4 配对）**：**−16.1（−8.8/−16.1/−19.4/−19.8）** vs 进程级 −20；
- **归因定谳**：唤醒税 ~80% 出在 1b 自身——**1b＝关键路径，它的等待反应
  速度就是帧率**；自旋不是浪费是「最快应答 GPU 完成」的姿势，任何粒度的
  「改姿势」都负收益。其他线程的睡眠税仅 ~4 帧；
- **路线收敛**：等待姿势路线（进程级/1b 级阻塞）双双证伪关闭。1b 减负仅剩：
  **②拆线程**（等待与提交并行化——不付唤醒税，待评估）、**③缩 GPU 链**、
  **④边算边收**、**⑤S4 设备化**——后三者才是消灭等待本体的正道。

## 三.6、【追加】JMW_PSPIN——省力空转（PAUSE 批轮询）：帧率中性 ✓

- **实现**：与 BSONLY 同一 helper 三模式（fc_executor 排水＋finishFront 两处
  sync）：PSPIN＝`cudaEventQuery` 轮询＋96×`_mm_pause` 批间隔——反应仍 µs 级
  （自旋式应答，无唤醒税），指令退休率降 ~50-100×＝功耗显著下降；
  OS 占用口径仍 ~100%（目的＝功耗非数字）；
- **ABBA（4 配对）**：−1.5 / −1.7 / −13.8(机器跳档污染：A6 独高 160) / −4.1，
  **中位 −1.71＝噪声级中性**（±3 带内两对；-4.1 边缘）——**帧率门通过**；
- **功耗口径**：未测（RAPL/LHM 工具缺席——10-26 档自注 LHM 无解压痕迹）。
  理论估计：单核纯自旋 ~8-12W → PSPIN ~3-5W，封装省 ~4-7W；**待 LHM 实测
  定谳**（需管理员 GUI，同 ThrottleStop 配合模式）；
- **适用声明**：健康态 1b 才自旋（衰减态本就 28%）——本臂救不了钳制态掉帧，
  价值＝产线长会话功耗余量/降频风险缓解。

## 三.7、【翻默认＋画像】PSPIN 默认开落地（2026-10-29 下午）

- **翻默认验证**：新默认（开）vs 显式关（JMW_PSPIN=0）ABBA＝**NO-REGRESSION
  （中位 −0.77，3/4 对带内）**；输出正确性抽验（cycle 100/101/500/900
  markers/laser 逐位同）；
- **逐核画像（同窗开/关对照，链路映射）**：

| LP/链 | PSPIN 开 | PSPIN 关 | 备注 |
|---|---|---|---|
| LP4 **1b** | **97-98%** | 98-100% | 占用口径不变（PAUSE 轮询仍是忙等） |
| LP1 ch2 | 42-44% | 36-50% | 不受影响 |
| LP2 1a | 17-24% | 18-19% | 不受影响 |
| LP6/8/10 Mk×3 | 21-28% | 22-31% | 不受影响 |
| LP0 系统 | 17-18% | 19-21% | — |
| fps | 163.4-166.6 | 160.8-166.7 | 中性偏正 |

- **测量教训（本档第二次）**：首轮画像测得 LP4=25% 系坏样本（负载段过滤
  混入换档期）——**同窗 A/B 对照当即揭穿**；跨窗/单窗样本永远不可直接引用；
- **结论**：PSPIN 默认开＝帧率中性、占用画像不变、功耗收益不可见于此口径
  （省电需 LHM/RAPL 实测，工具缺席待补）。留档状态：默认开已交付，
  `JMW_PSPIN=0` 一键回退。
