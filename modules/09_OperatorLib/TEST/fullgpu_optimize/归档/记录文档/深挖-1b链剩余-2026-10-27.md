# 深挖报告：1b 线程剩余 27.2 次/帧压缩方案（只读代理，2026-10-27 晚，基线 C2=52.07）

## 先说三个颠覆性发现（影响全部任务的前提）

1. **census v2 的 memcpyAsync 方向分类有缺陷**：`cuda_census.cpp:199-205` 对 `pr[3]`（CUPTI functionParams 是「指向各参数的指针的数组」）做 `reinterpret_cast<intptr_t>(pr[3])` 读到的是**指针值**而非 kind 枚举值，几乎恒落 `default: ++c->mcaH2D`。三组独立证据闭合：
   - 1b「mcaH2D」1340/150=8.93 ≈ **flat stats D2H 2/帧 + FinishFront 主批 D2H 7/帧 = 9/帧×150=1350**（吻合 99.3%）；
   - 1a 450=3/帧 ≡ gpu_accum.cu:190/200/202 的 RLE counts＋runs L/R 三笔 **D2H**；
   - fuse 450=3/帧 ≡ laser_cloud_fuse_cuda_impl.cu:424/426 等融合 count/stats **D2H**。
   - 历史互证：M0（13.75/帧）=flat2+interp逐发count2+前段sync#1逐发3+主批7；P2-1（11.77）=flat2+前段sync#1逐发3+主批7（interp count 已入 1B 图）；52.07（8.93）=flat2+主批7（sync#1 三笔随 B4 前段图入图）。三个时代全部吻合。
   - **结论：1b 稳态真实 H2D = 0 笔**（温表单管同源命中零上传 `laser_match_scan_v3_cuda_impl.cu:393-395`＋`:495-498`；undistort R 矩阵一次性上传 `:225`；灰度上传在 upload 线程走 cudaMemcpy2DAsync 未订阅故账外）。**C2/C0/C1 总量口径不受此缺陷影响**（只是列间语义搬家）。「压 mcaH2D」的真命题＝**压 D2H 笔数**。
2. **graphLaunch 2.98 的构成是「1B×2＋前段×1」而非「前段×2」**：前段图 `fgs_[gen]` 双槽（split_front.cu:1377/1449）但每帧只发射当前 gen 一个实例；graphInst=4＝1B L/R＋前段 gen0/gen1（稳态交替用）。
3. **launch 7.73 中的「杂项 1.7」已可基本定性**：tighten 1/帧＋暖机/毁图重捕/图回退帧的逐发体＋RLE 超窗尾拷 ≈ 0.7/帧；P2-3 文档归因的「label_hist memset ~1.7」应修正（memset 不计 launch 列；v3Fuse 默认关且 label_hist memset 已在前段图内）。

## D) undistort 归属建议

**可行性：发射完全静态零 host 依赖——并入图零障碍，纯工程性（捕获窗归属）。**

- 数据依赖：读 flat d_coords_/d_ids_（实例私有固定指针）；输出 d_output_（grow-only 65536 后恒定）；interp 读 d_output_ 与 flat d_stats_[0]——三段缓冲全实例私有跨帧稳定，同流 FIFO 保序。
- 签名/缓冲：21 实参全值参或固定指针；grid=(65536+255)/256 恒定；NDEBUG 无内部同步。
- 三案：**案 A（推荐，随前段大图）**——undistort 交出裸发射体（P2-4 launchLinkPhase 模式），并入前段大图 → −2 无新增 graphLaunch；案 B（独立小图）净 −1 薄收益；落选：并进现 1B 图（时序倒置须重构捕获窗＝案 A 工作量只得 −2）。
