# 逐核负载画像：四臂对比（2026-10-29 上午·健康窗）

> 目的：CPU 物理核×链的每核计算量及比例；承接昨日 M0 专档 §六单臂画像，扩为
> **M0 / B5(批B载体) / HDoff(HEAD关图) / HDon(HEAD默认)** 四臂同窗对比。
> 方法：12 LP 逐秒采样（typeperf %Processor Time×12＋总频率），负载段自筛
> （单样本 12LP 总和 ≥150% 才计入），四臂交错×2 块取均值；**每帧毫秒＝
> 利用率÷帧率**（同数据同工作量，臂间可比）。
> 机器态：ThrottleStop 复健后健康窗（负载频率均值 115-150%，M0=184fps）；
> LP 映射＝LP 2k/2k+1→物理核 k（fcCoreFirstLPs 绑核＋昨日负载分布双重确认）。

## 二、四个关键读数

1. **1b（LP4）＝全机最重单线程，且两处回归都在它身上显形**：
   ms/帧 3.74(M0) → **+0.5 →** 4.26(B5＝批B损失直接可见) → 4.24(HDoff＝
   批B之后串行改动零加重) → **+0.9 →** 5.17(HDon＝图族叠加损失)。
   与根因档「批B＋图族各扛一半」在单核粒度上完全对榫。
2. **1a（LP2）三种画像**：M0 25% → B5 18.8%（等待方式改变）→ **HDoff 50.4%
   （HEAD 串行路径 1a 烧 CPU 2.7×于 B5 但 fps 同＝忙等/提交形态改变，非关键
   路径）** → HDon 16.0%（图族消灭 1a 提交税——昨日"N-6 提交税大降实证"复现）。
   ⚠ 图族省下的 1a 时间没有转化为帧率——1b 同步等待反而+0.9ms，净 fps -13。
3. **Mk×3 与 ch2 四臂稳定**（Mk 各 1.6-1.85ms｜ch2 2.2-2.5ms）——两回归源
   均不在标记链/后段链；座位表设计对这两链有效。
4. **总量悖论**：12LP 总量 M0≈HDoff（327/335%）且 B5/HDon 更低（279%），
   但 fps M0 最高——**帧率由 1b 关键路径（链墙★）决定，不由 CPU 总功决定**；
   HDon 总功最低（图族省提交）却最慢＝省错了地方。
