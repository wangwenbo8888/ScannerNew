# laser_match_scan_v3（激光线匹配 V3）逻辑流程图

> 依据沙箱代码实况绘制（impl.cu 步骤注释＋内核名逐一对齐）；2026-10-30
> 定稿。配套：离面点云查BUG-2026-10-30.md（根因①即发生在 Step5+7 的歧义区）。

## 一、全景数据流

```
【输入】                                   【外部上下文】
 左目插值点 d_interpPoints (x,y) ─┐        CMTT 温表（按管号×温度档选表，
 左目段ID   d_line_ids  (track) ──┤         cmtt_table_loader 装载 → SetTempTable，
 右目插值点 (x,y) ────────────────┤         左点(uL,row,lid) → 预测 uR）
 右目行桶ID ──────────────────────┘        名义温度 SetCurrentTemperature
        │
        ▼
┌─────────────────────────────────────────────────────────────────┐
│ Step 1-4【右目建行索引】(仅右目)                                  │
│  genKeys(行,x打包32bit键) → CUB RadixSort → Scatter有序点        │
│  → kernelBuildCSRV3：行号 → 该行右点列表(CSR)                    │
│  参数：epipolar_row_step（行桶粒度，须与极线插值同值）            │
│        max_right_per_row（单行右点数防爆上限）                    │
└─────────────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────────┐
│ Step 5【发卡＝一级粗匹配】kernelIssueCardsV3                      │
│  对每个左点 × 每个 lid(1..25)：                                   │
│   查 CMTT 表得 uR_pred(uL, row, lid)                             │
│   在该行桶右点中找 |uR − uR_pred| ≤ match_threshold 的点          │
│   → 产出"卡片"(lid, hitRx, 残差)；一卡一票                        │
│  参数：match_threshold（验卡窗口 px）★歧义源头之一               │
│        vL_tolerance（左点查表容差 px）                            │
│        （可选 uRBias 逐线预偏置——默认关，历史停用）               │
└─────────────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────────┐
│ Step 6+7【段级投票】（V3 核心：把"点对点"变成"段对线"）            │
│  kernelSegVoteV3    按（段track, lid）累计票数直方图              │
│  kernelSegWinnerV3  每段 argmax → winner lid（平票取小 lid）      │
│  kernelConflictMarkV3 同段/行冲突 → 双弃（atomicCAS）             │
│  ★根因①位点：相邻线预测曲线收敛区，winner 可整段投错线号          │
│   （错配对视差偏 ~3.9 线距 → 重建 +120~170mm 鬼影）               │
└─────────────────────────────────────────────────────────────────┘
        │
        ▼  conflict_reelect=true 时先走 host 求解层
┌─────────────────────────────────────────────────────────────────┐
│ host 求解层【P5/P6b/P7 实验性冲突消解】（默认 off/off/on 基线）   │
│  P5 conflict_reelect：撞车输方重选次优（票≥max(2,30%×最优)）      │
│  P6b segment_split：串线吞并段按卡归属拆分                        │
│  P7 cascade_elim：友军合并→门槛级联→事后拼偶/间距安全检查         │
│  参数：cascade_gate_h/share/margin、cascade_friend_xpx/minrows、 │
│        cascade_spacing_px/tol（拼偶检查线距标定值）               │
└─────────────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────────┐
│ Step 8【收集】kernelGatherV3                                      │
│  按各段 winner 收卡片 → (左点,右点,lid,track) 四元组 + flags      │
│  无 winner 卡点记 noWinnerCard（不输出）                          │
└─────────────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────────┐
│ Step 9【紧缩】CUB DeviceSelect ×4（left/right/lid/track 平行筛）  │
│ Step 10【统计归约+唯一宿主同步】kernelStep10ReduceV3              │
│  → matchedCount、no-card/no-map/空段等诊断计数（一次 D2H）        │
└─────────────────────────────────────────────────────────────────┘
        │
        ▼
【输出】d_matched_left/right/line_ids/track_ids + matchedCount
        + 诊断计数 + 每点 status（ping-pong 双缓冲）
        │
        ▼  （算子边界到此；宿主侧）
┌─────────────────────────────────────────────────────────────────┐
│ ★【根因①修复·宿主视差门】（harness 串行 / fc_executor 五链分体） │
│  |对视差 − 帧鲁棒中位| > disp_gate_px(60) → 丢弃                  │
│  参数：disp_gate(开关) / disp_gate_px —— 仅近平面板场景适用        │
└─────────────────────────────────────────────────────────────────┘
        │
        ▼
   laser_reconstruct 三维重建 → 融合
```

## 二、三种调用形态（同一算法的拆分方式）

```
整体版 Execute（串行 harness / 五链 fullGpu 臂）
  Step1-10 全程 GPU 一口跑（图臂 JMW_V3GRAPH=1 时 Step1-4+5 五连发图化，默认关）

分体版（五链默认路径）
  GPU前段 ExecuteFront/FinishFront：Step1-5 + 紧缩 D2H（产出"卡片"）
  CPU后段 splitCpu Execute(front)：Step6+7 host 投票求解 + Step8-9
  （前段可图化 B4；参数与整体版同源 LaserMatchScanParamsV3）
```

## 三、参数速查（挂在哪一步、干什么）

| 参数 | 默认 | 生效步骤 | 作用 |
|---|---|---|---|
| match_threshold | 7.0 | Step5 | 验卡窗口：右点与表预测位置的允许偏差（px）。**窗口越大越易吸收错线＝歧义源** |
| epipolar_row_step | 0.67 | Step1/5 | 行桶行距（px），须与 epipolar_interp_dual 同值（启动强校验） |
| vL_tolerance | 0.6 | Step5 | 左点查表（uL 栅格）容差（px） |
| max_right_per_row | 1024 | Step1/5 | 单行桶右点上限（防爆） |
| conflict_reelect | false→级联开时 true | host层 | P5 撞车输方重选次优 |
| segment_split | false | host层 | P6b 串线吞并段拆分 |
| cascade_elim | false（基线开） | host层 | P7 级联判定总闸（隐含开 P5） |
| cascade_gate_h / share / margin | 30/0.70/2.0 | host层 P7 | 级联门槛：票数下限/占比/胜负倍率 |
| cascade_friend_xpx / minrows | 15.0/3 | host层 P7 | 友军合并：共享行横向均距/最少行数 |
| cascade_spacing_px / tol | 36.9/0.55 | host层 P7 | 拼偶检查：相邻线距标定值/容差 |
| disp_gate / disp_gate_px | false/60 | **宿主侧门**（非算子内） | 帧级视差一致性过滤（根因①修复；近平面板专用） |
| deviceId | 0 | 全局 | GPU 卡号 |

## 四、诊断输出口径（Result）

matchedCount＝最终对数；excludedLeft/noMapLeft＝无卡/查表失败左点；
noWinnerCard＝段无胜者卡点；emptyWinnerSeg＝空段；trackTotal/Dropped＝
段数/双弃段数；dispGateDropped＝宿主门丢弃数（修复①新增）。

## 五、Step 6-9 宿主求解详解（分体 CPU 后段 splitCpu，逐行对齐 split_cpu.cpp）

### 5.1 输入（GPU 前段产物，CSR 卡表）

```
f.leftPts[N]      左点(x,y)          f.cardPtr[N+1]  每左点卡区起止（CSR）
f.leftTracks[N]   每点段号(track)     f.cardLid[C]    卡=lid 候选
f.segmap[N]       点→段映射          f.cardRx[C]     卡=命中右点 x
f.leftStatus[N]   1 ok/0 无卡/-1 无表  f.cardRidx[C]   卡=命中右点下标
f.segCount        段总数（后段无上限，P6b 分裂可扩）
```

### 5.2 主流程

```
A【预处理】ptRow 复算（y/rowStep 远离零取整，不 clamp＝同 GPU 口径）
   └─ 顺带折出 noMap(-1)/noCard(0) 计数
        │
B【投票构建】单遍扫全部左点 i：
   ├─ seg=segmap[i] → segPts[seg].push(i)        （段内点集）
   ├─ row 位图 segRows[seg] 置位                  （行占用表，供冲突/友军用）
   └─ 对 i 的每张卡(lid)：++segVotes[seg][lid-1]  （段×26 线号票仓）
        │
C【选举】每段 s：
   winner[s] = argmax(segVotes[s])（平票取小 lid）
   second[s] = 次名 lid（供重选）      ★鬼影病灶：歧义区整段一致投错线号
        │
D【冲突消解】──按参数走三分支─────────────────────────────
   │
   ├─ conflict_reelect=true ─────────────────────────────┐
   │                                                     │
   │  D1【P6b 段分裂】（segment_split=true 时，≤3 轮）     │
   │   候选＝双峰三门槛全过：                              │
   │     ① 次名票 S ≥ max(30, 30%×winner票 W)            │
   │     ② 段内"持S不持W"点 ≥ max(30, 30%×W)（excl 计数） │
   │     ③ S 点行块连续（串线吞并段特征）                  │
   │   → 原段留 W、裂出新段改判 S                          │
   │        │                                            │
   │        ├─ cascade_elim=true → D2a【P7 级联】          │
   │        │   ① 友军合并（union-find）：共享行≥          │
   │        │     friend_minrows(3) 且横向均距≤            │
   │        │     friend_xpx(15) 的段并成一个判定单元      │
   │        │   ② 门槛级联（循环至无新判定）：              │
   │        │     过门槛者＝票≥gate_h(30) ∧ 占比≥          │
   │        │     gate_share(0.70) ∧ W/S≥gate_margin(2.0) │
   │        │     → 最高票单元先判线号 → 该线号从          │
   │        │       "行重叠未定段"票仓抹除 → 递进          │
   │        │   ③ 事后安全检查（违规整组禁赛重跑）：        │
   │        │     · 撞号：同 lid 出现在冲突位置            │
   │        │     · 拼偶：相邻 lid 横向间距须≈             │
   │        │       spacing_px(36.9)±spacing_tol(0.55)    │
   │        │                                             │
   │        └─ cascade_elim=false → D2b【P5 冲突重选】     │
   │            （≤10 轮）两段争同一(row,lid)格：          │
   │            胜方留线号；输方重选次优＝票≥              │
   │            max(2, 30%×自身winner) 且≠争议lid；       │
   │            无合格次优 → 整段弃                       │
   │                                                      │
   └─ conflict_reelect=false → D3【默认：同行同线双弃】    │
       cellOwner[row×26+lid] 首占者留名；                 │
       任何后到异段 → 两段同弃（不查已弃段＝GPU 净语义）   │
        │
E【Step8 收集】逐左点 i：
   seg 无效/已弃/winner<1 → 跳过
   在 i 的卡表里找 lid==winner[seg] 的卡：
     找不到 → noWinnerCard++（静默丢弃口径）
     找到   → 输出四元组 (左点, 右点(hitRx,左y), lid=winner, track)
              右点 status 标记已消费（rightUsed 统计）
        │
F【Step9 紧缩口径】CPU 版原序追加＝天然连续（对齐 GPU 的
   DeviceSelect 保序紧缩，无独立步骤）
        │
G【Step10 统计】droppedSegs/emptySegs 清点；matchedCount=输出数；
   excludedRight=rightCount−rightUsed
        │
        ▼
【输出】matched_left/right/line_ids（宿主 Mat，本帧有效）
        │
        ▼  （沙箱五链 ch2 处）
【宿主视差门】|对视差−帧中位|>60px 丢弃（根因①修复，仅在近平面板场景开）
        │
        ▼
   LaserReconstructCpu::ReconstructInto 三维重建
```

### 5.3 关键数据结构（三件套贯穿 B→G）

| 结构 | 形状 | 用途 |
|---|---|---|
| segVotes | 段×26 int | （段,lid）票仓——C 选举/D 消解的判据源 |
| segRows | 段×8192bit 行位图 | 行占用（D3 冲突检测、P7 友军共享行判据） |
| segPts | 段→点下标列表 | P6b excl 扫描、E 收集按段过滤 |

### 5.4 病灶与防线对照

| 环节 | 鬼影关联 |
|---|---|
| C 选举 | **病灶本体**：曲线收敛区整段票仓一致给错线号（argmax 无从分辨） |
| D2a 拼偶检查 | 现有防线之一：能抓部分相邻线错配，但 399 帧实测 7 帧漏网（A/B 实验证实其双刃性——关掉反而令部分帧净化） |
| 宿主视差门 | 输出端兜底（场景受限：近平面板） |
| 待建 | 匹配端歧义弃权（见查BUG报告§五.4）——在 C 处对"前两名票接近且两线预测曲线间距<2×验卡窗"的段直接弃权，不依赖平面假设 |

### 5.5 带参数一图流（代码默认 vs 基线配置 config_baseline.json）

> 约定：参数值标"码 X/基 Y"＝代码默认与基线配置不同；只标一个值＝两者相同。
> P6b/P5 的门槛（30、30%、2、10 轮）为**代码固定值**，非可配参数。

```
【前段产物】CSR 卡表：每左点挂候选卡(lid,命中右x,右下标)
     │      （前段 Step5 验卡窗 match_threshold=7 决定卡的多少——票仓的上游）
     ▼
A 预处理 ptRow=y/rowStep ────────────【epipolar_row_step=0.67】行桶粒度（须与极线插值同值，启动强校验）
     ▼
B 投票构建 ──────────────────────────（无参数；票仓固定 26 线号 × 8192 行位图）
   票仓 segVotes / 行位图 segRows / 段点集 segPts
     ▼
C 选举 winner=argmax(平票取小lid)＋second ─（无参数）★病灶位
     ▼
D 冲突消解 ── 路由开关 ──────────────【conflict_reelect 码false/基true】（cascade_elim=true 时强制 true）
   │
   ├ conflict_reelect=false → D3 默认同行同线双弃 ──（无参数；格表 8192×26 固定）
   │
   └ conflict_reelect=true
       ├ D1 P6b 段分裂（≤3轮）──────【segment_split 码false/基true】
       │    双峰三门槛（固定值）：次名票≥max(30,30%W) ∧ 持S不持W点≥max(30,30%W) ∧ 行块连续
       │
       ├ D2a P7 级联 ──────────────【cascade_elim 码false/基true】
       │    ① 友军合并: 共享行≥【cascade_friend_minrows=3】∧ 横向均距≤【cascade_friend_xpx=15.0】
       │    ② 门槛级联: 票≥【cascade_gate_h=30】∧ winner占比≥【cascade_gate_share 码0.70/基0.40】
       │                ∧ W/S≥【cascade_gate_margin 码2.0/基1.3】→ 最高票先判、票仓抹除递进
       │    ③ 安全检查: 撞号 + 拼偶——相邻线横向间距≈【cascade_spacing_px=36.9】±【cascade_spacing_tol=0.55】
       │                违规整组禁赛重跑
       │
       └ D2b P5 冲突重选（≤10轮，固定）─ 次优门槛（固定）：票≥max(2,30%×W) 且≠争议lid；无次优→整段弃
     ▼
E Step8 收集 ────────────────────────（无参数；段未弃且有 winner 卡→输出四元组，无卡→noWinnerCard）
     ▼
F Step9 紧缩 ────────────────────────（无参数；CPU 原序追加＝天然连续）
     ▼
G Step10 统计 ───────────────────────（无参数；matchedCount/droppedSegs/excludedRight…）
     ▼
【宿主视差门】───────────────────────【disp_gate 码false/基true】【disp_gate_px=60】
     ▼                                （根因①修复；仅近平面板场景，多深度须关）
   三维重建 ReconstructInto
```
