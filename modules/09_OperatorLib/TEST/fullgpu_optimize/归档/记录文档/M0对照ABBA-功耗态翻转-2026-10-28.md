## 三、定谳：胜负随功耗态翻转（机理解释）

- **满功耗态**：当前版并行 10+ 线程（最高优先级）＋图打包提交，吃满全核预算
  → 165 > M0 的 144（串行逐发提交受单线程提交税限制）
- **CPU 功耗钳制/过渡态**（本机 EC 干预后）：
  - M0 画像＝单线程串行提交 → 吃高单核 boost → **不降反升**（144→174，钳制
    解除了多核争抢反而利于其单线程）
  - 当前画像＝多核并发＋高优先级线程组 → 全核预算被钳 → CPU 段慢→GPU 饿
    → 165→148（−10%）
- 与下午两案（165→88 急坠、BD PROCHOT 复发）合并看：本机「显卡优先＋CPU
  功耗墙」干预下，**并行化深度越大，钳制敏感度越高**

## 六、【附】逐核利用率实测——翻转机理的微观实证（154fps 满载期，1s×24 样本）

实测核映射：LP 2k/2k+1＝物理核 k 的两个超线程（由负载分布反推确认）。

| 核/LP | 平均 | 峰值 | 承载 |
|---|---|---|---|
| 核0-LP0 | 20% | 36% | 系统中断/驱动 |
| 核0-LP1 | 39% | 59% | ch2 ⭐ |
| 核1-LP0 | 22% | 44% | 1a ⭐（N-6 后提交税大降的 CPU 侧实证） |
| **核2-LP0** | **80%** | **100%** | **1b ⭐ 全机最重** |
| 核3/4/5-LP0 | 31/32/34% | 52/53/59% | 标记点×3 ⭐（负载均衡） |
| 其余 LP1 | 6-10% | ≤24% | 浮动线程＋留空防 SMT 互踢 ✓ |

- **1b 的 80% 拆解**（wall1b≈6.2ms×154fps≈95% 单核）：~60% 排水/收尾同步的
  WDDM 忙等（等 GPU 执行，空转烧自己核——钳制态 GPU 变慢时它空转更久＝
  §三翻转的微观机理）＋~25% 提交税＋~15% 真活（参数块/统计/RLE 拷出）；
- 整机 CPU ≈25%——总算力不缺，瓶颈集中于 1b 单线程；
- **减负选项登记**（均未实施）：①阻塞式同步（cudaDeviceScheduleBlockingSync，
  80%→~30%，+唤醒延迟需 ABBA——最便宜实验）②1b 拆提交/收账双线程
  ③缩短 GPU 串行链 ④S4 设备化消费（消灭等待本身）。
