## 三、laser_match_scan_v3 优化（946→7.9ms）

### 根因
harness 每帧调用 SetTempTable + SetCurrentTemperature → 触发 uploadMapTable（873万条排序＋140MB×2上传）

### 已实施手段
1. **温表注备缓存**：同（源表指针,档温,rowStep）重复注入跳过
2. **单同步重构**：GPU segmap（CUB 排序→游程rank）＋GPU winner/second 选举＋GPU exclCount
3. **P6b 稀疏化**：segPts CSR＋exclSz GPU 预备＋量门预检
4. **P7 稀疏化**：稠密 S² 行主序累加器（累加序＝原版→逐位一致）
5. **D2H 两阶段瘦身**：先下 counts→知段数→按实际段数下 votes/winner/excl（512KB→~10KB）
6. **死传输删除**：h_secondI D2H 已删（全文件无读取点）
7. **winner/drop 回传改 pinned**

### v3 当前内部构成（7.9ms）
| 相位 | 耗时 | 说明 |
|---|---:|---|
| GPU 内核 | ~3.5ms | 排序＋发卡＋投票＋选举＋收集 |
| host P6b/P7 | ~1.5ms | CSR＋分裂＋级联（GPU 空闲） |
| D2H/sync | ~1.5ms | 两次 sync 往返＋~400KB 下载 |
| 发射间隙 | ~1.4ms | ~25 个内核的 WDDM 提交开销 |

## 四、mask_separation 优化（45.7→7.1ms）

### 已实施手段
1. **块内融合核**：tile(64×16+光晕)→共享内存→行前缀查表（O(R²)→O(R)）
2. **半宽查表**：hwTab 每块一次（替每像素 sqrtf）
3. **CUDA Graph**：18 个内核一次 graphLaunch
4. **pinned 上传**：锁页内存免 pageable staging
5. **块级一致跳过**：被减数全零块统一跳过（s4b 0.77→0.14ms）
6. **SWAR 前缀向量化**：4字节/步替逐字节
7. **P0 修复**：补 goto pipelineDone（消除每帧双执行，14.5→7.2ms）

### 掩膜分离内部构成（7.1ms/双眼）

| s3a 13×13腐蚀 | 0.50ms | 块内核 |
| s3b 15×15膨胀减法 | 0.80ms | 块内核（被减数稠密→跳过不命中） |

## 六、执行结构优化

1. **事件计时制**：纯 GPU 步骤不同步，帧尾统一结算
2. **双链并行**（JMW_PARALLEL=1 可选）：标记点链 CPU 工作线程 ∥ 激光链 GPU
3. **PNG 预取**（JMW_PREFETCH=1 可选）：双 IO 线程深度 2
4. **accumulateGlobalLaser 搬 GPU**：__dmul_rn/__dadd_rn 与 CPU 逐位一致
5. **日志降噪**：每帧 INFO→DEBUG（省 ~20ms 控制台 IO/帧）

## 七、GPU 负载率与并行实测

### 纯 GPU 压力测试（10000 次循环，无 CPU 步骤无读图）
| 指标 | 值 |
|---|---:|
| 全链单次 | 18.0ms（6 步双眼） |
| GPU 平均利用率 | 48.8% |
| 最高利用率 | 92%（个别内核） |
| ≥80% 时间 | 0.8% |

### GPU 利用率低的原因（逐算子分析）
| 因素 | 影响 | 浪费 |
|---|---|---:|
| v3 host P6b/P7 期间 GPU 空闲 | 最大单项 | ~2.5ms |
| 算子间驱动间隙（6 次 × ~0.4ms） | | ~2.4ms |
| L/R 双目串行（同流先左后右） | | ~1.5ms |
| steger 内部 3 处硬同步 | | ~1.0ms |
| 掩膜行前缀串行瓶颈 | | ~0.5ms |

### 双流/并行实测结论（重要）
| 尝试 | 结果 | 原因 |
|---|---|---|
| 双 CUDA 流掩膜分离 | 劣化 ~15% | WDDM 流切换 |
| 双 CUDA 流 steger | 劣化 4×（帧wall 116→470ms） | 同上＋steger 内 3 处硬同步 |
| 双流＋CUDA Graph | 仍劣化 | GPU 单眼内核已填满 48 SM |
| **双链并行（CPU链∥GPU链）** | **有效（省 ~8ms）** | CPU/GPU 重叠，非 GPU∥GPU |

**结论：此 GPU（RTX 5000 80W WDDM）上 GPU∥GPU 双流不可行；CPU∥GPU 双链可行。**

## 十一、关键排障记录

1. **P0 fall-through**：cudaGraphLaunch 后缺 goto → 每帧双执行 → 诊断模式恰好绕过 → 三代理审核发现
2. **UB 块级跳过**：__syncthreads 前部分线程 return → CUDA 未定义行为 → 修正为合法块级一致跳过
3. **双流回退遗漏**：改了双流后忘回退 → 所有步骤慢 2× → 与 GPU 降频叠加
4. **robocopy /MIR 误覆盖**：恢复产线算子时覆盖沙箱优化版 → 全清重建
5. **cv GpuMat upload 缩容**：upload 后缓冲缩小到源尺寸 → 扩容须写 ROI 视图
6. **nvcc FMA 收缩**：GPU double 默认 FMA 融合与 CPU 分步不同 → __d*_rn 显式指令
7. **ExclusiveSum 临时区竞态**：与排序临时区混用 → 异步崩溃 → 分离缓冲
8. **ccl 遗留默认流**：ccl 全部内核裸发射（无流参数）＋cudaDeviceSynchronize → 与主流串行化（安全但"GPU 并行"未生效）

## 十五、2026-10-17 增程（纯 GPU 压测工具＋三步优化）

### A. gpu_stress 重写（纯 GPU 口径）
一帧、CPU 只做一次解码上传、循环内零同步（含算子内部计时聚合）：
逐算子隔离循环（事件对逐圈记录）＋全链 N 次持续循环（无尾部同步、分批事件）＋
v3/steger/interp/掩膜四家内部计时聚合取中位。新开关：`--perop`；诊断开关
`JMW_STRESS_NOSTEG`（关 steger bench）。

**基准发现（万次连跑）**：算子真实 GPU 内核合计仅 ~8.3ms（利用率×时长两口径互证）；
利用率均值 44%（连跑）/56%（隔离），从未满载；核频稳定 1815MHz——瓶颈是等待不是算力。

### C. 本日排障记录（重要教训）
