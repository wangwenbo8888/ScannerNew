## 一、执行序（七步）

### 第 0 步：两个零代码实验（半天内出数，可能改变整个策略）
1. **ccl 搬 GPU 实测**：`config_allfull_flat_cclgpu.json` 已备好未测。GPU 密度 +3.33ms/帧（5.32→8.65）。
   若吞吐可接受而利用率≥80%，**KPI 可廉价达标，主线降级为吞吐专项**；
   若吞吐崩（GPU 8.65ms 装不进 9ms 帧周期），则维持主线。一趟 3×399 帧即知。
2. **OpenCV 线程压制 A/B**（`cv::setNumThreads(1)` 逐算子或全局）：factory_calib 提速案同款教训
   （OpenCV 内部并行与自有线程池互踩＝zernike/ellipse 膨胀 61-87% 的嫌疑主因）。零风险，可能白捡
   0.3-0.8ms 帧周期。

### 第 1 步：D1 v3 收尾小包（低风险落袋）
popcnt/BSF 替两段位扫描＋删两处确认性回读。预期 −0.3~0.5ms。金样对拍＋gtest。

### 第 2 步：回读普查（新发现驱动，v1 没有的一步）
实测 **25.2 次下载/帧**（v1 账面只有 6 个点位）——比已知的多 4 倍。逐调用点埋计数
（flat 整数回读、interp 计数、CUB DeviceSelect/RadixSort 计数、v3 计数、rle、recon……），
列出每帧每点的次数与代价，按性价比排序吃鱼。CUB select/sort 的"计数依赖"是盲区，
可能藏着一半回读。

### 第 3 步：D2 位图压缩＋同步合并（主线大项，配方已验证）
- GPU 内核把 segrows 位图（4096 定容＝4MB/帧 D2H）压成 (段,行) 紧凑对（几十 KB）；
- 下载瘦身后 interp/v3 同步①②合并为一次；
- 压缩内核本身＋GPU 活（顺带加密度）。
- 预期：消 A 类 ~0.5-0.8ms＋B 类下载变短 ~0.2ms。§十八半途回退分析已知坑。

### 第 4 步：计数级联扩展（普查结果的批量施工）
按第 2 步排序，用 steger 去重段验证过的"定容发射＋哨兵"配方逐点替换
（flat→undistort→interp→v3→recon 链式定容）。预期再消 A 类 0.3-0.5ms。
**此项完成前不做第 5 步**（碎片不连成片，重叠无从谈起）。

### 第 5 步：D3 v3 相位拆分（压轴，工程量最大）
v3 拆 Submit/Finish 两岗：提交岗发射完 GPU 内核即返回，收尾岗稍后做 CPU 配对。
此时 B 类大洞（~1.5ms）被其他 lane 的连续 GPU 段盖住。预期净 −1.0~1.4ms。
前提：第 3/4 步已让每 lane 的 GPU 活连成 ≥1ms 的片。

### 第 6 步（可选/并行）：C4 上传流卡顿小项
流 13（分离/上传）有 0.34-0.6 个大洞/帧（~0.4ms）：查 laserFed 闸门节奏＋上传双缓冲。
独立小项，可穿插做。

## 二、预期数字（保守/乐观，含测量协议修正）

| 阶段 | 帧周期 | FPS | 利用率 |
|---|---:|---:|---:|
| 基线 | 9.02ms | 111 | 60.6% |
| +第 0 步（若 setNumThreads 有效） | 8.4-9.0 | 111-119 | 60-63% |
| +第 1/2/3/4 步（消 A 类） | ~7.6-8.2ms | 122-132 | 65-70% |
| +第 5 步（盖 B 类） | **~6.6-7.2ms** | **139-152** | **74-81%** |
| +第 0 步 cclGPU（若采纳） | GPU 密度 8.65ms | 受 GPU 限 ~110-116 | **~95%**（吞吐换） |

不确定性 ±20%（nsys 剖析开销折算系数 0.61 的误差＋CPU 地板浮动）。每步独立验证、独立回退。

## 三、测量协议（吸收本轮教训）

1. 锁频确认 1500（每次测试前）；
2. 3×399 帧＋100ms 采样＋负载窗（util≥40）取均值——**不用 ≥45 偏置口径**；
3. **剔除收尾排空段**（最后 ~5 帧的 10.5ms 级伪影洞）；处理窗检测用密度法（50ms 桶≥35% 峰值）；
4. 判收益看全程吞吐＋util 双指标，步骤墙钟仅参考（含 lane 等待）；
5. nsys 复测须带 `--cuda-graph-trace=node`（否则形态学图内核全隐身，SM busy 假低 22pp）。

## 四、不做/缓做清单

- 形态学内核削减（2.68ms→目标 1.5ms）：KPI 反向（分子变小→util 降），留作吞吐专项；bitwise 门禁；
- zernike 整图模糊：等人工容差裁决（破坏逐位一致）；
- 宏打包：等 WDDM lane 流图崩溃归因（C 类 ~0.6ms 潜力）；
- v3 宿主级联搬 GPU／4 lane／绑核：已证伪，不再碰。
