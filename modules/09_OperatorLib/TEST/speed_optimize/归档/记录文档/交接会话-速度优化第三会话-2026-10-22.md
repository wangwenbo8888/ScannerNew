## 二、核心诊断迭代（本会话最重要产出）

1. **"同步链节拍"假说被 E4/E5 实证修正**：同步 6→3 后 wall1b 仅 8.1→7.8ms——等待没有消失而是**迁移**：nsys API 实测 cudaLaunchKernel 中位 32.8μs/p90 151.8μs（WDDM 深积压提交税），interp"纯提交"仍 4ms＝25 次发射×p90。
2. **新节拍模型＝GPU 串行依赖链＋提交税**：sep(3.4ms, golden 事件计时实证)→evGate→flat(0.8)→undist→interp(1.5)→v3(0.85) ≈6.7ms 链长≈e2e 7.4ms ✓；双流跨帧重叠近零（n2 trace 复算 sum/union=1.05；sep 忙时仅 7.3% 与他流交叠＝SM 排他实证 H1）。
3. **既有非确定性发现**：同一二进制不同运行长度（8 帧 vs 399 帧）个别帧结果不同（markersValid ±3、laserMatched ±1.4k）——疑 flat 出点 atomic 序（文档在案"点序非确定"）经功率模式/流水线状态放大；**全量 399 对拍稳定 PASS**（权威门），短跑抽查会偶发差异。⚠下会话专项。

## 五、踩坑与纪律（新增）

1. PowerShell 批量正则替换会漏缩进不同的同款代码（E2 漏 1bB 一处→空向量越界崩溃）——批量替换后必须全点复查
2. 短跑（<20 帧）全程处于时钟爬升窗，内核时间 2.5× 失真——内核测量须延迟窗或 ≥100 帧
3. **去同步 ≠ 去等待**：等待会迁移到提交税/串行链——优化前后必须 nsys API 侧（launch 耗时分布）＋内核侧双账
4. ctest 红＝先冷却 90 秒复跑再判（perf 用例热抖动，本会话三次验证）
5. R3 代理的"阻塞项"也可能误报（flat success 置位问题实测不成立）——审查结论要实证裁决，权威门是全量对拍＋用例
