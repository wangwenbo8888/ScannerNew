## 三、关键发现（测量口径修正——后续会话勿再踩）

1. **压测"同帧循环"是假象基线**：v3 发卡查 140MB 温度表，同帧循环＝表页热在缓存。
   真实变帧 g1 3.9ms vs 压测 1.34ms（+2.6ms 冷访存）。同帧×399 实验集（same399_raw）
   判别成功：同帧流水线 g1=1.28（显存降频/空档全保留仍快）→ **冷数据为主因，
   显存频率塌落（实测采样 22-37% 时间在 810MHz，-lmc 锁不住）被排除为 g1 主因**。
2. **CPU 争用实测**：标记链拖累 GPU 线程 steger +2.4/v3 +1.8（关链对照）；v3 内部
   P7 级联四场景恒 ~1.4-1.5 →"降频拖慢宿主段"对中位帧不成立（争用在重帧更明显）。
3. **机器热漂移是第一等变量**：同二进制同协议 50.6→42.7 FPS（30 分钟连续压测后，
   GPU 仅 47°C，CPU 深度降频）。**验收必须定义热状态口径**；A/B 实验必须背靠背交替。
4. **桶索引收益复盘**：预估 −1.7~2.1ms，实际 −0.86 → 冷代价大头不在二分链；
   分布在扩展校验段/占用率/排序段——需管理员 ncu（计数器权限被拒 ERR_NVGPUCTRPERM，
   待 UAC 终端跑）。
5. 统计陷阱两枚：PowerShell 逐步骤中位按字符串排序（"16.6"<"9.5"）；采样进程单次
   52.8ms（负载期占半核），对均值影响 ~0.3ms/帧但抬高分子步骤 max——分析长尾用无采样复跑。
6. 绑核（拓扑感知：枚举物理核、跳过 0 号中断核、每线程独占物理核）：GPU 线程步骤零变化
   → 争用主因是全核基频＋内存带宽，非摆放。默认关（JMW_AFFINITY=1 显式开，留作拆分
   收尾线程后复试）。本机 LP 交错编号（LP0/1=核0），朴素编号会成超线程兄弟。
7. 三代理审核（证据/架构/反方）共识：150 持续不可达（高置信），现实天花板 110~130；
   方案需补"槽位释放握手"（宿主条件变量，禁 GPU 事件跨流依赖＝死锁配方）；
   拆分范围比想象的大（interp 收尾/undistort/v3 上半场都得归收尾线程）；
   验收条款"399 帧×150FPS＝2.66 秒冲刺"可被冷机通过而产线连续工况不达标——口径要先谈。

## 八、★ 追加破案（会话尾）：冷代价真身＝WDDM 变尺寸发射开销，非访存

**实验链**（全部可复现，产物在 out/profiling_1018/）：
1. ncu 提权剖析（runNCU.bat/runNCU2.bat，逐内核＋缓存刷洗口径）：发卡内核
   冷热两态时长相同（0.573 vs 0.580ms），所有内核差 <2%，排序仅 ~0.1ms——
   **"冷查表/冷访存"假设被彻底推翻**（含桶索引收益复盘的解释：桶索引削了
   提交前的少量读，但大头不在那）；
2. g1 拆解路标（impl.cu 内 g1Sub0_/g1Wait0_）：
   变帧 sub=3.99/wait=0.15 vs 同帧 sub=1.06/wait=0.18（ms，P50）——
   **2.9ms 差额几乎全在"提交段"**；
3. 机理：每帧点数 17k-44k 变化 → ~30 个内核的网格/参数逐帧不同 → WDDM 无法
   复用已打包命令缓冲，~130µs/发射的重新打包成本；同帧＝参数恒定＝驱动缓存
   命中。与历史账"发射间隙 1.4ms（同帧）"完全衔接（真实数据下膨胀至 ~4ms）。

**推论与路线更新**：
- 对策＝**CUDA Graph 化**（掩膜分离已有全套先例：图捕获＋WDDM 捕获前排空流）。
  v3：固定容量缓冲＋网格尺寸定容＋计数经设备侧小缓冲（图内 memcpy 节点喂入）；
  CUB 排序两案：a) 只图化非 CUB 内核（~20 发射，低风险先做，预期回收 ~2-2.4ms）
  b) 全图化（CUB 定容＋哨兵填充，1-2 天）；
- **steger 墙钟 6.4 vs 内核 3.4 的 ~3ms 差额大概率同病**（同样逐帧变尺寸发射）——
  待同法拆解验证；两处合计潜在 **~5ms/帧（50.6 → ~67 FPS）**，为当前最大单项；
- 排查清单更新：占用率实验已证伪（__launch_bounds__(256,4) g1 +0.2ms 已回退）；
  "扩展段冷访存"“排序段”嫌疑解除；
- 精度：图化＝同内核同序单次发射，逐位一致可期（掩膜先例已逐字节验证过）。

## 九、★ 追加破案 2（会话尾）：v3"提交段"真凶＝每帧显存重分配（已修复 +4FPS）

**证据链**：五连发图化（scatter→CSR→发卡，逐字节验证通过）收益 ±0 → 深挖发现
`allocateBuffers` 名为容量式，实际 `GpuMat::create` 尺寸一变即释放重分配——
逐帧点数变化 → **每帧 ~27 对同步 cudaFree/cudaMalloc（≈1.5-2.7ms）**，全记在
提交段账上。同帧快＝点数恒定＝零重建，完整解释。

**修复**：growOnly（不足翻倍、永不缩小）覆盖 allocateBuffers 全部 27 项＋
7 处内联 create（d_seg_flags_/runrank_/map_/pt_row_/grp_*）。
**验证**：金样逐字节一致（report 0 diff＋PLY MD5 相同）；交替 A/B
**+3.6~4.8 FPS（43→46.7）**。图化基础设施保留（默认开，中性收益），
JMW_V3GRAPH=0 可关。

**理论修正**：单次发射真实成本 ~50-60µs（非 130µs）；"WDDM 变尺寸发射"半对
——大头是重分配。steger/interp 检查过：缓冲本就容量式 ✓ 无此病；steger 每眼
~2.2ms 提交段＝真实发射成本（~15 发，含 CUB 内部多发射），需图化收。

**后续（全自动执行中）**：v3 Run D 段扩图（~13 节点，纯内核无 CUB，~1ms）→
统计下载去同步 → v3 收尾包 → steger 段图化 → 重测基线＋大项裁决。

### 三层洋葱：利用率低的完整真相（全部实测）
1. **测量陷阱**：nsys `--trace=cuda` **看不见 CUDA Graph 内部内核**（分离
   算子整张图隐身 2.8ms/帧）——"D2D 空闲 5ms/帧"实为分离图在跑。间隙归因
   必须先排除图执行；nvidia-smi 43~47% ＝ SM 忙 ~30% ＋拷贝引擎 ~12% 的
   混合口径（对账闭合）。
2. **每帧 17.29ms 去向**：分离图 2.8＋可见内核 5~6（SM 忙共 ~9）＋
   **上传 2.9（拷贝引擎，SM 闲）**＋**v3 宿主段 2~2.5（SM 闲）**＋
   同步往返 ×12~15 共 1.5＋帧边界 ~1（SM 闲共 ~8）。
3. **新肥靶①——上传异常慢**：4.7MB/帧走锁页 DMA 实测仅 ~1.6GB/s（理论
   8~16GB/s，应 0.3~0.6ms）。嫌疑：cudaHostRegisterReadOnly 在 WDDM 未走
   真 DMA／PCIe 通道宽／与计算同流串行。**修复路径：换 cudaHostAlloc 双
   缓冲＋独立拷贝流＋事件依赖（与上一帧计算重叠）——预期 SM 空闲 −2~2.5ms**。
   排查入口：单测 pinned 读取速度（stream bandwidth test）→ 换注册标志 →
   双流交叠。
4. **新肥靶②——v3 宿主段**（SM 空闲第二大来源）：拆分 Submit/Finish＋专职
   收尾线程＋双实例＋槽位握手（三代理设计在 §三.7；预期 −2ms）。
5. **同步合并**：steger/interp 的计数回传同步改设备侧传递（挂账思路）→ −1ms。
6. **三管齐下预期：SM 利用率 30%→50%+，57.8 → 70+ FPS。**
