## 3. 调度底座设计（`sched/`）

### 3.1 CpuTopology — 拓扑探测与亲和

```cpp
namespace Scanner::pipeline::sched {
struct TopologyInfo {
    int pCores{0};        // 逻辑 P 核数（含超线程）
    int eCores{0};        // 逻辑 E 核数
    std::vector<uint64_t> pMasks, eMasks;   // 每核亲和掩码
    bool hybrid{false};   // 是否成功区分 P/E
};

class CpuTopology {
public:
    static TopologyInfo detect();                  // GetLogicalProcessorInformationEx
                                                  // + CPUID 0x1A.EAX[31:24]（0x20=E,0x40=P；hwloc 可选）
    static void pinThread(std::thread&, uint64_t mask);          // SetThreadAffinityMask
    static void setRealtime(std::thread&);                       // TIME_CRITICAL
    // 降级：hybrid=false → pCores=hwConcurrency，绑定退化为不绑（EventSink 记 Warning）
};
}
```

**X 的确定**：`X = clamp(min(P−1, E), 1, lanesMax=8)`；E 核不足时 X=E（P 核池相应缩减）；`SchedConfig.lanes>0` 可人工覆盖（联调用）。

### 3.2 PCoreBroker — P 核动态租用

```cpp
using PTask = std::function<Result()>;            // P 核重活（标记点链等）
class PCoreBroker {
public:
    Result start(int workers, const std::vector<uint64_t>& coreMasks);
    std::future<Result> submit(PTask task);       // E 核提交，worker 队列派发
    void shutdown();                              // 排空后停 worker
private:
    // X-1 worker，各永久绑 1 P 核（P1..P_{X-1}）；空闲 yield 让出
    // 队列 = 自研有界 MPMC（同 FrameResultQueue 组件，Block 策略）
};
```

- **职责**：收活派活 + future 交付；"X 条流水线抢 X-1 核"的竞争即在此兑现（先到先得）。
- **待命轮转**：不加特殊机制——X 条 lane 提交任务，任意时刻 ≤X-1 在跑，1 条在等 future 即事实待命位（两调度文档 §5.2 语义）。

### 3.3 GpuSlotService — GPU 槽

```cpp
class GpuSlotService {
public:
    Result start(int slots);                      // 创建 slots 条 cudaStream_t（1=姿态 / 2=扫描）
    // acquire 阻塞至有空槽或超时；guard 析构自动 release
    struct Guard {
        cudaStream_t stream;                      // 算子 Stream& 流亲和入口
        void reset();                             // 显式提前归还（A 模式 ccl 后即还）
        ~Guard();                                 // 归还槽（计数信号量 release）
    };
    std::optional<Guard> acquire(std::chrono::milliseconds timeout);
    void shutdown();
private:
    // 计数信号量：atomic<int> + mutex + condition_variable（先到先得）
    // SM 平分：方案 A 双 stream 软限制（硬件自动调度），零配置 —— 调度文档 §7.2 推荐
};
```

- 槽是**全局瓶颈资源**：扫描 2 槽每帧持槽串行跑完整 GPU 链中途不释放；姿态 1 槽（GPU 活轻）。
- acquire 超时（默认 2000ms，可配）→ 视为 GPU 异常：丢弃整帧 + EventSink 报 Fault（§6 错误表）。

### 3.4 IFrameSource — 抓帧策略两副面孔（缓冲容器本体在 06，见 §5.2）

```cpp
template<typename T>                               // T = CycleUnit(姿态) | EnhancedFrame(扫描)
class IFrameSource {
public:
    virtual ~IFrameSource() = default;
    // 扫描面孔：抓最新；lag > dropThreshold(=2X) 则跳到最新、丢中间（返回被跳帧数供统计）
    virtual SPtr<const T> grabLatest(uint64_t& myReadCounter, size_t& skipped) = 0;
    // 姿态面孔：顺序领取下一单元；缓冲空则阻塞等新帧（反压在容器写侧实现）
    virtual SPtr<const T> grabNext(uint64_t& myReadCounter) = 0;
    virtual uint64_t writePtr() const = 0;         // lag 计算/诊断
};
```

07 内提供两个薄包装（构造注入 06 `SlotRing<T>&`）：`GrabLatestSource<T>`（扫描）、`SequentialSource<T>`（姿态）。**反压语义**：姿态模式下 06 容器溢出策略=Block，采集线程写满即阻塞——由容器实现，07 只消费。

### 3.5 FrameResultQueue — 输出队列（MPMC，覆盖最旧）

```cpp
template<typename T>
class FrameResultQueue {                           // E 核 push / FuseConsumer 等下游 pop
public:
    explicit FrameResultQueue(size_t capacity);
    void push(T item);                             // 满时覆盖最旧，生产侧永不阻塞
    std::optional<T> pop(std::chrono::milliseconds timeout);
    size_t dropped() const;                        // 覆盖计数（诊断/监控）
private:
    // mutex + condition_variable 有界环形；push 侧单锁快速路径
};
```

- **选型论证**：moodycamel 本身不提供"满覆盖最旧"语义仍需包装；push 频率≈帧处理吞吐（数百/秒级），mutex 无竞争压力；自研 ~60 行可控可测。**接口形状按无锁队列设计**（push 非阻塞/pop 超时），后续若 profiling 显示热点可整体替换为 moodycamel 包装（07 §4.2-R1 不锁库选型）。
- 被覆盖的旧条目若持 GPU 显存块，经 `shared_ptr` 引用计数自动回收显存池（§5.1 FrameResult）。

### 3.6 PrevFrameState — 原子快照（复用 09）

全局持有 `std::shared_ptr<calib::AtomicFrameState>`，配准开始 `std::atomic_load(&g_prev)` 读最新（可能跨帧）、结束 `std::atomic_store(&g_prev, …)` 覆盖发布；**快照为 nullptr → 首帧初始化分支**（A/C 的 eFinalize/pChain 内处理，姿态文档 §6.4）。**"最新快照"模型打破链式等待**，X 核同时配准不互等（两调度文档决策 3；精度影响可忽略：帧间移动小）。类型即 09 现有 `core/scheduler/prev_frame_state.h`，07 不复制不继承。

### 3.7 LaneRunner + SchedulerRuntime — 通用编排引擎与运行时

```cpp
struct LaneHooks<TFrame, TFront, TResult> {        // A/C 各自装配，底座零算子知识
    // GPU 段（已持 GpuSlotGuard；返回 false=帧销毁，直接下一帧）
    std::function<bool(GpuSlotService::Guard&, const TFrame&, TFront&)> gpuChain;
    // ccl 就绪回调（GPU 段中途触发；C 在此提交 P 核任务实现帧内并行，A 留空）
    std::function<void(const TFrame&, TFront&)> onFrontReady;
    // P 核段（PCoreBroker 上执行；A=标记点链，C=标记点链+配准）
    std::function<Result(const TFrame&, TFront&, TResult&)> pChain;
    // E 核终段（A=融合+判姿+收集；C=汇合组装+发布）；future=Broker 提交 P 任务的返回
    std::function<Result(const TFrame&, TFront&, TResult&, std::future<Result>&)> eFinalize;
};

class LaneRunner {                                 // 1 lane = 1 E 核线程（TIME_CRITICAL）
    // 循环：PREFETCH → [gpuChain → onFrontReady → 等 pChain → eFinalize] → 下一帧
    // 抓帧面孔经 IFrameSource 注入（grabLatest / grabNext）
};

class SchedulerRuntime {
public:
    Result start(const SchedConfig&, IFrameSource<T>*, FrameResultQueue<R>*,   // 队列可空（A 不用：判定在 eFinalize 内完成）
                  const LaneHooks<...>&, PipelineEventSink*);
    void requestStop();                            // 置停标志，lane 跑完在飞帧后退出
    void drainAndShutdown();                       // 停 lanes → 停 Broker → 停 GpuService（逆序收摊）
    Stats stats() const;                           // fps/丢帧/各阶段延迟（原子计数）
};
```

**单帧生命周期（C 模式，双分支）**：E核 `grabLatest` → acquire GPU 槽 → GPU 链持槽串行（mask_separation→ccl→激光04~08）→ **ccl 就绪即** `onFrontReady` 提交 P 核任务（标记点链+配准，与 GPU 激光链帧内完全并行）→ E核等两边（cudaEventSynchronize + future.get）→ `eFinalize` 汇合组装 FrameResult → push 输出队列 → guard 析构释放槽 → 下一帧。

**启停顺序**（07 §1.2）：start＝拓扑→队列→GpuService→Broker→lanes；stop＝**外部先停采（工作流令 08）**→ `requestStop`（drain 在飞帧）→ 停 Broker → 停 GpuService。07 不直接指挥 08。

### 3.8 全局状态与线程安全总表

| 状态 | 归属 | 访问者 | 同步 |
|---|---|---|---|
| 06 `SlotRing` 槽位数组 | 06 | P0 写 / lane 读 | 原子 RMW + shared_ptr 引用计数 |

### 4.1 A — PosturePipeline（姿态判断，01-⑤）

**定位**：帧级单分支流水线，逐周期认姿态、集齐 25 个自动收口。GPU 1 槽、瓶颈在 P 核、**不丢帧反压**。

**装配**（01 在 ② new、⑤ start）：
- `SchedulerRuntime`（`SchedConfig{lanes=X, gpuSlots=1}`）+ `SequentialSource<CycleUnit>`（06 周期缓冲，Block 反压）
- 25 目标姿态表（06 会话件注入，只读）＋初始参数组（**与 2-6 同组**，一致性由装配保证单源）
- `PostureConfirmTable`（streak=3 可配）＋ `PostureSessionData`（输出容器）

**Lane 钩子**（GPU 前段与 P 核链串行——与 C 的帧内并行不同）：

| 段 | 位置 | 内容 |
|---|---|---|
| GPU 链 | 1 槽 | `mask_extract` → `frame_filter`（maskRatio<阈值=激光线帧→**销毁**，返回 false 直接下一周期）→ `ccl`（产出区域标签） |
| P 核链 | Broker | `image_split`→`zernike_edge`→`image_merge`→`undistort_cpu`(初始参数)→`ellipse_fit`→`marker_match`→`epipolar_intersect`→`edge_match`→`point_reconstruct` |
| E 核终段 | lane | 融合（`optical_flow_fuse` 读最新 PrevFrameState 快照；失败降级 `frame_fuse`；再失败沿用上帧 R/T 记 Degraded）→ `pose_estimate` → **PostureConfirmTable 确认** |

**PostureConfirmTable — 连续命中确认（01-D3"非盲收 N 帧"）**：

```cpp
class PostureConfirmTable {
    // per-pose：{bestIdx 连续计数, 上次 bestIdx}，25 行各一把细粒度 mutex（竞争≈0）
    // 流程：pose_estimate 输出 → argmin(ΔT+角度差) 得 bestIdx
    //   距离≥阈值 → 清零 streak，返回未命中
    //   距离<阈值且 bestIdx 与上行连续 → streak++ ；streak≥N(默认3) 且 !collected[bestIdx]
    //     → CAS exchange(true)：成功者独占写 g_postureData[bestIdx]（完整周期帧随单元一并存）
    //     → count.fetch_add(1)；count==25 → completionFlag
};
```

**收口（⑤→⑥ 衔接，遵循 D1+D2"④~⑦ 零干预"）**：A 不链 08/06——收口钩子 `onAllCollected` 在 **② 装配期由 01 注入**，体内依次：经注入的采集控制窄接口 `IAcquisitionControl::stopAcquisition()`（01 以 08 门面适配，07 不加链 08）→ 通知 06 会话件销毁周期缓冲 → `B->run(A->takeSessionData(), …)`。触发时序：`completionFlag` 置位 → A 先 `requestStop`+drain（在飞周期判完）→ 再触发钩子；同时 EventSink 发完成事件（01-⑧ 旁观显示用）。整个 ⑤→⑥ 过程 01 零运行期干预（钩子是 ② 装配时接好的自动管线）。

**PostureSessionData**（B 的输入，§5.1）：25×`PostureData{ markerL/R, laserFrames[], temperature, actualPosture, ellipseCentersL/R(姿态合格帧 2-7 输出，供 3-1 消费) }` ＋ 同一份初始参数引用（保证 2-6⇄3-1 一致性）。

**交互**：每帧 `pushPostureView`（实时姿态+标志点检出）；每确认一个→`confirmedCount`+1，渲染切下一目标；错误处理见 §6 表。

**内部结构（两线程并行 + 数据驱动跟随）**：

```
线程1 相机链                          线程2 激光链
3-1 inverse_distort(每姿态中心,        对 25 组周期帧的激光管帧：

3-3 extrinsic_calib        ├─→ 5-2 extrinsic_compensate            ↓ 激光后段（数据驱动跟随）

3-4 stereo_rectify ────────┘─→ setPromise ──▶                     → 4-6 epipolar_interp(lineIdCheck=true)
                                                                     → 4-7 laser_match → 4-8 laser_reconstruct(Q←3-4)
质量门禁（汇合后）                                                    → [编排] 跨姿态聚合 poses

                                                                     → 5-3 laser_extrinsic_compensate
```

- **两处参数一致性由装配保证**：3-1 初始参数=PostureSessionData 携带组（与 2-6 严格同组）；4-5/4-8/PJC 用 3-2/3-4 标定后最新参数。

### 4.3 C — ScanPipeline（扫描处理，02-⑤）

**定位**：主力帧级双分支流水线，速度优先。GPU 2 槽（瓶颈）、丢帧追新、X=活跃 X−1＋待命 1。

**装配**（02 在 ② new、③ 随采集 start）：
- `SchedulerRuntime`（`SchedConfig{lanes=X, gpuSlots=2}`）+ `GrabLatestSource<EnhancedFrame>`（dropThreshold=2X）
- `ScanConfig{ enableLaser, existingMarkers, enableFinalBA≡true, laserCacheBudgetMB }`——单一流水线＋开关（不拆两条，基准 3.3）
- `FuseConsumer`（独立线程，**不绑核、默认调度**——剩余 E 核按 07 §1.2 资源表归系统其它线程）+ `FrameObsAccumulator` + PrevFrameState 快照
- 标定快照经 06 缓冲出口随帧附带（**增强帧**，算子无查表动作）

**Lane 钩子（双分支帧内并行）**：

| 段 | 内容 |
|---|---|
| GPU 链（持槽串行） | `mask_separation` → `ccl` →（`onFrontReady` 在 ccl 就绪点触发）→ `enableLaser` 时续跑激光链 `steger(Flat)`→`undistort_cuda`→`epipolar_interp(lineIdCheck=false)`→`laser_match_scan(查温度表·帧温档已随快照)`→`laser_reconstruct`；**A 模式（enableLaser=false）ccl 后即 `Guard::reset()` 提前归还槽**（吞吐反升） |
| P 核链（ccl 就绪即提交） | 标记点链 03~11（同 A 的 P 核链，参数来自帧附标定快照）→ 配准：`optical_flow_fuse` 读最新快照（不严格等 N−1 帧）；失败降级 `frame_fuse`；再失败沿用上帧 R/T（Degraded 仍发布）→ store 新快照 |
| E 核终段 | 汇合组装 `FrameResult`（R/T＋标记点3D＋激光3D GPU 块）→ push 输出队列 |

**existingMarkers 三处接线（与 A/B 模式正交，启动时一次性检测装载；触发条件：非空且不含激光点——仅标记点——才作为高精度点加载。B 续扫来源数据可 seed 进融合但不打 `isHighPrecision`，GBA 同等权重，扫描文档 §5.1）**：
1. 配准：首帧以已有点为靶标（09 `optical_flow_fuse` 既有能力），匹配点拿 `globalId=bestIdx`；
2. 融合：start 前 `marker_cloud_fuse_cpu` 经 **`seed()` 预填**（09 算子待加接口，§5.3）；
3. GBA：透传 `isHighPrecision` 标签到 obs（D 消费）。

**FuseConsumer（C 对象内的融合环节，07-C"单帧结果进本对象融合"）**：

```
pop FrameResult → marker_cloud_fuse_cpu(标记点3D+R/T)
              → enableLaser: laser_cloud_fuse_cuda(激光3D+R/T) → laser_cloud_normal_cuda(新体素法线)
              → pushCloudSnapshot(节流可配，推 03 实时渲染)
              → ObsAccumulator.push({frameId, R_init/t_init, markerObs[], laser 帧引用})
```

**FrameObsAccumulator + LaserFrameCache（GBA 专用输入，不可取自融合累积器——体素去重云已丢逐帧结构）**：

```cpp
struct FrameObs {
    uint64_t frameId;
    double R_init[9], t_init[3];                   // 配准初值
    std::vector<MarkerObs> markerObs;              // {xyz(设备系), globalId, isHighPrecision}
    size_t laserCacheSlot;                         // 激光 3D 帧缓存槽引用（无激光=NPos）

class FrameObsAccumulator {
    void push(FrameObs&&);                         // FuseConsumer 调
    GlobalBADataset snapshot() const;              // D 调（导出后只读；mutex 仅护导出）
    // LaserFrameCache：逐帧激光 3D host 缓存（float xyz+lineId，预算上限 laserCacheBudgetMB）
```

- **globalId 一致性**：最新快照模型下（可跳帧/乱序），链式 globalId 传播正确性依赖 09 `optical_flow_fuse` 契约（`getGlobalIds()`）——07 只透传，§5.3 列为算子侧确认项。
- **暂停/续采（⑥ 就绪态再按键回 ③④⑤，同工作流）**：`pause()`＝lane 停抓新帧（缓冲写入由 08 停）、drain；`resume()`＝继续抓帧。累积数据（融合器/obs/快照）全保留。
- **停止（⑦ 前）**：02 收「完成扫描」→ C `requestStop`+drain → D start。

## 6. 错误处理与故障上报

**上报通道**：`PipelineEventSink` 默认实现＝base EventBus `publish(Event{FaultOccurred, sourceId=MODULE_ID_07, param1=错误码})`；QualityFlag→FaultSeverity 映射（Normal/Degraded→Info/Warning，Warning→Warning，Fault→Error）。

| 场景（帧级 A/C） | 处理 |
|---|---|
| 单帧质量降级（Degraded/Warning） | 仍走完并发布（C）/仍提交融合（A），带 flag |
| 配准：光流匹配点<3 | 降级 `frame_fuse`；再失败沿用上帧 R/T，记 Degraded |
| A 帧类型过滤判激光线帧 | 销毁该帧后续段，下一周期（正常路径非错误） |
| GPU kernel 失败 | 丢弃整帧不发布；lane 回 PREFETCH；连续失败>阈值 → Fault 上报 |
| GPU 槽 acquire 超时 | 丢整帧；标记 GpuService 异常；Fault 上报（全局降级决策归工作流/10） |
| 输出队列满 | 覆盖最旧（生产侧非阻塞），dropped 计数 |
| 姿态缓冲满（A） | 容器 Block 反压采集线程（06 实现），07 无动作 |
| 批处理 B/D/E 失败 | 阶段化返回 fail + Fault 上报；D GBA 失败给原位姿兜底（§4.4） |
| 取消（B/D/E） | 阶段边界检查 CancelToken，安全退出不产输出 |

**监控接口**（开放问题 3 的落点）：`SchedulerRuntime::stats()` 暴露 fps/丢帧数/各阶段延迟（atomic 计数），EventBus 周期发布或拉取式，供 UI/10 消费。
