# GBA 后激光散乱点根治 · 复盘总结

> 日期：2026-11-01 ｜ 状态：**已根治并验证**（commit `750e309`）
> 症状：关会话 GBA 完成后 4-5 秒，3D 视图蹦出一大堆散乱激光点
> 结果：PLY 平面体检离群率 **8.57% → 0.02%**，平面内点 86.0% → 98.8%

---

## 一、问题与最终根因

**症状**：扫描过程点云正常；会话关闭触发 GBA 全局优化，完成后约 4-5 秒（解冻推送重放云到渲染器的时间点）散乱点爆发。

**根因（一行）**：激光重放没有镜像 live 融合的门禁——live 融合从不融合 `hold/skip`（配准位姿过期）帧以防拖影，而 GBA 重放把这些帧的缓存激光**全部无条件重融**。这 99 帧（占激光帧 ~26%）带着过期位姿落点，整体错位 +10~170mm（均值 +41mm），构成 8.5% 离群散点。

**为什么七轮没找到**：散点被长期归因于「两链坐标口径错位」（问题①的根因）和「GBA 位姿质量」，两个假说都有部分证据支撑，导致火力集中在补偿与位姿平滑上；直到直接体检散点的空间结构（整帧错位特征）＋对拍 live/重放代码路径，才暴露「同数据两路消费、规则不同」的真凶。

## 五、经验教训

1. **先看病灶长什么样，再动刀**——前 7 轮盲修，第 8 轮才做空间结构体检；「结构量化」应是第一步。离群的形态（整帧错位/薄层/飞线）直接指向病因类别
2. **修复不动指标＝假说错了**——第 5/6/7 轮三连「微效」，8.57% 纹丝不动早已宣判位姿理论死刑，应立刻换方向而不是继续平滑加码
3. **同数据的两路消费必须同规则**——live 融合与 GBA 重放各自实现过滤，一门只写一路＝定时炸弹。规则要么共享，要么对拍测试锁定
4. **测量噪声≠信号**——σ4.6mm 的逐帧 dz 被当位置结构补偿，点数反涨 15% 就是报警；相关系数一测零结构一目了然
5. **正负号要立刻复测**——MKZ +1.6/−1.6 搞反一整轮，靠下一轮探针才发现；方向类参数改动后应立即用基线探针验证
6. **操作者的反直觉观察是最强线索**——「扫描时位姿不准激光反而规则、GBA 后位姿准了激光反而散」直接指向「激光要稳不要准」＋「问题在重放路径不在位姿本身」
7. **关联问题≠同因**——问题①（两链口径）与问题②（散点）共享「GBA 后可见」的表象，长期被当同一根因；口径错位是真的，但它只贡献常数级残差，不是散点病因
8. **便宜的诊断工具要早建**——PLY 体检/拟合器/DUAL-Z 探针各约 50 行，却是全程唯一下判决书的证据；磨刀不误砍柴工

## 七、类似问题排障手册（通用复用）

> 遇到「点云质量异常」（散点/错层/重影/模糊）按此流程走，不要直接跳到修补偿参数。

### 7.1 第一步永远是「给病灶拍照」（结构量化）

```
# 终版云体检（平面场景）——看离群的「形态」而非只看比例
cd build/bin/Release
./test_fc_replay.exe --gtest_filter=*AnalyzeFinalPly*
# 数据：离群比例 / 均值方向 / X-Y 覆盖范围 / 距离分布带
```

**形态→病因对照表**：

| 离群形态 | 特征 | 优先排查 |
|---|---|---|
| 整帧错位 | 离群点 X/Y 覆盖全板面、均值单向偏、成片 | 帧级路径不一致（融合门/位姿配对/槽位错位）——**对拍 live 与重放代码路径** |
| 薄层分离 | 双层平行面、层距 mm 级、单层内连续 | 两链口径常数差（DUAL-Z 探针看均值） |
| 弥散噪声 | 各距离段均匀分布、无结构 | 逐点质量（匹配窗/飞线门/离群滤波参数） |
| 远端飞块 | \|d\|>50mm 孤立块 | 坏帧（读帧失败/配准失败的墓碑帧是否漏入缓存） |

### 7.2 第二步：对拍「同数据两路消费」的规则一致性

散点类问题高发于：**同一份激光/标志点数据被两条路径消费**（live 融合 vs GBA 重放；C 线 vs 终版；入仓 vs 显示）。逐项对拍：

- 过滤门（哪些帧参与）——本案例的真凶就是这里
- 位姿来源与版本（P_live 与 P_obs 是否同源同时刻）
- 坐标口径（P2_tx0 vs 原始 P2）
- 参数（体素/门限/预算）是否同源

### 7.3 第三步：假说检验要有「处决标准」

- 改动前先记录基线数字（PLY 离群率/点数/探针值），改后同口径复测
- **一次只验证一个假说**；修复不动指标＝假说死，立即换向，不要同方向加码
- 补偿类参数（含正负号）改完立刻用探针复测方向
- 拿操作者的目视观察当一等证据——反直觉现象往往直指路径差异

### 7.5 本案例沉淀的「一定检查」清单

1. 新增任何「重放/回灌/重建」路径时：列出 live 消费路径的每一道过滤门，逐一镜像
2. 逐帧测量值入补偿前：先算相关系数（对帧序/位置），无结构＝只能用常数
3. 门限/阈值在两处出现（如 GBA 剔帧=3 vs 信任=2）：检查语义是否真的一致，不一致要写明
4. 点数异常涨/跌 >5%：先怀疑「数据集合变了」（门/槽/预算），再怀疑算法
