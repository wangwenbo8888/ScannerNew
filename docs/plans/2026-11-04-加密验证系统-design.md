## 一、背景与目标

### 1.1 威胁模型（人工确认，四项全要）

| # | 目标 | 一句话 |
|---|---|---|
| T1 | 防软件盗版 | LeadScannerK2.exe 被拷到未授权电脑跑不起来核心功能 |
| T2 | 防山寨下位机 | 第三方仿造下位机接入被识别拒绝 |
| T3 | 整套防克隆 | 上位机＋下位机整体被抄袭复制的成本极大化 |
| T4 | 授权运营 | 试用期/功能分级（精扫、深孔、面片分档售卖）/到期续费，全离线可用 |

### 1.2 产品决策（人工确认）

| 决策点 | 结论 |
|---|---|
| 失败行为 | **软门禁**：界面可进，扫描/标定/导出锁死，红色横幅引导联系售后 |
| 绑定关系 | **一机一狗**（狗↔下位机↔软件三元出厂配对），现场**离线**使用 |
| 密码狗选型 | **深思数盾 Virbox**（ECC 硬件引擎＋自带 Protector 加壳）；接口层做可替换 |
| 下位机 | 固件可改＋有安全算力——260831 协议扩展认证命令可行 |
| 过渡策略 | 真狗未到货期间：**固定码＋验证码弹窗**（§二），狗到货只换实现 |

### 1.3 方案比选记录

- **A（选定）：ECC 密码狗＋下位机双向挑战应答＋出厂三元配对**——四目标全覆盖，软件零秘密
- B：MCU 作主信任根＋存储型狗——便宜但授权块可整读克隆，防盗版弱，否决
- C：纯软件指纹＋VID/PID 枚举——2 元 U 盘可伪造，与目标全不匹配，否决
- 过渡期临时采用「固定码弹窗」（C 的弱化版）——**明知可逆向，仅撑到狗到货**，终态仍是 A

## 二、过渡方案（先行实施）：验证码弹窗

> **决策**（261104 人工确认）：**固定码**（全部设备同一码）＋**每次开机输入**（本机不缓存）。
> 输对 → license 自检项通过，走有狗流程；输错/取消 → 软门禁（§六场景表）。
> 狗到货后：本章全部退役，换 §三~§十一 实现（LicenseGate 演进为 IDongle/DongleGuard）。

### 2.1 流程与门禁原理

```
启动 → 主窗口显示 → 弹「授权验证」对话框（main.cpp，initDlg 之前）
  → 用户输码 → AppContext::submitLicenseCode()
  → 08 LicenseGate 做 SHA-256 比对 → notifySelfCheckItem("license", ok)
     ├─ 通过：自检 6 项全过 → system_ready 提交 → S1→S2，一切照旧
     └─ 失败：system_ready 永不提交 → 状态机滞留 S1 Init（既有门禁锁核心功能）
              状态栏「加密狗 ✗」横幅；菜单「输入授权码」可重试（免重启）
```

**软门禁不新写**——复用既有机制：`selfCheckAllPassed()`（AppContext.cpp:1195）含 license 项，失败则滞留 S1。
另加**显式守卫**（双保险，不依赖状态机细节）：`armScanSession`(:793) / `armCalibCapture`(:766) 入口、
MainWindow 导出两处（:2530 exportMarkers / :2543 exportCloud）加 `licensePassed()` 检查。

### 2.3 代码骨架

**LicenseGate.h**（08，无 UI 依赖）：

```cpp
#pragma once
#include <string>
namespace Scanner::device {
// 授权码校验（过渡件——真狗到货由 DongleGuard/IDongle 接替，见
// docs/plans/2026-11-04-加密验证系统-design.md §二/§七）
// 期望值以 SHA-256 十六进制注入：生产=编译期常量；测试=任意注入（预生成字面量）
class LicenseGate {
public:
    explicit LicenseGate(std::string expectedSha256Hex);
    // 去首尾空白 → SHA-256 → 小写十六进制 → 与期望值（大小写不敏感）比对
    bool verify(const std::string& code) const;
private:
    std::string expected_;   // 归一化小写
};
} // namespace Scanner::device
```

**LicenseGate.cpp**：哈希用 `QCryptographicHash`（QtCore，08 已链 Qt5::SerialPort 同源可用）；
期望值构造期归一化为小写；码本身**大小写敏感**（只 trim 不折叠大小写）；空码/空期望恒 false。

**AppContext 增量**：

```cpp

// AppContext.cpp —— 删 :686「notifySelfCheckItem("license", true); // 占位」后：
void AppContext::submitLicenseCode(const std::string& code) {
    // 占位码 88888888 的 SHA-256——正式码人工定后替换（换码命令见 §2.5）
    static constexpr char kLicenseSha256[] =
        "615ed7fb1504b0c724a296d7a69e6c7b2f9ea2c57c1d8206c5afdf392ebdfd25";
    const bool ok = Scanner::device::LicenseGate(kLicenseSha256).verify(code);
    if (ok) JMW_LOG_INFO("app", "[授权] 验证码校验通过");
    else    JMW_LOG_WARN("app", "[授权] 验证码校验失败");   // 失败留痕（售后取证）
    notifySelfCheckItem("license", ok);
}
bool AppContext::licensePassed() const {
    std::lock_guard<std::mutex> lock(selfCheckMtx_);
    return selfCheck_.license;
}
```

### 2.5 固定码管理

- 占位码：`88888888`（261107 人工定值；哈希已嵌入 §2.3 骨架）——后续换码同样走本节命令
- 换码命令（管理员 PowerShell，把结果填进 `kLicenseSha256`）：

```powershell
$c=[System.Security.Cryptography.SHA256]::Create()
[System.BitConverter]::ToString($c.ComputeHash([Text.Encoding]::UTF8.GetBytes("新码"))).Replace("-","").ToLower()
```

- 已知风险（接受）：固定码存于 exe 内可被逆向提取；码一旦外传需发版换码——过渡期容忍，真狗到货根治

## 三、信任架构（核心原则：上位机软件里零秘密）

### 3.1 密钥分布

```
工厂 CA（离线电脑保管根私钥，永不接触产品机/产线网络）
   │ 签发
   ├─→ 设备证书 Cert_MCU = Sign_CA(mcu_uid, mcu_pub)      → 存 MCU
   ├─→ 狗证书   Cert_DOG = Sign_CA(dongle_id, dongle_pub)  → 存狗
   └─→ 配对证书 Cert_PAIR = Sign_CA(mcu_uid ↔ dongle_id,
                  功能位图, 生效期, 版本)                    → 存狗授权区

驻扎：
  狗  ：ECC 私钥 dk_priv（不可导出）＋ 配对对称密钥 K_pair（只进不出，仅狗内运算）
  MCU ：ECC 设备私钥 mk_priv（读保护）＋ K_pair 副本（读保护）＋ 芯片 UID
  软件：CA 公钥（公开信息，提取无害）——此外什么都没有
```

### 3.2 三份证书的职责

| 证书 | 证明什么 | 防什么 |
|---|---|---|
| Cert_DOG | 狗是 CA 认可的原装狗 | 仿造狗/拷贝狗（私钥不出硬件） |
| Cert_MCU | 下位机是原装设备 | 山寨下位机（无 CA 签发私钥） |
| Cert_PAIR | 这只狗与这台下位机配对＋授权内容 | A 机狗插 B 机；现场改授权 |

## 四、开机验证序列（四步握手）

### 4.1 时序

```
 上位机软件              加密狗                     下位机 MCU
    │                      │                           │
 ① 验狗                   │                           │
    │─ nonce_sw（随机）──→│                           │
    │←─ Sign_dk(nonce_sw)＋Cert_DOG                    │
    │  软件用 CA 公钥验签    │                           │
    │                      │                           │
 ② 验下位机               │                           │
    │─ N17 A<nonce2>（串口下行，协议新增）──────────→│
    │←─ G04 <uid, Sign_mk(nonce2‖uid), nonce_mcu> ───│
    │  软件验设备证书链      │                           │
    │                      │                           │
 ③ 下位机验上位机（防山寨上位机驱动真扫描仪）           │
    │←─ nonce_mcu（②回包中 MCU 已出挑战）              │
    │─ 转发 nonce_mcu ──→│                           │
    │←─ CMAC_Kpair(nonce_mcu)                          │
    │─ N17 B<resp> ─────────────────────────────────→│
    │                                          MCU 验 CMAC ✓
    │
 ④ 验绑定＋授权            │
    │─ 读授权区 ────────→│
    │←─ Cert_PAIR＋授权块 │
    │  验签 → 比对证书内 mcu_uid == ②实测 uid → 查位图/有效期
    ▼ 全过 → 自检 license/mcuAuth 打勾；任一失败 → 软门禁
```

### 4.2 设计要点

- **③ 步「借狗作答」的原理**：上位机软件可被任意拷贝、自身无秘密；「能答对 MCU 挑战」证明**现场有配对狗在场**——软件可流动、狗不可仿造
- **nonce 全程随机＋回包必须回显原 nonce**：防录制重放
- **不在实时路径**：握手只在开机/复验/关键动作时发生；MCU 侧 ECC 软实现慢（100~500ms）可接受
- **协议扩展面**（260831 协议变更单需发固件方）：
  - 下行新增 `N17 A<hex-nonce>;`、`N17 B<hex-cmac>;` 两条
  - 上行新增 `G04 <uid-hex> <sig-hex> <nonce-hex>;` 一条帧型
  - 不动 N10~N16 / G01~G03 任何既有语义

### 4.3 周期复验与关键动作复验

| 时机 | 动作 | 强度 |
|---|---|---|
| 开机 | 四步全握手 | 完整 |
| 运行中每 60s±20s（随机抖动） | ① 验狗轻握手 | 单步 |
| 开扫/导出 STL 前 | ①＋④（狗在场＋授权仍有效） | 两步 |
| 串口重连后 | 重走 ②③（下位机可能被换） | 两步 |

## 五、授权运营（离线友好）

### 5.1 授权块（存狗授权区，CA 签名）

```
{ features: 位图（bit0 标定 / bit1 标点扫描 / bit2 面片 / bit3 深孔 / …）,
  not_before, not_after, 客户标识, 版本 }
```

### 5.2 运营动作

- **开机装载**：读出→验签→按位图开关功能入口；到期→软门禁＋续期提示（显示到期日）
- **离线续期**：售后在离线签发机生成新授权块 → 发客户 → 软件导入写入狗（写狗需 SDK 口令，防现场篡改）；授权单一来源始终是狗
- **功能分级售卖**：签不同位图即可，硬件零差异

## 六、失败处置（软门禁）

### 6.1 场景表

| 场景 | 行为 |
|---|---|
| 开机验狗失败/没插狗 | 界面可进；扫描/标定/导出全锁；横幅「未检测到授权狗，请联系售后」 |
| 下位机认证失败 | 同上，横幅「检测到未授权下位机」 |
| 绑定不符 | 同上，横幅「授权与设备不匹配」 |
| 授权到期 | 同上＋显示到期日，引导续期 |
| **运行中拔狗** | 周期复验发现 → FaultHandler 安全停链（N11 H0 停采），不丢已扫数据 |
| 下位机中途被换 | 串口重连后重新认证，不过不恢复采集 |
| （过渡期）验证码错误/取消 | 界面可进；核心功能锁；横幅＋「输入授权码」重试入口（§2.1） |

### 6.2 联动机制（复用现有件，不新造轮子）

- **10 CommandGate**：命令预检（过三关之预关）加 license 条件——`start_scan`/标定/导出命令要求授权态为真
- **状态机**：`IState.h` S1 Init 注释本就预留「自检：通讯/加密狗/授权」——本次落实
- **故障码**：新增 `0x0901 狗丢失` / `0x0902 MCU 认证失败`（0x08xx 旁开新段），走 FaultHandler 既有红灯/记档链
