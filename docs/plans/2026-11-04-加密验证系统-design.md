## 一、背景与目标

### 1.1 威胁模型（人工确认，四项全要）

| # | 目标 | 一句话 |

| T1 | 防软件盗版 | LeadScannerK2.exe 被拷到未授权电脑跑不起来核心功能 |

### 1.2 产品决策（人工确认）

| 决策点 | 结论 |
|---|---|
| 失败行为 | **软门禁**：界面可进，扫描/标定/导出锁死，红色横幅引导联系售后 |

### 1.3 方案比选记录

- **A（选定）：ECC 密码狗＋下位机双向挑战应答＋出厂三元配对**——四目标全覆盖，软件零秘密
- B：MCU 作主信任根＋存储型狗——便宜但授权块可整读克隆，防盗版弱，否决
- C：纯软件指纹＋VID/PID 枚举——2 元 U 盘可伪造，与目标全不匹配，否决

## 二、信任架构（核心原则：上位机软件里零秘密）

### 2.1 密钥分布

```
工厂 CA（离线电脑保管根私钥，永不接触产品机/产线网络）
   │ 签发
   ├─→ 设备证书 Cert_MCU = Sign_CA(mcu_uid, mcu_pub)      → 存 MCU
   ├─→ 狗证书   Cert_DOG = Sign_CA(dongle_id, dongle_pub)  → 存狗
   └─→ 配对证书 Cert_PAIR = Sign_CA(mcu_uid ↔ dongle_id,
                  功能位图, 生效期, 版本)                    → 存狗授权区

驻扎：
  狗  ：ECC 私钥 dk_priv（不可导出）＋ 配对对称密钥 K_pair（只进不出，仅狗内运算）
  MCU ：ECC 设备私钥 mk_priv（读保护）＋ K_pair 副本（读保护）＋ 芯片 UID
  软件：CA 公钥（公开信息，提取无害）——此外什么都没有
```

### 2.2 三份证书的职责

| 证书 | 证明什么 | 防什么 |
|---|---|---|
| Cert_DOG | 狗是 CA 认可的原装狗 | 仿造狗/拷贝狗（私钥不出硬件） |
| Cert_MCU | 下位机是原装设备 | 山寨下位机（无 CA 签发私钥） |
| Cert_PAIR | 这只狗与这台下位机配对＋授权内容 | A 机狗插 B 机；现场改授权 |

## 三、开机验证序列（四步握手）

### 3.1 时序

```
 上位机软件              加密狗                     下位机 MCU
    │                      │                           │
 ① 验狗                   │                           │
    │─ nonce_sw（随机）──→│                           │
    │←─ Sign_dk(nonce_sw)＋Cert_DOG                    │
    │  软件用 CA 公钥验签    │                           │
    │                      │                           │
 ② 验下位机               │                           │
    │─ N17 A<nonce2>（串口下行，协议新增）──────────→│
    │←─ G04 <uid, Sign_mk(nonce2‖uid), nonce_mcu> ───│
    │  软件验设备证书链      │                           │
    │                      │                           │
 ③ 下位机验上位机（防山寨上位机驱动真扫描仪）           │
    │←─ nonce_mcu（②回包中 MCU 已出挑战）              │
    │─ 转发 nonce_mcu ──→│                           │
    │←─ CMAC_Kpair(nonce_mcu)                          │
    │─ N17 B<resp> ─────────────────────────────────→│
    │                                          MCU 验 CMAC ✓
    │
 ④ 验绑定＋授权            │
    │─ 读授权区 ────────→│
    │←─ Cert_PAIR＋授权块 │
    │  验签 → 比对证书内 mcu_uid == ②实测 uid → 查位图/有效期
    ▼ 全过 → 自检 license/mcuAuth 打勾；任一失败 → 软门禁
```

### 3.2 设计要点

- **③ 步「借狗作答」的原理**：上位机软件可被任意拷贝、自身无秘密；「能答对 MCU 挑战」证明**现场有配对狗在场**——软件可流动、狗不可仿造
- **nonce 全程随机＋回包必须回显原 nonce**：防录制重放
- **不在实时路径**：握手只在开机/复验/关键动作时发生；MCU 侧 ECC 软实现慢（100~500ms）可接受
- **协议扩展面**（260831 协议变更单需发固件方）：
  - 下行新增 `N17 A<hex-nonce>;`、`N17 B<hex-cmac>;` 两条
  - 上行新增 `G04 <uid-hex> <sig-hex> <nonce-hex>;` 一条帧型
  - 不动 N10~N16 / G01~G03 任何既有语义

### 3.3 周期复验与关键动作复验

| 时机 | 动作 | 强度 |
|---|---|---|
| 开机 | 四步全握手 | 完整 |
| 运行中每 60s±20s（随机抖动） | ① 验狗轻握手 | 单步 |
| 开扫/导出 STL 前 | ①＋④（狗在场＋授权仍有效） | 两步 |
| 串口重连后 | 重走 ②③（下位机可能被换） | 两步 |

## 四、授权运营（离线友好）

### 4.1 授权块（存狗授权区，CA 签名）

```
{ features: 位图（bit0 标定 / bit1 标点扫描 / bit2 面片 / bit3 深孔 / …）,
  not_before, not_after, 客户标识, 版本 }
```

### 4.2 运营动作

- **开机装载**：读出→验签→按位图开关功能入口；到期→软门禁＋续期提示（显示到期日）
- **离线续期**：售后在离线签发机生成新授权块 → 发客户 → 软件导入写入狗（写狗需 SDK 口令，防现场篡改）；授权单一来源始终是狗
- **功能分级售卖**：签不同位图即可，硬件零差异

## 五、失败处置（软门禁）

### 5.1 场景表

| 场景 | 行为 |
|---|---|
| 开机验狗失败/没插狗 | 界面可进；扫描/标定/导出全锁；横幅「未检测到授权狗，请联系售后」 |
| 下位机认证失败 | 同上，横幅「检测到未授权下位机」 |
| 绑定不符 | 同上，横幅「授权与设备不匹配」 |
| 授权到期 | 同上＋显示到期日，引导续期 |
| **运行中拔狗** | 周期复验发现 → FaultHandler 安全停链（N11 H0 停采），不丢已扫数据 |
| 下位机中途被换 | 串口重连后重新认证，不过不恢复采集 |

### 5.2 联动机制（复用现有件，不新造轮子）

- **10 CommandGate**：命令预检（过三关之预关）加 license 条件——`start_scan`/标定/导出命令要求授权态为真
- **状态机**：`IState.h` S1 Init 注释本就预留「自检：通讯/加密狗/授权」——本次落实
- **故障码**：新增 `0x0901 狗丢失` / `0x0902 MCU 认证失败`（0x08xx 旁开新段），走 FaultHandler 既有红灯/记档链

## 七、防绕过要点（与档位匹配，不过度对抗）

1. 周期复验 60s±20s 抖动——防「验证后拔狗长跑」
2. 关键动作前即时复验
3. nonce 回显校验——防重放
4. 时序合理性（响应过快＝预录查表嫌疑）
5. Virbox Protector 加壳 exe（SDK 自带，构建配置一行）
6. 失败留痕 ObsLogger（错误码＋时间），售后取证
7. **不做** VMProtect 级深度对抗（YAGNI：密码学握手＋壳在工业客户档位已够）

## 九、产线配对工具（一次性开发）

```
产线工位流程：
 生成 K_pair → 写狗（SDK 口令）→ 触发 MCU 注入（固件方烧录协议）
```

## 十、风险与依赖

| 风险 | 缓解 |
|---|---|
| Virbox 到货周期 | `IDongle` 接口先行，MockDongle 先开发全链，狗到只换实现 |
