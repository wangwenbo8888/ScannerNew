## 2. 标定结果仓库 `CalibrationRepository`（06 新增，app 存活件持有）

**定位**：一格仓库两副基准面孔一体——「标定结果仓库」（01-⑦ 成果落盘持久）＋「标定参数仓库」（02-① 门禁与开机自检查询）。写入端＝01（经 07 B 流水线 run 尾 `ICalibRepoWriter::write(json)` 适配），读取端＝02 装配与 app 转接。

### 2.1 JSON 单文件（如 `calibration.json`，路径归 app 配置）

**仓库 JSON ＝ 07 `serializeCalib` 载荷原样 ＋ 外层 meta 补充**——仓库不发明第二套格式，也不在本文复制键清单（防与实现漂移；键名以 `CalibSerialize.cpp` 与算子 toJson 实现为准）：

```
{
  "version": 1,
  ...serializeCalib 五键原样（stereo / tempTables / pjc / planeMap / quality）...
  "meta": { "createdAt", "calibId", "imageSize" }
}
```

要点（与 07 实现对齐，2026-08-21 审查核实）：
- `stereo` 含内参 L/R、外参 **R/T**（即外参，无第二处）、R1/R2/P1/P2/Q、重投影诊断量
- `tempTables` 实为**四表**（intrinsic/extrinsic/rectify/laserExtrinsic）——全量原样保管（intrinsic/extrinsic/laserExtrinsic 供 01/08 温补链消费；rectify 表即出口查表消费的立体表）
- `planeMap.tempTable` 为算子自带 toJson 档表；`planeMap.map` 仅统计摘要（GpuMat 设备数据不落盘）
- **imageSize 不在 07 载荷内**——由写入端补：01 RepoWriter 适配器从构造参数（现状 `CalibrationWorkflow.cpp` setImageSize 同源）写入 `meta.imageSize`。若倾向 07 载荷补键属跨模块协调（§8-5）

### 2.2 接口语义（约 8 个公开方法，mutex 保护，`Result` 风格）

| 方法 | 谁调 | 干什么 |
|---|---|---|
| `write(const std::string& json, cv::Size imageSize)` | 01（适配 ICalibRepoWriter） | 解析载荷→校验五样→填内存→落盘（**临时文件＋原子改名**，防半写坏档）；imageSize 入 meta |
| `load(path)` | app 开机 | 读盘→解析→填内存；坏档返回 fail 不崩（开机自检「是否正确导入标定参数」查此结果） |
| `stereo()`（含 imageSize）/ `stereoTempTable()`（取 tempTables.rectify）/ `planeMapTiers()`（档温索引派生）/ `planeMapTempTableRaw()`（激光档表参数原文）/ `tempTablesRaw()`（相机四表原文） | 02 装配、app 转接、01/08 温补链、07/09 重算链 | 返回 06 侧类型（复用既有 `TempTableTypes.h`：`StereoTempTable` 等）；激光档表参数供下游重算网格映射用（§2.3） |
| `readyForScan(ReadyReport&)` | 02-① pre 谓词、开机自检 | 五样齐检查（对齐 01-D6）：内参 L/R＋**外参 R/T**＋立体矫正＋立体温度表（rectify）≥1 档＋激光档表≥1 档＋imageSize——缺哪样报哪样（AppContext 现 `hasData()` 谓词升级换代）。**注意**：激光判据现状为占位语义——只验「档表有档」，不代表激光网格数据可装配（§8-1） |
| `clear()` | 人工/测试 | 清内存 |

### 2.3 分工铁律

- **GpuMat 设备数据不落盘**（07 CalibSerialize 已定：设备指针不可移植）——仓库只存 host 数据。
- **激光档表两半分（照实，二轮修正）**：仓库存 4-13 档表 toJson 原样——每档为**温补后相机参数**（compensatedCameraMatrix L/R/T、R1..Q、lineStats）＋档温，**不含网格映射数据**（`leftToRightMap` 网格现无生产链：4-13 不产 mapData、4-12 设备数据不落盘、「按参数重算」09 侧无实现——三条候选路径见 §8-1）；`PlaneMapTempTableRef`（档温索引）由档表派生给 FrameEnricher 选档用；网格映射/GpuMat 表生产归 §8-1 协调项落地后接 07/09 装配。
- **相机四表原样保管**：intrinsic/extrinsic/rectify/laserExtrinsic 全存（§8-5），rectify 表即出口查表消费的立体表。
- 温度表分工守 01-D5：01 生成落盘、02 出口查表消费，生成与消费分离。

### 4.2 `ScanSessionData`（02 版会话件）

```
assemble(repo, cloudWh)           ← 02-② 装配：
    ① 出口查表装表：从 CalibrationRepository 取 StereoTempTable（内存 Matx）
       ＋激光档温索引（PlaneMapTempTableRef，由档表派生）
       ＝ FrameEnricher 查表输入齐备；激光网格/GpuMat 表依赖 §8-1 协调项，
       由 07/09 装配期另行构建
    ② 造 SlotRing<EnhancedFrame>（Overwrite——扫描面孔；槽位约定沿用现状 16，
       构造可配）
pushFrame(grayL, grayR, tempC, id) ← 帧唯一入口：FrameEnricher::enrich（选档＋
       附快照）→ ring.write；enrich fail → 丢帧＋warn＋计数（挂 10 故障桥）。
       **限采集回调单线程调用**（SlotRing write 为单生产者约定）
ring()                             ← 07 ScanPipeline attachRing 注入用
```

**帧路径**（对齐 07 已建成消费关系）：08 采集回调 → 02 侧适配 → `pushFrame` → ring → 07 GrabLatestSource。基准「缓冲出口逐帧查表」的语义落点＝**算子无查表动作**——查表收在数据面入环一处，环内帧自带快照（07 ScanPipeline 消费 `SlotRing<EnhancedFrame>` 已锁死此形态）。

### 4.3 `CalibSessionData`（01 版会话件）

标定配置＋初始参数＋25 目标姿态表加载（01 现状**无既有格式**，加载器格式批 C 与 01 共定——§8-2）＋ `SlotRing<CycleUnit>`（Backpressure——姿态面孔，07 PosturePipeline attachRing 注入；槽位沿用现状 8，构造可配）。不复用 ParameterManager（那是 app 参数键值仓，用途不同）——01 侧 TODO「标定文件装载」指向本会话件兑现。

### 4.4 销毁顺序（铁律，二轮补——attachRing 为裸指针注入）

**停采集 → 停流水线（07 对象）→ 再销毁会话件（ring 最后死）**。理由：SlotRing Backpressure 满环时写线程阻塞在环内 cv 上——若 ring 先析构＝等在已析构 mutex/cv 上 UB；故 ⑨/⑩ 收尾必须先停 08 采集回调、再 reset 07 流水线对象、最后才会话件析构（02 现状 `~ScanWorkflow→stop()→pipeline_.reset()` 的顺序即此语义，成文固化）。
