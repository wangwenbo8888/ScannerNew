# 重标定与双链对齐 — 开发计划

> **For AI:** 按任务逐项执行；每项有验收门，验收不过不进下一项。涉及 `factory_calib/`（AI 只读保护区）的每一步都必须有人工明确指令在先。

**Goal:** 产出一套同源几何口径的标定产物（相机＋激光），使「conic 标志点链 vs v3 激光链」同表面深度偏差从 ~3mm 收敛到 <1mm（DUAL-Z 验收），并完成扫描级重建验收。

**Architecture:** ①先用棋盘格内参指纹验证标定素材与现机硬件一致（防白做）→ ②梳理 factory_calib 双模块流水线与主工程最新算子的版本差异＋查清 CMTT 生成路径 → ③跑同次标定（module1→module2 链式共享几何）→ ④部署＋扫描验收（本季已建的全套诊断工具复用）。

**Tech Stack:** factory_calib module1（camera_calib.exe, CPU）/ module2（laser_calib.exe, CUDA）；OpenCV calib3d（棋盘格内参指纹）；主工程诊断用例（DUAL-Z / WhiteboardPlaneDiagnosis / GbaOnCheckpoint / ConicCropSolve）。

---

## 背景（为什么做）

1. **双链深度系统偏差 ~3mm**（261031 DUAL-Z 探针实测，测试数据 20 帧一致 −2.1~−5.4mm）：conic 标志点链吃 `config/camera_calib.json`（名义温档），v3 激光链吃 `config/curve_map_temp_table.bin`（CMTT）——**两套标定产物来自不同标定过程，几何口径不一致**。这是「标志点和激光点云不在同一平面」的根因。
2. 本季（261029-261031）已修完链路层问题：管型误判、质量门、GBA 关键帧/修正传递、飞点/飞线、坐标系显示——全部已提交，ctset 106/106 绿。剩余唯一未解＝标定口径，即本计划。
3. **素材**：`D:\calib`（10-03 采集）：calib0/1/2＝棋盘格帧对（left/right，2048×1536，20/47/143 张）＋laser0/1＋camera*.zip/laser.zip。**是否现机采集未验证**（阶段 1 解决）。
4. **备份已做**：`backup_config_20261031_1338/`（三处 config 全量＋MD5 指纹；.gitignore 已挡）。

## 阶段 1：硬件一致性确认（P0 阻断项）

**判定规则**：同对相机内参指纹（fx/fy/cx/cy）偏差 <1% → 同硬件，放行；>2% → 止损（先查相机个体/序列号/是否换过件）。

### Task 1.1 采集现机棋盘格帧
- 人工操作：重启 exe → 对准**棋盘格标定板**扫 5-10s（持稳、缓慢多姿态）→ M 停。
- 帧自动落 `build/bin/Release/diagnostics/fc_frames/`（L_/R_ 各 200 张，2048×1536 原图）。
- 验收：目录内今日新增 ≥100 对。

### Task 1.2 内参指纹对比工具
- 新建：`modules/PipelineManager/tests/test_calib_hwcheck.cpp`（或并入 test_fc_replay 新用例 `FcReplay.HardwareFingerprint`）。
- 实现：`cv::findChessboardSB`（角点）→ `cv::calibrateCamera` 分别对 [参照组＝D:\calib\calib0/1/2 合并采样] 与 [今日组＝diagnostics/fc_frames] 解算 L/R 内参 → 输出 fx/fy/cx/cy＋相对偏差表。
- 棋盘格规格从 factory_calib 现有 `data_in/camera/config.json` 读取（内格数；读取该文件属运行必需，人工已授权重标定流程）。
- 验收：工具单测绿（合成图冒烟）＋真机两组各跑一次。
- **门**：偏差表人工确认后再进阶段 2。

## 阶段 2：标定流水线梳理（最新算法对齐）

### Task 2.1 factory_calib 算子版本审计
- 对照清单：factory_calib 各算子源码副本 vs `modules/OperatorLib` 最新——重点核对 261027-261031 演化过的：flat_center（捕获模式）、mask_separation（捕获模式/useCudaGraph）、conic_reconstruct（07 A 链刚接入）、zernike/ellipse/match（A 链同步时是否触及）。
- 产出：drift 清单表（算子×差异×是否影响标定精度×同步建议）。
- ⚠ 此任务读 factory_calib 源码——**执行前人工确认**（逐字拷贝边界的审计是 AGENTS 例外清单内场景，但需点名放行）。

### Task 2.2 CMTT 生成路径调查（闭环关键）
- 问题：线上激光链吃 `curve_map_temp_table.bin`（180MB），factory module2 输出的是 `laser_calib.json`（含 planeMapTempTable）——**中间转换器在哪**。
- 调查点：主工程 `LoadTempTableFromCmtt`（消费格式）→ 反查生产者；沙盒 speed_optimize 工具链；factory_calib data_out 历史。
- 产出：路径结论＋（若缺失）转换器需求定义 → **人工裁决**（补转换器 vs 改消费端直读 laser_calib.json）。

### Task 2.3 端到端流水线定版
- 产出流程图：素材组装 → module1 → camera_calib.json →（拷入）→ module2 → laser_calib.json → [CMTT 转换] → 部署 → 验收。
- 决策记录：算子同步范围（Task 2.1 结论）、部署连带档范围（calibration.json/laser_calib.json/camera_calib.json/CMTT）、温度点覆盖。

## 阶段 3：执行标定

### Task 3.1 输入组装
- `D:\calib` → factory 布局映射脚本（纯拷贝/改名，不改工具）：camera/{config.json,temps.txt,left/,right/}；laser/{config.json,camera_calib.json←模块1输出,pose_XX/}。
- 温度点：查素材是否多温度组（calib0/1/2 是否即不同温度档）——若单温度，温度表退化为单档（记录为已知限制）。

### Task 3.2 相机标定（module1）
- Run: `camera_calib.exe data_in\camera data_out\camera_calib.json`
- 验收：rms ≤ 现档水平（backup 里 calibration.json 的 rms 参照）；人工看 reprojection 残差分布。

### Task 3.3 激光标定（module2）
- 拷入 Task 3.2 输出 → `laser_calib.exe data_in\laser data_out\laser_calib.json`
- 验收：退出码 0；framesOk/posesProcessed 覆盖率；accumulatedPoints3D 量级。

### Task 3.4 CMTT 生成＋部署
- 按 Task 2.2 结论执行（缺失则先停，人工裁决后继续）。
- 部署序：备份已在 → 新档进 exe config/（Release＋Debug）→ 记录新旧对照。
- 回滚预案：`backup_config_20261031_1338/` 原样拷回＋重启 exe。

## 阶段 4：扫描验收

### Task 4.1 离线双链验收
- Run: GbaOptimizedMarkersAndLaser（测试数据）→ DUAL-Z 偏差 **<1mm**。
- 注意：测试数据若与新标定不同源（laser-mark1688 是旧标定采的），此项预期会变——届时改用「现机新扫数据」验收，此处先跑留档基线。

### Task 4.2 在线白板验收（现机）
- 扫白板 → 关会话 → 查：
  - 日志 `[DUAL-Z]` 每 100 帧偏差 **<1mm**
  - 链路诊断：质量门弃帧率、飞线剪枝量合理
  - 新 checkpoint 跑 WhiteboardPlaneDiagnosis：单帧核 RMS ~0.5mm 档、联合平面内含率 >90%
  - 标志点/激光**目视同平面**（本计划的最终验收）

### Task 4.3 重建参数复核
- 新标定下重跑 ConicCropSolve（裁剪原点可能不再是 180,102——新 K 下重解）。
- 深度门限（laser_reconstruct min/maxDepth）、线平面门（linePlaneGateMm）按新工作距离复核。

### Task 4.4 回归＋收口
- 全量 ctest 双绿；开发进度.md 记录；artifacts 归档（新旧标定 DUAL-Z 对照数据）。

## 风险与决策点

| # | 风险 | 应对 |
|---|---|---|
| R1 | CMTT 转换器缺失（最大变数） | 阶段 2.2 提前暴露；缺失则人工裁决补/换路径 |
| R2 | 硬件指纹不一致（阶段 1 失败） | 止损——先解决硬件，标定不做 |
| R3 | factory 算子 drift 大、同步引入风险 | 精度绑定 vs 冻结——按 Task 2.1 清单逐算子人工裁决 |
| R4 | 素材单温度点 → 温度表单档退化 | 记录限制；必要时补采多温度组 |
| R5 | 新档与产线旧档（calibration.json 等）关系 | 阶段 2.3 定连带范围，一次换齐避免混搭 |
| R6 | 测试数据（旧标定采集）与新标定失配 | 验收以现机新扫为准（4.1/4.2） |
