# 设备状态机设计（7 状态模型）

> **日期**: 2026-08-09
> **来源**: `框架整体.md` 增补章节的设计推演（brainstorming 产物）
> **定位**: 仅文档描述（操作员视角的设备/系统状态模型）。现有代码 `framework/service/IState.h::ScannerState` 枚举暂不动，后续另排期对齐。
> **交付物**: 在 `框架整体.md` 新增一节"设备状态机"。

---

## 1. 目标与约束

- 用 7 个**两两互斥、绝不并行**的顶层状态描述扫描仪运行时的全部处境。
- 描述状态间合法转换关系（转换图 + 转换表）。
- 明确各状态的进入/退出条件、活跃子系统、UI 表现、子状态、错误处理。
- 暂停/急停/标定完成等行为**不升顶层状态**，作为子状态/标志/出口事件处理。
- **急停功能不采用**。

## 2. 七个状态

| 代号 | 状态 | 说明 |
|---|---|---|
| **S1** | 初始化 | 软件启动自检：通讯 / 加密狗 / 软件授权文件 |
| **S2** | 待机 | 空闲就绪，所有功能入口 |
| **S3** | 标定 | 多姿态采集→解算标定参数 |
| **S4** | 扫描标记点 | 纯标记点扫描（激光 OFF，ScanMode 二选一） |
| **S5** | 扫描标记点+激光 | 标记点+激光点扫描（激光 ON，ScanMode 二选一） |
| **S6** | 后处理 | 离线 batch 七阶段→出 STL |
| **S7** | 设备故障+自检中 | 设备故障（通讯/温度/GPU）触发；安全停机 + 自检恢复 |

## 3. 转换图

```
                     ┌──────────────────────────────┐
                     │ S1 初始化                     │
                     │ 自检: 通讯/加密狗/授权文件     │
                     └──────────────┬───────────────┘
                          自检通过  │  设备故障 → S7
                                    ▼
        ┌──────────────────────► S2 待机 ◄──────────────────┐
        │        启动标定/扫描/后处理 │                        │
        │        (扫描按 ScanMode     │                        │
        │         二选一 S4 或 S5)    ▼                         │
   ┌────┴───┐  ┌──────────┐  ┌───────────┐  ┌──────┐    完成/  │
   │ S3 标定│  │ S4 扫描   │  │ S5 扫描    │  │ S6   │   停止    │
   │        │  │ (标记点)  │  │(标记点+激光)│  │后处理│  (图标)  │
   └────┬───┘  └────┬─────┘  └─────┬─────┘  └──┬───┘           │
        └───────────┴──────────────┴────────────┘               │
                      (各状态完成→返回 S2)                       │

   ┌──────────────────────────────────────────┐
   │ S1–S5 检测到设备故障 → S7 设备故障+自检中 │
   │   S7 自检通过 → 回"退出前状态"，续作同一会话│
   │   ※ S6 免疫：不进 S7（离线，无设备可停/自检）│
   └──────────────────────────────────────────┘
```

## 4. 转换表

| 从＼到 | S1 | S2 | S3 | S4 | S5 | S6 | S7 |
|---|---|---|---|---|---|---|---|
| **S1** Init | — | 自检通过 | | | | | 设备故障 |
| **S2** Standby | | — | 启动标定 | 启动扫描(标记点) | 启动扫描(标记+激光) | 启动后处理 | 设备故障 |
| **S3** Calib | | 标定完成 | — | | | | 设备故障 |
| **S4** ScanM | | 上位机图标(回待机) | | — | | | 设备故障 |
| **S5** ScanML | | 上位机图标(回待机) | | | — | | 设备故障 |
| **S6** Post | | 后处理完成 | | | | — | **—（免疫）** |
| **S7** Fault | | （恢复目标之一） | （恢复目标之一） | （恢复目标之一） | （恢复目标之一） | | — |

> S7 恢复目标 = 退出前状态（S1/S2/S3/S4/S5 之一），续作同一会话；**永远不回 S6**（S6 从不进 S7）。

## 5. 规则

1. **互斥**：任意时刻只处于 7 状态之一；S3/S4/S5/S6 间无直接跳转，必经 S2。
2. **扫描二选一**：S4、S5 由 ScanMode 在 S2 入口决定；切换需经 S2 重选。
3. **故障恢复续作**：S7 自检通过后回到退出前状态并**续作同一会话**（接续断点，中间留缺口）。依赖检查点机制（当前代码 TODO）。
4. **S6 免疫**：后处理为离线 batch，不走硬件采集路径，**不进 S7**；其 GPU/算法失败由 `Result.status` 返回、操作员处置，不触发安全停机。
5. **S7 安全停机**：进入 S7 即下位机采集全停——**相机停 + 补光灯关 + 激光关**。
6. **S1 非设备类失败**（加密狗缺失/授权无效）不进 S7，留 S1 阻塞并提示。
7. **急停不采用**；扫描启停纯操作员驱动（无自动"扫描完成"退出，覆盖率仅显示）。

## 6. 各状态细化

### S1 初始化
- **进入**：软件启动（`app/main`）
- **退出**：自检全通过 → S2；设备故障 → S7
- **活跃**：模块8（相机枚举 + MCU 通信 + 加密狗/授权文件检查）、模块10（日志）
- **UI**：自检画面，逐项打勾（通讯☑ 加密狗☑ 授权文件☑）
- **子状态**：逐项自检进度
- **错误处理**：设备故障 → S7；加密狗/授权类失败 → 留 S1 阻塞告警
- ⚠️ 依赖未实现：模块8 上电自检、许可证检查（TODO）

### S2 待机
- **进入**：S1 通过 / S3·S4·S5·S6 完成 / S7 恢复
- **退出**：启动标定→S3；启动扫描→S4 或 S5（ScanMode）；启动后处理→S6；设备故障→S7
- **活跃**：模块8 硬件监控（`HardwareMonitor`）、模块3 渲染（空闲视图）、模块10
- **UI**：主界面，功能入口可见，设备状态指示
- **子状态**：无
- **错误处理**：设备故障 → S7

### S3 标定
- **进入**：S2 启动标定
- **退出**：标定完成 → S2（"标定完成"为出口事件，非独立状态）；设备故障 → S7
- **活跃**：模块1 标定工作流、模块9 标定算子、模块8（采集+MCU 触发）、模块3（姿态导引）、模块10
- **UI**：标定导引（姿态提示）、采集进度
- **子状态**：采集中 / 解算中
- **错误处理**：设备故障 → S7；恢复后续作同一会话

### S4 扫描标记点（激光 OFF）
- **进入**：S2 点击**上位机图标**启动扫描(ScanMode=纯标记点) → 落入**就绪**子态
- **退出**：点击**上位机图标** → S2（无论就绪/采集）；设备故障 → S7
- **活跃（就绪）**：设备连接保持、会话已开、渲染待机视图；不出帧
- **活跃（采集）**：相机出帧、模块2（mask_extract+单链·标记点链）、模块9、模块8（激光 OFF）、模块7（覆盖率/帧计数）、模块3 实时渲染
- **子状态机**：见 §7
- **错误处理**：设备故障 → S7（恢复后续作同一会话）；温度异常属设备故障

### S5 扫描标记点+激光（激光 ON）
- 与 S4 结构相同，差别：ScanMode=标记点+激光；模块2 用 mask_separation + **双链并行**（标记点 ∥ 激光）；**激光 ON**

### S6 后处理（免疫，不进 S7）
- **进入**：S2 启动后处理；**前提由操作员全权判定**（系统不做"有无扫描数据"门禁）
- **退出**：后处理完成 → S2
- **活跃**：模块4 离线 batch 七阶段（全局标记点优化→重融合→法线→封装→补洞→光顺→边界优化）、模块9（GBA/法线/网格算子）、模块6（STL 导出）、模块10
- **UI**：后处理进度、当前阶段
- **子状态**：七阶段进度
- **错误处理**：算法/GPU 失败由 `Result.status` 返回（不抛异常、不切状态、不进 S7）

### S7 设备故障+自检中
- **进入**：S1·S2·S3·S4·S5 检测到**设备故障**（通讯断连 / 串口超时 / 温度异常 / GPU 故障）；**不从 S6 进入**
- **进入动作**：**安全停机**——相机停 + 补光灯关 + 激光关
- **退出**：自检通过（设备健康恢复）→ 退出前状态（S1/S2/S3/S4/S5），续作同一会话
- **活跃**：模块8（自动重连/复检的自检循环 + 标记设备离线）、`FaultHandler` 聚合、模块10（故障日志）
- **UI**：故障告警、自检/重连进度、设备离线指示
- **子状态**：自检中 / 重连重试中（含重试次数/退避）
- **错误处理**：本态即错误处理态；重试耗尽仍失败 → 留 S7 持续告警，提示人工介入
- ⚠️ 依赖未实现：续作同一会话需检查点机制（`SessionService::loadCheckpoint` TODO）；故障主动响应链（模块8→FaultHandler 未接）

## 7. S4 / S5 子状态机（就绪 / 采集）

```
                 上位机图标（从 S2 进入）
                         │
                         ▼
                  ┌─────────────┐  扫描仪按键   ┌─────────────┐
                  │  就绪 Ready  │ ──────────► │ 采集 Capture │
                  │ (持连接,不出帧)│ ◄────────── │(实时出帧+算子链)│
                  └──────┬──────┘  扫描仪按键   └──────┬──────┘
                         │                             │
                         └──────── 上位机图标 ─────────┘
                              （就绪/采集任一，点击即退出）
                                    │
                                    ▼
                              S2 待机
```

- **就绪 → 采集**：按扫描仪硬件按键（MCU `KeyEvent`，`MCUDriver` 解析 `"K1;/K0;"`，已实现）
- **采集 → 就绪**：再按扫描仪按键（toggle）
- **任一 → S2**：点击上位机图标（UI 待建）
- **设备故障**：就绪/采集任一子态均可触发 → S7

## 8. 决策记录

| # | 决策 | 选择 |
|---|---|---|
| 定位 | 文档 vs 改代码 | 仅文档描述，代码另排期对齐 |
| 扫描 4/5 关系 | 顺序/二选一/中途切 | **二选一模式**（切换经 S2） |
| 暂停/急停/标定完成 | 顶层状态？ | **子状态/标志/出口事件**（不升顶层） |
| S7 恢复目标 | 恒回 S2 vs 回原态 | **回退出前状态 + 续作同一会话** |
| S6 与 S7 | 真并行 vs 免疫 | **S6 免疫**（顶层仍互斥，不引入并行） |
| S7 范围 | 仅通讯 vs 全设备故障 | **扩展为设备故障**（通讯/温度/GPU） |
| S7 进入动作 | 激光安全？ | **安全停机**：相机+补光灯+激光全停 |
| S6 进入前提 | 系统门禁？ | **操作员全权判定** |
| S6 GPU 故障 | 进 S7？ | **不进 S7**（走 Result.status，保持 S6 免疫） |
| 急停功能 | 采用？ | **不采用** |
| 扫描完成 | 自动？ | **纯操作员驱动**（仅图标点击退出） |

## 9. 落地依赖（按优先级）

1. **检查点机制**（`SessionService::loadCheckpoint` 解析实现）— S7 续作的硬依赖
2. **模块8 上电自检 + 许可证检查** — S1 自检实质功能
3. **故障主动响应链**（模块8 → `FaultHandler::reportFault`）— S7 聚合上报
4. **覆盖率计算**（体素哈希）— S4/S5 采集态显示
5. **UI**（自检画面/扫描图标/故障告警/覆盖率显示）
6. **（另排期）`ScannerState` 枚举对齐**：含就绪/采集子状态、删 EmergencyStop
