## 1. 背景与问题（为什么要改）

设备上有 4 个实体键（中/上/左/右），每键三种按法（短按/双击/长按），共 12 个「手势槽」。现状四个问题：

1. **扫描时调不了亮度**——亮度档位功能做好了，但门禁把扫描中的一切调节键都锁死；而扫描中看到过曝/欠曝，恰恰是最需要调亮度的时候
2. **「视野调节」是空壳**——调节对象里有个 View（视野），按键只在内部记个数，实际什么都不会发生
3. **长按白白浪费**——12 槽里 6 槽（两个长按＋左右键的双击/长按）一直空着
4. **菜单名不副实**——菜单①②叫「正常/大视野扫描」，实际只做扫描模式落地，跟视野（分辨率）毫无关系；真正的分辨率入口在屏幕界面

**不动的东西**：按键裁决骨架（手势→门禁→查表→动作）、菜单纯记账、模式三档（精细/深孔/普通交叉）、中键短按启停、中键双击切模式、标点扫描隔离——真机已验证，全部保留。

## 2. 方案选型（B · 档位梯泛化）

三个候选：A 打小补丁——视野用临时计数凑合，概念搞成两套，以后返工；**B 档位梯泛化（选定）**——把现有亮度梯抽成通用「梯子」，亮度梯和显示远近梯共用一套步进规则；C 推翻重来——取消菜单层，风险大、真机习惯全作废。选 B：四个问题全覆盖，又不推翻已验证的骨架。

## 3. 整体方案：三大主机制（接收 → 裁决 → 执行）

```
MCU 判手势 ──G01──► ① 接收（手势环）──► ② 裁决（门禁＋转移表＋功能口）
                                                        │
                                     ③ 执行（三轨路由：设备轨/账本轨/事件轨）
                                                        │
                              3.4 UI 同步与留痕（菜单/档位/反馈事件＋拦拒原因＋快照兜底）
```

一句话：**接收靠「环」、裁决靠「上下文＋两道关卡＋一张表」、执行靠「三轨路由」**。

### 3.1 接收机制——手势怎么进来（保持现状，本轮不动）

- **谁判手势**：MCU 判（1短/2双/3长），PC 只收结果 `G01 <键><位>`——判定口径单源，PC 侧不重判
- **怎么缓存**：独立 SPSC 手势环（深 64、环满丢新＋0x0806 报警）——与温度/计数分环，互不挤占
- **谁搬运**：逻辑线程每拍（10ms）pump 排空——单消费者、顺序天然保证
- 解析失败计数留痕；洪峰 100 帧不崩已有测试钉死

### 3.2 裁决机制——放不放行、派给谁（本轮改造重心）

**一次判定、一组上下文（手势＋KeyContext）、两道关卡（门禁层＋功能口）、两种结果（拦/拒）。**

#### 3.2.1 裁决输入：KeyContext（一次组装）

- 裁决所需的全部状态由逻辑线程每拍组装成一个只读结构：**界面态**（主界面/菜单/①⑤子态）、**菜单账本**（游标/调节对象/模式光标）、**模式态**（标定/标点）、**采集态**、**就绪凭据**、**自检态**
- 单一属主＝逻辑线程、无锁——杜绝多源拼接竞态；对外只出快照口（与既有 menuState/参数快照同款纪律）
- 就绪凭据：app 调就绪置位、收尾/重置/取消清位——启停与切模式的业务前置

#### 3.2.2 手势总表（12 槽，按主界面／菜单里两态对照）

| 手势 | 主界面 | 菜单里 |
|---|---|---|
| **中·短按** | 启停扫描 | 选中当前项（①-⑤） |
| **上·短按** | 进菜单 | 退菜单 |
| **左/右·短按** | 调当前对象档位（左降/右升一档） | 光标左移/右移 |
| **中·双击** | 切扫描模式（标点会话拒，现状） | 丢弃（仅主界面生效） |
| **上·双击** | **景深直切：近景深（默认）↔远景深（新增）** | 丢弃（仅主界面生效） |
| **左·双击** | **换调节对象：亮度↔显示远近（新增）** | 丢弃（仅主界面生效） |
| **右·双击** | 预留 | 预留 |
| **中·长按** | **急停（新增）** | 急停（全域一致） |
| **上·长按** | **一键回主界面（新增）** | 回主界面（全域一致） |

**三条规则**：

1. **短按随界面变**：中键＝启停↔选中；上键＝进↔退；左右键＝调档↔移光标（菜单优先于调节）
2. **双击一律仅主界面**：切模式/景深直切/换调节对象都在主界面生效，菜单里双击＝一律丢弃（效果被菜单盖住看不见）
3. **长按全域一致**：急停/回主界面不分界面；左右长按预留

**功能清单**（同一手势按所在界面分两种功能，共 11 项＋预留 3 槽）：

- 扫描启停——中键短按（主界面）
- 菜单五项（分辨率设置/进入就绪/扫描完成/后处理/重置）——中键短按选中（菜单里）
- 切换扫描模式——中键双击
- 急停——中键长按（新增）
- 进菜单——上键短按（主界面）
- 退菜单——上键短按（菜单里）
- 景深直切（近景深↔远景深）——上键双击（新增）
- 一键回主界面——上键长按（新增）
- 换调节对象（亮度↔显示远近）——左键双击（新增）
- 菜单光标左移/右移——左/右键短按（菜单里）
- 亮度档/显示远近档升降——左/右键短按（调节时）
- 预留 3 槽——右键双击＋左右键长按（本轮不启用）

#### 3.2.3 门禁层——按 10 态拦（第一道关卡）

- **真免门禁只留逃生类**：急停、回主界面——任何时候都不拦
- **其余四类（启停/切模式/调节/菜单）都问门禁**：门禁闭包签名升级为 **gate(类别)**——KeySemantics 按手势定类别，app 注入的闭包按「类别＋10 态」答话（08 内部态谓词〔自检/标定/凭据/标点〕在装配时组合进闭包）；KeySemantics 保持纯函数、08 始终不认识 10
- 门禁按 10 态查：**S1/S3/S6/S7 四个全拦态一律拦**（按键无效丢弃）；S2/S4/S5 放行，交给功能口细分
- 收紧一处：**双击一律只在主界面生效**（切模式/景深直切/换调节对象）；菜单里双击＝丢弃记日志（效果被菜单盖住，看不见）

#### 3.2.4 功能口拒——放行后的业务前置（第二道关卡）

放行态里「能走到、不能开」的组合在功能入口拒绝并**带原因码留痕**（真机排障直接查）：

- S2 未就绪（启停/切模式/景深/调节）
- S4 标点隔离（切模式）
- ①防呆（扫描中改融合密度）
- ②③④⑤经命令通道三关拒（已在会话/无会话/未收尾）

#### 3.2.5 七态约束矩阵（定稿口径）

裁决依据的「状态」分三层（各管各的）：

- **设备层**：采集开/关（真相源＝08 的采集记账）
- **会话层**（02 扫描工作流）：无会话 → 就绪 → 扫描中 → 停采保活 → 完成

**矩阵规则**：

1. **总前提**：设备已开机——按键靠下位机上报，串口没接线就没有按键
2. **S1/S3/S6/S7＝除逃生类全拦**：自检期/标定期（参数与流程预设死，不给按键打扰）/后处理期/故障期——按键一律无效
3. **后处理仅待机可用**：④行全表唯一 ✓ 在 S2
4. **调节全家只在扫描态**：景深/**调节档位（亮度/显示远近，不含菜单①的体素密度档）**/切模式/启停只在 S4/S5——待机时没有预览画面，调了看不见；S2 一律拒（未就绪）
5. **标点隔离**：S4 除切模式（拒·标点隔离）、②（拒·已在会话）、④（拒·未收尾）外，其余照常
6. **①仅 S2**：分辨率设置只在待机放行；S4/S5 拒\*（防呆见表注）
7. **②仅 S2**：菜单②就绪只在待机放行；S4/S5 拒（已在会话）——收尾只走菜单③，不提供「扫描中关旧开新」捷径
8. **⑤重置 S2/S4/S5 可用**：二次确认防误触（游标停⑤→再按中键执行，其他键取消）；S4/S5＝停采＋撕会话**不落库**＋清数据回 S2；S2＝清残留工作集——毁灭性操作与③（合账落库保数据）互补成对
9. **执行分两层**：门禁只拦四个全拦态（真免门禁仅逃生类，启停/切模式/调节/菜单四类都问门禁——app 注入闭包查 10 态，08 不认识 10）；放行态的细分场景由功能口拒（就绪凭据＝app 调就绪置位、收尾/重置/取消清位；标点隔离；①防呆；②③④⑤走命令通道三关）

### 3.3 执行机制——派出去怎么干

**设计原则（两轨制）**：按键分「设备/业务」两轨——设备轨按键只动硬件与设备记账，**业务态不归按键直接驱动**，全局态由屏幕命令通道迁移。例：M 键停采后全局态可能仍显示「扫描中」——设备停了、会话还活着，收尾要走菜单③。

**三轨路由**（按出口性质分流，各走既有通道）：

- **设备轨**：N10/N11/N14 命令直发（既有 post 编队）；急停内联直调不经二次编队（≤1 拍延迟）
- **账本轨**：MenuLogic/梯子/ParamStore——逻辑线程同步改账
- **事件轨**：EventBus 派发（**UserDefined p1 编号段**：menuSelect=101-105、菜单变化=110、档位变化=111-114〔亮度/远近/体素/景深〕、执行结果=120+〔拒因码等〕——与既有参数事件 p1=0-3 隔离防撞车）→ app 消费 → 命令通道三关——业务流程全在这轨

**一本账（账本四层）**——所有入口（按键/UI）读写同一本账：

| 层 | 记录 | 说明 |
|---|---|---|
| 参数账 | 曝光（相机）＋补光/激光（N10 两参）＋**拍照频率（固定值——现默认 120Hz，无任何调节入口，仅 N10 组帧读取）** | 逐设备生效值：钳制域＋来源＋确认态；曝光/激光/补光＝**亮度梯的投影**——唯一合法写入口是换档，**禁止绕过梯子直改三参**；**对比度不入账**——厂家标定固定值（与光圈、焦距同属出厂调死项），随相机配置下发，用户不可调 |
| 档位账 | 亮度档 1-20／显示远近 1-5／体素密度档（菜单①）／景深近-远 | 档号＋档值表（产线可整体注入替换）；**档号＝真相源**（三参只是投影） |
| 交互账 | 界面层/游标/①⑤子态/调节对象/模式光标 | MenuLogic（会话级，open 复位） |
| 凭据账 | 就绪凭据／当前扫描模式 | 启停与切模式的业务前置 |

纪律全账统一：入口即钳 → 生效才改账 → 在途后值胜出 → 防抖落盘（**只落档号**——三参开机由档号展开，频率固定不落）。

**换档事务性**：档切换跨「相机直设＋N10 重发」两段生效——**两段全成才提交档号**并广播；任一段失败＝档号回弹＋拒式留痕——档位账与参数账永不分家。在途时再来换档请求＝**后值胜出**（同参数在途机制：后到的目标档覆盖在途目标，基于目标档继续两段流程）。

**执行顺序（先相机、后下位机）**——相机配置（曝光＝账本值＋对比度＝厂家固定值，同步生效）→ 下位机命令（N10 灯参／N11 启停）→ 事件广播。先相机是为了参数在出图前生效（否则头几帧旧参数废帧）；任何入口进来同序，逻辑线程单队列保序：

| 场景 | 顺序 |
|---|---|
| R1 调节类（调档/改参） | 相机直设（曝光＋固定对比度）→ N10 灯参重发（采集中即时／空闲记账）→ 档位事件；两段全成才提交档号（见换档事务性） |
| R2 启停类 | **开采**：相机流先就绪 → N10 账本全参 → N11 H1（既有开采集链维持）；**停采**：N11 H0 灭触发 → flush → 相机停流（既有收口序——先灭触发再停流，「先相机」总则不适用于停采侧） |
| R3 多目标分发 | 同一变化 → 相机 → MCU → UI 依序 |

**一条红线**：出口回调内禁止再 publish/post（EventBus 同步派发持锁重入纪律）。

**一个尾巴**：每个出口执行后统一留痕（手势→判定→出口→耗时；拦/拒带原因码）＋经 UI 同步事件通知界面（见 3.4）——反馈是执行的收尾步骤。

#### 3.3.1 设备轨：急停与回主界面（两个长按新功能）

- **中键长按＝急停**：立刻停扫描＋所有灯全灭，一步到位；不在扫描中就只全灭灯，重复按不出错。只把设备打回安全状态，**不碰工作流、不关会话、不写参数盘**
- **上键长按＝回主界面**：不管菜单翻到哪、调节对象选的哪个，一键全部退掉回到干净状态（调节对象回默认亮度）；扫描模式与景深档的选择不动（那是业务状态，不是界面状态）
- 两者职责分开：中键长按管设备，上键长按管界面，互不代劳
- **急停的边界**：纯设备动作（停采＋灭灯），不改会话态、不改全局态、不落参数——状态机对急停「无感知」，后续走向由人决定（重新 M 键开扫，或走菜单③收尾）

#### 3.3.2 账本轨：档位与景深（三梯一档）

梯子＝台灯亮度档：右键升一档、左键降一档，到顶/到底再按无效（不绕圈），整张档位表可整体换。

- **亮度梯**（现状扩展）：每档＝曝光＋激光＋补光三个值一组，**内置 20 档**（具体档值表待产线对账）；调档写进参数记录，扫描中立即重新下发生效；UI 侧仅一根预设档滑条（与按键同梯同账），不提供三参单独调节控件
- **显示远近梯**（新增）：上位机显示端摄像机的远近预设，**共 5 档**；只改预览观看的远近，不碰采集参数；调节对象选中它后左右键步进，档位变化经事件广播给界面消费
- **景深档**（新增，双态直切，不是梯子）：近景深（默认）↔远景深，上键双击直接互换；**两档分辨率完全相同**，区别只在计算侧——只对相应景深区间内采到的图像做计算，激光匹配算法对不同景深区间做了屏蔽，切档＝换屏蔽区间；纯电脑处理侧参数，**扫描中切换立即生效**；屏蔽区间数值与激光匹配侧（07/09）的对接通道实施期对账〔待确认〕
- **体素密度档（菜单①内调）**（新增）：三维点云融合的体素哈希表密度预设——**采集图像分辨率不变**，换档＝改融合密度并按新密度重算点云；仅待机可调（见 3.3.3）
- **调节对象无「不调节」态**：账本上亮度↔显示远近永远二选一（默认亮度）；就绪后的主界面左右键在调当前对象——待机（S2）按下被拒（未就绪，见七态矩阵）；退出调节＝上键长按回主界面（对象回默认亮度）
- **档位可见**：界面能读到「亮度第几档/共几档、显示远近第几档/共几档、体素密度第几档（菜单①内）、当前景深是近还是远」——解决「按了半天不知道调到哪」的盲区

#### 3.3.3 账本＋事件轨：菜单五项重定义

菜单五项（原①「正常视野」②「大视野」删除——模式落地由中键双击即时完成，原①②一直是重复路径）：

- **①分辨率设置**——仅待机（S2）可用：选中后游标停在①，左右键直接切换档位（菜单内当场调，中键确认退出）。**采集图像分辨率不变**，换的是三维点融合的体素哈希表密度，换档按新密度重算点云——扫描中途改会打断累积，故 S4/S5 下游标可停在①、选中拒绝留痕
- **②进入就绪状态**——备好扫描会话但不开始采集，等设备 M 键开扫（就绪流程；屏幕模式键入口保留，菜单成第二入口）
- **③扫描完成**——收尾扫描会话：合账落库＋后台全局优化
- **④后处理**——进入后处理工作流
- **⑤重置**——丢掉当前全部会话数据、清零、回到待机（S2）：扫废了重来的总闸。与③相反：③合账落库**保数据**，⑤一切**归零不落库**。**二次确认防误触**：选中⑤进入确认子态（游标停⑤），再按一次中键＝执行，其他任意键＝取消——与①的子态同款交互模式

**子态与选中后的菜单处理**：

- **逃生类优先于子态**：急停/回主界面在①⑤子态内照常执行，并顺带解散子态——「任意键取消」不得吞掉全域逃生键
- **子态取消语义统一**：①⑤子态内，除各自功能键（①：左右切档/中键确认退出；⑤：中键确认执行）与逃生类外，**任意键（含 U 短按）＝取消子态、回菜单浏览态**——不直接退菜单，退菜单在回浏览态后再按 U 短
- **选中②③④＝执行并自动退菜单**（执行反馈交横幅/本地提示，屏幕回主视图不挡预览）；①⑤选中后先进子态、菜单保留（子态结束才退）

事件分工：①设备内部处理不发事件；②③④⑤派发事件（编号＝100＋游标值，即 102/103/104/105——与既有参数事件 p1=0-3 隔离防撞车）。查证实况：这类事件目前无订阅者（屏幕按钮走另一条命令通道）；②⑤需 app 新增消费（②接就绪流程；⑤新建重置命令——停采→撕会话不落库→清容器→回 S2），③④暂留观测、将来接线。**实现注意**：就绪凭据须在 10 转态完成后置位（防窗口期 M 键误放行）；⑤重置命令需 10 具备对应合法转态边（复用完成边或新增）；⑤清残留范围含编辑模块 pending 删除登记（05）——均实施期对账。

### 3.4 UI 交互与同步——执行的显示面

**原则**：按键接收并执行的信息内容要在 UI 界面显示，UI 相关参数同步更新。

**显示面清单**：

| 显示区 | 内容 | 通道 |
|---|---|---|
| 菜单视图 | 菜单五项＋游标位置；①子态体素密度当前档/档值；⑤子态「再按中键确认重置」 | 菜单面板＋**菜单期常驻大字横幅**（当前项名/子态提示）；菜单变化事件＋menuState() 快照（扩子态字段） |
| 档位面板 | 亮度第几档/共几档、显示远近第几档、体素密度第几档、景深近/远 | 档位变化事件＋ladderInfo() 快照 |
| 参数区 | 亮度＝**一根预设档滑条**（20 档，与按键同梯）；三参当前值（曝光/激光/补光）**只读显示**——UI 不提供三参单独调节控件 | 档位/参数变化事件→滑条与数值同步 |
| 执行反馈 | 拒因（未就绪/标点隔离/防呆…）、急停已执行、切模式后当前模式、调档/换对象/景深切换的瞬态确认 | 按键执行结果/档位变化事件 → **顶部大字横幅（仅按键来源——UI 来源走本地提示不横幅，P8）** |
| 会话区 | 就绪窗口（既有）；⑤重置执行后回待机界面 | 就绪既有链＋重置命令收尾 |

**同步机制**：**事件推送为主（变化即通知）＋快照口兜底（UI 启动/重连/事件丢失时读一次全量对齐）**：

- 新增一族 UI 同步事件（暂用 UserDefined，**p1 编号段**：菜单变化=110、档位变化=111-114、执行结果=120+；事件载荷〔param2/3 内容〕实施期定；base 专用事件类型＝既有 Important #4 待办，过会后换）
- 显示远近档事件同时驱动 03 显示端摄像机远近（跨模块消费点之一）
- menuState() 快照扩展子态字段（①调节中/⑤确认中）——屏幕同步渲染菜单与子态

**双向对齐**：亮度在 UI 只有**一根预设档滑条**（20 档）——拖滑条＝换档，与按键左右键操作**同一把梯、同一本账**，两个入口永远在档上，不存在「档外值」；三个参数（曝光/激光/补光）在 UI **不提供单独调节控件**，仅随档只读显示（参数仍记账供设备组帧；**落盘只落档号**，三参开机由档号展开）。

**远距可读（顶部大字横幅）**：操作者持设备距屏幕数米、注意力在工件上——所有瞬态反馈（拒因/急停/切模式/调档/换对象/景深切换）一律用**屏幕顶部大字横幅**呈现，一瞥即懂：

- 形态：顶部全宽条带、半透明底、高对比大字、**短语＋方向符号**（≤10 字），不遮中央预览画面
- 示例：`亮度 ▲ 第 5/20 档`／`调节：显示远近`／`景深：远`／`模式：精细扫描`／红底 `已急停`／红底 `未就绪`
- 节奏：停留 1.5~2 秒自动消失（远读需稍久），新提示顶掉旧的
- 颜色语义：红＝失败/急停，绿/白＝成功与中性信息
- **菜单期常驻**：进菜单后横幅**常驻不自动消失**，显示当前游标项（`菜单 ▸ ③ 扫描完成`），游标动即刷新、退菜单消失；①子态显 `体素密度 第 2/4 档`；⑤子态变红显 `再按中键确认重置`（毁灭性确认必须远读可辨）。**冲突规则**：菜单期内瞬态反馈（如拒因）插入显示、结束后**自动恢复菜单常驻内容**；①子态切体素档**不单独发横幅**——常驻行内直接刷新档位

本轮不做常驻大状态条与声音辅助（纯视觉反馈）；菜单面板本体维持常规尺寸，远读靠菜单期横幅。

**UI 入口对齐原则（UI 是第二入口，不是另一套系统）**——按键域机制为准，UI 操作翻译成与按键同款的请求，各按类型进同一条通道：

```
      按键入口（G01 手势）              UI 入口（按钮/滑条）
              │                            │
              │  各按类型进同一条通道（无旁路）│
              ▼                            ▼
   参数/档位类 ──► 门面 post 编队队列（08 逻辑线程串行化）
   业务功能类 ──► 命令通道三关（10）——就绪/完成/后处理/重置
   设备动作类 ──► 门面设备轨直调——启停/急停
              │
              ▼
   同一账本＋同一门禁＋同一反馈源（事件/快照）──► 回刷两边 UI
```

| # | 原则 |
|---|---|
| P1 | **一本账**：所有入口读写同一账本（参数/梯子/菜单），UI 不留状态副本 |
| P2 | **同类同通道**：业务功能类（就绪/完成/后处理/重置）→命令通道三关；设备动作类（启停/急停）→门面设备轨直调——UI 与按键各按类型进同一条，无旁路 |
| P3 | **一门禁**：七态矩阵同时约束按键与 UI 控件（置灰同步；真把关在三关/功能口——置灰只是体验优化） |
| P4 | **无旁路**：UI 不得绕过门面直调底层 |
| P5 | **回显阻断**：账本→UI 回显时阻断信号，防环路（回显只刷显示不再发请求） |
| P6 | **离散提交**：滑条按档离散刻度、松手（或值稳定）提交终值——拖动中仅预览 |
| P7 | **后到胜出**：并发无入口优先级，账本最终一致 |
| P8 | **反馈分源**：按键来源→大字横幅（远读）；UI 来源→本地提示；档位/模式横幅仅按键来源触发（UI 来源控件自显，不重复闪） |
| P9 | **不收编**：UI 独有功能（标定/导入导出/编辑工具等）不进按键域，只对齐重叠功能 |

**线程纪律**：EventBus 同步派发持锁——UI 订阅方锁内只拷贝、Queued 投递主线程（MainWindow 状态图标既有红线，沿用）。

## 4. 出错怎么办

| 场景 | 处理 |
|---|---|
| 亮度档下发失败 | 走既有参数链：失败不改账＋弹回广播（现状）；换档场景另加**档号回弹＋拒式留痕**（见换档事务性） |
| 景深/体素/显示远近档的事件没人接或丢失 | 档位账本为准——消费方以档位快照读口对齐兜底（启动/重连时读一次即同步） |
| 急停命令发失败 | 走既有故障码上报通道，急停本身不重试不卡住 |
| 被门禁拦下／功能口拒 | 各记一条日志（拦＝丢弃日志；拒＝带原因留痕） |
| 档到顶/到底 | 静默无效＋调试日志（现状） |

## 附录 A · 名词说明（词汇表）

- **扫描模式**——激光打法，按扫的对象分三档：精细（扫细缝细节）、深孔（扫深腔内壁）、普通交叉（常规面片，默认）；中键双击轮换（仅主界面）
- **开始/停止扫描**——中键短按的来回切换：就绪后没在扫＝开始（相机出图、激光按当前扫描模式打光采数据；未就绪按下会被拒）；正在扫＝停止（停止出图、激光灭灯）。只管设备层面的启停，**不结束扫描任务**——停了再按能继续，已采的数据不丢；真正收尾走菜单③「扫描完成」
- **分辨率设置（菜单①）**——选中后游标停在①，左右键当场切换档位，中键确认退出。注意：**采集图像的分辨率是不变的**，换的是三维点融合的**体素哈希表密度**（体素越小、点云越密越细），换档会按新密度重算点云——扫描会话中途改会打断累积，所以只在待机（S2）可用，扫描中选中会被拒绝
- **就绪状态（菜单②）**——扫描前的准备态：先把扫描会话备好（建账、备容器）但不开始采集，等按设备 M 键才真正开扫；相当于「子弹上膛」，备好后随时可扫
- **扫描完成（菜单③）**——一次扫描的收尾：结束会话、把采集数据合账落库，并在后台自动跑全局优化（整体修正累积误差）；之后想再扫需重新就绪
- **后处理（菜单④）**——对已完成的扫描数据做成品加工，输出最终可用的模型
- **重置（菜单⑤）**——丢掉当前全部会话数据、清零、回到待机：扫废了重来的总闸；与③相反（③保数据落库，⑤全丢）；选中后需再按一次中键确认执行（防误触），其他键取消——急停/回主界面例外（照常执行并解散子态）
- **景深档**——计算范围的档位：近景深（默认）只算近处景深区间内采到的图像，远景深只算远处区间；**两档分辨率完全相同**，区别只是激光匹配算法对不同景深区间做了屏蔽、切档＝换屏蔽区间；上键双击直切，扫描中切换立即生效
- **亮度档**——曝光＋激光＋补光三个值绑成一组预设（像台灯亮度档），调一档三个值一起变，内置 20 档；屏幕上只有一根档位滑条，三个参数不单独给调节钮
- **对比度（厂家固定）**——相机增益，与光圈、焦距同属厂家标定时调死的固定项：随相机配置下发、不进账本不进梯、用户不可调
- **拍照频率（固定）**——相机触发拍照的固定节拍（N10 H，现默认 120Hz）：无按键手势、无 UI 滑条，任何入口都不可调，仅 N10 组帧读取
- **显示远近档**——上位机显示端摄像机的远近（预览画面拉近/拉远），共 5 档；只影响看的远近，不影响采集
- **调节对象**——左右键当前在调什么：亮度或显示远近，账本上永远二选一（默认亮度），左键双击切换；就绪后（S4/S5）按键才实际生效，待机按下被拒
- **升/降一档**——右键升、左键降；到顶/到底再按无效，不会绕回另一头
- **急停**——立刻停扫描＋所有灯全灭，只把设备打回安全状态，不碰别的
- **回主界面**——菜单、调节状态一键全退，回到干净初始界面；扫描模式和景深档的选择保留
- **主界面／菜单里**——没翻菜单时＝主界面；正在翻菜单＝菜单里。同一个键在两处干的事不同
- **标点扫描**——只扫标志点的会话；期间除扫描模式（激光打法）切换无效外，其余按键功能照常可用
- **预留槽**——手势位置留出来了但暂时没分配功能，以后要加就用它
