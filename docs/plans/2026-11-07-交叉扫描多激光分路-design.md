# 交叉扫描多激光分路 方案设计

> 日期：2026-11-07
> 状态：设计稿（待人工确认后实施）
> 前置：左斜/右斜/精细/深孔 四类激光已完成标定；中竖（E 管）备用未标定

---

## 一、目标

单一扫描会话中 MCU 同时开启多管激光（T/V/C/D/E 任意子集），逐帧轮流触发。软件按相机时间戳判定每帧的激光管类型，路由到对应的 CMTT 标定表进行匹配重建，结果统一融合到同一片点云。

## 二、激光管与标定表

| 管号 | N10 参数 | 类型 | 线数 | CMTT 表文件 |
|---|---|---|---|---|
| T | laserT | 左斜 | 25 | `curve_map_temp_table_T.bin` |
| V | laserV | 右斜 | 25 | `curve_map_temp_table_V.bin` |
| C | laserC | 深孔 | 1 | `curve_map_temp_table_C.bin` |
| D | laserD | 精细 | 7 | `curve_map_temp_table_D.bin` |
| E | laserE | 中竖 | 25 | `curve_map_temp_table_E.bin`（备用） |

## 三、MCU 协议

N10 命令中启用的管子按固件协议逐帧轮流：
- `T1 V1` → T,V,T,V...（周期 2）
- `T1 V1 C1` → T,V,C,T,V,C...（周期 3）
- `T1 D1` → T,D,T,D...（周期 2）

轮转顺序固定为 T→V→C→D→E（固件已实现，无需改动）。

## 四、帧管类型判定（状态机＋时间戳）

### 4.1 原理

MCU 以固定频率 H 逐帧轮流启用管子（T→V→C→D→E→T...）。软件用**状态机**追踪当前管序，**时间戳**校验丢帧并补偿跳步。

```
状态机：记录当前在轮转序列中的位置，每帧递推一步
时间戳：若帧间隔 > 1.5×帧周期 → 判定丢帧，按丢帧数跳推状态机
```

### 4.2 优势

- **丢帧自愈**：时间戳检测到跳步后自动补偿正确管序
- **无需图像分析**：三维表面上激光线被物体弯曲，无法可靠检测角度
- **确定性**：状态机保证连续追踪，时间戳纠偏
- **四种产品形态全覆盖**：左斜＋右斜交叉、精细、深孔、中竖

### 4.3 实现

```cpp
struct LaserTubeTracker {
    std::vector<int> activeTubes;    // 启用管列表（如 {0,1}={T,V}；{0,1,3,4}={T,V,C,D}）
    int rotationIdx = 0;             // 当前轮转位置
    TimestampMs lastTs = 0;          // 上一帧时间戳（丢帧检测）
    double frameIntervalMs = 16.7;   // 帧间隔 = 1000/H

    // 每帧调用：返回该帧的管类型 ID
    int onFrame(TimestampMs ts) {
        if (lastTs > 0) {
            // 丢帧检测：间隔超过 1.5 帧周期 → 有丢帧，跳推
            const int64_t gapMs = ts - lastTs;
            const int missed = static_cast<int>(gapMs / frameIntervalMs) - 1;
            if (missed > 0) rotationIdx += missed;
        }
        const int k = static_cast<int>(activeTubes.size());
        const int tube = activeTubes[rotationIdx % k];
        ++rotationIdx;
        lastTs = ts;
        return tube;
    }

    // 会话启动时重置
    void reset(const std::vector<int>& tubes, double freqHz) {
        activeTubes = tubes;
        rotationIdx = 0;
        lastTs = 0;
        frameIntervalMs = 1000.0 / std::max(freqHz, 1.0);
    }
};
```

## 五、架构改动

### 5.1 核心思路

**流水线代码零改动**——帧在环缓冲区就携带 `laserType`，流水线读帧时按 `laserType` 索引到对应参数集（CMTT 表、线数、阈值等），直接用。

```
帧到达 → LaserTubeTracker 打标 laserType → FrameBuffer(image + laserType)
    ↓
流水线从环缓冲读帧
    ↓
按 frame.laserType 取参数集 → { CMTT, 线数, 阈值, 深度窗 }
    ↓
┌──────────────────────────────────────────┐
│  同一条流水线（代码不变，参数来自帧携带）    │
│  mask → steger → interp → match → recon  │
│  → fuse → 渲染                           │
└──────────────────────────────────────────┘
```

**关键：参数跟着帧走**——不需要独立的分流/路由/切换层。

### 5.2 参数切换实现

```cpp
// FiveChainAdapter 内——参数集（每管一套）
struct TubeParams {
    int tubeId;                       // 0=T 1=V 3=C 4=D
    std::unique_ptr<CmttReader> cmtt; // 各管 CMTT
    int expectedLineCount;            // T/V=25 C=1 D=7
    double matchThreshold;            // 各管匹配阈值
    double depthMin, depthMax;        // 各管深度窗
};
std::map<int, TubeParams> tubeParams_;  // 按管 ID 索引

// 帧处理时——按 laserType 选参数，传给现有流水线
void processLaserFrame(const FrameData& frame) {
    const auto& params = tubeParams_[frame.laserType];
    // 现有流水线照跑，只是参数来自 params 而非硬编码
    runPipeline(frame, params.cmtt.get(), params.expectedLineCount, ...);
}
```

## 六、部署清单

### 6.1 每管标定产物

每管需要**完整的 `laser_calib_XXX.json`** ＋ **CMTT sidecar 二进制**：

```
config/
├─ laser_calib_T.json                      ← 左斜标定结果（PJC＋外参＋温补＋CMTT meta）
├─ laser_calib_V.json                      ← 右斜
├─ laser_calib_C.json                      ← 深孔
├─ laser_calib_D.json                      ← 精细
├─ curve_map_temp_table_T.bin              ← 左斜 CMTT（sidecar）
├─ curve_map_temp_table_V.bin              ← 右斜 CMTT
├─ curve_map_temp_table_C.bin              ← 深孔 CMTT
├─ curve_map_temp_table_D.bin              ← 精细 CMTT
└─ curve_map_temp_table.bin                ← 单管兼容回退（保留）
```

## 八、风险与约束

| 风险 | 缓解 |
|---|---|
| GPU 内存×N（每管一组 CMTT ~49MB） | 按需装载（只装激活管）；显存监控 |
| 丢帧后时间戳计算偏差 | 帧间隔取整消抖；首帧时间戳从硬件触发取 |
| 单管 CMTT 质量差（DEGRADED） | 各管独立验收；差的管可单独关闭 |
| 五链 v1 限制（暂停/续扫不支持） | 交叉扫描会话不支持暂停（限制继承） |
| 中竖（E 管）未标定 | config 中不启用；标定后加入即可 |

## 九、兼容性

- 单管模式（仅 T1）：行为与现在完全相同，`laser_tubes.active = [0]` 即回退
- 不改 CMTT 表格式（每张表独立，与现有工厂标定产物兼容）
- 不改 MCU 固件（轮转协议原生支持）
