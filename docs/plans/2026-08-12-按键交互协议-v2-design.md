## 0. 版本变更与架构决策

### 0.1 v1.0 → v2.0 变更

| 维度 | v1.0 | **v2.0** |
|---|---|---|
| 手势种类 | 短按 / 连按2下（2 种） | **短按 / 双击 / 长按（3 种）** |
| 序号 seq_no | MCU 维护并发送 | **取消**——PC 自维护计数 |
| MCU 状态 | 4 个计数器 | **零业务状态**（只剩手势判定计时） |
| 报文长度 | `KMS1;`（变长，含数字） | **`KMS;`**（定长 4 字符） |
| 丢包自检 | 有（seq 跳变可检测） | **无**（接受静默错位风险，靠 UI 反馈缓解） |

**关键澄清**：原 §3.1 的"连按2下"语义**完整保留为"双击"**——并非改成长按。新增的"长按"是 §3.1 未用到的**预留手势**，将来赋功能不需动下位机固件。

### 0.2 三项架构决策（v2.0 已确认）

| # | 决策 | 含义 |
|---|---|---|
| 1 | **MCU 仅做手势分类 / PC 做一切语义判断** | MCU 只判定短按/双击/长按（硬件近端时序活儿）；所有计数、菜单、动作映射全在 PC |
| 2 | **隐式反馈（无专用 ACK）** | PC 不回专用确认报文；接受→翻译为已有 N10–N16 或本地执行，拒绝→默默丢弃 |
| 3 | **定长报文 `K<ID><手势>;`** | 上行报文格式：键号字母（U/L/M/R）+ 手势字母（S/D/H），定长 4 字符 |

**链路性质**：本协议为 **MCU→PC 单向上行扩展**，与协议表 N10–N16（PC→MCU 下行）正交，不冲突、不替代。

## 1. 总览与分工

### 1.1 职责切分

| 侧 | 负责 | 不负责 |
|---|---|---|
| **MCU**（下位机） | 消抖；测量按下时长/点击间隔；判定短按/双击/长按；按约定格式上报 | 不计数；不知菜单层级；不判扫描就绪；不映射动作 |
| **PC**（上位机） | 维护奇偶/游标计数器；菜单层级状态机；扫描就绪门控；动作映射→翻译 N10–N16 或本地执行 | 不管消抖/手势判定 |

设计意图：MCU 固件最简（零业务状态，只剩手势判定计时）；所有交互逻辑全在 PC 侧，随时迭代不牵动下位机发版。新增功能（赋值给预留的"长按"等）只改 PC。

### 1.2 端到端报文流示例

中键短按，PC 据自身奇偶计数决定开始/停止采集：

```
用户按中键 → MCU 消抖+判=短按 → 上行 "KMS;"        （MCU 不计数，只发手势）
PC 收到 → 查 parity[M][S]（PC 自维护）
        → 当前奇数 → 请求开始采集
        → 扫描就绪? 是 → 发 "N11 H1;" + 置"采集中" + parity++
                       否 → 丢弃(隐式) + parity 不增
```

### 1.3 与现有协议表的关系

- 协议表 `下位机协议命令列表.xlsx` 覆盖 **N10–N16**（PC→MCU 下行命令），**无按键定义**。
- 现 MCUDriver 解析的 `K1;/K0;`（匿名、单按下/松沿）**不在协议表中**，属历史临时实现，由本协议替代。
- 本协议填补"按键上行"空白，与 N10–N16 各走各的道。

## 2. 上行报文格式规约

### 2.1 BNF 文法

```
key_report ::= "K" key_id gesture ";"
key_id     ::= "U" | "L" | "M" | "R"      ; 上/左/中/右
gesture    ::= "S" | "D" | "H"             ; S=短按, D=双击, H=长按(Hold)
```

**定长 4 字符**，无数字、无变长。用 `H`（Hold）表示长按，避开与 `L`（左键）的视觉冲突。

### 2.2 字段编码

| 字段 | 取值 | 含义 |
|---|---|---|
| 前缀 | `K` | 固定，标识按键事件（保留与历史 `K1;/K0;` 同前缀） |
| `key_id` | `U` | 上键 |
|        | `L` | 左键 |
|        | `M` | 中键 |
|        | `R` | 右键 |
| `gesture` | `S` | 短按（按下→松开，单次，时长 ≤ `T_short`） |
|          | `D` | 双击（`T_short` 内两次合法短按） |
|          | `H` | 长按（按下持续 ≥ `T_long`） |

### 2.3 全部 12 种合法报文（4 键 × 3 手势）

| 键 | 短按 `S` | 双击 `D` | 长按 `H` |
|---|---|---|---|
| 上键 `U` | `KUS;` | `KUD;` | `KUH;` |
| 左键 `L` | `KLS;` | `KLD;` | `KLH;` |
| 中键 `M` | `KMS;` | `KMD;` | `KMH;` |
| 右键 `R` | `KRS;` | `KRD;` | `KRH;` |

### 2.4 PC 解析规则

替代 `MCUDriver::parseReceived` 中现有 `K1;/K0;` 分支：

- 长度 == 4，`data[0]=='K'`，`data[1] ∈ {U,L,M,R}`，`data[2] ∈ {S,D,H}`，`data[3]==';'`。
- 非法/不完整 → 丢弃 + `spdlog::warn`（不阻塞接收线程）。
- 解析结果承载到 `McuEvent`（扩展 `keyId` / `gesture` 字段，或在 `param1/param2` 编码——属实现侧决策）。

## 3. 预定义动作映射表（核心交付物）

> 该表为 PC 侧"按键事件 → 动作"映射规约，PC 据此执行。
> **门控**：所有动作仅在 PC 处于「扫描就绪」态（设备状态机的 **S2 待机**）时生效，否则丢弃（隐式反馈，计数器不增）。

### 3.1 中键（M）

| 报文 | 上下文 | 请求动作 | PC 执行 / 命中命令 |
|---|---|---|---|
| `KMS;` | `menu.layer == 1` 且 `parity[M][S]` 奇 | 开始采集 | 扫描就绪 → `N11 H1;` + `parity[M][S]++` |
| `KMS;` | `menu.layer == 1` 且 `parity[M][S]` 偶 | 停止采集 | `N11 H0;` + `parity[M][S]++` |
| `KMS;` | `menu.layer == 2` | 选中当前项并退出菜单 | 本地：执行选中项 + `layer = 1` |
| `KMD;` | — | 循环切扫描模式 | 本地 `modeCursor = (modeCursor % 3) + 1`：1=精细 / 2=深孔 / 3=普通交叉（默认）；影响下次 `N10` 参数 |
| `KMH;` | — | **预留**（待赋功能） | — |

**要点**：中键短按在 layer1 / layer2 动作不同，且 layer1 内按奇偶分开始/停止——全部由 PC 本地状态分叉，MCU 不知情。

### 3.2 上键（U）

| 报文 | 请求动作 | PC 执行 |
|---|---|---|
| `KUS;`（`parity[U][S]` 奇） | 进入菜单选项（切到第2层） | 本地：`layer = 2, cursor = ①` + `parity[U][S]++` |
| `KUS;`（`parity[U][S]` 偶） | 退出菜单选项（回第1层） | 本地：`layer = 1` + `parity[U][S]++` |
| `KUD;`（`parity[U][D]` 奇） | 进入视野调节功能 | 本地：`adjustCtx = 视野` + `parity[U][D]++` |
| `KUD;`（`parity[U][D]` 偶） | 进入亮度调节（曝光+补光+激光联动，默认） | 本地：`adjustCtx = 亮度` + `parity[U][D]++` |
| `KUH;` | **预留** | — |

**菜单第2层游标 ①–④**：① 正常视野扫描；② 大视野扫描；③ 扫描完成；④ 开始后处理。

### 3.3 左键（L）/ 右键（R）

| 报文 | 上下文 | 动作 |
|---|---|---|
| `KLS;` | `menu.layer == 2` | 游标左移（①←④环绕） |
| `KLS;` | `adjustCtx != none` | 减值（步进由 PC 按 context 定） |
| `KRS;` | `menu.layer == 2` | 游标右移（①→②→③→④→①） |
| `KRS;` | `adjustCtx != none` | 加值 |
| `KLD;`/`KLH;`/`KRD;`/`KRH;` | — | **预留** |

L/R **短按不区分奇偶**（每次按下即一次减/加或左/右移），无计数器。

### 3.4 未规定项（留 PC 实现自定）

- 中键短按在「视野调节 / 亮度调节」子模式内的行为（文档未规定；建议 = 退出该调节子模式）。
- 左/右键步进的粒度（按 context：曝光 ms / 补光 0–255 / 激光 0–255 各自定）。
- 7 个预留手势位（`KMH;` `KUH;` `KLD;` `KLH;` `KRD;` `KRH;`，及中键短按长按等）的赋值。

## 4. MCU 侧契约

### 4.1 时序参数（推荐值，固件实现，标定时可校准）

| 参数 | 推荐值 | 含义 |
|---|---|---|
| `T_debounce` | 20 ms | 机械抖动过滤窗口 |
| `T_short` | 400 ms | 短按最长按下时长 + 双击间隔窗口 |
| `T_long` | 800 ms | 长按触发阈值（按下持续超过此值即判 H） |
| 短按 S 判定 | 按下 → 松开，时长 ≤ `T_short` 且窗口内无第二次按下 | — |
| 双击 D 判定 | `T_short` 内两次合法短按 | 第二次松开后立即判 D |
| 长按 H 判定 | 按下持续 ≥ `T_long`（达到阈值即判，可不等松开） | — |

**手势互斥**：一次物理操作只产生 S/D/H 三者之一。MCU 状态机内部保证：先判 H（按时长），未达 `T_long` 即松开则判 S，`T_short` 内再来一次则升级为 D。

### 4.2 MCU 状态（极简）

- 仅手势判定所需的计时状态（按下时刻、双击窗口）。
- **无业务计数器、无菜单状态、无扫描状态感知**。
- 上电/重启不需要同步任何业务语义（因不持有）。

### 4.3 上报时机

- 每个手势判定完成的瞬间，立即发一条 `K<ID><手势>;`。
- 不批量、不合并、不延时。

## 5. PC 侧状态机契约（消费侧）

### 5.1 门控

所有 `K*` 报文到达后，PC 先查设备状态机当前是否在 **S2 待机**（「扫描就绪」）；非此态 → 丢弃（隐式反馈），且**不推进任何计数器**（保证重入扫描就绪后语义连续）。

> 详见 `docs/plans/2026-08-09-设备状态机-design.md`。

### 5.2 PC 维护的状态

```
state KeyStateMachine {
    // 奇偶计数器（仅"短按/双击"语义需要 toggle 的键）
    parity_M_S: int   // 中键短按：奇=开始采集 / 偶=停止采集
    parity_U_S: int   // 上键短按：奇=进入菜单 / 偶=退出菜单
    parity_U_D: int   // 上键双击：奇=视野调节 / 偶=亮度调节

    // 多态循环游标
    modeCursor: 1|2|3  // 中键双击切扫描模式

    // 菜单状态
    MenuState {
        layer:     1 | 2          // 1=默认/采集层, 2=菜单选项层
        cursor:    ① | ② | ③ | ④  // 第2层游标
        adjustCtx: none | 视野 | 亮度
    }
}
```

### 5.3 动作分叉规则

- **中键短按**：先看 `layer`（layer1→按 `parity_M_S` 开始/停止；layer2→选中退出）。
- **上键短按/双击**：按各自 `parity` toggle。
- **左/右键短按**：`layer==2` → 左/右移游标；`adjustCtx!=none` → 减/加值；否则忽略。
- **中键双击**：无条件推进 `modeCursor`。

### 5.4 与 N10–N16 衔接

| 按键动作 | 翻译为 |
|---|---|
| 中键短按（开始采集） | `N11 H1;` |
| 中键短按（停止采集） | `N11 H0;` |
| 中键双击切模式 | 仅改 PC 本地 `modeCursor`（影响下次 `N10` 采集参数选择） |
| 其他 | PC 本地状态变更，**不发下行命令** |

**不新增下行命令**——本协议纯粹是上行扩展。

## 6. 风险与权衡（v2.0 明确取舍）

| 风险 | 说明 | 缓解 |
|---|---|---|
| **串口丢帧 → 静默错位** | v2.0 无 seq_no，丢一帧则 PC 的 `parity` / `modeCursor` 错一格（如按"开始"却变"停止"） | **UI 显式反馈当前状态**（扫不扫、当前模式、菜单位），用户按一下即可自纠正；串口 115200 丢帧概率低 |
| **PC 重启丢计数** | PC 持有的 parity/cursor 全丢，重启后从默认开始 | 可接受（PC 重启 = 会话重置） |
| **长按误触发** | 用户长按想双击却超 `T_long` | 阈值 `T_long=800ms` 拉开足够裕度；MCU 状态机内部时序优先级保证 |
| **双击与两次短按混淆** | 两次独立短按可能被判为双击 | 这是双击的本质定义；业务上 PC 把"双击"作为独立手势，与"短按奇偶"分属不同键/手势位，不冲突 |

**总取舍**：v2.0 放弃了 v1.0 的丢包自检能力，换来 **MCU 极简（零业务状态）+ 报文定长 + 手势词汇可扩展（预留长按）**。这是 v2.0 的明确设计选择。

## 7. 异常处理与向后兼容

| 场景 | 处理 |
|---|---|
| 报文格式非法（如 `KMX;`、旧 `K1;`、`KMS1;`、`K;`） | PC 丢弃 + `spdlog::warn` |
| 未知 `key_id` / `gesture` | 丢弃 + warn |
| 预留手势位（如 `KMH;`） | PC 暂忽略（或日志 info 级记录"未赋功能"），不报错 |
| 串口丢帧 | 见 §6，靠 UI 反馈自纠正 |
| MCU 重启 | 不持有业务状态，无需同步；PC 侧状态延续（如需严格重置可加 PC 重置入口） |
| 双方版本不一致 | 本协议为上行独立扩展；旧 MCUDriver 解析需同步升级（见下） |

### 7.1 向后兼容

- 现 `E1;`（急停）语义已删（N15 重定义为温度读取，见 `docs/模块功能/08-设备管理.md` §2）。

## 附录 A · 通俗解释（大白话版）

### A.1 「MCU 只判手势，PC 做一切语义判断」

把按键处理想成**两人合作**：

- **MCU（下位机）** = 干"看手势"的体力活：你短按一下？双击两下？还是按住不放？它只判这三种**物理手势**，判完喊一声"中键短按！"——它**不知道这是第几次、在不在菜单、能不能扫**，也不关心。
- **PC（上位机）** = 干"拍板"的脑力活：这次是第几次按？现在在菜单第2层吗？能扫吗？该翻译成什么动作？全由 PC 算。

好处：MCU 固件写一次就稳（零业务状态，永远不用为加功能改版）；所有交互逻辑、奇偶计数、菜单、模式切换都在 PC 上随时改随时发版；**将来加新功能只需给预留的"长按"手势赋值，下位机一动不动**。

### A.2 「隐式反馈，无专用 ACK」—— PC 不回话

MCU 喊完"中键短按"后，**PC 不专门回一句"收到/同意"**。怎么算 PC 同意了？看 PC 有没有动作——

- 同意 → PC 直接干该干的（比如发 `N11 H1;` 启动扫描，或本地切个模式）
- 不同意（比如没在"扫描就绪"态）→ PC **默默丢弃，啥也不干，计数器也不动**

就像你跟同事说"帮我倒杯水"：他倒了就是答应了，没倒就是没答应，不用他先回"收到"。

### A.3 「定长报文 `K<ID><手势>;`」—— 喊话的格式

MCU 喊的那句话固定 4 个字符，比如 `KMS;`：

```
K  M  S  ;
↑  ↑  ↑  ↑
按键 中键 M 短按 S 句号 ;
   （键号字母） （手势字母）
```

- `K` = 开头标记，固定写"这是按键事件"
- `M` = 哪个键：`U/L/M/R` = 上/左/中/右
- `S` = 怎么按：`S`=短按 / `D`=双击 / `H`=长按(Hold)
- 没有数字，永远 4 字符

再举：`KMD;` = 中键双击（切模式）；`KUH;` = 上键长按（预留未用）；`KRS;` = 右键短按（加值/右移）。

### A.4 「MCU→PC 单向上行，与 N10–N16 正交」—— 不打架

- **单向上行** = 这套协议**只从 MCU 往 PC 喊**（汇报按键手势），PC 不会反过来用这套格式回话。
- **与 N10–N16 正交** = N10–N16 是 PC **往下发**的命令（"开机、调亮度、启动扫描…"），是**另一条道**。两套各走各的，互不干扰、互不替代。

**一句话总结**：MCU 只判"短按/双击/长按 + 哪个键"，用一句定长 4 字符的格式话告诉 PC；第几次、在不在菜单、该干啥，全由 PC 自己算——做完就完了，不用回话。
