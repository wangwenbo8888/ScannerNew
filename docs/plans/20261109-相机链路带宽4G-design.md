# 设计：开机双目相机链路带宽默认 4G

- 日期：2026-11-09
- 状态：已批准（用户同日确认）
- 归属：modules/08_DeviceManager（CameraControl）
- 关联在案：《开发进度.md》L64〔H120 USB 带宽饱和（~6Gbps）｜带宽复核/降档/双控｜待定〕

## 背景与目标

相机为大恒 VE2S-301-125U3M/C-S（USB3.0，Galaxy SDK）。其 GenICam 节点
`DeviceLinkThroughputLimit`（界面「设备 → 设备配置信息 → 设备链路带宽限制」）
当前出厂/默认约 3G。目标：软件每次开机打开相机时，将**左右两目**的该限值
统一设为 4G（bps：4,000,000,000），解除人为限速。

依据（查证留痕）：

- GalaxyView translation.xml：`DeviceLinkThroughputLimitMode`（枚举 On/Off）
  ＋`DeviceLinkThroughputLimit`（整数）＋`DeviceLinkCurrentThroughput`（只读）
- 相机文档四份（docs/开发需要的信息/相机/）与 SDK 头文件/示例中无更高层
  速度档；USB3 链路速率本身由物理层协商，本参数是唯一的设备侧带宽限幅器

## 设计

改动仅在 `CameraControl.cpp` `open()` 的双目循环内（`GetRemoteFeatureControl()`
成功后、每侧各执行一次）：

1. `IsImplemented("DeviceLinkThroughputLimit")` 为 false → INFO 日志跳过，
   不报错（机型不支持的防御）
2. `DeviceLinkThroughputLimitMode` → `On`（若实现）
3. 读 min/max/当前值记 INFO（开机日志留 3G→4G 证据链）
4. 设 `DeviceLinkThroughputLimit = 4,000,000,000`；**钳制域**：4G 超出相机
   max 时设到 max 并 WARN（日志说明实际能到多少）
5. 读回验证记 INFO
6. 任何异常 catch → WARN 不阻断 open（限幅是优化项，不杀启动链——与工程
   「读回验证就地收口」风格一致）

## 明确不做（YAGNI）

- 不进 ParamStore 参数表/账本——链路层一次性策略，非用户可调参数
- 不改 `CameraControl.h` / `IScannerCamera` 接口
- 不做相机 UserSet 持久化——代码每次开机都设，换相机/恢复出厂不丢
  （备选 B：仅 GalaxyView 存 UserSet——换机即丢、不在工程掌控，未采纳）

## 验收

- 08 相机层为真机层、无 SDK 单测桩：靠开机日志（设值＋读回＋min/max）验收
- 真机复核由人工执行（AI 工作纪律：不碰真机）
- 预期不改任何现有测试；ctest 08 全量应保持绿

## 已知边界（不因此变更）

- 该参数是限幅器不是加速器：4G 只是解除人为上限，实测仍受 USB3 Gen1
  单控制器实用上限（~3.1-3.5Gbps/口，CameraControl.cpp:72 在案）约束
- 双目 60Hz 合计 ~6Gbps 的带宽饱和问题（261102 在案）不因本改动消失，
  双控方案另行跟踪
