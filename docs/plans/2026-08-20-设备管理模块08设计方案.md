## 2. 串口协议层（SerialPort → FrameCodec → CommandChannel + 上行分流）

### 2.1 帧格式（v2/v3 开关收敛在 FrameCodec 一处）

```
v2（兼容现状，固件未升级期）:  载荷;                ← ';' 分帧，无校验（现状 A1+B2）
v3（目标）:                   $载荷<seq><crc>;       ← seq 2位hex(0~255循环)，crc 4位hex(CRC16-CCITT 查表，覆盖 $…seq)
```

- **半帧超时**（A3）：收到 `$` 后 50ms 无 `;` → 弃挂起缓冲（防干扰字节卡死分帧器）
- **帧长上限 32B**：超出即弃——防御异常流
- **载荷内禁 `$` 和 `;`**——v3 提案温度例 `$T25.3;24.8…` 自带矛盾（载荷含 `;` 与分帧规则冲突），本设计默认改 `,` 分隔（挂 §8 待确认）
- CRC/seq 校验不过 → 丢弃 + warn + 计数（B1/B2）
- 开关来源：`DeviceConfig.protocolVersion` 配置项，非运行时探测

### 2.2 下行命令表（typed 方法 ↔ 协议表 N10–N16 一一对应）

| typed 方法 | 帧示例（v3） | 语义（协议表为准） | 分级 | 业务挂点 |
|---|---|---|---|---|
| `setCaptureParams(H20-120, B0-255, T1-6, V1-6, L0-255)` | `$N10H60B80T1V1L120<seq><crc>;` | 拍照频率 / 背景灯亮度 / 交叉激光选择×2 / 激光亮度 | 关键 | ParamStore 下发、02-D2 |
| `startScan()` / `stopScan()` | `$N11H1…` / `$N11H0…` | 扫描启停（**幂等设态**，连按同值无害） | 关键 | KeySemantics 启停（02-D2） |
| `enterSelfCheck()` / `exitSelfCheck()` | `$N12Z1…` / `$N12Z0…` | 自检开/停 | 关键 | S1 开机自检、S7 故障自检（10 设计 §2.4/§4.5） |
| `enterStandby()` / `exitStandby()` | `$N13E1…` / `$N13E0…` | 进/退待机 | 关键 | `toIdle()` |
| `setHeatTarget(T0-100)` | `$N14T60…` | 设加热温度 | 关键 | WarmupSequence（01-③） |
| `queryTemperature(V0-2)` | `$N15V2…` | 读左/右/全部温度 | 查询（发不等） | 兜底轮询/调试；v2 兼容期巡检取温 |
| `enterCalibration()` / `exitCalibration()` | `$N16B1…` / `$N16B0…` | 进/出标定 | 关键 | `enterCalibration()`（01-②⑨） |

### 2.3 CommandChannel（关键命令可靠性；单发送者=逻辑线程）

```
send(命令): ① seq 自增 → ② FrameCodec 组帧 → ③ SerialPort 写
           → ④ 等 ACK（条件变量，超时 100ms[可配，50/100 待协议方确认]）
           → 超时重发 ≤3 次 → 3 败：Result::fail + Fault 事件 → 10
查询类（N15）：发不等（温度下周期还有——分级 C3）
```

- **单线程属主**=逻辑线程（2026-08-18 已定所有发令走它）；最坏阻塞 300ms 仅故障态，可接受
- **幂等支撑**：N10/N11 为设态语义，重发无副作用——与「显式状态+转移表」互为支撑（v3 文档 §三：漏一条启停命令状态即漂移，故必须可靠）
- ACK 帧 `$A<seq>;` 由逻辑线程在分流时回填 CommandChannel（§2.4）

### 2.4 上行分流（rx 线程零业务；逻辑线程消化）

```
串口rx线程: SerialPort.read → FrameCodec.feed → 完整帧入环形队列（复用 06 SlotRing）[C4]
逻辑线程:   取帧 → CRC/seq 校验 → 按首字符分流：
   T → TempFrame（1~4 路按位收，几路存几路）→ DeviceStateCache + EventBus + Warmup tick
   K → RawKeyEvent{键号 U/L/M/R, 按下/松开, MCU时刻ms} → KeyManager
   S → DeviceStatus{状态码} → DeviceManager 记账（原 3 号灯职责）
   A → Ack{seq} → CommandChannel 匹配（内部消化，不上业务）
   seq 跳变 → 丢帧计数（对账可观测；不重传——按键可重按、状态会再报）
```

- **v2 兼容期回退**：MCU 无主动上报时，巡检线程定时 `N15 V2` 轮询取温（v3 定稿后删——对齐 08 文档「删轮询」目标）
- 硬件层 B3（RS485/屏蔽/磁环）归产线评估，不在本设计代码范围

## 3. KeyManager 手势判定（PC 侧，零业务状态）

- **输入**：RawKeyEvent{键号 U/L/M/R、按下/松开、MCU 时刻 ms}——判定用 **MCU 时刻**（队列排队延迟不干扰手感），PC 接收时刻兜底
- **阈值**（v2.0 §4.2.4 原样迁 PC，构造传入可调）：消抖 20ms（MCU 侧保留 + PC 双保险）/ 短按 ≤400ms / 双击窗口 400ms / 长按 ≥800ms
- **判定时序**：松开且 ≤400ms → **不立即判**，静默等 400ms 无第二次按下才判 S（保双击升级路径）；窗口内第二次按下+松开 → 判 D；持续按 ≥800ms → **达阈即判 H**（不等松开）
- **互斥**：一次物理操作只出 S/D/H 之一；判定即发 KeyGesture{键号, 手势, 时刻}
- **驱动**：逻辑线程 10ms tick 检查超窗/长按阈值（事件驱动+定时兜底）；乱序/超期事件 → 丢弃 + warn
- **不做**：门控、计数、菜单、动作映射——全在 KeySemantics（2026-08-18 既定）

## 4. DeviceManager 门面（2026-08-18 设计全量沿用，本次 4 处增量）

对外窗口（open/close、切模式三口令、startWarmup、getDeviceState、getLastTemperatures、广播事件）与「两条铁规」（不漏零件指针、门禁回调注入不反链 07/10）**原文沿用 2026-08-18 设计 §1.2**。增量：

1. **命令通道接入**：KeySemantics「直接下令」与 ParamStore「下发执行」改经 CommandChannel——**3 败 fail 不改账不切板**（ParamStore「下发失败不改账」有了强制点）；ModeController 擦板改在**命令成功后**（发令→ACK→擦板→广播，防「板已切命令没到」）
2. **切模式命令映射**：`enterCalibration()`=门禁→N16 B1→黑板「标定中」；`toIdle()`=N13 E1；`startWarmup()`=N14 T<目标>；采集启停=查黑板→N11 H1/H0；S1/S7 自检=N12 Z1/Z0
3. **S 设备状态帧记账**：MCU 主动上报的状态码存「设备实际状态」字段；业务模式黑板（PC 意图）与实际状态**并存**，不一致记 warn + 广播（不自动改板——出事只报不动手）
4. **心跳联动**：任意有效上行帧刷新通讯心跳时间戳（供 §5 HardwareMonitor 查）

## 6. 线程模型 + 故障接线

### 6.1 四线程（三已有一定位，零新增线程）

| 线程 | 干什么 | 禁区 |
|---|---|---|
| 串口 rx（已有，提优先级[C7]） | read → 成帧 → 入环形队列 | 零业务零解析（CRC 都不做） |
| 逻辑线程（2026-08-18 已定） | 取帧→校验分流→KeyManager→KeySemantics→账本→CommandChannel 发令→Warmup tick | 不阻塞干等（ACK 最坏 300ms 仅故障态） |
| 巡检线程（已有） | HardwareMonitor 1s：外设层+自检采集+心跳检查→DeviceStateCache+EventBus | 阈值告警（归 10） |
| 调用方线程 | 门面方法；切模式经队列转逻辑线程执行 | — |

### 6.2 故障上报（只报不动手；全走 EventBus Fault 事件，08 不链 10）

2026-08-18 设计 §4 七类异常**全量沿用**（相机掉线/串口无声/温度爆表/温度乱跳/预热超时/按键队列挤爆/命令石沉大海），新增 3 类：

| # | 什么事 | 怎么发现 | 报什么 |
|---|---|---|---|
| 8 | ACK 重传 3 败 | CommandChannel | 哪条命令+等了多久 |
| 9 | seq 跳变丢帧 | 逻辑线程对账 | 计数（超阈值上报） |
| 10 | 通讯心跳丢失 | HardwareMonitor（C6） | 最后收到帧的时间 |

允许做的（不算越界）：重试一遍 / 老实报旧数 / 查询不装好（2026-08-18 §4.2 原文）。
