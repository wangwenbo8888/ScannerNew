## 2. 串口协议层（SerialPort → FrameCodec → CommandChannel + 上行分流）

### 2.1 帧格式（v2/v3 开关收敛在 FrameCodec 一处）

```
v2（兼容现状，固件未升级期）:  载荷;                ← ';' 分帧，无校验（现状 A1+B2）
v3（目标）:                   $载荷<seq><crc>;       ← seq 2位hex(0~255循环)，crc 4位hex(CRC16-CCITT 查表，覆盖 $…seq)
```

- **半帧超时**（A3）：收到 `$` 后 50ms 无 `;` → 弃挂起缓冲（防干扰字节卡死分帧器）
- **帧长上限 32B**：超出即弃——防御异常流
- **载荷内禁 `$` 和 `;`**——v3 提案温度例 `$T25.3;24.8…` 自带矛盾（载荷含 `;` 与分帧规则冲突），本设计默认改 `,` 分隔（挂 §8 待确认）
- CRC/seq 校验不过 → 丢弃 + warn + 计数（B1/B2）
- 开关来源：`DeviceConfig.protocolVersion` 配置项，非运行时探测

### 2.2 下行命令表（typed 方法 ↔ 协议表 N10–N16 一一对应）

| typed 方法 | 帧示例（v3） | 语义（协议表为准） | 分级 | 业务挂点 |
|---|---|---|---|---|
| `setCaptureParams(H20-120, B0-255, T1-6, V1-6, L0-255)` | `$N10H60B80T1V1L120<seq><crc>;` | 拍照频率 / 背景灯亮度 / 交叉激光选择×2 / 激光亮度 | 关键 | ParamStore 下发、02-D2 |
| `startScan()` / `stopScan()` | `$N11H1…` / `$N11H0…` | 扫描启停（**幂等设态**，连按同值无害） | 关键 | KeySemantics 启停（02-D2） |
| `enterSelfCheck()` / `exitSelfCheck()` | `$N12Z1…` / `$N12Z0…` | 自检开/停 | 关键 | S1 开机自检、S7 故障自检（10 设计 §2.4/§4.5） |

### 2.3 CommandChannel（关键命令可靠性；**非阻塞发送 + tick 驱动对账**——审查 A1 修正）

```
send(命令)【逻辑线程调用，立即返回，不等待】:
   ① seq 自增 → 挂待确认表{seq, 帧文, 已重传次数, 到期时刻} → ② FrameCodec 组帧 → ③ SerialPort 写
ACK 回填【逻辑线程分流 A 帧时】: 命中待确认表 → 销项 → 触发完成回调（擦板/改账/广播在此连锁）
超时检查【逻辑线程 10ms tick】: 到期未销项 → 重传（间隔=超时值，≤3 次）
           → 3 败：完成回调(fail) + Fault 事件 → 10
查询类（N15）：发不等（温度下周期还有——分级 C3）
```

- **非阻塞铁规**：send 不得等待 ACK——ACK 的消费与超时判定都在逻辑线程**自己的**分流/tick 里做；若 send 阻塞等（条件变量），同线程的 A 帧分流被卡死，ACK 永远到不了，每条关键命令必 3 败（自锁——本设计曾犯，审查修正，T10 守护）
- **下行单发送口（二轮 R2-A1 修正）**：所有下行帧——含 v2 兜底轮询 N15——**只由逻辑线程发**（§6.1 巡检线程不发命令，只发现「该轮询了」并置标志）；SerialPort 拒绝第二线程并发写（同句柄并发 WriteFile 会字节交错出乱帧）
- **命令组步链（二轮 R2-A2 修正）**：多命令序列（如 enterScan = N13 E0→N10→N11 H1）用**命令组**表达——前一条的 ACK 完成回调里发下一条，任一步 3 败即整组短路：组失败回调（**不擦板**+Fault）；已发命令均为幂等设态，**无需回滚**（重进组即重发同值）；组全部 ACK → 组成功回调（擦板/广播在此）
- **回调短平快铁律（二轮 R2-A3 修正）**：EventBus `publish` 为**同步派发且持锁调用 handler**（base/EventBus.cpp:6）——完成回调/逻辑线程内的广播链若被慢订阅者拖住，ACK 消费与超时对账随之停摆。故：逻辑线程回调内只做内存记账/擦板/入队 + publish；**订阅者回调必须非阻塞**（慢活自入队，对齐 10 设计「handler 非阻塞」审核项 E）
- **待确认表按 seq 键控**：逻辑线程可连续下发多条（如 N13 E0→N16 B1），表容量 8，满则最旧先判超时
- **单线程属主**=逻辑线程（2026-08-18 已定所有发令走它），无锁
- **幂等支撑**：N10/N11 为设态语义，重发无副作用——与「显式状态+转移表」互为支撑（v3 文档 §三：漏一条启停命令状态即漂移，故必须可靠）
- **可靠性随 D3 开关**：v2 模式下 send 发不等、不挂表、不判败、Fault 免报（结果恒 ok「未确认」）——见 §2.5 矩阵

### 2.4 上行分流（rx 线程零业务；逻辑线程消化）

```
串口rx线程: SerialPort.read → FrameCodec.feed → 完整帧按类入两个有界环[C4]：
                                   事件环（K/S/A，容量 64，满丢最旧+warn+计数）
                                   遥测环（T，容量 8，覆盖旧）
            ——环为串口层自带轻量实现（1生产者1消费者），不引 06（分层铁律；
              HardwareMonitor 引 DeviceStateCache 系既有特例——审查 C2 修正）
逻辑线程:   先排空事件环，再取遥测环 → CRC/seq 校验 → 按首字符分流：
   T → TempFrame（1~4 路按位收，几路存几路）→ DeviceStateCache（deviceId 约定 `MCU_T0..T3`，暂名——二轮 C1；帧位↔传感器对应待协议方，§8-3）+ EventBus + Warmup tick
   K → RawKeyEvent{键号 U/L/M/R, 按下/松开, MCU时刻ms} → KeyManager
   S → DeviceStatus{状态码} → DeviceManager 记账（原 3 号灯职责）
   A → Ack{seq} → CommandChannel 匹配销项（内部消化，不上业务）
   seq 跳变 → 丢帧计数（对账可观测；不重传——按键可重按、状态会再报）
```

- **v2 兼容期回退**（二轮 R2-A1 修正口径）：温度**默认沿用现状被动收**——现有固件本就主动推 1 路 `T…;` 帧（MCUDriver.cpp 现状即被动收）；仅当超 1 周期无 T 帧，由**逻辑线程 tick 定时**（非巡检线程）发 `N15 V2` 兜底轮询；v3 定稿后删兜底——对齐 08 文档「删轮询」目标。匿名 `K1;/K0;` 帧丢弃 + warn（按键链整体停用，见 §2.5 矩阵）
- 硬件层 B3（RS485/屏蔽/磁环）归产线评估，不在本设计代码范围

## 3. KeyManager 手势判定（PC 侧，零业务状态）

- **输入**：RawKeyEvent{键号 U/L/M/R、按下/松开、MCU 时刻 ms}——判定用 **MCU 时刻**（队列排队延迟不干扰手感），PC 接收时刻兜底
- **阈值**（v2.0 §4.2.4 原样迁 PC，构造传入可调）：消抖 20ms（MCU 侧保留 + PC 双保险）/ 短按 ≤400ms / 双击窗口 400ms / 长按 ≥800ms
- **判定时序**：松开且 ≤400ms → **不立即判**，静默等 400ms 无第二次按下才判 S（保双击升级路径）；窗口内第二次按下+松开 → 判 D；持续按 ≥800ms → **达阈即判 H**（不等松开）
- **互斥**：一次物理操作只出 S/D/H 之一；判定即发 KeyGesture{键号, 手势, 时刻}
- **驱动**：逻辑线程 10ms tick 检查超窗/长按阈值（事件驱动+定时兜底）；乱序/超期事件 → 丢弃 + warn
- **不做**：门控、计数、菜单、动作映射——全在 KeySemantics（2026-08-18 既定）
- **v2 兼容期**：整链停用（匿名帧构不出 RawKeyEvent——§2.5 矩阵）

## 4. DeviceManager 门面（2026-08-18 设计全量沿用，本次 5 处增量）

对外窗口（open/close、切模式三口令、startWarmup、getDeviceState、getLastTemperatures、广播事件）与「两条铁规」（不漏零件指针、门禁回调注入不反链 07/10）**原文沿用 2026-08-18 设计 §1.2**。增量：

1. **命令通道接入（非阻塞 + 完成回调——审查 A1 修正）**：KeySemantics「直接下令」与 ParamStore「下发执行」改经 CommandChannel——send 立即返回；**ACK 到达的完成回调**里连锁后续（擦板/改账/广播），**3 败回调**里保账保板 + Fault（ParamStore「下发失败不改账」、ModeController「命令成功后才擦板」的强制点——防「板已切命令没到」）
2. **切模式命令映射与次序**（PC 统一策略：**目标态非待机时先退待机** `N13 E0` 再发目标命令——待机与 N16/N11 是否正交待协议方确认，§8-11；审查 B1/B2 修正；多命令一律走**命令组步链**——二轮 R2-A2）：
   - `enterCalibration()` = 门禁 →（在待机? N13 E0）→ N16 B1 → 黑板「标定中」
   - `enterScan()` = 门禁 →（在待机? N13 E0）→ N10 当前参数 → N11 H1 → 黑板「扫描中+采集开」（02-D2：启停归 08，工作流只喊门面，不自发 N11）；**切态窗口说明**：gate 对 start_scan「通过即切 S4/S5」先于本组全部 ACK——窗口内用户再按键时黑板未写，KeySemantics 按旧态判启停，N11 H1/H0 幂等兜底无副作用
   - `toIdle()` = N13 E1 → 黑板「待机」；`startWarmup()` = N14 T<目标>（**停止加热机制待协议方**——T0 是否=关，§8-13；二轮 R2-B2）；S1 开机自检 = **`open()` 开机一条龙末尾发 N12 Z1**（作为 S1 自检清单的通讯项，10 设计 §2.4），`system_ready`（S1→S2）时 Z0 退出；S7 故障自检 = N12 Z1 / 通过后 Z0（10 设计 §4.5）
   - 采集启停 = 查黑板 → N11 H1/H0 → 翻转**采集子态（开/关）**（S4/S5 子态真相源，10 设计 §2.5 既定）
   - 采集参数变更（ParamStore）时若在采集中 → 重发 N10（协议表：更新参数需重设采集参数）
3. **S 设备状态帧记账**：MCU 主动上报的状态码存「设备实际状态」字段；业务模式黑板（PC 意图）与实际状态**并存**，不一致记 warn + 广播（不自动改板——出事只报不动手）；v2 期此字段置空（§2.5）
4. **心跳联动**：任意有效上行帧刷新通讯心跳时间戳（供 §5 HardwareMonitor 查；v2 期以轮询回包为心跳）
5. **ParamStore 改账时点（确认更新制——审查 B4 定案）**：v3 模式 ACK 成功 → 改账 → 广播（UI 毫秒级延迟可接受）；3 败 → 保旧值 + UI 弹回 + Fault；v2 模式无 ACK → 立即改账标 `confirmed=false`（沿 2026-08-18「无读回参数标期望」逻辑）

## 6. 线程模型 + 故障接线

### 6.1 四线程（三已有一定位，零新增线程）

| 线程 | 干什么 | 禁区 |
|---|---|---|
| 串口 rx（已有，提优先级[C7]） | read → 成帧 → 入环形队列 | 零业务零解析（CRC 都不做） |
| 逻辑线程（2026-08-18 已定） | 取帧→校验分流→KeyManager→KeySemantics→账本→CommandChannel 发令（**非阻塞**）+ 10ms tick 对账超时/重传→Warmup tick | 不阻塞干等（ACK 为非阻塞等待，tick 驱动——审查 A1） |
| 巡检线程（已有） | HardwareMonitor 1s：外设层+自检采集+心跳检查→DeviceStateCache+EventBus；v2 兜底轮询仅**置标志**由逻辑线程发令 | 阈值告警（归 10）；**不发串口命令**（下行单发送口——二轮 R2-A1） |
| 调用方线程 | 门面方法；切模式经队列转逻辑线程执行 | — |

### 6.2 故障上报（只报不动手；全走 EventBus Fault 事件，08 不链 10）

2026-08-18 设计 §4 七类异常**全量沿用**（相机掉线/串口无声/温度爆表/温度乱跳/预热超时/按键队列挤爆/命令石沉大海），新增 3 类：

| # | 什么事 | 怎么发现 | 报什么 |
|---|---|---|---|
| 8 | ACK 重传 3 败 | CommandChannel | 哪条命令+等了多久 |
| 9 | seq 跳变丢帧 | 逻辑线程对账 | 计数（超阈值上报） |
| 10 | 通讯心跳丢失 | HardwareMonitor（C6） | 最后收到帧的时间 |

允许做的（不算越界）：重试一遍 / 老实报旧数 / 查询不装好（2026-08-18 §4.2 原文）。
