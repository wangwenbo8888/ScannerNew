# 工程文件体系实施计划 · 261104

> 前置调研：`2026-11-04-工程文件体系调研报告.md`（同目录）。状态：**待人工审核**。
> 核心目标：通过导出/导入工程文件，能完整恢复之前的扫描状态（查看＋续扫＋重优化＋后处理）。

## 1. 目标（一句话）

> 扫描完成后一键「导出工程」→ 得到一个自包含目录 → 在任何同版本软件上「导入工程」→ 恢复到扫描刚结束时的状态（点云/标志点/位姿/标定/参数），并支持续扫与离线重优化。

## 2. 工程目录结构设计

```
projects/
└─ 20261104_153022/                    ← 工程目录（时间戳命名，一工程一目录）
   ├─ manifest.json                    ← 工程清单（唯一入口，人眼可读）
   ├─ calibration/                     ← 标定参数快照（导入时恢复）
   │   ├─ calibration.json             ← 相机内外参（复制当时的）
   │   ├─ laser_calib.json             ← 激光标定参数
   │   ├─ camera.json                  ← 相机运行参数（曝光/增益等）
   │   └─ curve_map_temp_table.bin     ← CMTT 查表（如体积可接受）
   ├─ data/
   │   ├─ cloud_final.ply              ← 终版融合点云（GBA 后）
   │   ├─ markers_global.ply           ← 标志点全局云（globalId 属性）
   │   ├─ poses.json                   ← 逐帧位姿（frameId + R/T + regSource）
   │   ├─ obs_checkpoint.dat           ← 观测检查点（GBA 重放原料，二进制）
   │   └─ scan_meta.json               ← 扫描统计（帧数/配准/耗时/丢弃）
   └─ edits/                           ← 编辑记录（如有）
       └─ edit_log.json                ← 圈选删除账本
```

## 4. 导出流程（扫描结束自动触发 or 手动导出）

### 4.1 自动导出（扫描结束时）

```
扫描会话关闭（finish_scan 完成，GBA 合账落库后）
  ↓ 自动触发
① 创建 projects/<时间戳>/ 目录
② 写 manifest.json（收集全部元数据 + 标定文件指纹）
③ 复制标定快照到 calibration/
④ 转存终版 PLY → data/cloud_final.ply
⑤ 导出标志点 PLY → data/markers_global.ply
⑥ 序列化位姿 JSON → data/poses.json
⑦ 移动观测检查点 → data/obs_checkpoint.dat
⑧ 计算全部产物 SHA256 哈希，回填 manifest
⑨ JMW_LOG_INFO "工程已导出到 projects/..."
```

### 4.2 手动导出（从任意历史工程重导出）

```
用户点「导出工程」→ 选择目录 → 同上流程
```

## 5. 导入流程（恢复扫描状态）

```
用户点「导入工程」→ 选择 manifest.json
  ↓
① 校验 schema 版本 + 软件版本兼容性
② 校验全部产物文件存在 + SHA256 完整性
③ 校验标定指纹（当前系统标定 vs 工程快照——不一致则提示）
  ↓ 通过
④ 加载点云到 3D 视图（cloud_final.ply）
⑤ 加载标志点到全局云（markers_global.ply）
⑥ 恢复扫描参数（亮度档/体素/深度窗）
⑦ 恢复编辑记录（如有 edit_log.json）
  ↓ 可选（用户选择）
⑧ 「续扫模式」：加载观测检查点 + 标定快照 → 恢复到可追加扫描状态
⑨ 「离线重优化」：加载观测检查点 → 重跑 GBA → 刷新点云
```

struct ProjectManifest {
    std::string schema = "leadscanner.project.v1";
    std::string version;

## 7. 技术决策点（需人工确认）

| # | 决策 | 选项 A（推荐） | 选项 B | 理由 |
|---|---|---|---|---|
| 1 | CMTT .bin（2.25GB）是否入工程 | 复制入 calibration/ | 只记指纹不复制 | 推荐 B（体积太大），标定快照只存 JSON 参数（几 MB），CMTT 可从参数重生成 |
| 2 | 自动导出时机 | 扫描结束自动 | 仅手动 | 推荐 A（用户不丢数据），目录名时间戳自动区分 |
| 3 | 历史会话保留策略 | 全部保留 | 最近 N 次 | 推荐 A（磁盘空间用户自行管理） |
| 4 | obs_checkpoint（可能 104MB+） | 压缩后入工程 | 不入（仅会话内续扫） | 推荐 A（用 zstd/gzip 压缩，可能缩到 30MB），续扫需要它 |
| 5 | 工程目录位置 | exe 旁 projects/ | 用户选择 | 推荐 A（默认） + 手动导出时可选 |

## 8. 依赖与风险

| 项 | 说明 |
|---|---|
| 不动 09 算子 | 本计划全在 06/app 层，不触碰算子库 |
| 不动公共头 | 06 新增文件不影响契约指纹 |
| SHA256 | 用系统 API（Windows BCrypt 或简单实现） |
| 大文件 | cloud_final.ply 可达数百 MB；obs_checkpoint 可达 100MB+——目录拷贝耗时需 UI 进度提示 |
| 兼容性 | manifest schema v1 定版后不再改字段名；后续扩展加新字段（向前兼容） |
