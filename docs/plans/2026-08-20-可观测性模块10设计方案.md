## 2. 状态机：9 态 → S1–S7（表驱动重写）

### 2.1 枚举

```cpp
enum class SystemState : uint8_t {
    Init = 1,          // S1 初始化（自检：通讯/加密狗/授权）
    Standby = 2,       // S2 待机（门禁主战场；「已标定」是门禁条件不是态）
    Calibrating = 3,   // S3 标定
    ScanMarker = 4,    // S4 扫描标记点
    ScanMarkerLaser=5, // S5 扫描标记点+激光
    PostProcessing=6,  // S6 后处理（免疫故障转态）
    FaultSelfCheck = 7 // S7 设备故障+自检中
};
```

删除：`DeviceReady`/`Calibrated`（并入 S2 语义）、`Paused`（暂停=工作流内部语义）、`Error`/`EmergencyStop`（S7 承接；急停全工程已弃用）。

### 2.2 转换矩阵（static 表，查表驱动，可直接表驱动测试）

照 10 文档 §4.1 转换表落：

- S3/S4/S5/S6 互斥必经 S2；扫描二选一（S4/S5 由 ScanMode 在 S2 入口定）
- S6 免疫故障边（见 §4.4）；S7 自检通过回 `lastHealthyState_`（**永不回 S6**，兜底 S2）
- 断连任一态→S1（**两处例外**：S6 免疫见 §4.5、S7 内保持 S7——自检含重连）
- 触发事件在 base/types.h 扩展（净 +5，见 §9 base 行）

### 2.3 原子性（审核 #3 修）

`transition()` 用 **CAS 循环**（compare_exchange on atomic<SystemState>）：load→查表→CAS 失败则重读重判；EventBus publish 与 onStateChange 回调放锁/CAS 外执行。命令通道线程与故障链线程并发转态不再丢转态/非法覆盖。

### 2.4 S1 的进入与退出（审核 C 项修）

- **S1→S2**：app 初始化自检清单（通讯 + 加密狗/授权文件 + 相机连接）**全部通过** → 经 gate 内部命令 `system_ready` 切 S2。现状 `ScannerWindow.cpp:273` 拿 DeviceConnected 直切的做法废除——设备连接只是自检清单**一项**，不再单独切态。
- **非设备类失败**（加密狗/授权）：留 S1 阻塞告警，**不进 S7**（S7 是设备故障语义）。

### 2.5 S4/S5 子态（审核 #5 修）

就绪⇄采集子态**不占全局态、10 不记账**——真相源 = 08 ModeController 模式黑板（08 设计 §2.4 既定）。02-③⑥ 按键启停对 10 只有 `canOperate` 门禁查询，无转态调用。

### 2.6 canOperate 重写

`calibrate/scan/postprocess` 均 S2 放行；**只判状态**——参数就绪（02-① 查 06）、可编辑点云（05）等业务前置由 CommandGate 的 precondition 谓词注入（§3.2），10 不依赖 06。字符串键风格沿用现实现，不强改枚举。

## 3. CommandGate 统一命令通道（铁律的强制点）

### 3.1 双口设计（审核 A 项修——拆开「触发」与「收尾」）

```
口一 submit(cmd, payload) —— 外部命令（UI 图标 / 08 按键菜单动作 / 自动策略）
    ① 命令已注册？ ② 门禁 canOperate？ ③ precondition 谓词？
    三关全过 → start 类立即切态（防装配期间他者闯入）→ 执行 handler（只点火）
    任一关挂 → 拒绝（带原因）+ CommandRejected 事件（UI 提示）

口二 notifyCompleted(cmd, ok) —— 工作流完成回报（唯一切态收尾口）
    工作流在 ⑨/⑩ 合账后调用 → finish 转态（S3/S4/S5/S6 → S2）
    属命令通道生命周期（start→finish 成对），非第三扇门——铁律不破
```

**与被否决的 WorkflowManager 划界**（审核 #9）：gate 只路由单命令到工作流自注册的 handler，**不集中注册/启停/管理三条工作流的生命周期**——装配、启停、回收仍归各工作流自治（01/02-D1）。

### 3.2 首批命令目录（切态时点已按 02/01 定稿修正）

| 命令 | 口 | 转态 | 语义 |
|---|---|---|---|
| `system_ready` | submit（内部） | S1→S2 | app 自检清单全过（§2.4） |
| `start_calibration` | submit | S2→S3，通过即切 | 01-① |
| `start_scan{mode}` | submit | S2→S4/S5，通过即切 | 02-①；precond=参数就绪谓词（查 06，由 02 注册） |
| `finish_scan` | submit（触发）+ notifyCompleted（切态） | 无 / S4/S5→S2 | **⑦ 用户点「完成扫描」只是触发命令**（gate 判放行→点火 GBA）；**S2 切态在 ⑩ 合账后由 notifyCompleted 执行**——⑦≠工作流终结的转态时点（02-D3/D4） |
| `finish_calibration` | notifyCompleted | S3→S2 | 01-⑨ |
| `start_postprocess` | submit | S2→S6，通过即切 | 04 进入（S6 进入前置=操作员全权，可选增强谓词「存在扫描产物」留注实现期） |
| `finish_postprocess` | notifyCompleted | S6→S2 | 04 完成 |

注：`enableFinalBA=false` 时 02 仍在 ⑩ notifyCompleted（GBA 只是跳过，收尾语义不变）。

### 3.3 失败路径（审核 B 项修）

- **handler 同步失败**（点火即败，如设备打不开）：gate 立即回滚 S2 + ERROR 日志 + CommandRejected 事件。
- **运行中异步失败**：工作流走故障链（S7，设备类）或主动 `notifyCompleted(cmd, failed)`→S2（非设备类）——不允许悬死在 S3/S4/S5/S6。

### 3.4 线程与阻塞（审核 #8/E 修）

- gate **不开线程**：submit 在调用方线程同步执行三关检查+切态（查表/CAS，微秒级）。
- **handler 仅点火**（毫秒级返回）：装配/启动流水线等长活归工作流自身线程——禁止把 GBA/标定计算整段塞进 handler（会卡死 UI/08 逻辑线程）。

## 4. 故障链（FaultHandler 改造）

### 4.1 故障档案表

活动故障 `{id, sourceId, severity, message, time, count}`；同源同类 **1s 窗口聚合计数**（防风暴刷屏/刷转态）。表并发防护：mutex（EventBus 回调线程与直调 reportFault 并发写——审核 F 项修）。

### 4.2 来源标识（修「事件丢 source」缺陷）

source 注册制（枚举 id：Camera/MCU/Monitor/Pipeline/Perf/…）；故障事件 `param1=severity, param2=sourceId`，消息体经档案查询补全。

### 4.3 独立灯事件

新增 `EventType::LedControl`（param1=灯色/亮灭），**废除复用 EmergencyStop 通道**（现 `FaultHandler.cpp:28`——语义解耦，审核 #11/G）。

### 4.4 S7 进入与恢复

```
reportFault(Error 级以上) 且当前态≠S6：
    存 lastHealthyState_ → transition(S7) → 经注入的安全停机回调（app 供给，10 不链 08）→ LedControl(红)
selfCheckPassed()：transition(lastHealthyState_)（续作语义仅转态；检查点/数据恢复后置，另议）
    lastHealthyState_ 兜底 S2；恢复目标可为 S1（自检中出故障的场景）
```

### 4.5 S6 免疫与断连例外（审核 D 项，落稿采纳）

- S6 免疫故障转态：只记档+事件，不进 S7（GPU/算法失败走 Result 人工处置——10 文档 §4.1 既定）。
- **S6 断连免疫**（本方案对 10 文档 §4.1「断连任一态→S1」全局边的补充）：后处理不碰设备，USB 抖动不应毁掉分钟级离线批处理——S6 内断连只记档+事件。
- S7 内断连：保持 S7（自检流程含重连）。
- ※ 落地时将此两条例外**同步回 10 文档 §4.1**（基准变更登记，见 §11 落地清单）。

### 4.6 08 检测源

留 `reportFault` 注入口（本方案不实现 08 侧——08 设计 §4 七类异常归其差距清单；08 落地时接）。

## 6. 性能消费端（PerfMonitor）

### 6.1 数据通路：通知 + 拉取（审核 #2 修——不动 base Event 结构）

Event 仅 param1/param2 两个 int64，塞不下 HealthMetrics 结构体。改为：

```cpp
// base/types.h 新增（与 DeviceState 同例的公共类型）
struct HealthMetrics {        // CPU温度/占用、GPU显存/温度、内存水位、磁盘剩余、
    ...;                      // 采集/处理帧率、丢帧率（字段定义对齐 08 差距清单）
};
// 10 侧定义窄接口，08 侧（或测试假源）实现并注入：
struct IHealthProvider { virtual HealthMetrics snapshot() const = 0; };
```

事件 `HealthReport` 只当 ping（param 放越限摘要枚举码）；PerfMonitor 收 ping 后经注入的 provider 拉**最新快照** + 存历史 ring。base 不加事件 payload 字段，保持极薄。

### 6.2 阈值规则表（可配置）

CPU 过热降频先导预警、内存 >85% 持续 10s、磁盘 <10GB 预警 / <1GB 停写保护、采集帧率 <目标 80% 持续 3s、处理/采集 <0.8 持续 5s → Degraded……越限发 Degraded 事件（UI 提示）或 Fault（转 §4 走 S7 链）。

### 6.3 UI 状态栏

PerfMonitor 定期广播快照摘要（EventBus，param 放核心摘要码，明细可查询），UI 订阅展示。测试：publish 合成 ping + 假 provider 即可全链路验证（08 未落地不阻塞，P3）。

## 7. 崩溃捕获（CrashHandler）

### 7.1 机制

`install()`：SetUnhandledExceptionFilter → filter 内**只做最小安全动作**——MiniDumpWriteDump（dbghelp）落 `dumps/` 固定目录 + 写标记文件；**不做**堆分配/加锁/日志系统调用/zip 打包（SEH filter 内不安全，会二次崩——审核 #4 修）。

### 7.2 启动残留检测

下次启动检测 dumps/ 残留 → 事件提示上报 → 此时（正常运行环境）才调 ObsLogger 打排障包（dump+日志+版本+系统信息）。

### 7.3 装配顺序（定死）

`main()`：ObsLogger → CrashHandler →（app 装配其余件）——dump 路径与日志配置先就位，其后任何启动崩溃都可留痕。

## 8. 两条编码规范（专节，成审查牙）

### 8.1 错误处理分层

1. 业务错误一律 **Result 返回值**（算子/工作流/服务契约既定铁律——禁热路径抛异常：栈展开性能毛刺 + 错误路径被隐藏）。
2. 异常仅限三处：**线程最外层兜底围栏**（catch(...) 记日志+FaultHandler 上报，防未知异常炸线程）/ **第三方库边界**（catch 转 Result，如 CGalaxyException、OpenCV）/ **构造函数参数校验**（RAII，invalid_argument）。
3. catch 后**禁止吞掉**（空 catch / 仅 continue）——必须记日志或上报，静默吞异常记为代码审查缺陷。

反例：`catch (...) {}`；正例：`catch (...) { JMW_LOG_ERROR("02-ScanWorkflow", "..."); return Result::fail(...); }`

### 8.2 关键路径强制日志

**任何错误必须有日志**（Result 失败处必记——错误无日志=审查缺陷，与吞异常同款牙齿）。四类必写：

1. **生命周期**：工作流进入/退出一律一条（会话 ID+时间戳）；开账/合账（ID+起止+统计）；私有件构造销毁；标定落盘（路径+门禁判定+指标值）；GBA 开始/结束（收敛+修正量）；编辑删除/undo/redo（点数）。
2. **数据流节点**：丢帧（每秒汇总：lag 值+丢弃数）、光流失败转兜底（帧号+匹配数）、温补表 lookup 降级、表加载（来源+条目数/缺失拒绝）。
3. **故障与异常**：温度跨档/超限（传感器+档位/阈值）、GPU/CPU/内存危险值（指标+当前值+阈值）、通信问题（seq 跳变丢帧/半帧超时/ACK 3 败）、FaultHandler 每次上报、兜底围栏 catch（内容+线程名）。
4. **硬件操作**：模式切换/启停/加热下发（含参数）、相机参数设置结果（请求值 vs 读回值）。

**格式纪律**：统一 `[模块-对象]` 前缀；sessionId/frameId 可过滤；周期事件汇总输出（禁逐帧刷屏，防 10MB×5 轮转冲掉关键日志）；日志不弹窗（UI 提示走 EventBus——日志是证据不是通知）。

### 8.3 审查牙落地

代码审查清单加两条：「关键路径无日志=缺陷」「错误无日志=缺陷」（与吞异常条款并列）。
