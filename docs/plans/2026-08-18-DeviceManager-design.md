## 0. 它是谁（一句话）

DeviceManager = **设备总管家**：app 一开机就造它、全程不销毁；相机、串口、按键、温度全归它管，外人只找它一个窗口，不许私摸零件。

下面几条是之前已经拍板的事，本文档照着执行：

| 拍板 | 内容 |
|---|---|
| 人工修正①③④⑤ | 相机只设参数（触发归下位机）；KeyManager 只认手势，逻辑全在总管家；下位机状态由总管家记账；总管家=收集→判断→发令 |
| 上行架构 | 串口一条道进来，按帧头分流（温度/按键/状态各走各链），最后在总管家汇合 |
| 本次 6 问 | 逻辑拆 4 个小组件（不挤一个类）；模式自己记+先问门禁；预热自己做（状态机）；出事只上报不动手；自持一条逻辑线程；组件平级放文件 |

## 1. 长什么样（文件 + 对外窗口）

### 1.1 新增文件（都在 `modules/08_devicemgmt/`，编入 `mod_devicemgmt`）

```
DeviceManager.h/.cpp   ← 总管家本体（对外唯一窗口，控制在 ~200 行）
MenuLogic              ← 菜单记账本（第几层/游标在哪/调什么 + 奇偶计数）
KeySemantics           ← 按键裁判（手势+菜单态+门禁 → 定动作）
WarmupSequence         ← 预热看火员（加热→盯温度→稳定了喊人）
ModeController         ← 模式黑板（待机/标定/扫描，改前先问门禁）
（已有）CameraControl / MCUDriver / KeyManager / HardwareMonitor
```

### 1.2 对外窗口（别人能喊它做的事，全部列出）

| 喊法 | 干什么 | 谁喊（步骤号） |
|---|---|---|
| `open()/close()` | 开机一条龙 / 关机倒着收 | app 启动/退出 |
| `enterCalibration()/enterScan()/toIdle()` | 切标定 / 切扫描 / 回待机 | 01-②⑨；02-②⑩ |
| `startWarmup(目标温度, 回调)` | 加热到温度稳了叫你 | 01-③ |
| `getDeviceState()` | 「设备行不行？」一句话总答 | 01-①；02-① 门禁 |
| `getLastTemperatures()` | 最近一次 4 路+相机温度快照（带时间戳，陈了自己判断）；※这是查询口，帧温随帧附带走的是另一条路（08 §1 上行架构） | 温度消费方 |
| 广播事件 | 温度更新 / 按键动作 / 模式变了 / 设备出事 | 全工程订阅 |

**两条铁规**：①窗口不漏零件——外面拿不到 CameraControl 等任何子对象指针；②问门禁用回调注入（指向 app 状态机），不反向依赖 07/10。

## 2. 四个小组件（各管一摊）

### 2.1 ModeController 模式黑板

- 黑板上写三个词之一：**待机 / 标定中 / 扫描中**（原子读写）
- 改板规矩：先问门禁（app 状态机）——不让改就拒绝并说明原因；让改→擦板写新词→发对应串口命令→广播「模式变了」
- 原 3 号灯的活归它：下位机自己没档位，「设备在干嘛」以这块黑板为准

### 2.2 WarmupSequence 预热看火员

```
待命 → 发加热命令 → 盯温度（温度自己上报，不轮询）
     → 火候判定：连续10s 温度几乎不动(≤0.1℃) 且 离目标 ≤2℃ → 稳了！回调通知
     → 等太久(默认15分钟)还没稳 → 超时回调（自己不停加热——报告上去，听人的）
```

- 目标温度/判定阈值/超时都构造时传入，换机型可调
- 只管预热；温度爆表这种危险判定不归它（归 §4 故障链）

### 2.3 MenuLogic 菜单记账本

- 记：第几层(1/2)、游标(①~④)、调节什么(无/视野/亮度)、三个奇偶计数、模式光标(1/2/3)
- 收到 KeySemantics 给的「语义动作」（开菜单/移游标/选中/加减…）→ 翻账本 → 广播给界面画
- **纯记账**：不判该不该（门控在裁判那）、不发命令

### 2.4 KeySemantics 按键裁判（「总判断」的按键落地）

```
收到 KeyManager 手势（哪个键+短/双/长按）
  ↓ 一问门禁：这类键现在让按吗？（采集中只放行启停键——M1 规矩）
  ↓ 二问账本：菜单开到哪了？
  ↓ 三问奇偶：这次是奇数按还是偶数按？
判出结果，三种去向选一：
  · 直接下令：开拍/停拍 → 发 N11（02-D2，08 自己定，不请示）
  · 改账本：菜单/模式切换（本地事）
  · 派工作流：「扫描完成」「开始后处理」→ 过门禁派给工作流
门禁不让按 → 丢弃，奇偶计数不动，记条日志
```

**依赖方向**：裁判→账本（单向只读）；裁判和账本都不碰硬件——发令统一经总管家。

## 3. 开关机与线程

### 3.1 开机一条龙（哪步砸了就把前面已开的倒着关掉，再报 `DeviceFault`）

```
1 找相机 → 2 开相机 → 3 开串口 → 4 起按键裁判 → 5 起巡检护士 → 6 起逻辑线程 → 7 广播「设备就绪」
```

- 只许 app 启动时调一次；开机默认待机；相机参数照配置文件下发

### 3.2 线程分工（谁跑在哪条线程、各有什么禁区）

| 线程 | 归属 | 干什么 | 禁区 |
|---|---|---|---|
| 串口接收（已有） | MCUDriver | 切帧分流：温度直接广播；**按键只丢进队列** | 不做任何业务逻辑 |
| 逻辑线程（新增，仅此一条） | DeviceManager | 一件件处理：取按键→裁判判→账本记→发令；预热看火也在这 tick | 不许阻塞干等 |
| 巡检线程（已有） | HardwareMonitor | 每秒看一眼在线/帧率 | 不做阈值判断 |
| 调用方线程 | app/工作流 | 喊门面方法 | — |

**为什么这样**：按键逻辑全在一条线程里排队——不用加锁（账本没人抢着写）；串口线程永不被业务拖住（队列有界，挤满了丢最旧+警告，靠 KeyManager 时序对账发现丢没丢）。

### 3.3 切模式/预热的线程规矩

- 切模式：调用方线程发起→逻辑线程干活→完事回调/事件回告
- 预热：温度事件一来 tick 一下看火员（不是定时瞎转）；「稳了」回调在工作流等的那儿响
- 关机倒着收：停逻辑线程→停巡检→关按键→关串口→关相机；没干完的预热/采集直接掐掉记日志（退出场景，不讲究）

### 3.4 app 装配收拢（迁移项）

现在 `AppContext.cpp:52-83` 自己 new 三个零件接线——落地后全收进 `open()`，AppContext 只剩三行：

```cpp
deviceManager_ = std::make_unique<DeviceManager>(cfg, gateQuery, eventBus);
deviceManager_->open();   // 退出时 close()
```

另 5 处直接摸 CameraControl 裸指针的（`ScannerWindow.cpp:42,62`、`MainWindow.cpp:200,251,439`）改走门面。

## 4. 出了事怎么办（只报不动手）

**总原则**：发现异常→打包上报给 10→**自己不停激光不停采不切模式**；怎么处置 10 说了算，处置动作回头还是走正常门面命令（比如喊 `toIdle()`）。唯一例外：关机清理。

### 4.1 要盯的 7 类异常

| # | 什么事 | 谁发现 | 怎么发现 | 报什么 |
|---|---|---|---|---|
| 1 | 相机掉线 | 巡检护士 | isOpen 变 false / 帧率归零 | 哪台+何时 |
| 2 | 串口没了声 | MCUDriver | 太久没收到任何上报（如 10s） | 最后收到的时间 |
| 3 | 温度爆表 | 温度链 | 超安全上限 | 哪路+多少度 |
| 4 | 温度乱跳 | 温度链 | 变化太快（如 >2℃/秒） | 哪路+多快 |
| 5 | 预热等不到头 | 看火员 | 超时态 | 目标温度+实际最后温度 |
| 6 | 按键队列挤爆 | 逻辑线程 | 队满丢旧 | 丢了几条 |
| 7 | 命令石沉大海 | 总管家 | 发令后久无回应（协议支持时） | 哪条命令+等了多久 |

### 4.2 上报之外允许做的（不算越界）

- **重试一次**：开机/发命令砸了先重试一遍，还不行才上报
- **老实报旧数**：温度停更后查询返回最后有效值+时间戳——不编数、不清零
- **查询不装好**：设备离线就说离线，不谎报就绪

### 4.3 不归它管的（防手长）

停不停机听 10 的；弹窗提示归 app（自己订阅故障事件）；日志存档归 10。

### 4.4 给测试留的口子

小组件全可插 Mock（门禁回调/假串口回灌帧/合成温度序列）；断连、超时、超温各留一个注错开关——供 10 联调和自动回归用。

## 5. 怎么算做完了（测试与验收）

### 5.1 策略：纯 PC 逻辑全自动测，真机只人工过一遍

| 层 | 测什么 | 怎么测 |
|---|---|---|
| 单元（gtest 入 ctest） | 四个小组件各自的状态机 | 全 Mock，无真机 |
| 集成 | 门面全链：开机/切模式/预热/按键 | 假相机+假串口（回灌帧脚本） |
| 真机冒烟（人工） | 协议对不对/真实预热多久/按键手感 | 手动清单，不进 CI |

### 5.2 核心用例 8 条

| # | 场景 | 要看到 |
|---|---|---|
| T1 | 开机第 3 步串口失败 | 倒着关干净（相机已关）、上报故障、无泄漏 |
| T2 | 门禁拒绝切扫描 | 模式没变、给出原因、串口没发任何命令 |
| T3 | 假温度先升后稳 | 「稳了」回调恰好响一次 |
| T4 | 假温度永不稳 | 超时回调（没自作主张停加热、没崩） |
| T5 | 扫描中按菜单键 | 丢弃+计数不动；采集中按启停键→N11 正确翻转 |
| T6 | 菜单全遍历（4键×3手势×2层） | 账本全状态覆盖（表驱动） |
| T7 | 按键洪峰 100 条 | 丢最旧+警告+对账对得上，逻辑线程不卡 |
| T8 | 采集中相机断连 | 故障内容正确；**没有任何**自主停采动作 |

### 5.3 过线标准

- T1–T8 全绿且可重复跑；逻辑线程无数据竞争（TSAN 或评审查锁点）
- 窗口不漏零件（grep：对外头文件搜不到 CameraControl/MCUDriver 类型）
- AppContext 设备相关 ≤ 3 行（构造+open+close）
