# 工厂标定流水线 — 算子说明文档

> ⚠ **目标设计（未实现）**：本文档阶段 4 采用 `projector_joint_calib` 替代旧端点链路（4-9/4-10/4-11），描述的是**目标设计**。主工程标定编排尚为骨架桩（`modules/01_calibration/calibration.cpp` 空命名空间、`framework/workflow/` 仅接口桩），未实现。当前唯一已实现的标定流水线是 `factory_calib`（仍用旧端点链路）。本文档是未来主工程编排实现时应采用的方案。

> **版本**: v2.2  
> **适用平台**: Windows 10/11 x64（兼容 Jetson Orin NX/AGX Orin）  
> **设备**: 手持式双目多线激光三维扫描仪  
> **算子总数**: 33 个标定算子 + 1 个辅助显示算子（阶段 2 新增 `frame_filter` 帧类型过滤；阶段 4 已用 `projector_joint_calib` 替代 4-9/4-10/4-11 三步）  
> **阶段结构（v2.2）**: 0 初始化 → 1 图像采集循环（独立）→ 2 扫描仪姿态判断（流水线，需集齐 25 个目标姿态）→ 3 相机标定（含 5-1/5-2）→ 4 激光标定（含 5-3）。原阶段 5 温度补偿已解散。
>
> **独立流水线说明**：阶段 0→1→2 为**第一独立流水线**（姿态采集与判断），持续运行直至集齐 25 个目标姿态；阶段 3 + 阶段 4 为**第二独立流水线**（标定参数计算），在集齐 25 姿态后**一次性执行**。阶段 4 的前段（4-1~4-4 激光线提取）可与阶段 3 并行；4-5 起需消费阶段 3 输出（内参/畸变/Q/立体参数），因此阶段 3 先行，阶段 4 以数据驱动方式跟随。

> **2-6⇄3-1 一致性风险**：`undistort_cpu`(2-6) 和 `inverse_distort`(3-1) 必须使用同一组**初始**内参/畸变/R1/P1。若两处参数来源不一致，3-1 逆变换结果存在系统性偏差，导致 3-2 内参标定输入错误。

>
> **3-5 标注**：`stereo_rectify_temp_table` 的输出（每温度阶梯的 R1/R2/P1/P2/Q）馈入**运行时扫描**管道，不在本标定流水线内消费。
>
> **温度补偿物理机理**：温度变化导致镜头铝壳热膨胀（焦距/主点漂移→内参变化）、骨架热膨胀/收缩（基线漂移→外参变化、激光器位置漂移→虚拟相机外参变化）。补偿基于线性热膨胀模型 `scale = 1 + CTE × ΔT`（6061-T6 铝合金, CTE=23.6e-6）。

>
> **4-5 标注**：`undistort_cuda` 的参数须使用阶段 3 **标定后的最新内参/畸变**，与阶段 2 的 `undistort_cpu`(2-6) 使用初始参数不同。
>
> **4-6 标注**：标定模式使用 **`lineIdCheck=true`**，同线 ID 判据 + 几何邻近双重条件；扫描模式使用 `false`（仅几何邻近）。
>
> **4-8 → projector_joint_calib 衔接**：`laser_reconstruct`(4-8) 产出单姿态 `d_points3d`，编排层跨姿态聚合为 `poses`（CPU `vector<PosePointSet>`，按姿态分组；区别于旧链路聚合为 GPU 合并的 `d_all_pts3d`）后喂给 `projector_joint_calib`（CPU 算子，点云需 download）。**聚合是编排层数据准备动作，非算子**；旧链路亦需此聚合（见 `factory_calib` CLI `d_all_pts3d`），原图漏画。
>
> **R=I 的依据（修正，非假设）**：投影机与左相机**绝对轴线平行**（机械默认值）。旧链路 `virtual_camera_pose` 把双目外参 `stereoR`(=R 左←右) 直接借用为 `virtualR`（源码 `virtual_camera_pose_cuda_impl.cu:245-246` `result.virtualR = stereoR`），与投影机实际 R=I 不符。`projector_joint_calib` 改用 R=I 是对该误用的**修正**。故 `plane_map`/4-13/5-3 的 R 输入应为 I（旧链路用 stereoR 实为误差源）。
>
> **求光心方法差异**：旧链路靠激光线**端点**（直线交汇解析求光心，端点不可见则失效）；`projector_joint_calib` 用激光线**中段点云**（多姿态反投影聚拢，LM 联合优化），不依赖端点。两者都只优化平移 T（自由度等价）。
>
> **emissionCurve 去向**：`projector_joint_calib` 额外输出发射曲线（9DOF 中除光心 t 外的 6DOF 曲线 C），当前 `plane_map` 不消费曲线（仅 K/R/T），预留供扫描时 `laser_match_scan` 使用。
>
> **光心初值**：`initialT` 来自机械装配公差（约 (80,3,3)mm），需在真值数毫米内（吸引盆小）。
>
> **Q 矩阵来源**：`laser_reconstruct`(4-8) 的 Q 矩阵从 `stereo_rectify`(3-4) 获取。运行时扫描使用 3-5 温度补偿表的查表结果。
>
> **标定 vs 扫描差异**：标定流程的激光线完整+有序，按 ByLabel 模式逐线编号(4-3)→分组提取(4-4)→逐线匹配(4-7)。扫描流程的激光线断裂+无序，使用 Flat 模式(统一占位 line_id) + 全局查表匹配(laser_match_scan)。

| 4-13 温度补偿映射表 `plane_map_temp_table` | ①virtualK=f+主点、virtualR=I、virtualT=projectorT ← projector_joint_calib ②立体标定结果 (左右相机内外参) ← 3-4 ③CTE/温度范围 (自身参数) | `PlaneMapTempTableResult` 含 `table` (每温度: 补偿内外参 + R1/R2/P1/P2/Q + d_left_to_right + d_right_u) | ①←PJC; ②←3-4 ✓ |
| 5-3 激光外参温度补偿表 `laser_extrinsic_compensate` | ①`CameraExtrinsics` (虚拟→左: R=I, T=projectorT, refTemp) ②`CameraExtrinsics` (虚拟→右: 由 stereoR/T 推导, 编排层) ← projector_joint_calib + stereoR/T | `LaserExtrinsicCompensateCPUResult` 含 leftResult + rightResult (每温度阶梯补偿 T，R 不变) | ①②←PJC+双目外参 ✓ |

## 四、阶段 1 — 图像采集循环

下位机同步硬触发两个相机、激光器、补光灯，按固定顺序循环采集：

```
┌──────────┬──────────┬──────────┬──────────┬──────────┬─────┐
│  标记点帧 │ 激光管1帧 │ 激光管2帧 │ 激光管3帧 │ 激光管4帧 │ …   │
└──────────┴──────────┴──────────┴──────────┴──────────┴─────┘
     │          │          │          │          │
   补光灯ON  激光管1 ON  激光管2 ON  激光管3 ON  激光管4 ON
   激光器OFF 补光灯OFF   补光灯OFF   补光灯OFF   补光灯OFF
```

| 项目 | 说明 |
|------|------|
| 每帧特征 | 每个采集帧只包含一种特征（标记点或某一激光管） |
| 触发方式 | 下位机 I/O 硬触发，保证双目相机严格同步 |
| 帧率 | 180 fps（单相机 1800×1200 ROI 区域） |
| 温度 | 每帧记录相机内部温度传感器和骨架温度传感器的值 |

## 五、阶段 2 — 扫描仪姿态判断 **【第一独立流水线】**

> 阶段 2 属于第一独立流水线（姿态采集与判断），**持续循环运行**直至集齐 25 个目标姿态，然后触发第二流水线。

### 流水线段

| 流水线段 | 设备 | 算子 | 职责 |
|---------|:----:|------|------|
| GPU 处理 | CUDA | 2-1, 2-1b, 2-2 | 掩膜提取、**帧类型过滤(排除激光线帧)**、连通域分析 |
| CPU 计算 | CPU | 2-3~2-11 | 分割→Zernike→合并→去畸变→椭圆拟合→匹配→极线→边缘点匹配→三维重建 |
| 配准 | CPU | 2-12 | 单帧配准求解 R/T（当前帧→全局系） |
| 姿态判断 | CPU | 2-13 | 设备姿态估计 + 达标判定（25 目标姿态） |
| 显示 | CUDA | 2-14 | 异步渲染（不阻塞流水线） |

### 25 姿态采集逻辑（多帧确认）

> 编排层需维护状态：①历史命中记录（上一采集循环命中的姿态号）②帧缓冲（暂存最近完整循环的 5 帧：1标记点 + 4激光管）③时间戳序列。

1. 姿态判断(2-13) 判断当前标记点帧命中预设姿态 X
2. **回溯确认**：检查上一采集循环的标记点帧是否也命中姿态 X（连续两周期同姿态，排除偶然单帧命中）
3. 若是 → **完整性检查**：验证这两个标记点帧中间的 4 个激光管帧时间戳是否连续（无丢帧）
4. 若连续 → **保存**：保存上一完整循环的 5 帧（1标记点帧 + 4激光管帧 + 温度），标记姿态 X 已采集
5. 未命中 / 不连续 / 已采集过 → 继续采集
6. 集齐全部 25 个姿态后 → 进入阶段 3 / 阶段 4（并行执行）

> **流水线调度方案**：详见 `姿态判断流水线方案.md`

## 六、阶段 3 — 相机标定参数计算 **【第二独立流水线】**

> 阶段 3 属于第二独立流水线（标定参数计算），在集齐 25 姿态后**一次性执行**，先行启动；阶段 4 以数据驱动方式跟随（4-5 起消费阶段 3 输出）。阶段 2 集齐 25 姿态后一次性触发。

**执行链**：3-1 → 3-2 → 3-3 → 3-4，参数扇出至 5-1(←3-2)、5-2(←3-3)、3-5(←3-2/3-3/3-4)。

**前置条件**：阶段 2 已集齐全部 25 个目标姿态，已保存每个姿态的全部采集图像。

---

## 七、阶段 4 — 激光器虚拟相机标定 **【第二独立流水线】**

> 阶段 4 属于第二独立流水线（标定参数计算），在集齐 25 姿态后**一次性执行**，前段（4-1~4-4）可与阶段 3 并行。阶段 2 集齐 25 姿态后一次性触发。阶段 3 `stereo_rectify`(3-4) 的输出为本阶段提供立体矫正参数。

**执行链**：激光线提取(4-1~4-4) → 匹配重建(4-5~4-8) → [编排层跨姿态聚合] → `projector_joint_calib`(求光心+发射曲线) → 映射表(4-12)，扇出至 5-3(←PJC)、4-13(←PJC+3-4)。

**核心思想**：每根激光线发射的激光面可视为一个虚拟相机的"成像面"，虚拟相机的内参与真实相机立体矫正后的参数一致。

**前置条件**：阶段 3 已输出相机内参（←3-2）与立体矫正参数（←3-4）、标定板固定在平整白色哑光墙面上、已保存 25 个目标姿态的激光管图像。
