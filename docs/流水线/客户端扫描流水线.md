> **灰度图的双副本投递**：循环队列读入当前帧固定内存块后，灰度图同时驻留于 Host 内存（供标记点 CPU 算子读取）和 Device 显存（供预处理-01、Steger 等 CUDA 算子使用），无需额外跨设备拷贝。

> **注**：标定流程 `plane_map`（激光平面映射表）与 `plane_map_temp_table`（温度补偿平面映射查找表）属于**独立的激光标定流程**，不在本扫描流程内。`plane_map_temp_table` 输出的温度补偿映射表保存在**内存**中，由本流程的 `laser_match_scan`（激光 07）查表调用。
>
> 标定流程 05（`stereo_rectify_temp_table`）属于**独立的标定流程**，不在本扫描流程内。其输出的温度补偿立体矫正参数表（R1/R2/P1/P2/Q）保存在**内存**中，由本流程的标记点 06（双目去畸变矫正）与激光 05（去畸变矫正）调用。
>
> **激光链双模式（扫描 vs 标定）**：扫描采集的激光线断裂+无序，无法像标定那样预先编号。因此扫描激光链的算子以"双模式"运行，line_id 语义与标定不同：
> - **激光 04 `steger`（Flat 模式）**：输入 `d_laserMask`(CV_8UC1 二值)，内部转均匀标签图后走 Hessian 提取，**不分组**，输出统一 `line_id`（占位）。标定模式（ByLabel）仍接受 CV_32SC1 标签图按线分组。
> - **激光 06 `epipolar_interp`（`lineIdCheck=false`）**：跳过 line_id 同线判据，仅靠几何邻近（`max_x_diff`/`max_y_span`）决定插值。
> - **激光 07 `laser_match_scan`（全局查表）**：输入点无标定 line_id，温度表按极线行重组后**全局搜索**，匹配同时**产出标定 line_id**（`d_matched_line_ids` 为输出）。line_id 在此算子内部确定，其前的算子不得依赖 line_id 的标定含义。

> **扫描模式变点标注（①，上图底图 = 情况B 完整流）**：两种扫描模式差异集中在 1 个变点（A 的激光链跳过）。GlobalOptimStage A/B 均必跑，不再是变点。变点按**算子名**定位（便于人/AI 检索，不依赖图中空间位置）：
>
> | 标记 | 图中节点（按算子名） | 情况A | 情况B | 权威定义 |
> |---|---|---|---|---|
> | ① | 激光链 04~08 **及** 激光融合 `laser_cloud_fuse`/`laser_cloud_normal` | **整段跳过**（ccl 后直达汇合；无激光3D → 激光融合无输入亦跳过） | 运行 | 3.3 `enableLaser` |
>
> **正交数据条件——已存在高精度标记点（`existingMarkers`）**：与 A/B 选择正交，A/B 均可挂载。启动扫描时一次性检测，**非空且不含激光点**（仅标记点）才加载（来源：外部文件 / 上次 A 扫描产出，数据为标记点三维点集 `MarkerCloudPoint`）。加载后给这些点打 `isHighPrecision` 标签，并影响三处（细节见第五节）：（配准）`optical_flow_fuse` 作为匹配靶标；（融合）`marker_cloud_fuse` 经 `seed()` 预填进体素哈希累积器；（GBA）作为软先验高权重残差。注：标记点与激光点融合算子内部各维护一个体素哈希累积器（`marker_cloud_fuse_cpu.h:95`），两累积器空间栅格一致（共原点/分辨率），位置可互查。
>
> **mask 前段条件标注**：上图 `预处理-01 mask_separation` 对 A 暂按"与 B 同"绘制；但情况A 的"无激光"工况**未经设计验证**（见 3.4）。若实测后 A 改走 `mask_extract`，该框成为**额外 A-vs-B 变点**，届时在此补标记。

### 3.2 两种情况

| 模式 | 说明 | 与基线(情况B)的差异 |
|---|---|---|
| **情况A 纯标记点扫描** | 设备只打补光灯、不打激光；每帧只算标记点三维重建 + 逐帧融合；扫描结束跑全局优化压实累积漂移 | 关闭激光链；不出网格，不进后处理网格阶段 |
| **情况B 标记点+激光（现有基线）** | 双分支全跑（即本文一/二节描述的流程） | —（基线） |

> A/B 均**必跑**收尾 GlobalOptimStage：A 靠它压实光流链式配准的累积漂移（A 的唯一漂移修正手段）；B 的标记点位姿同样经光流链式传播会漂移，亦需 GBA 压实。两模式均可**可选**挂载 `existingMarkers`（已存在高精度标记点，与模式选择正交，见第五节）。

### 3.3 设计决策：单一流水线 + 开关（不拆两条）

两情况共享绝大多数核心算子（标记点主干 13 算子 + 配准 + 融合全共用），**差异只在激光链这一整段**。拆两条流水线 = 把跨帧并行调度层（E核/P核/GPU槽，见 `扫描并行调度260629.md`）复制两份，必然漂移。故采用**单一 `ScanPipeline` + `ScanConfig`**：

| 开关 | 字段 | 情况A | 情况B |
|---|---|---|---|
| 激光链 | `enableLaser` | false | true |
| 已存在高精度标记点 | `existingMarkers`（标记点三维点集 `MarkerCloudPoint` + `isHighPrecision` 标签） | 可选 | 可选 |
| 收尾全局优化 | `enableFinalBA` | 必跑(true) | 必跑(true) |

> `enableFinalBA` 两模式均恒 true，不再构成差异，实际可降级为常量；保留在表中仅为显式说明 A/B 都必经 GBA。因 GBA 必跑，`existingMarkers` 的高权重永远有施展机会，不存在"挂载却不跑 GBA"的无效配置。

> **算子层零新增**。两情况的行为差异由编排层的 `if(enableLaser)` 短路表达；`existingMarkers` 是否挂载由启动时检测决定（见第五节），无需类型多态（与本工程"组合优于继承、算子纯函数无基类"的既定架构一致）。

### 3.4 情况A 的 GPU 前段（开放决策点）

`enableLaser=false` 时，GPU 链短路为 `mask_separation → ccl`（激光04~08 整段跳过，GPU 槽释放更早，吞吐反而上升）。但 **`mask_separation` 的"无激光"工况未经设计验证**——其算法按宽度差分离激光(粗)与标记点(细)，设计前提是"激光线与标记点并存且宽度有差异"（见 `mask_separation` 文档 G 节）。纯标记点输入下输出*大概率*仍正确（大特征提取为空集 → 相减得标记点），但需实测确认。备选方案：走标记点专用前段（被 `mask_separation` 替代的旧版 `mask_extract`/`MaskExtractCUDA`）。**待联调实测后定。**

## 四、收尾全局优化阶段（GlobalOptimStage）

### 4.1 阶段定位：独立于扫描、独立于后处理

两情况的收尾全局优化（GBA）都在**扫描结束后一次性批处理**（Ceres 大问题，秒~分钟级），与扫描的 200fps 流式是不同执行模型。后处理 7 阶段（`全局优化→重融合→法线→封装→补洞→光顺→边界优化`）中，**只有前两阶段是"位姿优化"，后 5 阶段是点云法线/网格曲面操作**。情况A 纯标记点不出网格，只需前两阶段。

**决策：把"全局优化(GBA) + 重融合"独立成 `GlobalOptimStage`**，置于扫描与后处理之间：

```
扫描(流式, 产逐帧obs+位姿链)  →  GlobalOptimStage(批处理)  →  后处理(法线/封装/补洞/光顺/边界)
   02_scanning                     [GBA + 重融合]               04_postprocess
```

- **情况A**：`扫描 → GlobalOptimStage → 待机`（不进网格后处理）
- **情况B**：`扫描 → GlobalOptimStage → 待机`，网格后处理为其后的独立下游工作流（`04_postprocess`）

> **触发与状态机**：GlobalOptimStage 由操作者点击 **"完成扫描"图标** 触发，是扫描会话的收尾步骤。状态流转：
>
> ```
> 扫描中 ──[点击"完成扫描"]──▶ GlobalOptimStage(GBA+重融合, 批处理阻塞) ──▶ 退出扫描状态 → 待机
> ```
>
> A/B 均必跑（见 3.3），**GlobalOptimStage 必须跑完才会退出扫描状态回到待机**。注：上图"扫描 → GlobalOptimStage → 04_postprocess"是**数据/工作流视角**的管道串联；**UI 状态机视角**下，完成扫描点击只阻塞到 GlobalOptimStage 结束即回待机，B 的网格后处理（`04_postprocess`）作为独立下游工作流另行进入。
>
> **display 行为**：GBA 批处理期间（秒~分钟级）display **保持末帧**（冻结于扫描最后一帧的融合点云），不更新。

> 为什么不把 GBA 留在后处理第1阶段：情况A 不需要网格阶段，若 GBA 埋在后处理里，情况A 要么被迫调用网格模块只跑 1/7 阶段、要么后处理得做成可配子集——本质退化为独立阶段。GBA 优化的是**位姿**（与配准同类），后处理其余阶段是**网格几何**，GBA 是后处理里的异类，概念上离扫描更近。

### 4.2 落地约束

| 项 | 说明 |
|---|---|
| 不新增模块 | 遵守 G1 决策（"保持 11 模块边界"）。`GlobalOptimStage` 是 workflow 层的 `Stage`（`framework/workflow` 的 Pipeline/Stage 契约），**07_session** 运行时编排：完成扫描触发 `GlobalOptimStage`，跑完即回待机；`PostprocessStage`（仅 B）作为独立下游工作流另行进入（逻辑数据管道仍为 `[ScanStage → GlobalOptimStage → PostprocessStage]`，见 4.1 触发与状态机） |
| 算子位置 | `global_ba_cpu`（Ceres + PGO + 闭环 + Tukey 鲁棒）已实现，留 `09_operatorlib/scanning/global_optim/` |
| 数据交接 | 扫描把逐帧 `{R_init, t_init, markerObs[]}` 写入 **WorkflowArtifactStore**（ADR 7.10）；GBA 读入、写回修正位姿；后处理读修正位姿做重融合 |
| **逐帧观测累加器** | GBA 需每帧 `{R_init, t_init, markerObs[]}`，**不能**从 `marker_cloud_fuse` 的 `fusedPoints_`（体素去重云，已丢逐帧结构）取。须在调度层另维护一个逐帧 obs 缓冲 |
| GBA + 重融合成对 | GBA 只产"修正位姿"，必须紧跟重融合（用修正位姿重跑 `marker_cloud_fuse`/`laser_cloud_fuse`）才有"修正后点云"。两者同属 `GlobalOptimStage` |

> **globalId 来源**：GBA 输入的 `markerObs.globalId` 由配准链产出（`optical_flow_fuse::getGlobalIds()`）：首帧 `globalId=i`（若挂载 `existingMarkers`，匹配上的点 `globalId=bestIdx` 指向已有点），后续帧经光流匹配链式传播。注意并行调度层采用"最新快照"模型（`扫描并行调度260629.md §4.3 决策3`，可跳帧/乱序读 `g_prevState`），globalId 链一致性须在此模型下保证。

## 五、已存在高精度标记点（`existingMarkers`）机制

> **原则**：已存在的标记点**默认高精度**，是权威参考。扫描数据去对齐它，而非反过来。

### 5.1 来源与触发

| 项 | 说明 |
|---|---|
| **来源** | ① 外部基准点文件（默认高精度）；② 上次 A 模式扫描产出（每次 A 扫描都经 GBA 优化、且无激光干扰，识别与计算精度均较高） |
| **数据形态** | 标记点三维点集（`MarkerCloudPoint`：xyz/法线/whiteRadius，与 `fusedPoints_` 同构），**仅含标记点、不含激光数据**。`seed()` 注入融合算子内部的体素哈希累积器（与激光哈希累积器共栅格，空间位置一致） |
| **触发** | 启动扫描时一次性检测，`existingMarkers` 非空**且不含激光点**（仅标记点）才作为高精度点加载；与 A/B 模式选择正交，两模式均可挂载 |
| **标签** | 加载后给这些点打 `isHighPrecision` 标签，随融合持久化、随逐帧 obs 透传到 GBA |

> **为何触发条件要求"不含激光点"**：existingMarkers 的高精度前提是"标记点单独采集、无激光干扰"（见来源 ②）。若已有数据来自 **B 模式续扫**（标记点+激光），其标记点未享受无激光的高精度采集，**不应**当高权重控制点——否则会用"不够准的旧点"锚住"更准的新点"。故触发条件排除含激光的数据。此种 B 续扫数据按**普通续扫**处理：可 seed 进融合作起始状态，但**不打** `isHighPrecision`，GBA 中与新扫描点**同等权重**优化。

### 5.2 各阶段处理

| 阶段 | 处理 |
|---|---|
| 配准 `optical_flow_fuse` | 已有点作**匹配靶标**：`fuseFirstFrame`(`cpp:265`)/`fuseSubsequentFrame`(`cpp:374`) 拿当前帧去匹配已有点、解 R/T 对齐过去，全程**不回写**已有点坐标。匹配上的点拿到指向已有点的 `globalId=bestIdx`——这是三阶段（配准→融合→GBA）的连接键 |
| 逐帧融合 `marker_cloud_fuse` | 开扫前将已有点**经 `seed()` 预填进融合算子的体素哈希累积器**：体素"首个落入者为代表"天然保住先入点。当前算子**无注入接口**（仅 `Clear()`，`marker_cloud_fuse_cpu.h:120`），**需新增 `seed()` + 保证 seed 发生在任何扫描帧之前**。显示器从第 0 帧即可见 |
| 全局优化 `global_ba_cpu` | 已有点作**软先验高权重**（非硬固定），见 5.3 |
| 重融合 | 已有点位置经 GBA 微调（高权重残差允许亚噪声级移动），重融合读取修正位姿重跑，已有点随之更新到修正后位置 |

### 5.3 GBA 高权重（软先验，核心改造）

**问题**：`global_ba_cpu.cpp:485-496` 的残差块把**位姿(q,tt)和标记点位置(X)都设为自由优化变量**，全代码仅帧0位姿被 `SetParameterBlockConstant`（行476-479），**无任何 X 被固定/加权** → GBA 会把已有点当成和新观测同等噪声的普通点，挪动它去贴合扫描观测，与"已有点高精度"相反。

**解法（软先验高权重）**：对已有点的 3D 位置 X 额外加一残差项 `‖X − X_existing‖² / σ²`，σ 取极小（如 0.001mm 量级）使其等效高权重：
- **已有点 = 高权重软先验**（允许亚噪声级微调，吸收其微小系统误差，但几乎不被扫描观测挪动）；
- **位姿 + 全部标记点 = 自由变量**（被优化）；
- 扫描帧最优地贴合高权重已有点 + 新点 → 整体漂移被已有点锚住。
- σ/权重具体取值与判定算法**待联调标定**。

> **为什么默认软先验而非硬固定**：硬固定（`SetParameterBlockConstant`，位置零移动）实现更简单、约束更强，但要求已有点"绝对无误差"。已有点虽高精度，仍可能含微小系统误差（外部文件标定残差、上次 A 扫描 GBA 收敛残差），软先验允许亚噪声级自校正更鲁棒。若实测发现某批已有点可信度极高、不希望任何移动，可对该子集升级为硬固定（见下"升级路径"）。

**所需改动**：

| 项 | 说明 |
|---|---|
| `GlobalBAInput`/`GlobalBAParams` 新增 `highPrecisionGlobalIds` + 各自 `X_existing`/`σ` | 标记哪些 globalId 是已有点、及其先验位置与权重（当前 `global_ba_cpu.h:36-51` 无此字段） |
| Ceres 构造加残差块 | `if (globalId ∈ highPrecisionSet) problem.AddResidualBlock(priorCost(X, X_existing, σ), nullptr, X[idx].data());` |
| globalId 一致性 | 已有点在配准时拿到 globalId（`fuseFirstFrame` 行322 `globalId=bestIdx`），该 id 须透传到 GBA 的 `highPrecisionGlobalIds`——**globalId 是三阶段(配准→融合→GBA)的连接键** |
| 外点剔除安全 | GBA 的 chi-square gate 剔除**观测**（`obsInfos.culled`，行486），**不剔除标记点** → 已有点安全，顶多其某次噪观测被剔除 |
| 升级路径（可选） | 若某已有点需绝对固定：对该 id 改用 `problem.SetParameterBlockConstant(X[idx].data())`（硬固定），与帧0位姿固定方式一致 |

> **算子算法未定**：高权重的具体实现（软先验 σ 取值、是否分批/分级权重、是否对部分点升级硬固定）属算法细节，本节只锁定"已有点高精度、GBA 中施加高权重"的方向，具体待联调实测后定。
