# 日志规范（v1.1）

> 全工程日志的**唯一口径**。装配实现：`modules/10_observability/ObsLogger.*`＋`jmw_logging.h`；
> 09 算子库自有宏 `CALIB_LOG_*`（core/common/calib_logging.h）与本规范同构。
> 改本文件先过会——pattern/tag/级别纪律三处改动影响全工程日志可读性与排障包。

---

## 1. 体系架构（谁装配、写到哪里）

```
main.cpp 启动序（§7.3）：obsLoggerInit → CrashHandler::install → 其余件
                                    │
                     spdlog default logger "jmw"
                     ├─ stdout_color_sink_mt        （控制台）
                     └─ daily_file_sink_mt          （文件）
```

| 项 | 规则 |
|---|---|
| 文件路径 | `<工作目录>/logs/jmw_YYYY-MM-DD.log`（**按日一文件**，日期插在扩展名前） |
| 切换时机 | 跨零点首次写入自动换新文件（**运行中生效**，无需重启） |
| 保留策略 | **7 天**（`ObsLoggerConfig.maxFiles`）；init 时主动清积压最旧＋sink 轮转时清 |
| 落盘时机 | **warn 及以上即时 flush**（崩溃留痕）；info 靠缓冲（性能） |
| 幂等 | 重复 `obsLoggerInit` 先拆旧装配再重建（旧句柄释放、余量落盘） |
| 句柄纪律 | Windows 下删 logs 目录前**必须** `obsLoggerShutdown()`（daily sink 持当日文件句柄） |

## 2. 行格式（pattern 定死，勿动）

```
[HH:MM:SS.mmm][level][jmw][文件名:行号] [tag] 消息
```

实例：

```
[14:32:07.412][info][jmw][main.cpp:24] [app] === ScannerFramework 启动 ===
[14:32:08.003][warning][jmw][ScanChains.cpp:243] [07-ScanChains] mask_separation L 失败: ...
```

- `%s` 只显示**文件 basename**（spdlog 自动截路径）；`%#` 行号——由宏在**调用点**捕获，调用方零负担
- 没有源位置的行（理论不应再出现）会显示 `[:0]`——见到即违规（见 §3）

## 3. 书写规则（唯一入口＝宏，禁散装调用）

| 场合 | 用法 | 说明 |
|---|---|---|
| **全工程新代码** | `JMW_LOG_INFO/WARN/ERROR/DEBUG("tag", "fmt {}", args)` | 唯一合法入口；源位置自动带 |
| 09 算子库内部 | `CALIB_LOG_*`（同构宏） | 沿用算子自有宏；tag 用文件内 `kLogTag`（`CALIB_DEFINE_LOG_TAG(0, 算子名)`） |
| **禁止** | `spdlog::info/warn/...` 函数直调 | **无源位置**（日志显示 `[:0]`，无法定位）；ObsLogger.cpp 装配体自身除外 |
| **禁止** | 自建 logger/sink/set_pattern | 全库只允许 ObsLogger 一处装配；否则 pattern 漂移、排障包遗漏 |

## 4. tag 命名（模块-对象 双钥匙）

格式：`<模块号>-<对象短名>`；app 层用 `app-<对象名>`；09 用算子 PascalCase 名。

| 示例 | 归属 |
|---|---|
| `07-ScanChains` / `07-PosturePipeline` / `07-CpuTopology` | 07 流水线 |
| `08-DeviceManager` / `08-MCUDriver` / `08-SerialPort` | 08 设备 |
| `06-CalibRepo` / `10-FaultHandler` / `01-CalibWorkflow` | 其余模块 |
| `app` / `app-SceneFeed` / `03-OSGWidget` | app/渲染 |
| `IntrinsicCalib` / `GlobalBA`（CALIB_LOG kLogTag） | 09 算子 |

纪律：**一个 .cpp 一个 tag**（文件粒度）；新文件按此表风格起名，不发明新格式。

## 5. 级别纪律

| 级别 | 语义 | 用例 | 落盘 |
|---|---|---|---|
| `info` | 关键流程节点（启停/状态迁移/会话边界） | 工作流 start/stop、open/close | 缓冲 |
| `warning` | **可继续的降级**（数据缺失/超时重试/预算截断） | 单帧算子失败丢帧续跑、缓存超限 | **即时 flush** |
| `error` | **该路径失败**（需人工关注） | 装配失败、渲染挂起、仓库写失败 | **即时 flush** |
| `debug` | 高频过程细节（默认不落盘，排障时开） | 逐帧心跳、freeze 通知 | 不输出（level=info） |

防刷屏纪律（既有先例必须遵守）：
- **持续性事件一次性上报**：循环里首次发生记 warning，后续静默或计数汇总（先例：FuseConsumer `laserDegradeReported_`、OSGWidget `suspendRender` 幂等）
- **热路径禁 info**：每帧循环体内只允许 debug；聚合后按秒/会话级再 info
- 计数优于重复：能 `n 次累计后汇总` 就不逐条打

## 6. 与故障事件的分工（日志 ≠ 事件）

- **Fault/Degraded 语义事件**走 EventBus（带事件码：07 的 16xx/19xx、03 的 03xx、08 的 08xx）——供 UI/状态机消费
- **日志**负责同一事件的**人读现场**：事件发布点旁必须有一条同 tag 的 warn/error，消息里带事件码（先例：`[render] 0x{:04X} {}`）
- 两通道并存：事件可订阅、日志可 grep——谁也不替代谁

## 7. 排障包联动（崩溃后的取证链）

```
崩溃当场：CrashHandler filter → dumps/crash_<tick>.dmp ＋ crash_pending 标记（零分配，不打日志）
下次启动：detectResidualDump 检出 → obsExportDiagnosticsPackage(residual)
           → <logs 旁>/diagnostics_<时间戳>/{ logs/(最近7天全量), dumps/(最旧一份), version.txt }
```

- warn+ 即时 flush 正是为"崩溃前最后一条 warning 必在文件里"服务
- 排障包含**多天日志**（按日文件的红利）——崩溃对齐用时间戳＋`[:行号]`

## 8. 路径与部署

- `logs/`、`dumps/` 均为**相对工作目录**——位置随启动方式漂移（VS 调试/双击 exe/命令行各不同）
- 产线部署若需固定位置：`obsLoggerInit` 传绝对路径（CrashHandler 已在 install 时解析绝对路径缓存，ObsLogger 同款处理即可，待办）
