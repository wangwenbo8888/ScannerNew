### 1.1 模块背景〔AI 预填，迭代时刷新〕

- **模块定位**：三维扫描仪的计算零件箱——全部纯计算叶子算子的集合；算子自己不编排、不碰设备，标定/扫描两条流水线要什么算子都来这里拿
- **上下游依赖**：
  - 上游：06（标定档案/温度表契约类型同源）＋07（参数与帧数据注入）
  - 下游：07 五流水线（A 姿态/B 标定计算/C 扫描处理/D 全局优化/E 后处理）消费全部算子
  - 下游：01/02 工作流经 07 间接受益；05 编辑消费两融合算子的 removePoints 契约
- **关键约束**：
  - 统一契约（全库一致）：三元组＝Params（validate/toJson/fromJson）＋Result＋Operator（Execute/Warmup/SetParams/Destroy，pImpl 禁拷贝）
  - CUDA 算子统一 `Stream&` 流亲和（不内部同步默认流）；目录约定 `<name>_cuda.h`/`.cpp`/`_pimpl.h`/`_impl.cu`/`tests/test_*.cpp`
  - 命名空间 `calib::`（3DSCANNER 机械迁入保留）；单 STATIC 库 `OperatorLib`（core＋calibration＋scanning 合建）
  - `GLOB_RECURSE` 收源：增删算子源文件需手动重跑 cmake；bench/benchmark 与 gba_dataset_runner 不入库
  - BUILD_CUDA 门控 CUDA 算子；BUILD_GLOBAL_OPTIM 门控 Ceres 链接与 global_ba_cpu 编入
  - 算子质量经 QualityFlag（ok/degraded/warning 语义）随 Result 返回，不抛业务异常
  - 契约细节见 [`算子规范.md`](../../算子规范.md)；逐算子说明见 [`算子目录.md`](../../算子目录.md)→`docs/算子说明文档/`
