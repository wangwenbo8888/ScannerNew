## 1. 信息〔人＋AI〕

### 1.1 模块背景〔AI 预填，迭代时刷新〕

- **模块定位**：出厂打包员——把软件装进客户机（产品级安装包/卸载）并陪用户走完第一次开机（首运行向导：连设备/选语言/初始标定引导/许可证激活/进主界面）
- **上下游依赖**：
  - 上游：构建产物 LeadScannerK2.exe 及其全部运行时依赖（Qt/OSG/OpenCV/CUDA/Galaxy SDK/CRT）
  - 下游：首运行向导衔接 08 设备管理（设备连接检测）与 01 标定工作流（初始标定引导）；许可证激活衔接 08 G12（现为占位）
- **关键约束**：
  - 模块本体为空桩——`mod_deploy` 仅 INTERFACE 占位保 CMake 目标名，无源码、无部署逻辑
  - 现有「部署」实现均为**开发期辅助**（构建后拷 DLL），非产品级安装能力
  - 三方库路径硬编码本机绝对路径，与根 CMakeLists CACHE 变量（JMW_QT5_PREFIX/OSG_ROOT/OpenCV_DIR）当前取值一致但重复维护、bat 不接收变量；`环境配置汇总.md`（2026-05-20 版）路径已过期不同步，换机即断
  - factory_calib 厂家标定子工程有独立 CRT 部署（fc_deploy_crt）——AI 只读保护区，不归 11 管辖
- **构建与测试**：无源码、无测试；本模块文档主要记录散落各处的部署设施现状

### 4.1 总图

```
【开发期部署链：构建产物如何变得可直接运行】
LeadScannerK2.exe（app 构建目标）
    ├─ POST_BUILD copy_dlls.bat ──► Qt5×6＋OSG×7＋OpenCV×11＋CUDA cudart64_12＋
    │                                Galaxy SDK×14＋platforms/qwindows 插件
    ├─ POST_BUILD config 部署 ───► camera.json（装机口径，每次覆盖）＋
    │                                calibration/laser_calib.json（仅缺失播种）
    ├─ VS 调试支持 ─────────────► 工作目录指 exe 目录＋启动项目设 LeadScannerK2

        gba_dataset_runner；LeadScannerK2 靠系统 CRT，见应用层 04 D3）
```
