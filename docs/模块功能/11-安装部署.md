# 模块11 · 安装部署

> 一句话：本模块是**出厂打包员**——负责把软件装进客户机（安装包/卸载）并陪用户走完第一次开机（首运行向导：连设备/选语言/初始标定引导）。
> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)

## 1. 功能目标

- 做什么：安装包/卸载，首运行配置向导（设备连接检测→语言选择→初始标定引导→许可证激活→进主界面）。
- 交互：交付目标态——产物 scan_demo.exe 及其全部运行时依赖（Qt/OSG/OpenCV/CUDA/Galaxy SDK/CRT）的可安装形态；首运行向导衔接 08 设备管理（连接检测）与 01 标定工作流（初始标定引导）。

## 2. 实现现状（以代码为准）

> 一句话：模块本体为空桩；现有「部署」实现均为散落工程根/app/cmake 的**开发期部署辅助**（构建后拷 DLL），非产品级安装部署能力。

### 2.1 `modules/11_deploy/CMakeLists.txt`（mod_deploy）
- 核心能力：INTERFACE 占位库，仅保 CMake 目标名，无源码、无部署逻辑。
- 编译归属：不参与任何链接产物。
- 状态：预留

### 2.2 散落的开发期部署设施（不在 11_deploy 目录内，属「部署」语义的现状实现）

```
构建产物 scan_demo.exe
  ├─ POST_BUILD copy_dlls.bat ──▶ Qt5×6 + OSG×7 + OpenCV×10 + platforms/qwindows 插件
  ├─ jmw_deploy_crt() ──▶ VS2022 redist CRT×3（msvcp140/vcruntime140/140_1）
  └─ cmake/ 构建辅助 ──▶ 编译器配置 / nvcc pin 补丁 / Version.h 模板
```

- `app/copy_dlls.bat`（经 `app/CMakeLists.txt:120-123` 挂 scan_demo POST_BUILD）
  - 核心能力：构建后拷贝运行时 DLL 到 exe 目录——Qt5（Core/Gui/Widgets/OpenGL/Svg/SerialPort）＋OSG（osg161 系×6＋ot21-OpenThreads）＋OpenCV（core/calib3d/imgproc/imgcodecs/features2d/flann＋cudaarithm/cudawarping/cudaimgproc/cudev），区分 Debug/Release；并部署 Qt platforms/qwindows 插件。
  - 现状限制：三方库路径硬编码在脚本头部（对齐本机 `环境配置汇总.md`），与 CMake 变量体系脱节。
- 根 `CMakeLists.txt` 的 `jmw_deploy_crt(target)`（`CMakeLists.txt:132-144`）
  - 核心能力：把 VS2022 redist CRT 三 DLL 拷到 exe 旁（System32 旧版 CRT 会致 OpenCV 崩溃）；当前被 06/07/08/09/10 各测试 exe 与 gba_dataset_runner 调用。
  - 交互：CRT 源目录经缓存变量 `JMW_MSVC_REDIST_CRT_DIR` 配置。
  - 现状限制：版本号硬耦本机 redist（14.44.35112）。
- `cmake/CompilerSettings.cmake` — 编译器统一配置（MSVC `/W4 /MP`、MultiThreadedDLL CRT、Debug 映射 Release OpenCV），决定构建产物形态。
- `cmake/PatchVcxproj.cmake`＋`cmake/PatchCudaVcxproj.bat.in` — nvcc 12.6 pin 补丁（修正生成工程的 CUDA 工具集）。
- `cmake/Version.h.in` — 版本号模板（configure 生成 Version.h 注入版本宏）。
  - 现状限制：宏前缀仍为 `ScannerFramework_VERSION_*`（framework 已退役的旧命名）。
- `factory_calib/cmake/fc_deploy_crt` — 厂家标定子工程的等价 CRT 部署（**AI 只读保护区，独立子工程，不归 11 管辖**）。
