## 1. 代码实际实现的

> `modules/11_deploy/` 为空桩（仅 `CMakeLists.txt`，INTERFACE 库 `mod_deploy`，无源码）。现有"部署"实现均为散落在工程根 / 各子工程的**开发期部署辅助**，非产品级安装部署能力。

### 模块空桩
- `modules/11_deploy/CMakeLists.txt` — INTERFACE 占位库 `mod_deploy`，仅 3 行，无任何部署逻辑

### 散落工程根的部署辅助（不属于 11_deploy，但属"部署"语义）
- `cmake/CompilerSettings.cmake` — 编译器统一配置（MSVC `/W4 /MP`、`MultiThreadedDLL` CRT、Debug 映射 OpenCV Release），影响构建产物形态
- `cmake/PatchCudaVcxproj.bat.in` + `cmake/PatchVcxproj.cmake` — nvcc 12.6 pin 补丁（修正生成工程的 CUDA 工具集）
- `cmake/Version.h.in` — 版本号模板（CMake configure 生成 `Version.h`，注入 `ScannerFramework_VERSION_*`）
- `app/copy_dlls.bat` — 构建后拷贝运行时 DLL 到 exe 目录：Qt5（Core/Gui/Widgets/OpenGL/Svg/SerialPort）+ OSG（osg161 / ot21）+ OpenCV（core/calib3d/imgproc/imgcodecs/features2d/flann/cuda*），区分 Debug/Release；并部署 Qt `platforms/qwindows` 插件
- 根 `CMakeLists.txt` 的 `jmw_deploy_crt(target)` 函数（`CMakeLists.txt:94`）— 把 VS2022 redist CRT DLL（`msvcp140.dll` / `vcruntime140.dll` / `vcruntime140_1.dll`）拷到 exe 旁；当前被 `modules/09_operatorlib`（gba_dataset_runner + 各算子测试 exe）调用。CRT 路径经 `JMW_MSVC_REDIST_CRT_DIR` 缓存变量配置
- `factory_calib/cmake/factory_calib_common.cmake` 的 `fc_deploy_crt(target)` — 厂家标定独立子工程的等价 CRT 部署函数（**AI 只读保护区，独立子工程，不归 11 管辖**）

## 2. 代码需要调整的

- **部署设施未归拢到 11_deploy**：`jmw_deploy_crt` 写在根 `CMakeLists.txt`、`copy_dlls.bat` 放在 `app/`、构建补丁在 `cmake/`，均散落各处。建议把通用部署能力（CRT 部署函数、DLL 拷贝脚本封装、版本/补丁工具）作为"部署设施层"归拢到 `modules/11_deploy/`，由其统一暴露给 app / 算子测试等目标调用
- **`copy_dlls.bat` 路径硬编码**：Qt5/OSG/OpenCV 路径写死在脚本中（对齐 `环境配置汇总.md`），与 CMake 变量体系脱节，应改为从 CMake 生成或读取缓存变量，避免环境漂移再次踩坑（脚本头部已记录 2026-08-13 的一次别机路径修正）
- **`Version.h.in` 仍用 `ScannerFramework_VERSION_*`**：framework/ 已退役，命名前缀应同步迁移到新工程命名空间（参见 `modules/09_operatorlib/core/common/version.h`）
