# 模块7 · 流水线管理

> 一句话：本模块给 01/02/04 三条工作流供应「会算会跑」的流水线——5 条业务流水线对象＋1 套并行调度底座；算子在 09、容器在 06、采图在 08，这里只管「编排与调度跑起来」。
> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)

## 1. 功能目标

构成＝**5 条业务流水线对象**（全是会话私有件：由工作流装配启停、逆序回收，对象自治）＋**1 套并行调度底座**（两条帧级流水线共用；三条离线批流水线不走底座）。

### 1.1 A 姿态判断流水线（01-⑤）
- 做什么：逐周期认姿态——从环形缓冲顺序领取采集周期单元（标记点帧＋全部激光管帧＋温度，整单元读），跑完整标记点算子链判出设备当前姿态；连续命中同一目标姿态才确认（01-D3，非「盲收 N 帧」）。
- 怎么跑：帧级流水线、单分支——GPU 轻前段（掩膜提取→帧类型过滤[激光线帧直接销毁]→连通域）→ P核标记点链（瓶颈在 P核）→ E核融合（光流优先，失败降级单帧配准）＋姿态判断。
- 帧策略：不丢帧——处理跟不上就反压采集线程（暂停写入等消费），每帧都要过姿态判断，防漏检 25 个目标姿态。
- 命中动作：多流水线同时命中同一姿态只算一次（原子标记防重复）；保存完整周期帧（激光管帧作「乘客」随单元一并存）。
- 交互：边跑边推实时姿态＋标志点检出状态给渲染，每确认一个→渲染切下一目标；集齐 25 姿态自动收口——停采＋销毁缓冲＋叫醒标定计算流水线（01-⑤→⑥）。

### 1.2 B 标定计算流水线（01-⑥）
- 做什么：姿态集齐后一次性批算标定参数（批处理，不走帧级调度底座）。
- 内部结构：相机链 ‖ 激光前段（激光线提取）并行 → 激光后段以数据驱动跟随（PJC 联合标定，01-D4 定版）→ 质量门禁（参数合格与否先判一道）。
- 交互：吃 A 存下的 25 组姿态周期帧；算出的标定参数＋两张温度表交 06 标定结果仓库落盘（01-⑦）。

### 1.3 C 扫描处理流水线（02-⑤）
- 做什么：主力干活的——从环形缓冲抓最新帧（抓到即「增强帧」：06 缓冲出口已按帧温查好两张补偿表、随帧附标定快照，算子无查表动作）。
- 怎么跑：帧级流水线、双分支、速度优先——并行 X 条流水线，每条＝1 个独占 E核（编排）＋动态租用 P核＋共享 GPU 槽；单帧生命周期：E核抓帧 → GPU 整链持槽串行（掩膜分离→连通域→激光链）→ 连通域一就绪 P核立刻开跑标记点链＋配准（与 GPU 激光链帧内完全并行）→ 两边齐了 E核汇合组装单帧结果发布输出队列；恒有 1 条流水线待命（预取＋预处理提前做完，P核一空就接管，无空窗）。
- 帧策略：消费落后超阈值就跳到最新帧、丢中间帧——永远追新帧（速度优先）。
- 配准：读 PrevFrameState 最新快照（不严格等上一帧；帧间移动小，精度影响可忽略）；光流失败降级单帧配准兜底、再失败沿用上帧 R/T。
- 双模式：单一流水线＋开关——A 纯标记点整段跳过激光链（enableLaser=false）；不拆两条流水线（拆了调度层得复制两份）。
- 交互：单帧结果出输出队列后进本对象的融合环节做累积（标记点 CPU／激光 CUDA 体素哈希），点云越滚越大边滚边推渲染；同时攒逐帧观测进累加器喂 GBA；故障/降级上报 10。

### 1.4 D 全局优化对象 GBA（02-⑦）
- 做什么：收尾纠偏师——扫描结束（用户点软件「完成扫描」，02-D3）才上场的批处理：读逐帧观测累加器 → Ceres GBA＋位姿图闭环消累积漂移 → 用修正位姿重融合（GBA 只产修正位姿，必须紧跟重融合才有修正后点云，两者成对同属本对象）；期间渲染冻结末帧。
- 观测来源：逐帧 {R_init, t_init, markerObs[]} 由 C 逐帧攒——不能从融合累积器取（体素去重云已丢逐帧结构）。
- 基准点：挂已存在高精度标记点（existingMarkers，与 A/B 正交，来源＝app 点云仓库）时作高权重软先验，锚住整体漂移。
- 归属边界：编排在 02 工作流内触发（不在帧级流水线与调度层里）；算完＝工作流终结（02-D4）。

### 1.5 E 后处理流水线（04 后处理工作流；04 无定稿流程图，不挂步骤号）
- 做什么：离线批处理五阶段——法线重算 → 封装（网格化）→ 补洞 → 光顺(HC) → 边界优化，出 STL。
- 不含什么：全局优化(GBA)＋重融合不在此——已归 02 扫描收尾。
- 输入/输出：输入＝02 产出的 GBA 修正后点云（06 点云仓库内存调用，app 存活件，免文件中转）；输出＝STL/PLY 经 06 文件服务落盘。
- 怎么跑：离线批处理，不走帧级调度底座（与 B 同类）；不碰设备——不过设备门禁，状态机走 S6 后处理态（离线免 S7）。
- 交互：记账（进度/取消/产物）归 04 自身；消费 09 算子（法线已有；封装/补洞/光顺/边界四族网格算子待 09 新建）。

### 1.6 并行调度底座（两条帧级流水线共用一套实现，仅配置不同）

资源分法（X 个 P核＋Y 个 E核＋1 块 GPU）：
- P0 一核锁给 Windows 系统＋采集线程（08 写环形缓冲）
- P核池：X-1 个绑核 worker 线程跑 CPU 重活，动态租用（X 条流水线抢 X-1 核）
- E核：每条流水线独占 1 个（共 X 个），纯编排不扛计算，全生命周期不换
- GPU 槽：扫描 2 槽（每帧持槽串行跑完整 GPU 链、中途不释放）／姿态 1 槽（GPU 活轻）
- 流水线数：X 条＝活跃 X-1＋待命 1（防 P核空转）

双模式对照：
- 扫描（02-⑤）：双分支（标记点 CPU ‖ 激光 CUDA，帧内并行）／GPU 2 槽为瓶颈／跳最新丢中间／用户停止／单帧结果（R/T＋标记点3D＋激光3D）→融合
- 姿态判断（01-⑤）：单分支（GPU 前段与 P核链串行）／GPU 1 槽轻非瓶颈（瓶颈 P核）／不丢帧反压采集／25 姿态集齐即停／姿态判定＋命中存周期帧

共用能力清单：
- CPU 拓扑探测（认 P核/E核）与线程亲和绑定
- P核 worker 池：收活派活，流水线提交任务后在 future 上等结果
- GPU 槽服务：先到先得占用/释放（计数信号量语义）
- 抓帧策略两副面孔：扫描「抓最新＋丢帧」／姿态「顺序领＋反压」（缓冲容器本体属 06）
- 无锁输出队列（MPMC）：单帧结果发布给下游，满时覆盖最旧、生产侧不阻塞
- PrevFrameState 原子快照：上一帧标记点＋位姿的全局原子指针，读最新、写覆盖，多核同时配准不互相等
- 启停有序：先停采集→排空在飞帧→停流水线→停 worker→停 GPU 服务（逆序收摊）

### 1.7 不管什么（防职责蔓延）＋依赖方向
- 不管：会话记账（01/02/04 自身）／门禁与切态（状态机＝app 存活件，代码在 10）／数据容器与环形缓冲本体、缓冲出口查表（06，本模块消费）／设备驱动与采图（08）／算子（09，含待建网格算子）／UI 命令入口（app）／工作流编排（01/02/04——本模块对象被其装配启停）。
- 依赖方向：mod_pipelinemgmt → base（types/EventBus）＋ mod_fileio（容器/原语）；经 06 缓冲消费 08 的帧；调用 09 算子；故障上报 10。

## 2. 实现现状（以代码为准）

模块形态：`modules/07_pipelinemgmt/`，STATIC 库 `mod_pipelinemgmt`，命名空间 `Scanner::pipeline`；两层分工——`sched/`＝调度底座（纯机制，不认识算子，算子链全靠钩子注入），`pipelines/`＝五条业务流水线对象＋公共装配件。不链 08/10——设备、渲染、仓库走窄接口由工作流注入。
数据流一张图：

```
【A 姿态 01-⑤】SequentialSource(06 Backpressure 环·CycleUnit)
      └▶ SchedulerRuntime 单分支 ─▶ PostureConfirmTable ─集齐25─▶ 停采＋交棒 PostureSessionData
                                                                              │
【B 标定 01-⑥】CameraChain ‖ LaserChain（future 衔接）─▶ QualityGate ─▶ serializeCalib ─▶ 06 仓库落盘(01-⑦)

【C 扫描 02-⑤】GrabLatestSource(06 Overwrite 环·EnhancedFrame)
      └▶ SchedulerRuntime X lane 双链并行 ─▶ FrameResultQueue ─▶ FuseConsumer(融合＋推渲染)
                        │                                    └▶ FrameObsAccumulator(逐帧观测)
                        ▼
【D 全局优化 02-⑦】GlobalOptimObject：GBA＋重融合 ─▶ 06 点云仓库

【E 后处理 04】PostProcessPipeline 五阶段（离线批，不走底座）─▶ STL(06 fileio)
```

五条流水线对象统一 `IPipelineObject` 生命周期（configure→start⇄stop），全部为【私】会话件（工作流构造、逆序回收；A/C 明确 stop 后不可重启，重开建新对象）。
