## 职责

编排扫描的端到端处理流程：**采集 → 预处理 → 标记点链 → 激光链 → 融合**（设计目标另含 GBA 收尾），支持双模式（A 纯标记点 / B 标记点+激光），逐帧累积点云并写入 `PointCloudBuffer` 供渲染（03）与后处理（04）消费。

> **现状定位**：当前代码是**单线程 CPU 调试版**骨架（`scanLoop` 同步串行 5 个 Stage），距离设计目标的多流水线并行调度差距较大。下文 §1 以实际代码为准，§2 列差距，§3 列待增项并保留设计目标三视图作流程参考。

## 1. 代码实际实现的

### 1.1 ScanWorkflow 工作流骨架

- `modules/02_scanning/ScanWorkflow.h` / `ScanWorkflow.cpp` — 扫描工作流，命名空间 `Scanner::workflow`，实现 `IWorkflow`。核心类型：
  - `ScanWorkflow` — 工作流主体（`initialize/start/pause/resume/stop` + `scanLoop()` 单线程扫描循环 + `setScanMode/setCalibration`）。
  - `ScanCalibration` — 扫描所需标定参数（L/R 内参畸变 + `R1/R2/P1/P2/Q` + `imageSize`），由 CalibrationWorkflow 产出注入。
  - `ScanFrameResult` — 单帧结果（markerPoints3d / laserPoints3d / markerNormals / R / T）。

### 1.2 五个 Stage（Stage0~Stage4）

| Stage | 类 | 现状实现 |
|---|---|---|
| Stage0 Capture | `CaptureStage` | 从 `FrameBuffer::popFrame(100ms)` 取帧到 `latestFrame_` |
| Stage1 Preprocess | `PreprocessStage` | **CPU 手搓掩码**：`cv::adaptiveThreshold` + `morphologyEx` 生成左右标记点掩码（非 `mask_separation_cuda` 算子） |
| Stage2 Marker | `MarkerStage` | 标记点链：`connectedComponentsWithStats`(CCL) → `calib::ZernikeEdgeCPU` → `calib::EllipseFitCPU` → `calib::MarkerMatchCPU` → `calib::PointReconstructCPU`。算子对象在 Stage 构造时创建一次复用 |
| Stage3 Laser | `LaserStage` | **空壳**：`MarkerOnly` 直接返回 ok；否则记日志"需要 CUDA，跳过"。激光链完全未接入 |
| Stage4 Fuse | `FuseStage` | `calib::LaserCloudFuseCPU` 体素融合 → `PointCloudBuffer::pushPointCloud` |

`ScanWorkflow::scanLoop()`（`ScanWorkflow.cpp:335`）：单线程 `while(running_)` 同步串行跑 Capture→Preprocess→Marker→(Laser 跳过)→Fuse，每 100 帧打一条日志。**非**设计目标的多流水线并行。

### 1.3 扫描算子（在 `modules/09_operatorlib/scanning/`，命名空间 `calib::`）

扫描【算子】物理位于 09 算子库，非 02 模块：

| 目录 | 算子 | 是否已接入 02 |
|---|---|---|
| `preprocess/mask_separation/` | `laser_markingpoint_mask_separation_cuda`（联合掩膜分离，CUDA） | 否（Stage1 用 OpenCV 替代） |
| `laser/laser_match_scan/` | `laser_match_scan_cuda`（激光线匹配扫描，查温度映射表） | 否（Stage3 空壳） |
| `fusion/laser_cloud_fuse/` | `laser_cloud_fuse_cpu`（体素哈希融合，CPU） | **是**（Stage4） |
| `fusion/laser_cloud_fuse_cuda/` | `laser_cloud_fuse_cuda`（CUDA 版融合） | 否 |
| `fusion/laser_cloud_normal/` | `laser_cloud_normal_cpu`（法线估计） | 否 |
| `fusion/laser_cloud_normal_cuda/` | `laser_cloud_normal_cuda` | 否 |
| `global_optim/` | `global_ba_cpu` + `ba_residuals.h` + `pose_graph_residuals.h`（GBA/PGO）；`gba_dataset_runner.cpp` 离线 exe | 否（算子已实现，工作流未接入） |

> 注：steger / undistort_cuda / epipolar_interp / laser_reconstruct 等【激光链算子】位于 `modules/09_operatorlib/core/laser/`，标记点链其余算子位于 `modules/09_operatorlib/core/marker/`（双链前端共用 `core/vision`）。详见 [09-算子库.md](09-算子库.md)。

### 1.4 编译归属 & 相关文件

- `ScanWorkflow.{h,cpp}` 由 `app/CMakeLists.txt:47-48` 编入 `jeammware.exe`（注释明确"Phase 5：自 fw_workflow 接管编译归属；物理仍 in modules"）。`modules/02_scanning/CMakeLists.txt` 仅占位 `add_library(mod_scanning INTERFACE)`，不构建 02 模块库。

## 2. 代码需要调整的

| 项 | 现状 | 问题 |
|---|---|---|
| **LaserStage** | 空壳，CPU/CUDA 均不调算子 | 设计目标 GPU 激光链（steger→undistort_cuda→epipolar_interp→laser_match_scan→laser_reconstruct）完全未接入；B 模式实际无激光输出 |
| **PreprocessStage** | OpenCV 阈值+形态学手搓掩码 | 未用 `mask_separation_cuda`；掩膜分离语义/质量与设计不一致，无法产出 `d_laserMask` 供激光链 |
| **MarkerStage 算子链** | CPU 简化版 | 缺 `image_split`/`image_merge`/`undistort_cpu`/`epipolar_intersect`/`edge_match`/`optical_flow_fuse` 环节；CCL 用 `cv::connectedComponentsWithStats` 替代 GPU `ccl/region_analyze` |
| **并行调度** | `scanLoop` 单线程串行 | 设计目标的 X 流水线 / E-P 核 / GPU 2 槽（§3 视图③）完全未实现 |
| **标定参数注入** | `ScanCalibration` 内联 R1/R2/P1/P2/Q | 未走温度补偿表（`stereo_rectify_temp_table` / `plane_map_temp_table`），无运行时温度补偿 |
| **库边界** | `02_scanning/CMakeLists.txt` 占位 INTERFACE | 与 ScanWorkflow 实际编译归属 app 不一致，库边界模糊 |
| **GBA 收尾** | `global_ba_cpu` 算子在 09 已实现 | 未作为 `GlobalOptimStage` 接入工作流；"完成扫描"无全局优化闭环 |

## 3. 需要增加的

### 3.1 待新增项（代码）

- **`ScanConfig.h`（新建）**：双模式开关 `enableLaser`（A=false / B=true）、`existingMarkers`（与 A/B 正交）、`enableFinalBA`（恒 true）。现仅 `ScanMode` 在 `base/types.h`，无配置结构。
- **多流水线并行调度**：X 流水线（1 E 核独占编排 + 动态 (X-1) P 核 worker + 共享 GPU 2 槽），持槽串行、帧内并行（见 §3.2 视图③）。
- **PrevFrameState 配准链**：`atomic<shared_ptr>` 全局唯一快照，`load`（配准读，可跨几帧）/ `store`（配准写，原子覆盖），打破链式等待。
- **globalId 三阶段连接键**：配准产出（首帧=i，挂 existingMarkers 时=bestIdx）→ 融合持久化 → GBA 软先验高权重残差。
- **GlobalOptimStage（GBA）**：接入 `global_ba_cpu`（Ceres GBA + PGO 闭环 + Tukey 鲁棒）；点击"完成扫描"触发批处理，跑完回写融合层重融合，期间 display 冻结末帧。
- **existingMarkers 注入路径**：外部基准点/上次 A 扫描产出 → `seed()` 融合 + 配准靶标（globalId 键）+ GBA 软先验。
- **配准兜底分支**：`optical_flow_fuse` 失败 → `frame_fuse`（兜底是否产出 globalId 未定 → GBA highPrecisionGlobalIds 可能失效，开放问题）。
- **设计目标环形缓冲**：`atomic<shared_ptr<Frame>>[]` 4X 槽，消费端 lag>2X 跳最新丢中间；现状为 `framework/data/FrameBuffer`（容量 60、DropOldest），迁移治理见 [`06-文件管理.md §2`](06-文件管理.md)。

                                  load/store g_prevState (最新快照)

                                → 释放 GPU 槽 · 回 ①

### 3.3 关键机制速查（配合三视图）

| 机制 | 要点 | 图位置 / 源文档 |
|---|---|---|
| **双模式开关** | `enableLaser`: A=false（纯标记点，激光 04~08 整段跳过）/ B=true（基线）；`enableFinalBA` 恒 true；`existingMarkers` 与 A/B 正交 | 视图① `ScanConfig` · `客户端扫描流水线 §3.3` |
