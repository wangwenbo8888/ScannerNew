# 模块2 · 扫描工作流

> 一句话：本模块是客户端扫描的编排者——装配流水线、记账会话，把 08 采集、07 帧处理、03 显示串成一次扫描，自身不做帧级计算。
> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)

> ⚠ **定稿保护**：§1 流程图与数据流图为人工定稿，AI 不得自行修改；发现与代码或其他文档冲突时，须先向人说明冲突点、获得认可后才可改动。仅 §2（实现现状）随代码演进由 AI 更新。

## 1. 功能目标

### 1.1 设计定案（D1–D7）

- **D1 对象自治**：设备管理（08）、扫描处理流水线（07）、全局优化（07）、数据管理（06）、渲染（03）五对象封装自治；02 只做 ①门禁进入、②装配（注入＋构造，见 D7）、⑨旁观显示、⑩停止回收（仅会话私有件）。
- **D2 硬件按键触发**：③ 启动采集与 ⑥ 停止采集只由硬件按键电报触发（08 DeviceManager 接收 → 指令转发下位机），软件不直接启停采集。
- **D3 GBA 软件触发**：⑦ 由用户点击软件界面「完成扫描」触发；④⑤⑧ 为自动段（02 零干预）。
- **D4 生命周期边界**：⑦ GBA 优化完成＝工作流终结。续扫必须从 ① 重开新工作流（旧点云经 existingMarkers 注入作基准点）；⑥ 后就绪态内再按键续采（回 ③④⑤）仍属同一工作流。
- **D5 结果不落盘**：⑧ 优化后点云留存内存（点云缓冲），04 后处理从内存调用；落盘仅在明确请求时执行。
- **D6 会话记账归 02**：会话记账由 02 自己承担，不设独立会话对象——①开账（会话 ID＋开始时间戳）、④⑤计数（帧数/覆盖率，经事件汇总只记数值）、⑩合账（结束时间戳＋统计存档）；01 标定工作流不记帧数/姿态数。无自动定期存档：存档仅由人工手动触发（与 D5 一致）。
- **D7 对象所有权拆分**：跨工作流存活件归 **app**（应用生命周期；02 只接线注入，⑩ 不销毁）——DeviceManager(08)、标定参数仓库＋点云仓库(06)、渲染基座(03)、EventBus(base)、状态机(10)。会话私有件归 **02**（② 构造、⑩ 逆序销毁）——扫描处理流水线/全局优化对象(07)、帧环形缓冲实例(06)、场景内容供给器(03)。点云仓库不随 ⑩ 销毁：D5「留存内存供 04」由 app 仓库兑现，D4 续扫 existingMarkers 基准点亦从该仓库读取；DeviceManager 于 ⑩ 切回 idle。判据：数据跨工作流存活 → 容器归 app；仅会话内消费 → 归工作流。

### 1.2 app 存活件（应用启动即构造，先于本工作流存在）

【公】＝app 存活件（跨工作流公用）；流程中反复出现，先列出便于阅读。

- DeviceManager 设备管理器（08）【公】——08 对外唯一门面：把相机＋下位机＋按键＋温度监测封装成一个「采集服务」；02 调 `enterScan()` 即切入扫描模式。
- 数据管理（06）【仓库公＋会话件私】——仓库（公用，app 持有）：标定参数仓库（内参/矫正参数＋两张温度补偿表，01 产出）＋点云仓库（扫描结果的内存保管处，02→04 内存交接点）；会话件（私有，② 构造、⑩ 销毁）：ScanConfig 装配数据＋帧环形缓冲实例，见 ②。
- 渲染基座（03）【公】——三维视窗＋场景切换器；纯显示，不反向控制流程。
- EventBus 事件总线（base）【公】——全局事件订阅/发布通道；02 靠它「旁观」帧数/覆盖率/温度等事件（只记数值，不碰数据 ★D6）。
- 状态机（10）【公】——全系统唯一一份「现在处于什么状态」的裁决者：① 门禁检查与 ③⑥⑩ 状态切换都问它。

## 2. 实现现状（以代码为准）

> 维度：D1 职责能力 / D4 数据流交互 / D2 生命周期归属 / D8 编译归属 / 状态（✅ ◐ 预留）。

### 2.1 `modules/02_scanning/ScanWorkflow.h/.cpp`（Scanner::workflow::ScanWorkflow）

- 核心能力：扫描工作流编排/记账壳——实现 `IWorkflow` 生命周期（`initialize/start/pause/resume/stop`），`start()` 内装配并启动 07 ScanPipeline，`stop()` 停流水线＋落会话记账（起止时间戳/帧计数）；旧单线程五 Stage（Capture/Preprocess/Marker/Laser/Fuse）已退役。
- 交互：经 `WorkflowContext` 取 06 标定仓库（出口查表装表）与点云仓库（`snapshotMarkers` 取续扫基准注入 `existingMarkers`）；经 EventBus 发 `ScanStarted/ScanStopped`；`setOnFinished` 完成回报由 app 注入（02 不依赖 10，回调反向解耦）。
- 生命周期归属：会话私有件构造者——`session_`（06 ScanSessionData）与 `pipeline_`（07 ScanPipeline）由本类构造/销毁；声明序铁律（session_ 先声明后析构，ring 随会话最后死）；流水线 stop 后不重启，续扫建新对象。
- 编译归属：`app/CMakeLists.txt:47-48` 编入 `scan_demo.exe`。
- 状态：◐（编排/记账/装配已实现；接入期接线项见 07 文档）

### 2.2 `modules/02_scanning/ScanWorkflow.h`（Scanner::workflow::ScanCalibration）

- 核心能力：扫描所需静态标定参数包——L/R 内参畸变＋`R1/R2/P1/P2/Q`＋`imageSize`，值语义成员。
- 交互：01 CalibrationWorkflow 产出 → `setCalibration` 注入 → 07 `attachCalib`（GPU 链初始化用）；逐温档 K/D 另经 06 出口查表并行生效。
- 生命周期归属：随工作流对象存续。
- 状态：◐（静态 K/D 过渡契约）

### 2.3 消费的他模块对象（物理在 06/07，02 持有其会话生命周期）

- `modules/07_pipelinemgmt/pipelines/scan/ScanPipeline.h`（Scanner::pipeline::ScanPipeline）——帧处理引擎：抓帧→双链并行（GPU 激光链 ‖ P核标记点链）→融合消费，会话私有件；细节见 [07-流水线管理.md](07-流水线管理.md)。状态：✅（真帧源接入前 ring 空转，防御路径保留）
