## 1. 代码实际实现的（真实文件路径 + 简述）

### 1.1 文件清单与编译位置

模块库 `mod_devicemgmt`（STATIC），定义于 `modules/08_devicemgmt/CMakeLists.txt`；链接 `base` / `OpenCV` / `spdlog`（PUBLIC）+ 大恒 Galaxy SDK `GxIAPICPPEx.lib`（PRIVATE）。

| 文件 | 说明 |

| `modules/08_devicemgmt/IScannerCamera.h` | HAL 接口：双目相机抽象 `Scanner::hal::IScannerCamera` + `StereoFrame`/`CameraIntrinsics`/`StereoExtrinsics`/`FrameCallback` |
| `modules/08_devicemgmt/IMCU.h` | HAL 接口：下位机抽象 `Scanner::hal::IMCU` + `McuEventType`/`McuEvent`/`McuEventCallback` |
| `modules/08_devicemgmt/CameraControl.h` / `.cpp` | 大恒 Galaxy SDK 双目相机采集封装 `Scanner::device::CameraControl`（实现 `IScannerCamera`） |
| `modules/08_devicemgmt/MCUDriver.h` / `.cpp` | 下位机 MCU 串口驱动 `Scanner::device::MCUDriver`（实现 `IMCU`，Windows 串口） |

### 1.2 相机管理 — `CameraControl`（实现 `IScannerCamera`，大恒 Galaxy SDK）

- 设备枚举：`CameraControl::enumerateDevices()` → `IGXFactory::UpdateDeviceList()`
- 打开/关闭：`open()` 按 SN 以 `GX_ACCESS_EXCLUSIVE` 独占打开左右两台；`close()` 逆序释放并 `Uninit`
- 曝光：`setExposure(ms)` → `ExposureAuto=Off` + `ExposureTime` 下发（µs）+ 读回验证（`applySideParams`）
- ROI 分辨率：`setResolution(w,h)` → 读 `WidthMax/HeightMax/Inc`，步进对齐 + `OffsetX/Y` 居中 + 读回
- 像素格式 Mono8（帧拷贝硬编码 `CV_8UC1`）
- 双目硬件触发同步：`TriggerSelector=FrameStart` + `TriggerMode=On` + `TriggerSource=Line2`（可配置）；`AcquisitionFrameRateEnable=false` 解除帧率上限
- 同步抓帧 `grabFrame`：双侧 `stream->GetImage(timeoutMs)`，右图 180° 翻转（`rotateRight180`，默认 true）
- 异步采集 `startAsyncCapture(cb)`：SDK 回调线程 → `CaptureEventHandler` → 左右按 `frameId` 配对交付（`tryDeliver`），右图 180° 翻转后回调
- 相机温度：`getTemperature()` → `DeviceTemperature` 特征（左相机）
- 平台标识：`getPlatform()` 返回 `"Windows"`

> 空桩（签名存在、无实现，归入 §3.2）：`setGain` / `setFrameRate` / `loadCalibration` + `getLeftIntrinsics`/`getRightIntrinsics`/`getStereoExtrinsics`（标定参数）/ `setLaserOn` / `setLaserPower`（激光实际由 MCU 控制，见 §1.3）。

### 1.3 MCU 串口控制 — `MCUDriver`（实现 `IMCU`，Windows 串口）

- 串口打开/关闭：`open(port)` 用 `CreateFileA`（自动补 `\\.\` 前缀）+ DCB（默认 115200/8N1）+ COMMTIMEOUTS；`close()` 停接收线程 + 关句柄
- 独立接收线程 `receiveLoop`：按 `;` 分帧，逐帧交 `parseReceived`
- 扫描控制（扩展方法）：`startScan(freq,bgLight,laserLight,trigger,version)` → `N10 H{} B{} T{} V{} L{};`；`stopScan()` → `N11 H0;`
- 软触发：`sendSoftwareTrigger()` → `N12 T0;`
- 激光：`setLaserPower(level)` → `N13 L{level};`；`setLaserOn(false)` → `N13 L0;`（开=true 时不发命令）
- 补光灯：`setLedOn(true)` → `N14 B{fillLight};`；`setLedOn(false)` → `N14 B0;`
- 急停：`emergencyStop()` → `N15 E1;`（见 §2，协议表无急停，N15 应为温度读取）
- 上行解析 `parseReceived`：`T25.3;`→温度（缓存 + `Temperature` 事件）；`K1;/K0;`→`KeyEvent`（`param1`=数字，仅事件接收，语义层见 §3.1）；`E1;`→`EmergencyStop` 事件
- 温度缓存：`getTemperature()` 返回最近一次解析值

> 当前代码命令编号映射（N12=软触发 / N13=激光 / N14=补光 / N15=急停）与协议表目标语义（N12=自检 / N13=待机 / N14=加热 / N15=温度读取）冲突，属 §2 调整项。

### 1.4 设备状态监控 — `HardwareMonitor`（周期轮询，默认 1000ms）

- 依赖注入式：`setMCU` / `setCamera` / `setDeviceStateCache` / `setEventBus` / `setFrameCounter`
- `monitorLoop` 每周期：采 MCU 温度 + 相机温度 + 帧率（注入回调），写入 `DeviceStateCache`（`DeviceStateInfo`），并发布 `TemperatureUpdate` 事件
- 在线/离线标记：基于各设备 `isOpen()` 写 `DeviceState::Connected/Offline`
- 纯读取，不做阈值判断（`start` 间隔最小 100ms）

## 2. 代码需要调整的

下列功能现状代码中存在，但与真实设备能力不符，需调整：

> **协议来源**：`docs/开发需要的信息/下位机和按键/下位机协议命令列表.xlsx`——**此为当前协议版本，仍待修改**（下位机协议尚未定稿，下列调整项随之可能变动）。

| 现状项 | 调整为 | 原因 |
|---|---|---|
| 软件触发 / 硬件触发模式切换 | **仅硬件触发**（删除切换） | 系统只用硬件触发 |
| 帧率设置（`H{freq}`） | **删除**上位机帧率设置 | 帧率由下位机开关时间控制 |
| 急停命令 `emergencyStop`（`N15 E1;`） | **删除** | 协议表无急停功能；N15 真实语义为温度读取（见下） |
| 扫描启停命令混淆（`N10` 当启动） | `N10` 仅设采集参数；启停用 `N11 H1;`/`N11 H0;` | 协议表：N10=设参数（H 频率/B 背景灯/T·V 激光选择/L 激光亮度），N11=扫描启停（H0 停/H1 开） |
| N15 温度读取参数 | `N15 V0-2;`（0=左 / 1=右 / 2=全部） | 协议表 N15 是温度读取而非急停；现协议仅 L/R 两路，与下方"4 路"有出入，待协议方确认 |
| 温度读取（单路 `"T25.3;"`） | **4 路温度传感器**独立上报 | 实际 4 路传感器（协议表当前仅 L/R 两路，待协议修改补齐） |
| 缺失命令：自检 / 待机 / 加热 / 标定控制 | 补 `N12 Z0-1`(自检启停) / `N13 E0-1`(待机进出) / `N14 T0-100`(加热温度) / `N16 B0-1`(标定进出) | 状态机 S1 自检 / S2 待机 / S3 标定 转态的下发缺环；`MCUDriver` 现用 N12/N13/N14/N15 承载软触发/激光/补光/急停（见 §1.3），与协议表语义冲突，需按协议表重映射 |

## 3. 需要增加的

### 3.1 按键交互协议（v2.0）

> **协议来源**：本节由 `docs/plans/2026-08-12-按键交互协议-v2-design.md`（brainstorming 产物）权威迁移落地；v1.0（`2026-08-12-按键交互协议-design.md`）保留作历史。
> **链路性质**：MCU→PC **单向上行**扩展，与协议表 N10–N16（PC→MCU 下行，见 `docs/开发需要的信息/下位机和按键/下位机协议命令列表.xlsx`）正交，不冲突、不替代。
> **前提**：所有按键仅在「扫描就绪」态（设备状态机 **S2 待机**，见 `docs/plans/2026-08-09-设备状态机-design.md`）实际生效；非此态丢弃且计数器不增。
> **现状**：当前代码仅有 `K1;/K0;` 匿名事件接收（见 §1 MCU），**无按键语义状态机**——本节为待实现协议规格。

**按键物理布局**：上键居顶，下方自左至右为 左 / 中 / 右。

#### 3.1.1 架构决策与分工

三项已确认决策：

1. **MCU 仅做手势分类 / PC 做一切语义判断**：MCU 只判定短按/双击/长按（硬件近端时序活儿）；所有计数、菜单、动作映射全在 PC。
2. **隐式反馈（无专用 ACK）**：PC 接受→翻译为已有 N10–N16 或本地执行；拒绝→默默丢弃（计数器不增）。
3. **定长报文 `K<ID><手势>;`**：键号字母 + 手势字母，定长 4 字符。

| 侧 | 负责 | 不负责 |
|---|---|---|
| **MCU** | 消抖；测时长/间隔；判短按/双击/长按；上报 | 不计数；不知菜单层级；不判扫描就绪；不映射动作 |
| **PC** | 奇偶/游标计数器；菜单层级状态机；扫描就绪门控；动作映射 | 不管消抖/手势判定 |

#### 3.1.2 上行报文格式

```
key_report ::= "K" key_id gesture ";"
key_id     ::= "U" | "L" | "M" | "R"      ; 上/左/中/右
gesture    ::= "S" | "D" | "H"             ; S=短按, D=双击, H=长按(Hold)
```

定长 4 字符。用 `H`（Hold）表示长按，避开与 `L`（左键）冲突。全部 12 种合法报文（4 键 × 3 手势，均以 `;` 结尾）：

| 键 | 短按 `S` | 双击 `D` | 长按 `H` |
|---|---|---|---|
| 上键 `U` | `KUS;` | `KUD;` | `KUH;` |
| 左键 `L` | `KLS;` | `KLD;` | `KLH;` |
| 中键 `M` | `KMS;` | `KMD;` | `KMH;` |
| 右键 `R` | `KRS;` | `KRD;` | `KRH;` |

PC 解析规则：长度 == 4，`data[0]=='K'`，`data[1]∈{U,L,M,R}`，`data[2]∈{S,D,H}`，`data[3]==';'`；非法→丢弃 + `spdlog::warn`。

#### 3.1.3 功能映射表（按键 → 手势 → 动作）

> 原"连按 2 下"语义**完整保留为"双击 D"**（非长按）；"长按 H"为原 §3.1 未用到的**预留手势**，将来赋功能不动下位机固件。

**中键（M）**：

| 报文 | 上下文 | 请求动作 | PC 执行 / 命中命令 |
|---|---|---|---|
| `KMS;` | `menu.layer==1` 且 `parity[M][S]` 奇 | 开始采集 | `N11 H1;` + `parity[M][S]++` |
| `KMS;` | `menu.layer==1` 且 `parity[M][S]` 偶 | 停止采集 | `N11 H0;` + `parity[M][S]++` |
| `KMS;` | `menu.layer==2` | 进入当前选项并退出菜单 | 本地：执行选中项 + `layer=1` |
| `KMD;` | — | 循环切扫描模式 | `modeCursor=(modeCursor%3)+1`：1=精细 / 2=深孔 / 3=普通交叉（默认）；影响下次 `N10` 参数 |
| `KMH;` | — | **预留** | — |

**上键（U）**：

| 报文 | 请求动作（按 parity toggle） | PC 执行 |
|---|---|---|
| `KUS;` | 奇→进入菜单选项 / 偶→退出菜单选项 | 奇：`layer=2, cursor=①`；偶：`layer=1` |
| `KUD;` | 奇→进入视野调节 / 偶→进入亮度调节（曝光+补光+激光联动，默认） | `adjustCtx = 视野 / 亮度` |
| `KUH;` | **预留** | — |

**菜单第 2 层游标 ①–④**：① 正常视野扫描；② 大视野扫描；③ 扫描完成；④ 开始后处理。

**左键（L）/ 右键（R）**（短按不区分奇偶）：

| 报文 | `menu.layer==2` | `adjustCtx != none` |
|---|---|---|
| `KLS;` | 游标左移（①←④环绕） | 减值（步进按 context 定） |
| `KRS;` | 游标右移（①→②→③→④→①） | 加值 |
| `KLD;`/`KLH;`/`KRD;`/`KRH;` | **预留** | — |

#### 3.1.4 MCU 侧契约（手势判定，零业务状态）

| 手势 | 判定（推荐阈值，标定时可校准） |
|---|---|
| 短按 S | 按下→松开 ≤ `T_short`（400 ms），且窗口内无第二次按下 |
| 双击 D | `T_short`（400 ms）内两次合法短按；第二次松开即判 |
| 长按 H | 按下持续 ≥ `T_long`（800 ms）；达到阈值即判（可不等松开） |
| 消抖 | `T_debounce` = 20 ms |

**手势互斥**：一次物理操作只产生 S/D/H 之一（MCU 状态机内部时序优先级保证）。**MCU 零业务状态**——无计数器、无菜单、无扫描感知；每个手势判定完成即发一条报文，不批量、不延时。上电/重启不需同步任何业务语义。

#### 3.1.5 PC 侧状态机契约

**门控**：所有 `K*` 报文先查 S2 待机；非此态→丢弃且计数器不增（保证重入扫描就绪后语义连续）。

PC 维护：

```
parity[M][S]   // 中键短按：奇=开始采集 / 偶=停止采集
parity[U][S]   // 上键短按：奇=进入菜单 / 偶=退出菜单
parity[U][D]   // 上键双击：奇=视野调节 / 偶=亮度调节
modeCursor     // 中键双击切扫描模式：1/2/3 循环
MenuState{ layer: 1|2; cursor: ①..④; adjustCtx: none|视野|亮度 }
```

**动作分叉规则**：
- 中键短按：先看 `layer`（layer1→按 `parity[M][S]` 开始/停止；layer2→选中退出）。
- 上键短按/双击：按各自 `parity` toggle。
- 左/右键短按：`layer==2`→左/右移游标；`adjustCtx!=none`→减/加值；否则忽略。
- 中键双击：无条件推进 `modeCursor`。

**与 N10–N16 衔接**：中键短按（开始）→`N11 H1;`；（停止）→`N11 H0;`；模式切换仅改 PC 本地 `modeCursor`（影响下次 `N10` 参数）；其余 PC 本地变更，**不新增下行命令**。

#### 3.1.6 风险与权衡（v2.0 明确取舍）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 串口丢帧→静默错位 | 无 `seq_no`，丢一帧则 `parity`/`modeCursor` 错一格（如按"开始"却变"停止"） | **UI 显式反馈当前状态**（扫不扫、当前模式、菜单位），用户按一下自纠正；串口 115200 丢帧概率低 |
| PC 重启丢计数 | parity/cursor 全丢，重启后从默认开始 | 可接受（PC 重启 = 会话重置） |

**总取舍**：v2.0 放弃 v1.0 的丢包自检能力，换 **MCU 极简（零业务状态）+ 报文定长 + 手势词汇可扩展（预留长按 H）**。

#### 3.1.7 异常处理与迁移

- 格式非法 / 未知键号手势 / 预留手势位 → PC 丢弃 + warn（预留位降为 info，记"未赋功能"）。
- 现 `K1;/K0;`（匿名按下/松沿）**废弃**，由本协议替代；`T25.3;` 温度解析不变；`E1;` 急停语义已删（N15 重定义为温度读取，见 §2）。
- **MCUDriver 迁移**（模块 08 后续实现项）：`parseReceived` 中 `K` 分支升级为定长 4 字符解析；`McuEvent` 扩展 `keyId`/`gesture`；PC 侧新增 `KeyStateMachine`（待编排层 `framework/workflow` 契约具体化后落地）。
