# 模块8 · 设备管理

> 一句话：08 是**设备总管家**——相机、下位机、按键、温度计都归它管，别人要用电设备只找它一个，不许私下摸。
> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)

## 1. 功能目标

### 1.1 DeviceManager 设备管理器（【公】app 存活件，开机即造、全程不销毁）
- 做什么：总管家——①一键开关机（open()/close() 包办全部设备）；②切模式（去标定/去扫描/回待机）；③总判断——收集各路信息→判断→发执行命令（含全部按键语义：菜单/门控/动作映射）；④记账广播（下位机状态记录[原 3 号灯]、温度、设备消息、参数变化——ParamStore 唯一参数账本，UI 控件与其双向同步）。
- 交互：01-②③④⑨；02-②③④⑥⑩。

### 1.2 CameraControl 相机管理（08 内部）
- 做什么：相机参数师——**只设相机参数**：开闭相机、曝光、分辨率、增益、装标定参数、报相机温度；拍照触发不归它管（开闭由 MCUDriver 经下位机硬触发）。
- 交互：01-④；02-④（帧温上报）。

### 1.3 MCUDriver 下位机驱动（08 内部）
- 做什么：串口传令兵＋时序司令——①下发相机硬触发开关及每次开关时间；②下发激光/补光硬触发开关及时间控制；③统一上行入口（见 §1.7 上行架构）。
- 交互：01-③④；02-③④⑥。

### 1.4 KeyManager 按键手势分类（08 内部）
- 做什么：按键手势分类器——**只判「哪个键＋短击/双击/长击」**（PC 侧），其余一概不管。
- 交互：02-③⑥（按键电报）；01 全程无按键。

### 1.5 HardwareMonitor 硬件监控（08 内部）
- 做什么：体检护士——每秒巡检两层：①外设层（在线状态/帧率/左右配对失败率，2 号相机灯在此）；②上位机自体检（CPU 温度[过热降频先导预警]、CPU 占用[仅记录存档不告警]、GPU 显存/温度、内存水位、磁盘剩余[<10GB 预警/<1GB 停写保护]、关键线程心跳＋业务三件套：采集帧率/处理帧率/丢帧率——计数器挂 06 容器，巡检广播在此；UI 状态栏显示）。
- 交互：01-④；02-④⑤。

### 1.6 许可证/激活（目标）
- 做什么：设备开锁——加密狗/软授权检查、试用期、功能等级。
- 交互：—。

### 1.7 上行架构（「串口一条道，进门分道走，总管家汇合」）
- 传输合：上行共用一条串口一个分帧器；处理分：温度（周期遥测可丢）与按键（离散事件丢失代价高）消费节奏不同，禁止混入同一处理器；汇合：各链到 DeviceManager 统一判断。
- 配套：温度改 MCU 定时主动上报替代 PC 周期轮询（省下行带宽）。

```
        下行(命令)                          上行(上报)
app/工作流 ──► DeviceManager ──► MCUDriver ──串口──► 下位机
                 ▲   │命令(N10设参/N11启停/激光补光时序)      │
                 │   ▼                                   串口(一条道)
   相机参数 ◄── CameraControl                        MCUDriver 分帧
                                                    │ T 温度 ──► 温度链(可丢,下周期还有)──┐
                                                    │ K 按键 ──► KeyManager 判手势 ──────┤► DeviceManager
                                                    └ 设备状态 ────────────────────────┘  (收集→判断→发令)
                                                                                         │
                                                       EventBus 广播(温度/按键/设备消息) ─┘► app/工作流
```

> 状态机照应：全工程状态机灯现 3 台——1 号全局门禁机（app 第 5 存活件，代码在 10）、2 号相机灯（08 HardwareMonitor）、4 号按键菜单机（08 DeviceManager 内菜单逻辑）。原 3 号下位机灯已裁撤（状态由 DeviceManager 记录）；原 5 号手势判定机取消（手势判定上收 PC KeyManager）。

## 2. 实现现状（以代码为准）

- 编译归属：STATIC 库 `mod_devicemgmt`（`modules/08_devicemgmt/CMakeLists.txt`），PUBLIC 链 base＋OpenCV＋spdlog，PRIVATE 链大恒 Galaxy SDK＋Pdh（自检 CPU 占用）；命名空间 `Scanner::device` / `Scanner::device::serial` / `Scanner::hal`。
- 生命周期与线程总图：

```
【公】DeviceManager（app 存活件）
  ├─ 逻辑线程（10ms 一拍）：排空任务队列→pump 上行环→按键 dispatch
  │    →CommandChannel 对账 tick→Warmup tick→v2 温度兜底→故障巡检→参数快照
  ├─ MCUDriver（:IMCU）
  │    ├─ rx 线程（零业务）：read→feed→按首字符入 4 环（K/S/A 各 64＋T 8）
  │    └─ 逻辑线程：send*/pump（排空环→分流回调＋onAck＋seq 对账）
  ├─ CameraControl（:IScannerCamera）：SDK 回调线程→双缓冲左右配对交付
  ├─ HardwareMonitor：巡检线程（默认 1s，纯读取）
  └─ 无锁零件（CommandChannel 表/ParamStore/MenuLogic/Warmup/KeyManager）
       单一属主＝逻辑线程；门面变异入口经 post() 编队（容量 64 满丢新）
```

- 测试覆盖：tests/ 14 个测试 exe 注册 ctest（serial 层 4＋按键链 4＋门面零件 6）；工程全量 ctest 95/95 绿。

### 2.1 `IScannerCamera.h`（IScannerCamera，08-1）【接口】
- 核心能力：双目相机的统一遥控器约定——open/参数/标定注入/同步异步采集/温度。
- 协议/契约：标定参数注入式（app 从 06 仓库喂入，08 不做第二真相源）。
- 状态：✅

### 2.2 `IMCU.h`（IMCU，08-2）【接口】
- 核心能力：下位机的统一遥控器约定——typed N10–N16 命令＋上行三分流出口（McuUplink）。
- 协议/契约：所有 send\* 非阻塞，结果经 DoneCb 异步回告（v2 恒立即 ok「未确认」）；pump() 回调内不得再调 pump/send（短平快铁律）。
- 状态：✅

### 2.3 `serial/SerialPort.h/.cpp`（SerialPort，08-3）
- 核心能力：串口线的水管工——纯 Win32 串口 IO 封装，只管字节进出不懂协议。
- 协议/契约：8N1＋50ms 间隔超时＋4096 缓冲；HANDLE 藏 void\* 不进头。
- 线程/并发：**写单线程铁律**（首调线程记属主，他线程调 fail）；close 靠 CloseHandle 令阻塞 read 退出。
- 测试：test_frame_codec（经 MCUDriver 组合链）。
- 状态：✅

### 2.4 `serial/FrameCodec.h/.cpp`（FrameCodec，08-4）
- 核心能力：串口字节的翻译官——字节流拼帧/校验/拆包的 v2/v3 帧成拆器，**协议开关收敛此处**。
- 协议/契约：v2＝「载荷;」直通无校验（兼容现状固件）；v3＝`$载荷<seq><crc>;`（seq 2 位 hex 循环＋CRC16-CCITT 查表覆盖 $…seq）；载荷禁 `$` `;`、帧长≤32B、半帧超时 50ms。
- 线程/并发：feed 与 advanceTimeout 须同线程（挂起缓冲无锁）。
- 测试：test_frame_codec。
- 状态：✅

### 2.5 `serial/CommandChannel.h/.cpp`（CommandChannel，08-5）
- 核心能力：下发命令的快递员——非阻塞 send＋tick 驱动 ACK 对账/重传（总尝试 1+3，三次送不到算失败）。
- 协议/契约：**命令组步链**（前条 ACK 回调里发下条，任一步 3 败整组短路）；待确认表容量 8（满逐出最旧＝判超时）。
- 错误/降级：v2 降级（reliable=false）发不等恒 ok「未确认」。
- 线程/并发：非阻塞铁律（send 内等待＝自锁）；单线程属主＝逻辑线程（无锁设计）。
- 测试：test_command_channel。
- 状态：✅

### 2.6 `serial/McuFrame.h/.cpp`（McuFrame 类型集＋SpscRing，08-6）
- 核心能力：上行数据的分拣架——Temp/RawKey/Status/Ack 四类帧类型＋4 载荷解析＋满丢新有界 SPSC 环。
- 协议/契约：v3 载荷格式 `T25.3,24.8` / `KM1,1234` / `S0A` / `A0B`（＋seq＋crc）；协议默认口径见头注（未定稿，改只改这里）。
- 线程/并发：SPSC（串口 rx 线程生产/逻辑线程消费）；满环丢新——生产者永不碰 head\_ 根除竞态（64 深下丢新＝用户可重按，安全）。
- 测试：test_mcu_frame。
- 状态：✅

### 2.7 `MCUDriver.h/.cpp`（MCUDriver，08-7）
- 核心能力：下位机驱动的组装壳——SerialPort＋FrameCodec＋CommandChannel＋4 有界环拧成一体，:public IMCU。
- 交互：typed N10–N16（N10 设参/N11 启停/N12 自检/N13 待机/N14 加热/N15 温度查询/N16 标定进出）；旧错牌命令（软触发/急停等）已删净。
- 线程/并发：rx 线程零业务（read→feed→入环）；channelTick 单独出口（对账归门面逻辑线程驱动）；记账口 lastRxTime 心跳/seqGapCount/keyDropCount/parseFailCount。
- 错误/降级：writeOverride 测试缝（测试模式单线程不开真串口）。
- 测试：test_mcu_driver。
- 状态：✅

### 2.8 `DeviceManager.h/.cpp`（DeviceManager，08-8）【公】
- 核心能力：设备大总管——外面只找它，它管相机/下位机/按键/温度所有硬件；组合根内部 unique_ptr 持有全部零件（铁规：不漏零件指针/类型，对外只出值类型与薄转发）。
- 交互：open 一条龙（相机→MCU→N12Z1→逻辑线程，任一步败倒序关）；切模式＝命令组步链（组成功回调才擦板）；参数双口（get 互斥快照/set 编队）；menuSelect ③/④ 经 EventBus UserDefined 广播派工作流。
- 生命周期归属：【公】app 存活件。
- 线程/并发：门面一切变异入口经 post() 任务队列编队（mutex+deque 容量 64 满丢新），logicTick 一拍排空；同步返回值口径——门禁检查调用方线程同步做，命令组编队异步。
- 错误/降级：**故障 8 码**（0x0801 相机掉线～0x0808 seq 跳变＋0x0810/0x0811 开机段）——边沿锁＋恢复清锚防爆屏、只报不动手；EventBus FaultOccurred＋spdlog。
- 测试：test_device_manager。
- 状态：✅（真机联调待做）

### 2.9 `KeyManager.h/.cpp`（KeyManager，08-9）
- 核心能力：按键手势识别器——分清短按/双击/长按（S/D/H）；判定用 **MCU 时刻**（排队延迟不扰手感）。
- 协议/契约：零业务状态（不门控不计数不映射——判完即出 KeyGesture，语义归 KeySemantics）；一次物理操作只出 S/D/H 之一；阈值可配（消抖 20ms/短按 400ms/双击窗 400ms/长按 800ms）。
- 线程/并发：事件优先＋全局扫（任一 onRawEvent 以已见最大 MCU 时刻扫一遍），tick 仅 PC 域兜底；每键独立 4 态状态机；单逻辑线程属主无锁。
- 错误/降级：乱序/超期事件丢弃＋droppedCount 对账。
- 测试：test_key_manager。
- 状态：✅

### 2.10 `KeySemantics.h/.cpp`（KeySemantics，08-10）
- 核心能力：按键裁判——手势＋当前状态→转移表→执行动作；纯函数式（无内部计数、**弃奇偶**——显式状态＋状态转移表）。
- 协议/契约：11 出口动作（captureToggle/menuSelect/cycleMode/enterMenu/exitMenu/cycleAdjustCtx/adjustUp/adjustDown/cursorLeft/cursorRight/dropped）；启停键不问门禁，菜单/模式/调节键 gate 关一律丢弃；左右键短按菜单优先于调节。
- 交互：依赖方向单向只读——裁判→账本/黑板（MenuLogic/ModeController）。
- 测试：test_key_semantics。
- 状态：✅

### 2.11 `MenuLogic.h/.cpp`（MenuLogic，08-11）
- 核心能力：屏幕菜单的记账本——层(1/2)/游标①~④/调节上下文/模式光标(1 精细/2 深孔/3 普通交叉，默认 3，**唯一真相源**——02 不存副本)；纯记账不判该不该不发命令。
- 协议/契约：转移表钉死（EnterMenu 必回①/ExitMenu 清 ctx/游标①←④环绕/CycleMode 1→2→3→1）；会话级不持久化，Reset 全回默认。
- 线程/并发：单逻辑线程属主无锁。
- 测试：test_menu_logic。
- 状态：✅

### 2.12 `ParamStore.h/.cpp`（ParamStore，08-12）
- 核心能力：设备参数的唯一账本——全工程唯一真相源：UI 纯视图双向同步、按键/滑条两入口同队列串行、开机有档读档无档统一初始值、人工触发才落盘。
- 协议/契约：**确认更新制**——v3＝ACK 成功才改账＋广播、3 败保旧值；v2＝立即改账 confirmed=false（期望值）；字段定义（ParamSpec）归 08；序列化手写 `key=value;...`。
- 线程/并发：单逻辑线程属主无锁；Dispatch 完成回调须回逻辑线程再调；在途后值胜出（gen 判据，旧回调到达不改账）；入口即钳回 spec 范围。
- 测试：test_param_store。
- 状态：✅

### 2.13 `WarmupSequence.h/.cpp`（WarmupSequence，08-13）
- 核心能力：预热看火员——待命→加热→（稳了｜超时）时序；火候判定＝双点锚点法（窗口内偏出锚点重锚重计时；窗满且离目标≤nearTargetC 才判稳）。

- 线程/并发：单逻辑线程属主无锁；时基统一 PC 接收时刻。
- 测试：test_warmup_sequence。
- 状态：✅

### 2.14 `ModeController.h/.cpp`（ModeController，08-14）
- 核心能力：当前模式的黑板——Idle/Calibrating/Scanning 原子读写＋采集子态。

- 线程/并发：黑板与子态均 atomic。
- 测试：test_mode_controller。

### 2.15 `CameraControl.h/.cpp`（CameraControl，08-15）
- 核心能力：大恒相机的实际驾驶人——Galaxy SDK 立体相机对，:public IScannerCamera。
- 交互：开闭相机/曝光/分辨率/增益（按 GainRaw 原生单位）/标定缓存注入式/报温度；触发开闭全由下位机管（仅 Line2 硬触发线配置）。
- 线程/并发：SDK 回调线程→双缓冲**左右配对交付**（ready 原子位，frameId 取 max）；右图可 180° 旋转；内部 mutex＋回调转发。

- 状态：✅

### 2.16 `HardwareMonitor.h/.cpp`（HardwareMonitor，08-16）
- 核心能力：硬件体检员——每秒抄一遍表不做诊断（阈值判定归 10-PerfMonitor）。
- 交互：相机行（isOpen/温度/fps/丢帧累计）写 06 DeviceStateCache；MCU 温度改**注入快照直传**（DeviceManager getLastTemperatures，不持 IMCU 指针不发命令）；HealthMetrics 快照出口供 app 侧适配器喂 10-PerfMonitor。
- 生命周期归属：随【公】门面存活（app 装配）。
- 线程/并发：巡检线程默认 1s；依赖全注入零直连（指针＋std::function 可空）。
- 协议/契约：**08 不链 10**——心跳经注入回调上报，超时判定与发 Fault 归注入方。
- 测试：test_hardware_monitor。
- 状态：✅

### 2.17 `SelfCheckCollector.h/.cpp`（SelfCheckCollector，08-17）
- 核心能力：电脑自检采集器——CPU/内存/磁盘/GPU 抄表→HealthMetrics。
- 协议/契约：Honest 原则——取不到留 -1 不编数（CPU 占用 PDH 首调返 -1 建基线；CPU 温度 WMI 降级不采恒 -1；NVML 动态加载无 dll→GPU 字段 -1）；帧率三件套归 HardwareMonitor 填。
- 线程/并发：线程心跳注册制（beat/staleHeartbeats）；头文件零 Win32 依赖（pimpl 藏 .cpp）。
- 测试：test_self_check_collector。
- 状态：✅
