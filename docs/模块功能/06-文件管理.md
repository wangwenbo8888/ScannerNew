# 模块6 · 文件管理与数据管理

> 一句话：06 是**数据大管家**——运行中数据（帧/点云/设备状态）的容器、跨工作流交接的仓库（标定结果/点云）、每次开工要装配的配置与缓冲，外加文件导入导出，都归它管。
> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)

## 1. 功能目标

### 1.1 数据管理·仓库（【公】app 存活件，开机即造、全程不销毁）
- 做什么：跨工作流的「数据保险柜」，三个格子——①**标定结果仓库**：收 01-⑦ 标定成果统一落盘（相机内/外参、立体矫正、激光平面映射、两张温度表），持久基准量；②**标定参数仓库**：01 产出的参数存这里，02-① 门禁「参数就绪」查它（开机自检「是否正确导入标定参数」也查它）；③**点云仓库**：02-⑧ 优化后点云留内存、不随 ⑩ 销毁——供 04 后处理内存调用、续扫作 existingMarkers 基准、人工请求才导出。
- 交互：01-②⑦ 写入；02-①②⑧、04、03 读。

### 1.2 数据管理·会话件·01 版（【私】01-② 构造、⑨ 逆序销毁）
- 做什么：标定开工三件套——加载标定配置＋初始参数＋25 目标姿态表；创建帧环形缓冲实例（周期帧＝标记点帧＋N 路激光管帧＋温度）。
- 交互：01-②④⑤。

### 1.3 数据管理·会话件·02 版（【私】02-② 构造、⑩ 逆序销毁）
- 做什么：只管装表＋ring——创建帧环形缓冲实例（双目帧）；**出口查表**：装配期装载两张温度补偿表（激光表同时上载显存），缓冲出口按帧温逐帧查表、随帧附标定快照（「增强帧」，算子无查表动作）。配置归 07 ScanConfig，06 不造。
- 交互：02-②④⑤。

### 1.4 环形缓冲容器（随会话件【私】）
- 做什么：帧的传送带——08 只管往里放、流水线只管往外取，采图与计算互不等待；02 消费 lag 超限就跳最新丢中间，永远追新帧。
- 交互：01-④⑤；02-④⑤。

### 1.5 文件 IO（06）
- 做什么：落盘/读盘的搬运工——点云 PLY/XYZ、网格 STL/OBJ、标志点、标定参数的导入导出（冷路径）。
- 交互：01-⑦（落盘）；02-⑧（按需导出）；03/05（模型与标志点加载）。

### 1.6 流水线原语（IWorkflow / ParameterManager，06）
- 做什么：执行引擎零件——工作流统一接口＋参数键值仓。
- 交互：01/02/04 工作流消费。

> 支撑约定：**温度表分工**——01 生成两张温度补偿表（0.2℃ 阶梯）随标定结果落盘，02 扫描侧在缓冲出口逐帧查表消费，生成与消费分离；**会话记账**——账本归 01/02 自身，06 只管存取（存档仅人工手动触发）。
> 数据语义分层（L1–L4）与判定规则见根目录 [`数据管理原则.md`](../../数据管理原则.md)：06 管的是 L3 逐帧产物容器与 L4 跨阶段产物仓库；L1/L2 暂存与累积器归 09 算子内部。

## 2. 实现现状（以代码为准）

- 编译归属：STATIC 库 `mod_fileio`（`modules/06_fileio/CMakeLists.txt`），链 base＋spdlog＋OpenCV＋nlohmann_json；SlotRing/RingBuffer/三 Sink/IWorkflow/数据类型头为纯头文件不入库源。
- 测试覆盖：`tests/` 5 个测试 exe 注册 ctest（calib_repository / scan_session / calib_session / file_io / cloud_warehouse）；全量 ctest 95/95 绿（Debug＋Release）。
- 数据流一张图：

```
01 RepoWriter ──write──▶ CalibrationRepository（JSON 落盘）
                              │ readyForScan / typed getters
                              ▼
                     ScanSessionData.assemble 装表
                              │
08 采集 ──pushFrame──▶ ScanSessionData ──出口查表(FrameEnricher)──▶ Overwrite 环 ──▶ 07 C 扫描链
                        （帧唯一入口，产出 EnhancedFrame）

08/01 采集 ──CycleUnit──▶ CalibSessionData 姿态环（Backpressure）──▶ 07 A 姿态链

07/09 融合 ──pushPointCloud──▶ PointCloudBuffer（点云仓库）──快照──▶ 03 渲染 / 04 后处理 / 02 续扫基准
08 HardwareMonitor ──pushState──▶ DeviceStateCache ◀──轮询── UI
04 / 03 / 人工导出 ──▶ fileio（exportSTL / exportCloud / importMesh…）
```

### 2.1 `SlotRing.h`（SlotRing\<T\>，06-1）
- 核心能力：原子槽位环——帧的传送带，一格一格循环放帧，采图与计算互不等待；07 抓帧策略的缓冲底座。
- 交互：07 Posture/ScanPipeline 经 attachRing 注入；环实例随会话件持有（CalibSessionData 姿态环 / ScanSessionData 扫描环）。
- 生命周期归属：容器，随持有者（会话件）存活。
- 线程/并发：单 mutex＋双 condition_variable（写侧反压等腾位 / 读侧等新帧）；单生产者约定；槽为 shared_ptr 原子换入（已取引用覆盖后仍安全）；read 近似语义——先 waitFor 确认写入再 read。
- 状态：✅

### 2.2 `RingBuffer.h`（RingBuffer\<T\>，06-2）
- 核心能力：通用线程安全 FIFO 环（std::queue 包装）。
- 交互：FrameBuffer 内部包装它。
- 生命周期归属：容器，随持有者存活。
- 线程/并发：mutex＋双 cv；溢出三策略 DropOldest / DropNewest / Block；pop 带超时返回 nullopt。
- 状态：✅

### 2.3 `FrameBuffer.{h,cpp}`（FrameBuffer，06-3）
- 核心能力：原始帧蓄水池——`IFrameSink` 实现，保最新帧供消费。
- 交互：app 的 AppContext 持 60 槽实例注入各处（显示链路用）；ScannerWindow 另自建显示用实例；旧链遗留（新链走 ScanSessionData）。
- 生命周期归属：实例归 app（AppContext）。
- 线程/并发：默认 60 槽 DropOldest；popFrame(100ms) 供工作流取帧。
- 状态：✅

### 2.4 `PointCloudBuffer.{h,cpp}`（PointCloudBuffer，06-4）
- 核心能力：点云仓库——扫描成果存内存，谁要谁取快照；`IPointCloudSink` 实现＋marker 独立通道。
- 交互：07/09 融合产出经 pushPointCloud 写入；03 渲染只读快照、04 后处理内存调用、02 续扫 snapshotMarkers 取基准（MarkerRecord 的 globalId 只走内存通道，落盘格式只有坐标）；exportCloud/exportMarkers＝人工导出唯一出口（扩展名分派 ply/pcd/xyz）。
- 生命周期归属：【公】app 存活件，不随 02-⑩ 销毁。
- 线程/并发：shared_mutex 读写锁（融合线程写、渲染线程并发只读）；云/marker 双版本号（独立锁独立版本），UI 检版本再取快照。
- 测试：test_cloud_warehouse。
- 状态：✅

### 2.5 `DeviceStateCache.{h,cpp}`（DeviceStateCache，06-5）
- 核心能力：设备状态公告板——按 deviceId 只存最新一条；`IDeviceStateSink` 实现。
- 交互：08 HardwareMonitor 写、UI 轮询读（温度/fps/丢帧便捷查询）。
- 生命周期归属：【公】app 存活件。
- 线程/并发：mutex＋unordered_map。
- 状态：✅

### 2.6 `ScanSessionData.{h,cpp}`（ScanSessionData，06-6）
- 核心能力：02 扫描会话行李箱——assemble 装表＋pushFrame 出口查表入环；不含 ScanConfig（归 07）。
- 交互：CalibrationRepository 两 getter 拷入装表；pushFrame＝帧唯一入口（enrich→ring.write）；ring() 供 07 ScanPipeline 抓帧。
- 生命周期归属：【私】02 会话件（② 构造、⑩ 销毁前先停 07）。
- 线程/并发：pushFrame 限采集回调单线程（SlotRing 单生产者约定）；Overwrite 环默认 16 槽，槽位构造期定死。
- 错误/降级：装表两表全空→fail「标定表未就绪」；单表空放行→pushFrame 期 warning（tier=-1 自证）；enrich fail→丢帧不写环＋droppedFrames 计数（挂 10 故障桥）；warning 帧仍入环。
- 测试：test_scan_session。
- 状态：✅

### 2.7 `CalibSessionData.{h,cpp}`（CalibSessionData，06-7）
- 核心能力：01 标定会话行李箱——load 会话档 JSON 三键（initialParams 原文透传 / targets 每条 16 数 / boardPoints）＋内嵌姿态环。
- 交互：01 侧调用 load；cycleRing() 供 07 PosturePipeline attachRing 注入。
- 生命周期归属：【私】01 会话件。
- 线程/并发：Backpressure 姿态环 8 槽（满则阻塞写侧，反压 08 采集）。
- 错误/降级：targets/boardPoints 缺键或空数组→fail；initialParams 缺省容空对象（01 侧 paramsReady 兜底）；逐元素类型校验。
- 测试：test_calib_session。
- 状态：✅

### 2.8 `CalibrationRepository.{h,cpp}`（CalibrationRepository，06-8）
- 核心能力：标定结果档案柜——一格仓库两副面孔（01-⑦ 落盘持久＋02-① 门禁查询）；JSON 单文件＝07 serializeCalib 载荷＋外层 meta。
- 交互：01 RepoWriter 直写；app 开机 best-effort load；02-① 谓词查 readyForScan；ScanSessionData.assemble 经 typed getters 取表（stereo()/stereoTempTable()/planeMapTiers() 等）。
- 生命周期归属：【公】app 存活件。
- 线程/并发：mutex 全量护；lastPath 锁内返回拷贝（并发改写安全）。
- 错误/降级：write＝解析→校验→临时文件＋原子改名，落盘成功才提交内存；readyForScan 缺样清单（缺哪报哪）。
- 测试：test_calib_repository。
- 状态：✅

### 2.9 `EnhancedFrame.h`（EnhancedFrame/CalibSnapshot，06-9）
- 核心能力：带「体温匹配参数」出厂的帧——gray L/R host 副本＋帧温＋命中两表的标定快照（R1/R2/P1/P2/Q＋档索引）。
- 交互：ScanSessionData.pushFrame 产出 → 07 C 扫描链消费（算子直接用 snapshot，无查表动作）。
- 生命周期归属：纯数据类型，随环流转。
- 状态：✅

### 2.10 `CycleUnit.h`（CycleUnit，06-10）
- 核心能力：一个采集周期的全家福——marker L/R＋N×2 激光管帧（偶 L 奇 R）＋周期温度打成一包。
- 交互：08/01 采集侧打包入姿态环 → 07 A 姿态链命中姿态时整单元保存。
- 生命周期归属：纯数据类型，随环流转。
- 状态：✅

### 2.11 `FrameEnricher.{h,cpp}`（enrich()，06-11）
- 核心能力：出口查表纯函数——按帧温取最近档（0.2℃ 阶梯，并列取低温档）填 CalibSnapshot 产出 EnhancedFrame。
- 交互：ScanSessionData::assemble 装表＋pushFrame 逐帧调用（激光表上显存归 07/09 侧）。
- 生命周期归属：无状态纯函数。
- 错误/降级：单表空→warning（tier=-1 自证）；两表全空→fail；越界→clamp 首/末档＋warning；空 Mat 输入透传空帧。
- 测试：经 test_scan_session（pushFrame 路径）覆盖。
- 状态：✅

### 2.12 `TempTableTypes.h`（StereoTempTable 等，06-12）
- 核心能力：两张温度补偿表的数据壳——立体侧持 Matx 档数据；激光侧仅档温索引（Ref 后缀，表数据归 07/09 GpuMat）。
- 交互：CalibrationRepository getters ↔ FrameEnricher/ScanSessionData。
- 生命周期归属：纯数据类型。
- 状态：✅

### 2.13 `IFrameSink.h` / `IPointCloudSink.h` / `IDeviceStateSink.h`（三 Sink 契约，06-13）
- 核心能力：数据投递的收件口约定——设备只认口，不管背后是谁（依赖倒置插座）。
- 交互：08 经它推送帧/点云/设备状态，不反向依赖 Data 实现。
- 生命周期归属：接口。
- 状态：✅

### 2.14 `IWorkflow.h`（IWorkflow，06-14）
- 核心能力：工作流统一遥控器——initialize/start/pause/resume/stop/getState/进度回调。
- 交互：01/02/04 三条工作流实现它。
- 生命周期归属：接口。
- 状态：✅

### 2.15 `ParameterManager.{h,cpp}`（ParameterManager，06-15）
- 核心能力：软件参数小账本——variant 参数键值仓（int/double/bool/string，类型化 getter）＋相机/扫描默认预设组。
- 交互：app 持有并注入 WorkflowContext，装配期与运行期读写。
- 生命周期归属：【公】app 存活件。
- 线程/并发：mutex＋unordered_map。
- 状态：✅

### 2.16 `file_io.{h,cpp}`（file_io＋MeshData，06-16）
- 核心能力：点云/网格/标志点文件的存取读写器——导入导出自由函数集，ply/pcd/xyz/txt 自动识别＋STL/OBJ。
- 交互：PointCloudBuffer 人工导出、04 STL 落盘、03/MainWindow 加载共用；点类型 cv::Point3f（已解 OSG 依赖）。
- 生命周期归属：无状态自由函数。
- 错误/降级：PCD import 头解析既有缺陷（钉测固定现状不修）。
- 测试：test_file_io。
- 状态：✅

### 2.17 `WorkflowArtifactStore.h`（WorkflowArtifactStore，06-17）
- 核心能力：L4 产物仓库抽象（put/get/list），仅头文件。
- 交互：暂无消费者（等扫描/GBA/后处理接线时落地）。
- 生命周期归属：接口。
- 状态：预留
