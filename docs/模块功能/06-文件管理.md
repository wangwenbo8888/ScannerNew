# 模块6 · 文件管理与数据管理（数据管理统一模块）

> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)
> 数据归属原则（L1–L4 分类、持有者 vs 共享范围、判定规则）见根目录 [`数据管理原则.md`](../../数据管理原则.md)。

## 职责
framework/ 退役后，本模块由「文件管理」升格为「数据管理统一模块」，承担四块：
1. **运行时数据容器**——帧流 / 点云 / 设备状态（自 framework/data 迁入）
2. **Sink 契约**——依赖倒置接口（HAL/算子产出 → 容器）
3. **工作流框架**——`IWorkflow` + `Pipeline`/`Stage`（自 framework/workflow 迁入）+ 参数管理 `ParameterManager`（自 framework/service 迁入）
4. **文件 IO**——点云 / 网格 / 标志点落盘与读取

> 跨阶段产物仓库（`WorkflowArtifactStore`，L4 落点）尚未建，见 §3。

## 1. 代码实际实现的（真实文件路径 + 简述）

静态库 `mod_fileio`（`modules/06_fileio/`），CMakeLists 链接 `base + spdlog + OpenCV`。命名空间分布：容器/Sink/RingBuffer 在 `Scanner::data`，工作流框架在 `Scanner::workflow`，参数管理在 `Scanner::service`，文件 IO 在全局 `file_io`。

### 1.1 运行时容器（`Scanner::data`）
| 文件 | 实现 | 要点 |
|---|---|---|
| `FrameBuffer.h/.cpp` | `FrameBuffer : IFrameSink` | 包装 `RingBuffer<FrameData>`，溢出策略 `DropOldest`（实时扫描优先最新帧）；`popFrame()`（默认 100ms 超时）供 Workflow Stage0 消费 |
| `PointCloudBuffer.h/.cpp` | `PointCloudBuffer : IPointCloudSink` | `shared_mutex` 读写锁（融合线程写 / 渲染线程并发只读）；版本号机制 `version_` 每写递增，UI 检测变化后再取快照 |
| `DeviceStateCache.h/.cpp` | `DeviceStateCache : IDeviceStateSink` | mutex 保护设备状态 map；便捷查询 `getTemperature/getFps/getTotalDroppedFrames` |

### 1.2 Sink 契约（`Scanner::data`，依赖倒置）
| 文件 | 契约 |
|---|---|
| `IFrameSink.h` | `FrameData{frameId,timestamp,leftGray,rightGray(cv::Mat)}` + `IFrameSink`（pushFrame / getBufferLevel / reset） |
| `IPointCloudSink.h` | `PointCloudFrame{frameId,Pose,points,colors,pointCount}` + `IPointCloudSink`（pushPointCloud / getSnapshot / getTotalPointCount / clear） |
| `IDeviceStateSink.h` | `DeviceStateInfo{deviceId,deviceType,state,temperature,fps,droppedFrames,timestamp}` + `IDeviceStateSink`（pushState / getState） |

> 依赖倒置：HAL 产出帧/状态推给 Sink，算子/融合线程产出点云推给 Sink，均不反向依赖容器实现。

### 1.3 环形缓冲（`Scanner::data`）
- `RingBuffer.h`：线程安全模板环形缓冲。`OverflowPolicy{DropOldest,DropNewest,Block}`；`push/pop` 用 mutex + 双条件变量（notEmpty/notFull），`pop` 带超时返回 `optional`。`FrameBuffer` 与 `Pipeline` Stage 间通信均依赖它。

### 1.4 工作流框架（`Scanner::workflow`，自 framework/workflow 迁入）
| 文件 | 内容 |
|---|---|
| `IWorkflow.h` | `WorkflowState{Idle,Running,Paused,Stopping,Completed,Error}`、`WorkflowProgress{state,currentStage,totalStages,stageName,message,progress}`、`WorkflowCallback`；`IWorkflow` 接口（getName / initialize / start / pause / resume / stop / getState / setProgressCallback）。标定/扫描/后处理三条工作流均实现此接口 |
| `Pipeline.h/.cpp` | `Stage` 基类（`process()` 纯虚 + `stop()` + `stopped_` 原子标志）+ `Pipeline` 编排器（addStage / start / stop / waitComplete，**每阶段一线程**，Stage 间经 RingBuffer 通信 + 背压） |

### 1.5 参数管理（`Scanner::service`，自 framework/service 迁入）
- `ParameterManager.h/.cpp`：`ParamValue = variant<int,double,bool,string>`；mutex 保护键值存储；`set/get/has/remove/clear` + 类型化 getter（getInt/getDouble/getBool/getString，均带默认值）；预设组 `setCameraDefaults() / setScanDefaults()`。

### 1.6 文件 IO（全局命名空间 `file_io`，`file_io.h/.cpp`）
按扩展名自动分派：
- **点云 IO**（`importPointCloud / exportPointCloud`）：PLY（导入 ASCII+二进制 / 导出 ASCII，支持 xyz + 法线）、XYZ/TXT（导入+导出，xyz + 法线）、PCD（导入 ASCII+二进制 / 导出 ASCII）
- **网格 IO**（`importMesh / exportMesh`，`MeshData{vertices,indices,normals}`）：STL（导入自动识别 ASCII/二进制带面法线 / 导出二进制自动算面法线）、OBJ（导入+导出，顶点 + 三角面索引，支持负索引）
- **标志点 IO**（`importMarkers / exportMarkers`）：JSON 数组 `[[x,y,z],...]`

> 注：`file_io.cpp` 当前**未纳入 `mod_fileio` 构建**（见 §2）。

### 1.7 数据归属现状（framework 退役后）

L1–L4 定义见 `数据管理原则.md`。各层实证：
- **L1 典型**：steger 的 Hessian 导数图与临时 GpuMat（`steger_extract_cuda_pimpl.h`）、intrinsic_calib 的临时矩阵——从不逃出算子。
- **L2 典型**：laser_cloud_fuse_cuda 的体素哈希表（Device 常驻）、marker_cloud_fuse_cpu 的 `fusedPoints_`（Host）。
- **L3 典型**：所有 Result struct（StegerResult、EllipseFitCPUResult、LaserReconstructResult…），通过 move 或 `shared_ptr<GpuMat>` 逐级传。
- **L4 典型**：标定温度补偿表（`StereoRectifyTempTable` / `LaserPlaneMapTempTable`，`calib_result_types.h`）、GBA 逐帧 obs / 修正位姿、existingMarkers 跨会话复用集。

当前归属（管理者）：

| 数据 | 管理者 | 状态 |
|---|---|---|
| L1 算子内暂存 / L2 算子内累积器 / L3 算子间逐帧 | modules/09 算子 pImpl + Result move | 已就位 |
| 帧流 / 点云 / 设备状态容器 | **modules/06**（`Scanner::data`） | 已迁入 |
| Sink 契约 | **modules/06**（`Scanner::data`） | 已迁入 |
| 工作流框架 / 参数管理 | **modules/06**（`Scanner::workflow` / `Scanner::service`） | 已迁入 |
| 标定参数 | **modules/01**（`CalibStore`，已自 framework/data 迁入 01）+ `calib_result_types.h` 契约 | 已迁入（接线见 §2） |
| 对象所有权 / DI | app/AppContext（unique_ptr） | framework `WorkflowContext` 随退役删除 |
| L4 跨阶段产物 | **WorkflowArtifactStore**（归 06，待建） | 未建（见 §3） |

## 2. 代码需要调整的

- **`file_io.cpp` 未纳入构建**：`modules/06_fileio/CMakeLists.txt` 的 `add_library` 仅列 5 个 .cpp（FrameBuffer / PointCloudBuffer / DeviceStateCache / Pipeline / ParameterManager），**不含 file_io.cpp**——文件 IO 当前不被 `mod_fileio` 编译产出，是孤儿源。需补进 CMake 或确认其去留。
- **`file_io` 依赖 OSG 且命名空间不一致**：`file_io.h/.cpp` 全面使用 `osg::Vec3`（OSG 依赖），而模块 CMake 仅声明依赖 `base/spdlog/OpenCV`（未链 osg）；且 `file_io` 是全局命名空间，与本模块其它 `Scanner::*` 子命名空间不统一。建议改为 `base/types.h` 的点类型（或 `cv::Point3f`——`PointCloudBuffer` 即用此）并归入 `Scanner::dataio`，再纳入构建。
- **modules/01 标定结果契约未接线**：`CalibStore` 已落 modules/01（`modules/01_calibration/CalibStore.h/.cpp`），但 `CalibrationWorkflow.cpp:251` 处仍为 TODO（`intrinsicResult/extResult/rectResult/tempResult → CalibStore`），尚未统一到 `calib_result_types.h` 契约——需在 01 侧补齐接线。
- **L2 借用护栏未代码化**：算子内累积器（`fusedPoints_`、体素哈希表）仅靠文档约定防悬垂，无代码层强制（对应 `数据管理原则.md §1.5` 的 L2 硬约束）。

## 3. 需要增加的

### 3.1 跨阶段产物仓库（L4 落点）
- **`WorkflowArtifactStore`**：工作流产物统一存储（注册 / 检索 / 版本管理）。归本模块，等扫描 / GBA / 后处理接线时再建。L4 是「公共数据统一管理」的唯一落点（详见 `docs/流水线/客户端扫描流水线.md` ADR 7.10）。

### 3.2 文件 IO 增强
- PLY 二进制导出（当前仅 ASCII 导出）
- PLY 颜色 (RGB) 支持（当前仅 xyz + 法线）
- LAS 测绘格式导入 / 导出
- 标定参数 JSON IO（`CalibrationArtifacts` 序列化 / 反序列化：内参 / 外参 / 矫正 / plane_map / 温度表）
- 工程 / 工件文件管理（工程目录结构、`project.jmw` 工程配置、扫描产物组织）

### 3.3 已知偏离点（待专项治理，跨模块）
- **编辑 / 融合点云冲突**：编辑模块直接改渲染 Geometry buffer，权威源却是融合算子的 `fusedPoints_`，两套点云不同步（`docs/模块功能/05-编辑.md`）。
- **Stream 同步策略不统一**：steger 用 cudaEvent，fuse 与 reconstruct 都用 `cudaMemcpyAsync` + `cudaStreamSynchronize` 阻塞——两类策略并存，破坏异步流水线。
- **部分 Warmup 空实现**：ellipse_fit、marker_cloud_fuse_cpu、laser_cloud_normal_cuda、intrinsic_calib 未真正预分配。
