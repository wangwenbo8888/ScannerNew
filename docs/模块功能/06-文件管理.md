# 模块6 · 文件管理与数据管理

> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)
> 数据归属原则（L1–L4 分类、持有者 vs 共享范围、判定规则）见根目录 [`数据管理原则.md`](../../数据管理原则.md)。

## 职责
文件 IO（PLY/STL/标定参数导入导出、工程/工件文件组织）+ 运行时数据管理（帧流/点云/设备状态容器、Sink 契约、跨阶段产物仓库）。

---

## 1. 代码现状功能（已实现，以代码为准）

### 1.1 文件 IO

**点云 IO**（`file_io::importPointCloud` / `exportPointCloud`，按扩展名自动分派）
- **PLY 导入**：ASCII + 二进制，支持 xyz 与法线
- **PLY 导出**：ASCII，支持 xyz 与法线
- **XYZ/TXT 导入/导出**：支持 xyz 与法线
- **PCD 导入**：ASCII + 二进制
- **PCD 导出**：ASCII

**网格 IO**（`file_io::importMesh` / `exportMesh`，按扩展名自动分派）
- **STL 导入**：自动识别 ASCII / 二进制，带面法线
- **STL 导出**：二进制，自动计算面法线
- **OBJ 导入/导出**：顶点 + 三角面索引（支持负索引）

**标志点 IO**
- **标志点导入/导出**：JSON 数组格式 `[[x,y,z], ...]`

### 1.2 运行时数据管理现状（截至 2026-08-11）

**各层实证**（L1–L4 定义见 `数据管理原则.md`）：
- **L1 典型**：steger 的 Hessian 导数图与临时 GpuMat（`steger_extract_cuda_pimpl.h`）、intrinsic_calib 的临时矩阵。从不逃出算子。
- **L2 典型**：laser_cloud_fuse_cuda 的体素哈希表（Device 常驻）、marker_cloud_fuse_cpu 的 `fusedPoints_`（Host）。
- **L3 典型**：所有 Result struct（StegerResult、EllipseFitCPUResult、LaserReconstructResult…），通过 move 或 `shared_ptr<GpuMat>` 逐级传。
- **L4 典型**：标定温度补偿表（`StereoRectifyTempTable` / `LaserPlaneMapTempTable`，`calib_result_types.h`）、GBA 逐帧 obs / 修正位姿、existingMarkers 跨会话复用集。

**数据当前归属**：

| 数据 | 当前位置 / 状态 |
|---|---|
| L1/L2/L3 算子数据 | 已在 modules/09_operatorlib，算子自管，已就位 |
| 帧流/点云/设备状态容器（FrameBuffer/PointCloudBuffer/DeviceStateCache） | **寄居 framework/data**，定义仅在此；被 app/AppContext + modules/02、03、08 实际依赖（承重墙） |
| Sink 契约（IFrameSink/IPointCloudSink/IDeviceStateSink） | 寄居 framework/data |
| 标定参数 | **双轨**：framework `CalibStore`（AppContext 创建但 `CalibrationWorkflow` 未编译 → 孤儿）∥ modules/01 `CameraCalibResult`+JSON（已编译，但**未接线** `calib_result_types.h` 契约） |
| 对象所有权 / DI | app/AppContext（unique_ptr）+ framework `WorkflowContext`（注入裸指针） |
| L4 跨阶段产物 | **无统一管理**：温度表内存常驻、逐帧 obs 由调度层临时缓冲 |

> framework/ 已定为过时层（`framework/AGENTS.md`），但 data 层容器仍承重——当前最大的归属错位（治理见 §2）。

## 2. 修改目标（framework 退役与数据归属迁移）

骨架（组合根 + Sink/Store/Buffer 分层）sound，不动；核心是把承重数据迁出 framework，让 framework 能删。

**目标归属（framework 退役后）**：

| 数据 | 目标管理者 | 机制 |
|---|---|---|
| L1 算子内暂存 | 算子 pImpl | 自管（已就位） |
| L2 算子内累积器 | 算子实例 + 会话层触发 Clear | 自管，**需加借用护栏** |
| L3 算子间逐帧 | Result 接收方（move） | 自管（已就位） |
| 帧流/点云/设备状态容器 | **modules/06**（从 framework/data 迁入） | Sink push + Ring/Snapshot |
| Sink 契约 | **modules/06**（随容器迁入） | 依赖倒置 |
| 标定参数 | **modules/01** + `calib_result_types.h` 契约 | CalibStore 删除 |
| 对象所有权 / DI | **app/AppContext** | WorkflowContext 退役，由 app 接管 |
| L4 跨阶段产物 | **WorkflowArtifactStore**（归 06，待建） | 统一注册/检索/版本 |

**framework 退役路径**：
1. **迁容器**：`FrameBuffer`/`PointCloudBuffer`/`DeviceStateCache` + 三个 Sink 契约，从 `framework/data` 迁入 modules/06。
2. **删 CalibStore**：无生产者，直接删；标定走 modules/01，并统一到 `calib_result_types.h` 契约（当前 modules/01 编译路径用自有 `CameraCalibResult`+JSON，**尚未接线契约**，迁移时需采纳）。
3. **退役 WorkflowContext**：AppContext 改用 modules 内 DI。
4. **删 framework 整树**：前三步完成后。

迁移完成后，本模块由「文件管理」升格为「数据管理」统一模块（运行时容器 + Sink + 落盘 + L4 产物仓库）。

## 3. 待增加

### 3.1 已知偏离点（待专项治理）
- **编辑/融合点云冲突**：编辑模块直接改渲染 Geometry buffer，权威源却是融合算子的 `fusedPoints_`，两套点云不同步（`docs/模块功能/05-编辑.md`）。
- **DeviceContext 裸指针无护栏**：仅靠文档约定防悬垂，无代码层强制（对应 `数据管理原则.md §1.5` 的 L2 硬约束，尚未代码化）。
- **Stream 同步策略不统一**：steger 用 cudaEvent，fuse 与 reconstruct 都用 `cudaMemcpyAsync` + `cudaStreamSynchronize` 阻塞——两类策略并存，破坏异步流水线。
- **部分 Warmup 空实现**：ellipse_fit、marker_cloud_fuse_cpu、laser_cloud_normal_cuda、intrinsic_calib 未真正预分配。

### 3.2 文件 IO 增强
- PLY 二进制导出（当前仅 ASCII 导出）
- PLY 颜色 (RGB) 支持（当前仅 xyz + 法线）
- LAS 测绘格式导入/导出
- 标定参数 JSON IO（`CalibrationArtifacts` 序列化/反序列化：内参/外参/矫正/plane_map/温度表）
- 工程/工件文件管理（工程目录结构、`project.jmw` 工程配置、扫描产物组织）

### 3.3 跨阶段产物仓库
- `WorkflowArtifactStore` 工作流产物统一存储（注册/检索/版本管理；归本模块，等扫描/GBA/后处理接线时再建）
