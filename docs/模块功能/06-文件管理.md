## 1. 目标功能（以 01/02 流程图 + 模块功能目录 §三 基准为准）

> 一句话：06 是**数据大管家**——运行中数据（帧/点云/设备状态）的容器、跨工作流交接的仓库（标定结果/点云）、每次开工要装配的配置与缓冲，外加文件导入导出，都归它管。

| 对象（归属） | 管什么（通俗） | 用在（步骤号） |
|---|---|---|
| **数据管理·仓库**（【公】app 存活件，开机即造、全程不销毁） | 跨工作流的「数据保险柜」，三个格子：①**标定结果仓库**——收 01-⑦ 标定成果统一落盘（相机内/外参、立体矫正、激光平面映射、两张温度表），是持久基准量；②**标定参数仓库**——01 产出的参数存这里，02-① 门禁「参数就绪」查它（开机自检「是否正确导入标定参数」也查它）；③**点云仓库**——02-⑧ 优化后点云留内存、不随 ⑩ 销毁：供 04 后处理内存调用、续扫作 existingMarkers 基准、人工请求才导出 | 01-②⑦；02-①②⑧ |
| **数据管理·会话件·01 版**（【私】② 构造、⑨ 逆序销毁） | 标定开工三件套：加载标定配置＋初始参数＋25 目标姿态表；创建帧环形缓冲实例（周期帧＝标记点帧＋N 路激光管帧＋温度） | 01-②④⑤ |
| **数据管理·会话件·02 版**（【私】② 构造、⑩ 逆序销毁） | 06 会话件只管装表＋ring——配置归 07 ScanConfig（ScanTypes.h 已有已消费；设计方案 §8-7，2026-08-21 人工确认口径）：创建帧环形缓冲实例（双目帧）；**出口查表**——装配期装载两张温度补偿表（激光表同时上载显存），缓冲出口按帧温逐帧查表、随帧附标定快照（「增强帧」——算子无查表动作） | 02-②④⑤ |
| **环形缓冲容器**（随会话件【私】，支撑约定） | 帧的传送带：08 只管往里放、流水线只管往外取，采图与计算互不等待；02 消费 lag 超限就跳最新丢中间，永远追新帧 | 01-④⑤；02-④⑤ |
| **文件 IO**（06） | 落盘/读盘的搬运工：点云 PLY/XYZ、网格 STL/OBJ、标志点、标定参数的导入导出（冷路径） | 01-⑦（落盘）；02-⑧（按需导出）；03/05（模型与标志点加载） |
| 流水线原语（IWorkflow / ParameterManager）（06） | 执行引擎零件：工作流统一接口＋参数键值仓，供 01/02/04 消费（Pipeline/Stage 已按 D3 裁删） | 01/02/04 工作流内部 |

> 支撑约定（目录 §三）：**温度表分工（01-D5）**——01 生成两张温度补偿表（0.2℃ 阶梯）随标定结果落盘，02 扫描侧在缓冲出口逐帧查表消费，生成与消费分离；**会话记账**——账本归 01/02 自身，06 只管存取（存档仅人工手动触发）。
> 数据语义分层（L1–L4）与判定规则见根目录 [`数据管理原则.md`](../../数据管理原则.md)：06 管的是 L3 逐帧产物容器与 L4 跨阶段产物仓库；L1/L2 暂存与累积器归 09 算子内部。

## 2. 现状对齐（核心能力一句话；本节随代码演进更新）

> 一句话：**容器、传送带、出口查表器已在岗能用，「仓库/会话件」两层对象还没立**——07 五流水线已实际消费 06 的 SlotRing/CycleUnit/EnhancedFrame（attachRing 注入）；app 已构造持有三容器并注入工作流（仓库的「壳」有了）；出口查表器本体已建但未接线；标定参数存在 01 的 CalibStore（YAML）里、点云仓库由 PointCloudBuffer 兼任；ScanConfig、产物仓库都没建；file_io 能用但编在 app 里、点类型拴在 OSG 上。

库 `mod_fileio`（STATIC，`modules/06_fileio/`，链 base/spdlog/OpenCV）：

| 文件/类 | 现状核心能力 |
|---|---|
| `RingBuffer.h`（`Scanner::data`） | 线程安全环形缓冲模板：溢出三策略（丢最旧/丢最新/阻塞），pop 带超时 |
| `FrameBuffer`（:IFrameSink） | 帧中转站：DropOldest 保最新帧，`popFrame(100ms)` 供工作流取帧。app 的 AppContext 持有一个 60 槽实例注入各处；ScannerWindow 另自建一个显示用实例 |
| `PointCloudBuffer`（:IPointCloudSink） | 点云快照仓：读写锁＋版本号，写（02 融合 Stage）/读（OSGWidget 渲染）并发安全——现兼作「点云仓库」雏形（app 持有） |
| `DeviceStateCache`（:IDeviceStateSink） | 设备状态记账：mutex 保护，温度/fps/丢帧便捷查询（08 HardwareMonitor 写、UI 读） |
| `IFrameSink.h` / `IPointCloudSink.h` / `IDeviceStateSink.h` | 依赖倒置插座：HAL/算子产出推给容器，容器不认识具体设备 |
| `SlotRing.h`（纯头文件） | 原子槽位环（单写多读，槽位 shared_ptr 原子换入）：Overwrite（扫描·满则覆盖最旧永不阻塞）/ Backpressure（姿态·满则阻塞等 done() 腾位）——**07 五流水线的实际输入容器**（Posture/ScanPipeline 经 attachRing 注入指针） |
| `CycleUnit.h` / `EnhancedFrame.h` / `TempTableTypes.h`（纯头文件） | 07 消费的数据单元三件：CycleUnit 采集周期单元（标记点帧＋N 路激光管帧「乘客」＋温度，A 姿态链消费）；EnhancedFrame 增强帧（双目灰度＋帧温＋CalibSnapshot 标定快照，C 扫描链消费）；TempTableTypes 两张温度表 06 侧持档类型（立体侧持 Matx 数据；激光侧仅档温索引，GpuMat 表归 07/09 持有） |
| `FrameEnricher.{h,cpp}` | 出口查表器：按帧温选最近档（0.2℃ 阶梯，并列取低温档）填 CalibSnapshot 产出 EnhancedFrame；降级规则（单表空→warning／两表全空→fail／越界→clamp＋warning）。**已建未接线**——app/02 侧暂无人调用，装配期装载温度表＋激光表上显存未做 |
| `IWorkflow.h`（`Scanner::workflow`） | 工作流统一接口：留（01/02/04 三消费者实现它）；`Pipeline`/`Stage` 已删（2026-08-21 批 A，零消费者；07 自建 SchedulerRuntime＋LaneHooks 编排未复用——裁决 D3） |
| `ParameterManager.{h,cpp}`（`Scanner::service`） | variant 参数键值仓（类型化 getter＋相机/扫描两预设组）——app 持有并注入 WorkflowContext |
| `file_io.{h,cpp}`（全局命名空间） | 点云 PLY（读 ASCII＋二进制/写 ASCII）、XYZ、PCD，网格 STL（自动识别）、OBJ，标志点 JSON 的导入导出——**编入 app 的 scan_demo**（`app/CMakeLists.txt:61`，不在 mod_fileio 库），点类型用 `osg::Vec3`，被 MainWindow/OSGWidget 调用 |

仓库/会话件现状：

- **标定参数仓库**：现为 01 的 `CalibStore`（`modules/01_calibration/`，mod_calibration；`cv::FileStorage` YAML）＋ calib_workflow 的 JSON 存取**两套并存**；无温度表/激光平面映射字段；01 写入端尚有 TODO（`CalibrationWorkflow.cpp:251`）
- **点云仓库**：PointCloudBuffer 兼任（见上表）；「供 04 内存调用 / 续扫基准 / 按需导出」三用途未接线
- **会话件（01/02）**、**ScanConfig**、**WorkflowArtifactStore**：均未建；**出口查表**：查表器本体已建（FrameEnricher，见上表），剩装配期装载两张温度表（激光表上显存）＋缓冲出口逐帧调用接线未做
