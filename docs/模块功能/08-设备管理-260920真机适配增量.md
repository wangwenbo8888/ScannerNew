## 1. 协议层变更（5 处）

### 1.1 搜口凭据：回显 → 上行帧

| | 原设计（§2.7） | 现行 |
|---|---|---|
| 探测命令 | N12 T100 | N10 H50 B50 T1 V1 C0 D0 L50（七参点灯帧） |
| 命中凭据 | G 帧到达（N12 开温度上报后 G02 到来） | **`probeHit_` 置位**——rx 收到任一 G0x 帧/数值行即命中 |
| 未命中原因 | 固件不响应 N12 | **260919 真机实证：现固件不回显命令**——原回显判据恒 miss → open 失败 → 自检整链不跑（N11 H0 缺失根因） |
| 回环安全 | 纯回环线不回 G 帧 ✓ | 同（回环线只回显不产上行帧） |
| 补充 | — | open() 复位时清 `lastEcho_`（防陈旧回显跨会话串染 stage0） |

代码锚：`MCUDriver.cpp probeAutoPort()` / `feedTextLine()`

### 1.2 G02 四路温度入链

| | 原设计 | 现行 |
|---|---|---|
| G02 消费 | DeviceManager 温度链（温度→Warmup/双警/缓存） | 同——**新增解析** `G02 A37.59 B36.17 C37.23 D37.62` → TempFrame{celsius[4], channels=4} → 推入 `tempRing_` → pump → onTemp 回调 |
| 旧版 | v2 数值行（~133 单位待定）不入 TempFrame | 保留旧数值行 probeHit 路径，**不入温账**（量纲待固件方确认） |
| 生效链 | — | UI「MCU温度」显示（四路取最高）＋预热喂数＋0x0803/0x0804 双警＋N15 兜底停用（G02 每 ~300ms 刷新 tempRxTime_） |

代码锚：`MCUDriver.cpp feedTextLine()` G02 分支

## 2. 新增功能

### 2.1 自检降级路径完整语义

```
stage0（≤8s）:
  回显匹配 → bgLight/laser = true → stage1
  超时 → 上行活证（lastRxTime 距今 <3s）→ bgLight/laser = true（降级凭据）→ stage1
       → 上行静默 → bgLight/laser = false → stage1（仍走相机验证）

stage1（1s 灯停留）→ stage2（N11 H0 收口＋相机判定）
```

### 2.2 globalId 原子序列晋升

| | 原设计 | 现行 |
|---|---|---|
| 新标志点发号 | ScanChains 首帧 `ids[i]=i`＋后续 `++maxGid` | **单一文件级原子序列** `s_markerGidSeq`（首帧/晋升共用——跨 lane 唯一） |
| 根因 | — | 算子对 unmatched 恒 -1 且 gid<0 匹配对被丢 → matched 恒 3 → SVD 欠定漂移；两处独立计数器互撞 = 300+ 伪点 |

代码锚：`ScanChains.cpp runRegistration()`
