## 1. 信息〔人＋AI〕

### 1.1 模块背景〔AI 预填，迭代时刷新〕

- **模块定位**：扫描收尾的离线批处理编排者——把 02 全局优化（GBA）修正后的点云加工成 STL（3D 打印通用三角网格文件）成品，供用户导出
- **上下游依赖**：
  - 上游：06 PointCloudBuffer 点云仓库（快照只读；02 GBA 修正点云写入后的内存形态即本模块输入）
  - 上游：app 装配注入（输出路径/跳段位掩码/完成回报钩子/进度回调）
  - 下游：07 PostProcessPipeline（五阶段编排引擎，E 对象）
  - 下游：06 fileio::exportSTL（STL 落盘）；10 CommandGate（完成经 app 注入回调合账，04 不直接依赖 10）
- **关键约束**：
  - 范围边界：五阶段离线批处理＝法线重算 → 封装(网格化) → 补洞 → 光顺(HC) → 边界优化，出 STL；GBA 与重融合归 02 收尾执行，本模块只消费其修正后点云
  - 职责边界：04 只做编排与记账（生命周期/进度透传/产物记账），五阶段编排在 07 E 对象、算子在 09
  - 编译归属：PostProcessWorkflow 源码直编入 scan_demo（app 编译单元），mod_postprocessing 仅为 INTERFACE 占位库
  - 解耦约束：STL 导出经 StlExportFn 适配器接 06（07 不依赖文件 IO）；完成回报经 std::function 回调（04 不 include 10 头）
  - 线程约束：postThread_ 独立阻塞批处理线程，start 建、stop 必 join；取消经 CancelToken 在阶段前/导出前检查点安全退出
  - 五阶段编排引擎（07 E 对象）细节见 [`07-流水线管理.md`](07-流水线管理.md)；GBA 归属见 [`docs/流水线/客户端扫描流水线.md`](../流水线/客户端扫描流水线.md)

## 4. 已有代码现状〔AI〕

### 4.1 总图

```
【后处理数据流主线】
06 PointCloudBuffer（点云仓库·02 GBA 修正后点云的内存形态）
        │ getSnapshot（点云快照）
        ▼
04 PostProcessWorkflow.makeCloudData → MeshData(xyz)
        │ start()：装配 07 E（skipStages/outputPath 透传＋法线实注）
        │           ＋起 postThread_ 阻塞批处理
        ▼
07 PostProcessPipeline.run（五阶段：法线→封装→补洞→光顺→边界）
        │ 产物 MeshData ── StlExportFn 适配器 exportStlViaFileIo
        ▼
06 fileio::exportSTL → output.stl（法线数量匹配时随片透传）
```

### 4.2 功能实现清单（按功能域分组）

#### 4.2.1 批处理编排域（服务 G1/G3/G4）——工作流生命周期、07 E 装配触发、进度透传与产物记账

```
┌──────────────┐
│   start()    │──点云空/装配失败──► Error＋message（不起批处理线程）
└──────┬───────┘
       ▼ 装配 07 E＋起 postThread_（会话私有件：start 建、stop 收）
┌───────────────────────┐
│ postProcessLoop       │──进度透传 callback_（百分比/20→阶段号 0..5）
│ pipeline->run 五阶段   │
└──────┬────────────────┘
       ▼ 记账 PostProcessResult（三角面数/耗时/输出路径/成败）
┌───────────────────────┐
│ onFinished_(ok)       │──用户取消──► ok=true（正常终止非故障）
│ 恰一次回报             │──阶段失败──► ok=false
└───────────────────────┘
       ▼ 任意时刻 stop()：取消令牌＋pipeline.stop＋join＋复位 Idle
```
