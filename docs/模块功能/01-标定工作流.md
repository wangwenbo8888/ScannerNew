## 职责

本模块负责**标定的编排、参数存储与 UI**：多姿态图像采集 → 相机标定（内参/外参/立体矫正）→ 激光虚拟相机标定 → 温度补偿表 → 结果持久化（供扫描工作流读取）。

> **重要边界**：本模块只含**编排层 / 存储层 / UI 层**。标定**算子**本身（`intrinsic_calib` / `extrinsic_calib` / `stereo_rectify` / `stereo_rectify_temp_table` / `laser_*` / `projector_joint_calib` / `plane_map` / `*_compensate` 等）实现在 `modules/09_operatorlib/calibration/`，不在 01。

> **编译归属**（framework/ 退役后）：物理文件均在 `modules/01_calibration/`，但编译分两处——
> - `CalibStore.cpp` → 静态库 `mod_calibration`（`modules/01_calibration/CMakeLists.txt`）
> - `calib_workflow.*` / `CalibrationWorkflow.*` / `CalibDialog` / `CalibDisplay` / `IntegrateTestDialog` → 直接编入 app 可执行（`app/CMakeLists.txt` 的 `MOD_CALIBRATION` 与 `MOD_WORKFLOWS`）
>
> 另：`app/stubs/camera_calib_workflow.h`、`app/stubs/laser_calib_workflow.h` 为桩头（见 §2）。

> **流水线规格交叉引用**：完整的 33 算子目标流水线（阶段 0 初始化 → 1 采集 → 2 姿态判断标记点链 2-1~2-13 → 3 相机标定 3-1~3-5 → 4 激光标定 4-1~4-13 → 5 温度补偿）详见 [`docs/流水线/客户端标定流水线.md`](../流水线/客户端标定流水线.md) 与 [`docs/流水线/姿态判断并行调度方案.md`](../流水线/姿态判断并行调度方案.md)。**注意：该目标设计与本模块当前代码存在差距**（见 §2、§3）。

## 1. 代码实际实现的

### 1.1 标定参数存储 — CalibStore

`modules/01_calibration/CalibStore.h` / `.cpp`，类 `Scanner::data::CalibStore`（线程安全，`std::mutex` 保护）。

- `save(path)` / `load(path)`：基于 `cv::FileStorage` 持久化（实际产出 YAML，如 `calibration.yml`）。
- 存储字段：`cameraMatrixL/R`、`distCoeffsL/R`、`R1/R2/P1/P2/Q`、`extR/extT`、`imageSize`。
- 对外 getter：内参/畸变/矫正矩阵/图像尺寸；`hasData()` / `clear()`。
- 编译入 `mod_calibration` 静态库；供 `CalibrationWorkflow` 写入、扫描工作流读取。

### 1.2 标定算法函数 — calib_workflow（namespace calibration）

`modules/01_calibration/calib_workflow.h` / `.cpp`，编入 app。

- 固定标定板常量：`CHESSBOARD_COLS=6`、`CHESSBOARD_ROWS=7`、`CHESSBOARD_SQUARE_MM=15.0`、`CALIB_FRAME_COUNT=25`。
- `runCameraCalibration(CameraCalibInput, progress)`：**已实现**。编排算子链 `intrinsic_calib_cpu` → `extrinsic_calib_cpu` → `stereo_rectify_cpu`（算子来自 09），输入为采集阶段已检测的左右角点，输出 `CameraCalibResult`（内参/外参 R,T,E,F/立体矫正 R1,R2,P1,P2,Q/各项 RMS）。
- `runLaserCalibration(LaserCalibInput, progress)`：**桩**。仅校验相机标定存在与图像非空，函数体为 TODO，返回 `"laser calibration: operator integration TODO"`（`calib_workflow.cpp:147-172`）。
- JSON 持久化（`nlohmann_json`，独立于 CalibStore 的 YAML 路径）：`saveCalibResult/loadCalibResult`（相机，已实现）、`saveLaserCalibResult/loadLaserCalibResult`（激光，仅 `lineCount/endpointCount` 占位字段）。

### 1.3 标定工作流 — CalibrationWorkflow（IWorkflow 实现）

`modules/01_calibration/CalibrationWorkflow.h` / `.cpp`，类 `Scanner::workflow::CalibrationWorkflow`（继承 `IWorkflow`），编入 app。

线程化 6 阶段主循环（`calibrationLoop()`，`CalibrationWorkflow.cpp:57-270`）：

1. **采集**：从 `WorkflowContext::frameBuffer()` 弹帧，收满 `numPoses_`（默认 25）组左右灰度图。
2. **角点检测**：直接用 `cv::findChessboardCorners` + `cv::cornerSubPix`（OpenCV，**非**标记点算子链）。
3. **内参标定**：算子 `intrinsic_calib_cpu`。
4. **外参标定**：算子 `extrinsic_calib_cpu`（`rotateRightImage180=true`）。
5. **立体矫正**：算子 `stereo_rectify_cpu`。
6. **温度补偿表**：算子 `stereo_rectify_temp_table_cpu`（CTE=23.6e-6，参考 25℃，范围 -10~+10℃，步长 0.2℃）。

完成后将内参/畸变/外参 R,T/矫正矩阵写入 `CalibStore` 并 `save("calibration.yml")`。进度经 `WorkflowCallback` 回调上报。

### 1.4 标定 UI

物理在 `modules/01_calibration/`，编入 app（`MOD_CALIBRATION`）：

- `CalibDialog.h/.cpp`：标定入口对话框，提供「相机标定」「激光标定」两个按钮（`cameraCalibClicked` / `laserCalibClicked` 信号）。
- `CalibDisplay.h/.cpp`：`buildCalibScene(stlPath)` 构建 OSG 标定场景；`CalibBoard2D` 为 Qt 绘制的 2D 标定板控件（无 3D）。
- `IntegrateTestDialog.h/.cpp`：集成测试对话框，串联 `modules/08_devicemgmt/CameraControl` 采集、参数调节（曝光/频率/背景/激光强度）、左右图像显示、标定操作。

### 1.5 app 桩头

`app/stubs/camera_calib_workflow.h`、`app/stubs/laser_calib_workflow.h`：`CameraCalibWorkflow` / `LaserCalibWorkflow` 类，`run()` 直接返回 `"Stub: ... not implemented"`。

## 2. 代码需要调整的

### 2.1 CalibStore：注释与实现不符 / API 不完整

- `CalibStore.h:5` 注释称「JSON 格式存储」，实际 `save/load` 用 `cv::FileStorage` 产出 YAML（`.yml`）。注释应改为 YAML/FileStorage。
- 有 `setExtrinsicR/T` setter 且 `save` 写入 `extR/extT`，但**无对应 getter**——外参写入后无法读出。应补 `extrinsicR()` / `extrinsicT()`。

### 2.2 双重持久化路径未统一

存在两套互不相通的持久化：CalibStore 的 FileStorage（YAML，`calibration.yml`）与 `calib_workflow.cpp` 的 `nlohmann_json`（`saveCalibResult`）。同一份相机标定结果有两套序列化、字段与格式不一致，需收敛到单一权威路径。

### 2.3 温度补偿表「生成即丢弃」

`CalibrationWorkflow` 阶段 6 调用 `stereo_rectify_temp_table_cpu` 生成温度补偿表（`tempResult`），但**仅记日志、未写入 CalibStore**，扫描侧无法读取。需打通生成→存储→加载链路。

### 2.4 app/stubs 与真实实现类型名冲突（ODR 风险）

`app/stubs/camera_calib_workflow.h` 与 `app/stubs/laser_calib_workflow.h` 在**同一 `namespace calibration`** 内重复定义 `CameraCalibInput/Result`、`LaserCalibInput/Result`，与 `modules/01_calibration/calib_workflow.h` 同名；且字段形状冲突（桩 `CameraCalibInput` 用 `vector<cv::Mat> images`，真实用 `vector<vector<Point2f>> corners`）。若同时被翻译单元包含会触犯 ODR。需删除桩或重命名隔离。

### 2.5 两条相机标定代码路径重复

`calibration::runCameraCalibration`（calib_workflow.cpp）与 `Scanner::workflow::CalibrationWorkflow::calibrationLoop`（CalibrationWorkflow.cpp）各自实现一遍内参→外参→矫正编排，逻辑重叠但不一致（前者无温度表/无 CalibStore 写入，后者有）。需明确单一归属，消除重复。

### 2.6 实际流程与目标流水线设计的偏离

相对 [`客户端标定流水线.md`](../流水线/客户端标定流水线.md) 目标设计，当前 `CalibrationWorkflow` 的偏离（需评估是临时简化还是缺陷）：

- **无姿态判断链**：未用标记点算子链 2-1~2-13 + `pose_estimate` 选 25 个目标姿态，而是盲目收满 N 帧即标定。
- **跳过 3-1 逆畸变**：角点直接喂 `intrinsic_calib`，未先经 `inverse_distort`（3-1）逆变换；与流水线 3-1→3-2 顺序不符。
- **角点检测用 OpenCV 而非标记点链**：`cv::findChessboardCorners` 与目标设计的标记点/Zernike/椭圆拟合链路不同。
