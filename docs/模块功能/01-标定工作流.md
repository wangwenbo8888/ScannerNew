# 模块1 · 标定工作流

> 一句话：把「拍照 → 算参数 → 存文件」的标定流程串起来的**编排者**——01 只做编排、记账、UI；算子在 09、流水线对象在 07、数据容器与仓库在 06、设备在 08。
> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)

## 1. 功能目标

### 1.1 定案要点

| 定案 | 内容 |
|---|---|
| **D1 对象自治** | 设备管理（DeviceManager/08）、姿态判断流水线（07）、标定计算流水线（07）、数据管理（06）、渲染（03）五对象封装自治；**01 只做①门禁进入、②装配（注入+构造，见 D8）、③启动预热、⑧旁观显示、⑨停止回收（仅会话私有件，见 D8）** |
| **D2 全自动无人为中断** | ③ 启动后 ④~⑦ 自动段 **01 零干预**——自动采图入环形缓冲、自动集齐 25 姿态、自动算参数、自动落盘（区别于扫描的按键启停/软件完成） |
| **D3 完整姿态判断链** | 保留 14 算子标记点链 + `pose_estimate` 凑 25 目标姿态（连续命中同一姿态才确认），不采用"盲收 N 帧"简化路线 |
| **D4 激光标定定版 PJC** | `projector_joint_calib` 替代旧端点链路；factory_calib 保持旧链路（有意分歧） |
| **D5 温度表分工** | 标定侧生成两张温度补偿表（0.2℃ 阶梯）落盘、扫描侧查表消费 |
| **D6 结果落盘** | ⑦ 标定结果统一落盘（相机内/外参、立体矫正、激光平面映射、两张温度表），供扫描工作流读取（与扫描「留存内存不落盘」相反——标定结果是持久基准量） |
| **D7 会话记账归 01** | 标定会话记账（**仅计数之外的开/合账**：会话 ID + 起止时间戳 + 结果统计存档）由 01 自己承担，不设独立会话对象。**帧数/已集姿态数不记**：由姿态算子内部处理 |
| **D8 对象所有权拆分** | 跨工作流存活件归 **app**（应用生命周期；01 只接线注入，⑨ 不销毁）：DeviceManager(08)、标定结果仓库(06)、渲染基座(03)、EventBus、**状态机（第 5 个 app 存活件：全局状态唯一且跨工作流互斥存活，故实例归 app 构造持有）**——⑨ 时 DeviceManager 切回 idle、仓库留存（02 ① 门禁「标定参数就绪」即查此仓库）。**会话私有件归 01**（② 构造、⑨ 逆序销毁）：姿态判断/标定计算流水线(07)、帧环形缓冲实例(06)、场景内容供给器(03)。判据：数据跨工作流存活→容器归 app，仅会话内消费→归工作流 |

### 1.2 app 存活件（应用启动即构造，先于本工作流存在）★D8

以下对象由 app 构造并持有整个应用生命周期——不归本工作流构造/销毁（② 只接线注入、⑨ 不销毁），但流程中反复出现，先列出便于阅读。判据（D8）：数据跨工作流存活 → 容器归 app；仅会话内消费 → 归工作流。除 06 兼私有两副面孔外，均为公用。

- **DeviceManager 设备管理器（08）**：08 对外唯一门面——把相机＋下位机＋温度监测封装成「采集服务」（预热、周期采图、指令下发）；01 调 `enterCalibration()` 即切入标定模式
- **数据管理（06）**：仓库公用＋会话件私有（同一对象两副面孔）——**仓库（app 持有）**：标定结果仓库，01→02 跨工作流交接点（相机内/外参、立体矫正、激光平面映射、两张温度表，落盘持久）；**会话件（② 构造、⑨ 销毁）**：标定配置＋初始参数＋25 目标姿态表＋帧环形缓冲实例（详见 ②）
- **渲染基座（03）**：三维视窗＋场景切换器；纯显示，不反向控制流程
- **EventBus 事件总线（base）**：全局事件订阅/发布通道；01 靠它旁观进度/完成事件
- **状态机（10）**：全系统唯一「现在处于什么状态」的裁决者——① 门禁检查与 ⑨ 状态切换都问它；实例归 app（实例 app 造、代码模块出——与 EventBus/仓库同模式）

## 2. 实现现状（以代码为准）

> 一句话：**编排壳已立**——CalibrationWorkflow 装配 07 A/B 两流水线、直写 06 仓库、装载会话档；旧棋盘格 6 步简化链已退役。
> 编译归属：文件物理在 `modules/01_calibration/`，**全部直接编入 app 的 `scan_demo.exe`**（`app/CMakeLists.txt`），无独立库目标。

### 2.1 CalibrationWorkflow（`CalibrationWorkflow.{h,cpp}`）

- 核心能力：编排壳——IWorkflow 生命周期编排＋装配启停 07-A PosturePipeline／07-B CalibComputePipeline（集齐 25 姿态自动移交批算），批算结果经内嵌适配器直写 06 标定仓库，进度回调透传 UI、完成回报回调给 app
- 交互：01→07-A/B；06 会话档→A/B 注入；B→06 CalibrationRepository；onFinished→app 合账
- 公/私：私（会话编排件）
- 状态：◐ 壳已立；08 帧源、08 采集门面、03 场景推送三处接入期待线（TODO 在文件头）

### 2.2 calib_workflow（`calib_workflow.{h,cpp}`）

- 核心能力：相机标定函数集——`runCameraCalibration` 角点输入版三步链（内参→外参→立体矫正，含进度回调）完整可用；`runLaserCalibration` 桩（仅输入校验，算子未对接）；激光结果 JSON 存取（占位字段）
- 交互：UI/集成测试调用；消费 09 算子（内参/外参/矫正）
- 状态：◐ 相机链 ✅；激光链桩

### 2.3 CalibDialog（`CalibDialog.{h,cpp}`）

### 2.4 CalibDisplay（`CalibDisplay.{h,cpp}`）
