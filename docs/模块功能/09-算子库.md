# 模块9 · 算子库

> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)

## 职责
三维扫描仪全部纯计算叶子算子的集合，供标定 / 扫描两条流水线复用。覆盖核心视觉前端（掩膜提取 / 连通域 / 帧过滤）、标记点链（CPU）、激光线链（CUDA）、标定独有算子（相机 / 激光虚拟相机 / 姿态 / 温度补偿）、扫描独有算子（掩膜分离 / 激光匹配 / 点云融合）以及全局优化（Ceres BA）。本模块自 `3DSCANNER` 机械迁入，命名空间保留 `calib::`，自带 `core/common/` 共享类型层，**不依赖已退役的 `framework/`**（未受框架退役影响）。

> 算子契约与工程集成规范见 [`算子规范.md`](../../算子规范.md)（§0–§7：执行与资源 / 接口形状 / 数据端口 / 状态模型 / 失败与质量 / 一致性检查 / 工程集成合并规范）；逐算子功能说明见 [`算子目录.md`](../../算子目录.md) → [`docs/算子说明文档/`](../算子说明文档/)（core 19 / calibration 17 / scanning 7）。

### 1.3 算子契约（三元组 + pImpl + Stream&）

每个算子遵循 [`算子规范.md`](../../算子规范.md) §1–§5 的统一契约：

- **三元组**：`Params`（参数）+ `Result`（结果）+ `Operator`（执行体）
- **接口**：`Execute()` / `Destroy()` / `Warmup()`
- **实现隔离**：pImpl 模式（`*_pimpl.h` 持有实现）
- **流亲和**：CUDA 算子统一 `cuda::Stream&` 入参，不内部同步默认流
- **目录约定**：`<name>_cuda.h` / `.cpp` / `_pimpl.h` / `_impl.cu` / `tests/test_*.cpp`

## 2. 代码需要调整的

- **命名空间 `calib::` 与工程约定不一致**：3DSCANNER 机械迁入保留 `calib::`（`CMakeLists.txt:3` 明示），与工程其余模块的 `Scanner::<层>::` 命名约定不统一。改动面大（机械迁入遗留），是否 / 如何统一**待评估**——非缺陷，记录为现状差距。
- **跨算子隐式 include 耦合**：`CMakeLists.txt:33-42` 把**所有算子自目录**加入 `mod_operatorlib` 的 PUBLIC include，使任意算子可 include 任意他算子的自目录头（如 `plane_map_temp_table` → `plane_map_cuda.h`）。这是脆弱耦合，与算子规范 §7.3「头文件组织 / 目录结构」期望的自包含有偏差，建议收敛为显式 include 路径或公共头聚合。
- **GLOB 收源不追踪增删**：`file(GLOB_RECURSE)` 收集算子源，新增 / 删除算子文件不触发重配置，需手动重跑 cmake（CMake 常见 caveat，记为现状，非阻塞）。

## 3. 需要增加的

- **`marker_cloud_fuse_cpu` 单测缺失**：43 个算子 / 组件中 42 个有 `test_*.cpp`，**仅 `core/marker/marker_cloud_fuse_cpu`（标记点点云体素哈希融合）无单测**。建议补齐，达成全算子单测覆盖。
- **算子级性能基准缺位**：`3DSCANNER` 原有 `bench/benchmark` 未纳入本库（`CMakeLists.txt:5` 明确「不含 bench/benchmark」）。若需算子级性能回归（如 `steger` / `laser_reconstruct` / CUDA 融合的吞吐 / 延迟基准），当前无现成工具，需新建。
