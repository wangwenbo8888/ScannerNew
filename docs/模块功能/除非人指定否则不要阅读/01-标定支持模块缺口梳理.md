# 01-标定流程 · 支持模块缺口梳理

> 状态：**缺口清单（2026-08-15）**——按标定主流程（伪代码/功能单元分解的执行顺序）逐步走查，每一步标注"调用了谁、现有什么、缺什么"
> 盘点基准（已核实）：06 FrameBuffer(FrameData)、08 IMCU/MCUDriver(无标定命令)、base types.h EventType(无姿态事件)、09 算子接口全量就绪、calib_result_types.h 契约类型已含 lookup
> 定位：给 G8 类跨模块小件（FU-8.x）的**完整化清单**——比功能单元分解里的 4 项更细，按流程顺序展开
> 原则：**支持模块只加"通用能力"，不掺标定业务**——标定语义（如 N16 命令）在 01 编排层组装，支持层提供原子功能

---

## 走查路线（= 标定流程执行序）

```
S0 Init → S1 Warmup → S2 姿态采集循环 → S3 相机标定 → S4 激光标定 → S5 门禁落盘
```

---

## S1 Warmup（设备控制）

流程需要：进入标定模式 / 加热 / 周期读 4 路温度 / 温度曲线记录 / 倒计时。

| # | 调用 | 现有 | 缺口 | 缺在哪 | 需加的功能单元 |
|---|---|---|---|---|---|
| S1-1 | 进入/退出标定模式 | IMCU 无此命令 | N16 B0-1 收发 | **08 IMCU+MCUDriver** | 接口 `enterCalibMode()/exitCalibMode()`（IMCU 纯虚 + Driver 实现 + 协议帧组装在 Driver 内） |
| S1-2 | 加热控制 | 无 | N14 T0-100 | **08 同上** | `setHeaterTemp(double celsius)` |
| S1-3 | 4 路温度读取 | `getTemperature()` 单路（IMCU.h:57）且 `const`（阻塞式单点读） | **4 路数组返回**；建议非阻塞（缓存最近上报值） | **08 同上** | `getTemperatures() -> std::array<double,4>`（L相机/R相机/骨架/环境——语义命名）；实现取 MCU 周期上报的缓存（HardwareMonitor 已有 1s 轮询可挂） |
| S1-4 | 温度上报事件化 | `TemperatureUpdate` 事件已定义；HardwareMonitor 周期 publish | param 只有 1 个 int64 装不下 4 路 | **base Event 结构**（不动 ABI 的前提下） | 方案 A：param1=索引 param2=值×1000（定点化）逐路发；方案 B：Event 增 `double temps[4]` 载荷（改结构，影响面大）。**建议 A**（事件本就"通知不带载荷"原则，细值走 S1-3 拉取） |
| S1-5 | 温度曲线记录器 | 无 | 预热期每秒 4 路 → 报告数据 | **06（数据容器域）** | `TimeSeriesRecorder<double,4>`（通用：record(t, vals)/summary()/clear()）——只做记录不求值，报告格式化在 01 |
| S1-6 | 倒计时/等待中断 | 无 | 可中断的 sleep（stop() 要能打断预热） | **06（IWorkflow/Pipeline 域）** | `interruptibleSleep(ms, abort)->bool`（工具函数，condition_variable 实现）——标定/扫描/后处理工作流通用 |

## S2 姿态采集循环（流水线 1）

流程需要：取 Cycle 周期单元 → 标记点链 → 配准姿态 → 多帧确认 → 集齐 25。

| # | 调用 | 现有 | 缺口 | 缺在哪 | 需加的功能单元 |
|---|---|---|---|---|---|
| S2-1 | **Cycle 采集单元结构** | FrameData 仅 {frameId, ts, leftGray, rightGray}（单帧双目） | 无"周期"概念（标记点帧+N 激光管帧+温度+时间戳组） | **06（DataPlane）** | `struct CalibCycle { uint64 cycleId; FrameData markerFrame; std::vector<FrameData> laserFrames; std::array<double,4> temps; std::vector<uint64> ts; }` |
| S2-2 | **周期缓冲容器** | RingBuffer<T> 模板已有（含 Block 策略）；FrameBuffer 是 RingBuffer<FrameData> 特化 | 无 `RingBuffer<CalibCycle>` 的具名封装 + IFrameSink 式的推送接口 | **06** | `class CycleBuffer { pushCycle()/grabNext(timeout, abort) }`（内部 RingBuffer<CalibCycle, Block>，容量 4×X）——FU-8.1 的完整形态 |
| S2-3 | **采集侧组包器**（把 N+1 帧+温度打包成 Cycle 推入缓冲） | CameraControl 回调产出 StereoFrame（逐帧）；无组包逻辑 | 谁在 HAL 回调里识别"这是标记点帧还是激光管 i 帧"？ | **08（采集域）→ 06（容器）边界** | `CycleAssembler`（08）：订阅帧回调 + MCU 触发序号（或帧类型标记，取决于 W0-4 协议）→ 组包 → `cycleBuffer.pushCycle()`。**依赖 W0 触发时序定版**；接口先行：`onFrame(FrameData, FrameRole)` |
| S2-4 | 帧角色标记 | StereoFrame 无"帧类型"字段 | 标定采集需区分标记点帧/激光管帧（触发序号或 MCU 事件对齐） | **06（FrameData）+ 08（回调）** | `FrameData` 增 `enum class FrameRole : uint8_t { Marker, LaserTube0..N, Unknown }`（默认 Unknown 不影响扫描路径） |
| S2-5 | 姿态进度事件 | EventType 无姿态组 | UI 引导与外部观测需要 | **base（EventType）** | `PostureHit = 0x0503`（param1=姿态号 param2=已集数）、`PostureAllCollected = 0x0504`、`CalibrationPhaseChanged = 0x0505`（param1=Phase 枚举值）——FU-8.2 扩展为 3 个 |
| S2-6 | 实时命中数据给 UI | WorkflowProgress 有 stageName/progress 浮点 | 装不下"当前姿态 4×4 矩阵+已集清单" | **06（IWorkflow 契约）** | `WorkflowProgress` 增 `std::string detailJson`（通用扩展位，01 序列化姿态明细塞入；不改 ABI 主结构） |
| S2-7 | 合成周期源（开发期） | 无 | B3 无真机时驱动 Collector | **01 自建**（测试基建） | `SyntheticCycleSource`（FU-3.2 已列；放 01/tests/） |

## 缺口汇总（按模块归组 = 跨模块改动清单的完整版）

### 06_fileio（容器+配置+IO 域）——最集中
| 单元 | 类型 | 服务于 |

| `TimeSeriesRecorder<double,4>` | 通用记录器 | S1-5 |

| `writeTextReport` | file_io 函数 | S5-1 |
| `WorkflowProgress::detailJson` | IWorkflow 契约扩展 | S2-6 |

### 08_devicemgmt（设备域）
| 单元 | 类型 | 服务于 |
|---|---|---|

| `CycleAssembler`（帧→周期组包） | 采集域组件 | S2-3（依赖 W0-4 时序定版） |

### base（最底层）
| 单元 | 类型 | 服务于 |
|---|---|---|
| `EventType::PostureHit/PostureAllCollected/CalibrationPhaseChanged` | 枚举追加 | S2-5 |

### 01_calibration（业务侧，已在 G1~G7 分解，此处只列"支持性质"的）
| 单元 | 说明 |
|---|---|
| `GpuMatPool`（S0-5） | 编排层自建，不进 09 |
| `SyntheticCycleSource`（S2-7） | 测试基建，01/tests |

### 明确不缺的（核实过，避免重复建设）
- 09 全部标定算子接口（三元组契约齐全，含 PoseTarget::fromJson、RoundTripVerify、lookup 查表）
- RingBuffer 模板的 Block 策略（反压语义已有，CycleBuffer 只是封装）
- EventBus 订阅发布机制
- HardwareMonitor 周期轮询骨架（4 路温度上报可挂现有 1s 轮询）

## 实施批次（并入 B 批次序列）

```
B1'  06 基础件：readJsonFile/writeJsonFile + ParameterManager 标定段 + interruptibleSleep
     + TimeSeriesRecorder + WorkflowProgress.detailJson + base 事件枚举      ← 全部无硬件依赖
B2'  06 DataPlane：CalibCycle 结构 + FrameData.frameRole + CycleBuffer        ← 依赖 B1' 类型
B8'  08 设备件：IMCU 三接口 + CycleAssembler（接口先行，协议实现待 W0 冻结）
     —— 原 B8 扩展为完整版；其余批次（B1~B7 业务编排）不变，Mock 就绪即可开工
```

> 与《功能单元分解》的关系：本文档把 FU-8.1~8.4 四个"小件"展开为 **20 个支持单元**并排定先后；
> 业务单元（G1~G7 共 54 个）不受影响，依赖关系以此文档的 S0~S5 走查为准。
