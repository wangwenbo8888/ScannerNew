> 状态：**实现蓝本（2026-08-15）**——`01-标定工作流伪代码.md` 的进一步拆解：每个伪代码块拆到**最小可独立实现/可独立测试的功能单元**（一个函数或一个小类，≤80 行实现体）

## G2. MarkerChain（B2）——标记点链编排壳

> 每单元 = 一个薄封装函数（构造算子 + 顺序 Execute + 结果传递）。算子对象在 Chain 类构造时创建一次，单元函数只做调用与胶水。

### FU-2.1 Chain 类骨架与算子池
- 逻辑：构造函数创建 12 个算子成员（2-1~2-11 共 12 算子）+ `cuda::Stream` + 持有 `InitialParams`；析构按逆序
- 依赖：FU-1.4（InitialParams 注入）
- 测试：构造/析构不泄漏（ASAN 或观察显存计数）

### FU-2.2 单路上传与掩膜（2-1 单侧）
- 输入：`Mat gray`
- 输出：`MaskExtractResult{d_grayImage, d_cleanedMask}`
- 逻辑：`maskExtract_.Execute(gray, stream_)` ☠
- 测试：合成亮斑图 → d_cleanedMask 非零像素占位正确（下载比对）

### FU-2.3 帧类型过滤（2-1b 单侧）
- 输入：`d_cleanedMask`
- 输出：`isMarkerFrame`
- 逻辑：`frameFilter_.Execute`；**决策不在算子内**——返回调用方判定
- 测试：标记点帧通过 / 纯激光线帧被拒（合成两类图）

### FU-2.4 连通域（2-2 单侧）
- 输入：`d_cleanedMask` → 输出：`components`（Host 包围盒）
- 测试：N 个孤立斑 → N 个 component，包围盒吻合

### FU-2.5 frontend 组合（2-1→2-1b→2-2，左右两路）
- 输入：`Mat grayL, grayR`
- 输出：`FrontendOutput{frameType, grayL/R(Host 引用), componentsL/R}`
- 逻辑：FU-2.2~2.4 左右各跑；任一侧非标记点帧 → 返回 `{frameType:LaserFrame}`（调用方销毁）
- 依赖：FU-2.2/2.3/2.4
- 测试：左右正常帧组合通过；右路激光帧整体被拒

### FU-2.6 图像分割（2-3 单侧）
- 输入：`Mat gray + components` → 输出：`vector<Mat> splitImages`（深拷贝 ROI）
- 测试：ROI 内容与原图对应区域一致

### FU-2.7 Zernike 批量（2-4 单侧）
- 输入：`splitImages` → 输出：`vector<ZernikeEdgeCPUResult>`（逐块）
- 测试：合成椭圆子图 → 边缘点落在椭圆周界附近（半径误差 < 1px）

### FU-2.8 合并（2-5 单侧）
- 输入：`vector<Zernike...> + rects` → 输出：`mergedEdgePoints + groupIds`
- 测试：K 块合并后 groupId 连续无重叠

### FU-2.9 去畸变（2-6，左右汇合点）
- 输入：`mL.mergedEdgePoints, mR..., groupIds + InitialParams（★只从构造时注入的取）`
- 输出：`StereoUndistortResult`
- 测试：零畸变参数 → 输出≈输入（恒等性）

### FU-2.10 椭圆拟合批量（2-7）
- 输入：`rectifiedPoints1/2 按 groupId 分组`
- 输出：`ellL/ellR（每椭圆 center/major/minor/angle）`
- 测试：合成椭圆点集 → 中心误差 < 0.1px

### FU-2.11 匹配与极线（2-8/2-9/2-10 三连）
- 输入：`ellL/ellR`
- 输出：`centerMatches, ellipseResults（极线交点）, EdgeMatchCPUResult`
- 逻辑：marker_match → epipolar_intersect(左右) → edge_match
- 测试：双目合成对应点 → 匹配率 100%，极线残差 < 阈值

### FU-2.12 compute 组合与三维重建（2-11 + 全链入口）
- `processMarkerFrame(grayL, grayR)`：FU-2.5 → 2.6~2.11 左右穿插 → point_reconstruct
- 输出：`{marker3D, ellL, ellR}`
- 测试：**端到端合成帧**——生成含 K 个标记点的双目图对（已知 3D 真值）→ marker3D 重投影误差 < 0.5mm

## G3. PostureCollector（B3）

### FU-3.1 CollectedPose 数据结构
- 定义：`{poseId, markerL/R: Mat, laserFrames: vector<Mat>, temps: array<double,4>, ts: vector<uint64>, ellipseL/R}`
- 纯数据单元，无逻辑
- 测试：编译期

### FU-3.2 周期源适配器接口
- `CycleSource` 抽象：`grabNext(abort) -> optional<Cycle>`
- 实现 A：`SyntheticCycleSource`（合成，B3 阶段驱动）
- 实现 B：`FrameCycleBufferSource`（真机，B8 接）
- 测试：合成源按序产出 N 周期

### FU-3.3 时间戳连续性判据
- 输入：`ts1[](上一周期), ts2[](当前周期)`
- 逻辑：拼接后单调 && 相邻差 ≤ 1.5×帧周期
- 输出：bool
- 测试：正常连续/缺一帧/乱序 三例

### FU-3.4 命中状态保持（多帧确认第 1 跳）
- 输入：`pe.anyMatched, pe.bestMatchId, collected_[]`
- 输出：三态 `{NoHit, FirstHit(id), ConfirmCandidate(id)}`
- 逻辑：无命中→NoHit 清 lastHit_；命中且 =lastHit_ →ConfirmCandidate；命中且 ≠ →FirstHit 更新 lastHit_
- 测试：模拟序列 命中A→命中A→确认候选；命中A→命中B→FirstHit(B)

### FU-3.5 确认与 CAS 采集（多帧确认第 2 跳）
- 输入：ConfirmCandidate + 周期连续(FU-3.3) + lastCycle_
- 逻辑：通过 → `collected_[id].CAS(false→true)` 成功才：暂存 lastCycle_ 到 pendingPoses_、count++、发进度；失败（他路已采）→ 忽略
- 依赖：FU-3.1/3.3/3.4
- 测试：并发模拟两路同时确认同 id → 只计一次

### FU-3.6 2-12/2-13 调用封装
- 输入：`marker3D + globalMarkerSet_ + poseTargets_`
- 逻辑：globalSet 空→首帧建立+identity；否则 frame_fuse ☠ → pose_estimate
- 输出：`{R, T, PoseEstimateCPUResult}`
- 测试：合成已知位姿 → 估计位姿误差 < 阈值

### FU-3.7 椭圆中心旁路缓存
- 逻辑：确认姿态时 `ellipseByPose_[id] = {ellL, ellR}`；FirstHit 时暂存待确认
- 测试：确认后可取；未确认姿态不残留

### FU-3.8 Collector 主循环
- 组装 FU-3.2~3.7：grabNext → frontend→compute（FU-2.12）→ FU-3.6 → FU-3.4/3.5 → 进度回调 → 至 25 或 abort
- 依赖：G2 全部 + FU-3.2~3.7
- 测试：**合成 25 姿态序列端到端**——SyntheticCycleSource 喂 30 周期（含重摆/噪声）→ 精确集齐 25，无重复无遗漏

### FU-3.9 takeCollected 交付
- move 语义转移，清内部状态
- 测试：调用后再调用返回空
