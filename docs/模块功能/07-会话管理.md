# 模块7 · 会话管理

> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)

## 职责
扫描启/停/暂停/恢复, 覆盖率统计, 断电续扫, 会话元数据。

> 本模块在 `framework/` 退役后收编了原 `framework/service` 的状态机与会话管理。代码现位于 `modules/07_session/`，构建为静态库 `mod_session`（命名空间仍为 `Scanner::service`）。故障处理 `FaultHandler` 已迁至 `modules/10_observability`，不在本模块。
>
> 状态机演进目标为 7 态模型（S1–S7），设计见 [`docs/plans/2026-08-09-设备状态机-design.md`](../plans/2026-08-09-设备状态机-design.md)；**当前代码仍是 9 态半接线版**，对齐工作另排期。

---

## 1. 代码实际实现的

### 状态机接口与枚举 — `modules/07_session/IState.h`
- `Scanner::service::ScannerState` 枚举 9 态：`Init` / `DeviceReady` / `Calibrating` / `Calibrated` / `Scanning` / `Paused` / `PostProcessing` / `Error` / `EmergencyStop`（`IState.h:13-23`）
- `IState` 抽象接口：`getCurrentState` / `getStateName` / `transition(EventType)` / `canOperate(operation)`（`IState.h:25-37`）

### 状态机实现 — `modules/07_session/StateMachine.h` / `StateMachine.cpp`
- `StateMachine : public IState`，事件驱动状态转换 `transition()`，内含合法转换校验 `isValidTransition()`（`StateMachine.cpp:31-64`）
- 已接线的转换：`DeviceConnected`(Init→DeviceReady)、`DeviceDisconnected`(→Init)、`ScanStarted`(Calibrated|DeviceReady→Scanning)、`ScanStopped`(Scanning→Calibrated)、`ScanPaused`(Scanning→Paused)、`FaultOccurred`(→Error)、`FaultCleared`(Error→DeviceReady)、`EmergencyStop`(→EmergencyStop)、`SessionStarted`(Calibrating→Calibrated)
- 状态查询 `getCurrentState` / `getStateName`、操作权限判定 `canOperate`（scan/calibrate/postprocess/connect，`StateMachine.cpp:91-98`）
- 状态变更回调 `onStateChange`，并经 `EventBus` 发布 `StateChanged` 事件（`StateMachine.cpp:80-86`）

### 会话生命周期 — `modules/07_session/SessionService.h` / `SessionService.cpp`
- 启/停/暂停/恢复：`startSession` / `stopSession` / `pauseSession` / `resumeSession`
- 状态查询：`isActive` / `isPaused`
- 帧计数：`onFrameProcessed` / `onFrameFused`（暂停态不计数）
- 覆盖率写入接口 `setCoverage(percent)`（仅 setter）
- 会话元数据 `SessionMetadata`：sessionId、projectName、起止时间、总帧数、融合帧数、覆盖率、saved 标志（`SessionService.h:16-25`）
- 断电续扫存盘 `saveCheckpoint(path)`：手写 JSON 文件（`SessionService.cpp:83-100`）

### 构建配置 — `modules/07_session/CMakeLists.txt`
- 静态库 `mod_session`，链接 `base` + `spdlog`（`CMakeLists.txt:2-7`）

## 2. 代码需要调整的

- **状态机转换表不完整**：`ScanPaused` 将 Scanning→Paused，但**无 Resume 事件**将 Paused→Scanning，Paused 成死端态（`StateMachine.cpp:31-64`）
- **`loadCheckpoint` 不解析 JSON**：仅读文件入字符串，`SessionService.cpp:110` 标 TODO，metadata 未恢复——检查点恢复链断裂
- **`saveCheckpoint` 手写 JSON**（`SessionService.cpp:88-95`）：未用 nlohmann_json、未写 endTime/saved、无转义，字段易出错
- **`ScannerState` 枚举与目标 7 态模型(S1–S7)不一致**：保留 `EmergencyStop`（目标删除）、`Calibrated`/`Paused`（目标折叠为出口事件/子态）、缺就绪/采集子态
- **SessionService 与 StateMachine 未联动**：两者各自独立，会话启停不驱动状态机转换，无集成层
- **命名空间仍为 `Scanner::service`**（framework 迁入保留）：若后续 modules 统一命名空间需同步调整

## 3. 需要增加的

- **覆盖率实际计算**（体素哈希：已填充体素 / 预估总体素）——当前仅 setter，无计算逻辑
- **覆盖率可视化**（已扫描/未扫描区域着色）
- **断电续扫恢复完整链**：启动时未完成会话检测 + 定期自动存盘 + JSON 解析恢复 metadata（S7 故障续作的硬依赖）
- **故障主动响应链**（相机断连 / MCU 通信失败 / GPU OOM → 暂停/降级 → 上报 `FaultHandler`）——`FaultHandler` 在 `modules/10_observability`，本模块未接入 `reportFault`
- **状态机对齐 7 态模型(S1–S7)**：就绪/采集子状态机、删 EmergencyStop、Calibrated/Paused 折叠（另排期，见设计文档 §10）
- **SessionService ↔ StateMachine 联动集成层**：会话启停驱动状态转换
