## 1. 代码实际实现的（真实文件路径 + 简述）

### 1.1 FaultHandler（本模块主体）
位于 `modules/10_observability/`，构建为静态库 `mod_observability`：
- `modules/10_observability/FaultHandler.h` / `FaultHandler.cpp` — 故障处理器，命名空间 `Scanner::service`
- `modules/10_observability/CMakeLists.txt` — `mod_observability` STATIC，链接 `base` + `mod_session` + `spdlog`

**依赖类型**：`FaultSeverity`、`EventType`（含 `FaultOccurred=0x0400` / `FaultCleared=0x0401`）定义于 `base/types.h:82,107`；`StateMachine`（`Scanner::service`，来自 mod_session）；`EventBus`（`Scanner::infra`，头在 `base/EventBus.h`）。

**实际行为**（`FaultHandler.cpp`）：
- `start()`（`:11`）订阅 `EventType::FaultOccurred` → `spdlog::error` 记录 → 若 `severity >= Error` 调 `StateMachine::transition(FaultOccurred)` 转 Error 态 → **复用 `EmergencyStop` 通道** `publish` 一个红灯事件（`:26-31`）→ 触发已注册的 `faultCallback_`
- `reportFault(source, severity, message)`（`:45`）：手动上报 —— 记日志 + `publish(FaultOccurred)` + (>=Error) `transition` + 回调
- `clearFault(faultId)`（`:63`）：记录 + `publish(FaultCleared)` + `transition(FaultCleared)`
- `onFault(cb)`：注册故障回调；`setEventBus` / `setStateMachine`：注入依赖

**装配**：`app/AppContext.cpp:40-45` 实例化 `faultHandler_` → `setEventBus` + `setStateMachine` + `start()`；经 `AppContext.h:37` 的 `faultHandler()` 暴露。

### 1.2 散落在外的日志实现（非本模块目录，但属可观测性范畴）

## 2. 代码需要调整的

- **`reportFault` / `clearFault` 无任何外部调用者**（全仓 grep 仅命中定义与声明）—— 手动故障上报 API 形同虚设，需接线（见 §3 故障主动响应链）。
- **EventBus `FaultOccurred` 无探测器 `publish`** —— `start()` 的订阅链半接：当前仅 `reportFault` 手动触发，硬件/算子链路未发布故障事件，自动响应路径实际不激活。
- **红灯事件复用 `EmergencyStop` 通道**（`FaultHandler.cpp:28`）—— 语义混淆（故障≠急停），需引入独立的指示灯控制事件类型。
- **`reportFault` 发布的事件丢失 `source` 标识** —— `evt.param2=0`（`:52`），订阅侧日志只能打印 `source=0`；故障来源信息未进入事件流。
- **`CALIB_LOG_*` 分类标签仅在算子库可用** —— 未推广到其他模块，统一日志口径缺失。

## 3. 需要增加的

### 3.1 故障主动响应链（接线）
- 模块 7（会话/扫描）检测相机断连 / MCU 通信失败 / GPU OOM → 主动降级或暂停 → 调 `FaultHandler::reportFault`（当前模块 7 未接入）
- 模块 8（设备管理）检测 USB 断连 / 串口超时 / 温度异常 → 自动停激光 → 调 `FaultHandler::reportFault`（当前模块 8 未接入）
- 接入后 `start()` 订阅链方能真正自动触发（→ 转 Error 态 + 红灯 + 回调）

### 3.2 统一日志
- 配置文件驱动（级别 / 格式 / 轮转 / 多 sink）
- 日志轮转（文件 10MB × 5）
- 多 sink（控制台彩色 + 文件 + 可选远程 syslog）
- 分类标签（`CALIB_LOG_*`）推广到全部模块

### 3.3 性能监控
- `PerfCounters`（采集帧率 / 丢帧 / 处理帧率 / GPU·CPU·端到端延迟 / 标记点·激光点·融合点数 / 温度 / GPU 显存）
- 实时 Dashboard 折线图
- 告警（帧率低于阈值 / 温度过高 / GPU OOM）

### 3.4 崩溃捕获
- Windows 崩溃捕获（`SetUnhandledExceptionFilter` + `MiniDumpWriteDump`）
- 崩溃后自动重启 + 会话恢复
- 崩溃报告打包（minidump + 日志 + 系统信息）上传
