# 模块10 · 可观测性运维

> 一句话：10 是**全系统的裁判与黑匣子**——门禁（谁能不能开工）、故障（出事了谁管怎么停）、日志（干了什么留痕）、性能（干得怎么样）、崩溃（死了留遗书）。
> 返回索引：[`模块功能目录.md`](../../模块功能目录.md)

## 1. 功能目标

### 1.1 全局门禁状态机（1 号灯）（【公】app 第 5 存活件，开机即造全程不销毁）
- 做什么：门卫——7 态互斥模型（S1 初始化/S2 待机/S3 标定/S4 扫标记点/S5 扫标记＋激光/S6 后处理/S7 故障自检）；三条全局边（任一态→S7 故障、S7 自检通过→回退出前态续作、断连→S1）；门禁查询 `canOperate`（02 扫描前置＝已标定；05 编辑前置＝存在可编辑点云）与转态 `transition`（StateChanged 事件广播）。
- 交互：01/02/05 全部 ①（进入门禁）与末步（切回待机）；04 进入（S6 免疫设备故障）。

### 1.2 FaultHandler 故障聚合（08 汇合点下游）
- 做什么：消防队长——收故障上报（08 检测：相机掉线/串口超时/温度异常/GPU OOM/心跳丢失）→ 记档 → 转 S7（Error 级以上）→ 安全停机联动（设备切 idle 由 08 执行）→ 事件广播。
- 交互：任意态（S1–S5）故障触发；S6 免疫。

### 1.3 统一日志
- 做什么：史官——spdlog 统一配置（级别/格式/轮转 10MB×5 文件 sink）；`JMW_LOG_*` 分类标签；出厂排障包（日志＋minidump＋系统信息）；关键部分必写/错误必有日志。

### 1.4 性能监控
- 做什么：仪表盘——消费 08 HardwareMonitor 巡检广播（上位机自体检＋帧率三件套＋外设状态）→ 汇总展示（UI 状态栏/仪表盘）；阈值告警事件（Degraded/Fault）转发 FaultHandler。
- 交互：01-④⑤；02-④⑤；编辑/后处理全程。

### 1.5 崩溃捕获
- 做什么：黑匣子——`SetUnhandledExceptionFilter`＋`MiniDumpWriteDump`；崩溃后打包（dump＋日志＋版本号）存固定目录；下次启动检测崩溃残留并提示上报。
- 交互：全程。

控制流一张图（门禁＋故障链）：

```
                命令入口（统一命令通道）
  屏幕图标(app) ─┐
  硬件按键(08→DeviceManager) ─┤─▶ 10 状态机 canOperate 门禁查询
  自动策略 ─┘        │ 通过/拒绝
                    ▼
             01/02/04/05 工作流（自治执行）
                    │ 完成事件
                    ▼
             10 状态机 transition（切回 S2 待机）

 故障链（独立于命令通道的第二个转态入口）：
  08 检测源（温度/掉线/OOM/心跳）─▶ FaultHandler.reportFault
       ─▶ 记档 + transition(S7) + 08 安全停机（设备 idle）
       ─▶ S7 自检通过 ─▶ transition（回退出前态，续作语义）
```

> 转态入口收敛铁律：只许命令通道与故障链两个门进（工作流不得自发 transition——01/02 流程图中「10 切回待机」均由本模块执行）。

## 2. 实现现状（以代码为准）

- 编译归属：STATIC 库 `mod_observability`（`modules/10_observability/CMakeLists.txt`），链 base＋spdlog＋dbghelp；命名空间 `Scanner::service`。
- 测试覆盖：tests/ 9 个测试 exe 注册 ctest（无真机，gtest 入 ctest）；工程全量 ctest 95/95 绿（Debug＋Release）。
- app 接线现状：main 按 ObsLogger→CrashHandler 顺序最先装配＋残留检测打包；AppContext 六件装配＋自检清单全过 `submit("system_ready")` 切 S2；01 标定（submit/notifyCompleted 成对）；02 扫描（start_scan 参数就绪谓词/finish_scan 触发型只点火 GBA/⑩ 合账后 notifyCompleted→S2）；04 后处理（handler＋notifyCompleted 备好，无 UI 入口——后处理窗口未建）；05 编辑不走 gate 不占态（canOperate("edit") 查询口已登记）；ScannerWindow 直连 transition 收敛至一处（DeviceDisconnected 设备事件桥）。UI 状态图标暂无 StateChanged 订阅者。

### 2.1 `StateMachine.h/.cpp`＋`IState.h`（StateMachine，10-1）【公·实例 app 造】
- 核心能力：全系统唯一的红绿灯——7 态表驱动全局门禁（18 条合法边入转换矩阵 static 表）＋**CAS 原子转态**（并发竞争不丢转态/不非法覆盖）。
- 交互：canOperate 门禁键 7 个（S2 四键 calibrate/scan/postprocess/edit＋三态键 scanning[仅 S4/S5]/calibrating[仅 S3]/postprocessing[仅 S6]——触发型命令用）；StateChanged 经 EventBus 广播；CommandGate/FaultHandler 消费它转态。
- 生命周期归属：【公】app 第 5 存活件。
- 线程/并发：state_/lastHealthy_ 均 atomic；onStateChange 回调并发转态下可能乱序到达（回调方需当前态请查 getCurrentState()）。
- 错误/降级：lastHealthy 记账（S7 恢复回前态续作，永不回 S6、兜底 S2）；S6 故障免疫；断连例外两处（S6 免疫/S7 保持）。
- 测试：test_state_machine（转换矩阵全组合）/ test_state_machine_concurrent（8 线程×200 CAS 压力）。
- 状态：✅

### 2.2 `CommandGate.h/.cpp`（CommandGate＋Spec，10-2）
- 核心能力：所有开工命令的统一大门（双口）——submit 走三关（注册/门禁/pre 前置谓词）→ start 类即切态 → handler 仅点火毫秒级返回（同步失败回滚 S2＋CommandRejected）；notifyCompleted＝唯一切态收尾口（start→finish 成对）。
- 交互：Spec 含 startedEvent/finishedEvent（kNoEvent＝触发型不切态，如 finish_scan 只点火；切态型无 finishedEvent＝收尾禁用型，如 system_ready）。
- 线程/并发：不开线程——三关＋切态在调用方线程（查表/CAS 微秒级）；mutex 仅护注册表，handler/pre/转态一律锁外。
- 测试：test_command_gate。
- 状态：✅

### 2.3 `DefaultCommands.h`（makeDefaultCommandSpecs()，10-3）
- 核心能力：首批 7 条命令花名册——system_ready/start_calibration/start_scan{mode}/finish_scan（触发型）/finish_calibration/start_postprocess/finish_postprocess。
- 交互：handler/pre 留空待 app 装配方。
- 测试：test_default_commands。
- 状态：✅

### 2.4 `FaultHandler.h/.cpp`（FaultHandler，10-4）
- 核心能力：故障接警台——档案表（活动故障 {id,sourceId,severity,message,time,count}，同源同类 **1s 窗口聚合计数防风暴**）＋来源注册制（registerSource 稳定 id）。
- 交互：红灯走独立 `EventType::LedControl`（param1 灯色，不复用 EmergencyStop）；Error 级转 S7＋app 注入安全停机回调（10 不链 08）；clearFault 仅清档，恢复走 selfCheckPassed（S7→lastHealthy＋绿灯）。
- 线程/并发：**两口分工防死锁**——reportFault 直调＝完整故障链；EventBus 订阅口（start 后）仅记档（总线同步分发持锁，锁内转态/发灯事件会重入死锁）。
- 错误/降级：08 故障 8 码（0x0801–0x0811）经 EventBus FaultOccurred 上总线，订阅口可收但有两处现状——①param1 语义错位（08 发故障码/本件期望 severity 枚举，档案记越界值＋source=0）；②订阅口仅记档不转态（完整链 Error 级转 S7＋安全停机需 app 侧桥接 reportFault 直调，现状未接——08 故障上总线后只记档不转态）。
- 测试：test_fault_handler（聚合/S7/S6 免疫）/ test_fault_recovery（S7 恢复边界）。
- 状态：◐（本体全落地；08 故障桥两待办半接）

### 2.5 `PerfMonitor.h/.cpp`（PerfMonitor＋IHealthProvider，10-5）
- 核心能力：健康预警器——**poll() 显式拉取模型**（拉取快照→阈值判定→双级告警；避免 EventBus 订阅回调内 publish 重入死锁）。
- 交互：IHealthProvider 注入窄接口（app 侧 HealthAdapter 把 08 HardwareMonitor::snapshot()——SelfCheckCollector PDH/NVML＋帧率三件套——喂入）；poll() 挂 MainWindow m_infoTimer（1s）；预警级走 HealthReport(param1=摘要码)、故障级（磁盘停写保护）走 reportFault 完整链。
- 错误/降级：阈值规则表（CPU 温度/内存持续/磁盘双档/帧率比持续）；持续类规则连续越限满 N 秒才降级、恢复清锚；边沿发事件防刷屏；指标 -1＝未知跳过、阈值 -1＝禁用该规则；process/drop 计数器暂缺（采集侧未供给）。
- 测试：test_perf_monitor（阈值边界＋假源）。
- 状态：✅（采集源与轮询已接通）

### 2.6 `ObsLogger.h/.cpp`（ObsLogger，10-6）
- 核心能力：统一日志管家——stdout＋rotating_file（10MB×5）双 sink 组 spdlog default logger（幂等，重复调用先拆旧再重建）；排障包 `obsExportDiagnosticsPackage`（logs 副本＋dump＋version.txt 收进 diagnostics_\<时间戳\>/，每步容错，不引 zip）。
- 交互：main 最先装配（ObsLogger→CrashHandler 顺序定死）；shutdown 须在删日志目录前调（rotating sink 持句柄）。
- 测试：test_obs_logger（轮转）。
- 状态：✅

### 2.7 `jmw_logging.h`（JMW_LOG_\* 宏，10-7）
- 核心能力：全工程统一的打日志快捷键——spdlog＋fmt 直透，tag 显式传参输出 `[模块-对象] msg` 前缀。

### 2.8 `CrashHandler.h/.cpp`（crash::install/detectResidualDump，10-8）
- 核心能力：崩溃黑匣子——SetUnhandledExceptionFilter＋MiniDumpWriteDump 落 dumps/ 固定目录＋crash_pending 标记。

## 3. 附录

### 3.1 全局门禁 7 态规格（S1–S7）

七态两两互斥（操作员视角）：

- S1 初始化——软件启动自检：通讯/加密狗/授权文件
- S2 待机——空闲就绪，所有功能入口（门禁查询主战场）
- S3 标定——多姿态采集→解算（01 全程一态，内部 Phase 经事件上报不占全局态）
- S4 扫描标记点——纯标记点扫描（含就绪⇄采集子态）
- S5 扫描标记点＋激光——双链扫描（含就绪⇄采集子态；GBA 阻塞段仍 S4/S5）
- S6 后处理——离线五阶段出 STL（**免疫 S7**；GPU/算法失败走 Result 人工处置）
- S7 设备故障＋自检中——安全停机＋自检恢复；恢复＝回退出前态续作（**永不回 S6**）

关键规则：S3/S4/S5/S6 互斥必经 S2；扫描二选一（S4/S5 由 ScanMode 在 S2 入口定）；S7 进入即安全停机（08 执行）；非设备类失败（加密狗/授权）留 S1 阻塞告警不进 S7；断连例外两处（S6 免疫只记档、S7 内保持——自检含重连）。

合法边清单（与代码 kEdges 表同构；空缺组合＝不允许、需经 S2）：

```
S1 ──自检通过──▶ S2        S1 ──设备故障──▶ S7
S2 ──启动标定──▶ S3        S2 ──启动扫描(标记点)──▶ S4
S2 ──启动扫描(标记+激光)──▶ S5                S2 ──启动后处理*──▶ S6
S2 ──设备故障──▶ S7        S2 ──断连──▶ S1
S3 ──标定完成──▶ S2        S3 ──设备故障──▶ S7        S3 ──断连──▶ S1
S4 ──完成/退出──▶ S2       S4 ──设备故障──▶ S7        S4 ──断连──▶ S1
S5 ──完成/退出──▶ S2       S5 ──设备故障──▶ S7        S5 ──断连──▶ S1
S6 ──后处理完成──▶ S2      （S6 对设备故障/断连免疫——无边）
S7 ──自检通过──▶ 回 lastHealthy 续作（恢复目标；永不回 S6）
```

> \* S6 进入前置：操作员全权判定（无系统门禁）。05 编辑进入待机态内完成（不占 7 态之一——编辑是 S2 内的交互会话，门禁条件＝可编辑点云存在）。

### 3.2 与各模块照应

- 08：检测源上行（HardwareMonitor 巡检/串口心跳）→ FaultHandler；安全停机执行方。
- 01/02/04/05：门禁查询者＋完成事件触发转态者（经本模块，不自发）。
- app：状态机为 app 第 5 存活件；UI 状态图标消费 StateChanged（暂无订阅者）。
