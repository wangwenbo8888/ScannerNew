## 1. 工作流程图（对象自治版）🔒 最终确定版 · 2026-08-18

### 1.1 定案要点（AI 一眼可见）

| # | 定案 | 内容 |
|---|---|---|
| **D1** | **对象自治** | 选择服务（05）、撤销/重做栈（05）、数据管理（06）、渲染（03）四对象封装自治；**05 只做①门禁进入、②装配、③交互会话承载、④旁观显示、⑤停止回收（仅会话私有件）** |
| **D2** | **编辑时机=就绪态内、GBA 之前** | 编辑是 **02-⑥ 就绪态内的一个会话**（非独立全局态）：用户停止采集（⑥）后、点「完成扫描」（⑦ GBA）**之前**进入；数据源=**融合累积器实时点云**（未经 GBA 修正）。门禁前置：处于 S4/S5 就绪态且融合累积器有点 |
| **D3** | **三栏选择模型（正交开关）** | 圈选配置三栏独立：**工具类型**（套索/多段线）× **选择类型**（贯穿/只选第一层）× **对象类型**（激光点/标记点/标记点和激光点）——任意组合合法 |
| **D4** | **删除为软删除+双账本作用** | 删除只**标记**（工作集内 tombstone），不物理移除——undo/redo 的实现基础。应用时**双账本作用**：①融合累积器移除该批点（渲染/后续融合即不见）②**逐帧观测累加器中相应观测标记剔除**——⑦ GBA 求解不含已删点（人工裁定 Q1=a，2026-08-18） |
| **D5** | **撤销/重做栈** | 操作粒度=一次删除（含所选点集）；undo=恢复该批点、redo=再删；新动作清空 redo；栈深上限可配（默认 20，逐出最旧）；**会话内存态，不持久化**。undo/redo 同步作用双账本（融合累积器+obs 剔除标记双向） |
| **D6** | **记账归 05** | 开账（会话 ID+开始时间戳）/合账（结束时间戳+编辑统计：删除次数/点数、undo/redo 次数）；不设独立会话对象（同 01-D7/02-D6 款） |
| **D7** | **所有权拆分** | **app 存活件**（⑤ 不销毁）：融合累积器+obs 累加器（**随 02 会话私有**，见 D8）、渲染基座（03）、EventBus。**编辑会话私有件**（② 构造、⑤ 逆序销毁）：场景内容供给器[编辑层]（03）、选择服务、撤销/重做栈。判据同 01-D8/02-D7 |
| **D8** | **编辑不终结扫描工作流，编辑后可续采** | 编辑会话退出回 **S4/S5 就绪态**（人工裁定 Q2，2026-08-18）——就绪态三个出口任选：**再按键续采**（回 02-③④⑤，同一工作流继续累积）/ **再进编辑** / **点「完成扫描」**（进 ⑦ GBA，此时才终结）。编辑成果经双账本自然延续到 GBA 与重融合 |
