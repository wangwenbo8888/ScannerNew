# 文档结构性调整规范

> **什么是一次结构性调整**：迁移、重排、批量改名、目录级终态裁定——一次动 5 份以上文档的结构性动作。
> 日常新建与更新不走本规范（见《工程文档管理规范.md》）；本规范是其总原则（存量不改名）的**唯一法定例外通道**。

## 1. 发起

- 仅人工发起，AI 不得自行发起
- 常见触发：文档规范大版本升级／模块重组／目录搬迁／目录级终态裁定

## 2. 方案先行（动文件之前）

- AI 出**一页方案**报人工批准，四要素：范围（动哪些文件）｜动作（每处改什么）｜链接影响面（哪些引用会断）｜登记变化
- 批准前不动任何文件

## 3. 三道闸（执行中遇到必停）

1. **目标段改动**：人审核后才可写入（《工程文档管理规范.md》§2.3）
2. **批量删除/退役**：人工批准（单文件删除/退役走《工程文档管理规范.md》§4.1 日常通道，不属本闸）
3. **目录级/批量终态裁定**：人工批准（沙箱收官、单文件退役是日常小终态，走日常通道）

## 4. 执行纪律

- 批量操作脚本化：UTF-8 无损写回，保留 BOM 与换行风格
- 分批提交，一批一个主题
- 新写文件同样受《工程文档管理规范.md》§5 写法约束

## 5. 校验

- grep 旧名/旧口径残留＝0
- 引用路径存在性抽查
- 计数对账（登记表 vs 磁盘）；对账清单格式同《工程文档管理规范.md》§6

## 6. 收口

- `开发进度.md` 日志一行＋裁定入关键决策（如有）
- `工程地图.md` 登记同步（可批量）
- 规范／AGENTS 中的相关指针同步
