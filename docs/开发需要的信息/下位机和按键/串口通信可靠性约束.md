## 一、三类问题与措施总表

### 1. 消息粘连（串口是字节流，无消息边界）

| # | 措施 | 层 | 状态 |
|---|---|---|---|
| A1 | 分隔符分帧（`;`） | 协议 | ✅ 现状已做 |
| A2 | 起止符成对（`$` 起始 + `;` 结束）+ 载荷内分隔符转义 | 协议 | v3 新增 |
| A3 | 半帧超时丢弃（收到无尾符字节挂起超 50ms 即弃，防干扰字节卡死分帧器） | PC 软件 | v3 新增 |

### 2. 传输干扰（EMI/误码/字节翻转丢失插入）

| # | 措施 | 层 | 状态 |
|---|---|---|---|
| B1 | **CRC16 校验**（帧尾 2 字节；短帧 <16 字节漏检概率 < 2⁻¹⁶）——性价比最高 | 协议 | v3 核心 |
| B2 | 格式校验（长度/首字符/枚举域合法，非法丢弃+warn） | PC 软件 | ✅ 现状已做 |
| B3 | RS485 差分总线替代 RS232 电平；线缆屏蔽/磁环 | 硬件 | 产线评估 |

### 3. 丢帧（缓冲溢出/整帧损坏被弃/线程阻塞）

| # | 措施 | 层 | 状态 |
|---|---|---|---|
| C1 | **帧序号 seq**（1 字节循环递增；PC 检测跳变即知丢哪帧，可对账） | 协议 | v3 核心 |
| C2 | **关键命令 ACK+重传**：MCU 执行后回执 `A<seq>;`；PC 超时 50~100ms 重发，最多 3 次；3 败→告警 10 可观测性 | 协议 | v3 核心 |
| C3 | 周期遥测不重传（温度丢了下一周期还有——按数据价值分级） | 协议 | v3 新增 |
| C4 | 接收线程只分帧入队，解析/处理独立线程（环形队列解耦，防解析阻塞反压接收） | PC 软件 | 实现约束 |
| C5 | 串口驱动缓冲区调大（≥4KB） | PC 软件 | 实现约束 |
| C6 | 帧率监控：HardwareMonitor 每秒查温度帧计数，为 0 判通讯故障→故障上报链 | PC 软件 | 实现约束 |
| C7 | 接收线程高优先级 | 系统 | 实现约束 |

## 二、v3 帧格式提案

```
通用帧结构（文本，兼容现状分帧器思路）：
  $ <载荷> <seq> <crc16> ;

下行（PC→MCU）：
  设参数   $N10H20B128T3V2<seq><crc>;      ← 采集参数（频率/补光/激光管/亮度）
  启停     $N11H1<seq><crc>;               ← 开采集（H0=停）★关键命令
  读温度   $N15V2<seq><crc>;               ← 兜底轮询（MCU 主动上报启用后仅调试用）

上行（MCU→PC）：
  温度     $T25.3;24.8;26.1;23.9<seq><crc>;   ← 4 路独立（周期主动上报，可丢不重传）
  按键     $KM1<ts><seq><crc>;                ← 原始按键事件（键号+按下/松开+时刻；
                                                 手势判定在 PC KeyManager——08 修正③）
  设备状态 $S<状态码><seq><crc>;              ← DeviceManager 记录（原 3 号灯职责）
  命令回执 $A<seq><crc>;                      ← ACK（关键命令专用）
```

**格式规则**：
- 载荷内禁止出现 `$` 与 `;`（转义或编码约束），保证分帧唯一性
- `<seq>`：1 字节 0~255 循环；上行帧同样携带（PC 侧对账）
- `<crc>`：CRC16-CCITT 查表（MCU 侧约 50 行实现），帧内容含 seq
- 帧长上限 32 字节（超出即弃——防御异常流）

## 三、可靠性分级（按数据价值，非一刀切）

| 级别 | 报文类 | 策略 |
|---|---|---|
| **关键命令** | N10 设参 / N11 启停 / 模式切换类 | seq + ACK + 超时重传×3 + 失败告警→10；**幂等设计**（N11 H1/H0 重发无副作用） |
| **周期遥测** | T 温度 / 在线状态 | CRC 校验，错则丢，**不重传**（下一周期自愈） |
| **离散事件** | K 按键 / S 设备状态 | CRC + seq（丢帧可对账发现，不重传——按键可重按、状态会再报） |

> 关键命令可靠性与 08 修正④（parity 废除→显式状态+状态转移表）互为支撑：显式状态要求命令通道可靠（漏一条启停命令状态即漂移），故 v2.0 时代"放弃自检换极简"的取舍不再成立。

## 四、带宽核算（可行性）

| 项 | 数值 |
|---|---|
| 帧长 | 4 → ~10 字节（含 $/seq/crc/;） |
| 115200 8N1 有效字节率 | ~11.5 KB/s |
| 单帧传输时间 | <1ms |
| 最坏工况（温度 4 路 1Hz + 按键连打 + 命令重传） | <5% 带宽占用 |

## 五、实施路径（成本排序）

```
零成本（现状已具备）：A1 B2
纯 PC 侧（不动固件）：A3 C4 C5 C6 C7

硬件（产线）：B3
```
