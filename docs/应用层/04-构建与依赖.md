# 04 · 构建与依赖（app/CMakeLists.txt）

> `app/CMakeLists.txt`（134 行）。产物 `scan_demo.exe`，定义 app 与部分 modules 文件的编译、链接与运行时部署。framework 层（`fw_common`/`fw_data`/`fw_infra`/`fw_workflow`）已退役删除，改链基础库 `base` 与各 `mod_*` 模块库。

## 产物
- 可执行文件：**`scan_demo`**（即 scan_demo.exe）。

## 条件构建
整个 `scan_demo` 目标包在条件块内，缺一即跳过（库 + 测试基线不受影响）：
```
if(Qt5_FOUND AND Qt5Svg_FOUND AND Qt5SerialPort_FOUND
   AND EXISTS stubs/LEADSCANSeries.h)
```
- Qt5 / Qt5Svg / Qt5SerialPort 已装齐；当前 `stubs/LEADSCANSeries.h` 等桩源码缺失 → 源码不完整 → 默认跳过以保构建绿。stubs 补齐后自动启用（输出 `app/scan_demo 跳过…` 状态消息）。

| 开关 | 值 | 说明 |

| `AUTOMOC` | ON | 自动 MOC（Q_OBJECT） |
| `AUTOUIC` | ON | 自动 UIC（.ui → ui_*.h） |
| `AUTORCC` | **OFF** | QRC 不自动处理，改为手动 `rcc.exe` 命令 |

- `CMAKE_PREFIX_PATH` 追加 `C:/devlibs/Qt-5.15.2-msvc2019_64/5.15.2/msvc2019_64`
- `resources.qrc` 经 `add_custom_command` 调 `C:/devlibs/Qt-5.15.2-msvc2019_64/.../bin/rcc.exe` 生成 `qrc_resources.cpp` 编入 exe（路径硬编码，见待改进）。
- 注意：`dark.qss` 物理在 `app/` 但未列入 `resources.qrc`，故 `:/icons/dark.qss` 资源无效（`main.cpp` 样式加载当前静默失败）。

## 编入源码（非全部链接 mod_ 库）
```
APP_SOURCES      = main + AppContext + MainWindow + WorkflowContext
MOD_CALIBRATION  = modules/01_calibration/{calib_workflow,CalibDialog,CalibDisplay,IntegrateTestDialog}.cpp/h
MOD_SCANNING     = app/ScannerWindow.cpp/h/.ui        （本地，非 modules/02）
MOD_WORKFLOWS    = modules/02 ScanWorkflow + modules/01 CalibrationWorkflow + modules/04 PostProcessWorkflow
MOD_RENDERING    = modules/03_rendering/OSGWidget.cpp/h
MOD_FILEIO       = modules/06_fileio/file_io.cpp/h
```
- 这些文件被直接编进 exe，而非（或不完全）通过 `mod_xxx` 库链接。原因：带 UI 的模块（widget/dialog/OSG 视图）与 exe 紧耦合；工作流（MOD_WORKFLOWS）为 Phase 5 自已删除的 `fw_workflow` 接管编译归属（物理仍在 modules/）；纯算子/设备/会话库则正常链接（见下）。
- `MOD_SCANNING` 现为 app 本地的 `ScannerWindow`（原 `modules/02_scanning/ScannerWindow` 已移入 app/）；modules/02 的扫描逻辑体现为 `ScanWorkflow`（编入 MOD_WORKFLOWS）。
- 注意 `mod_calibration` 与 `mod_fileio` 既被链接、其同名 UI 源码又另编入 exe（半编半链，见待改进）。

## 链接库
| 类别 | 库 |
|------|----|
| 基础 | `base`（替代退役的 `fw_common`/`fw_data`/`fw_infra`） |
| 模块 | `mod_devicemgmt` `mod_operatorlib` `mod_fileio` `mod_calibration` `mod_session` `mod_observability` |
| Qt | `Qt5::Widgets` `Qt5::OpenGL` `Qt5::Svg` `Qt5::SerialPort` |
| 第三方 | `${OSG_ROOT}/lib/{osg,osgDB,osgViewer,osgGA,osgUtil,osgText,OpenThreads}.lib`（**直接 lib，非 imported target**） `Eigen3::Eigen` `${OpenCV_LIBS}` |

> framework 退役后不再链接任何 `fw_*` 库。OSG 因本机安装未提供 imported target，直接按 `${OSG_ROOT}/lib/*.lib` 链接 7 个导入库 + `${OSG_ROOT}/include` 头目录（`OSG_ROOT=C:/devlibs/osg-install`）。Eigen 用 `Eigen3::Eigen`（注意命名空间是 `Eigen3::`，非 `Eigen::`）。

`NOMINMAX`（避开 Windows min/max 宏）、`_CRT_SECURE_NO_WARNINGS`。

## 运行时部署（POST_BUILD）
```cmake
add_custom_command(TARGET scan_demo POST_BUILD
    COMMAND copy_dlls.bat "$<TARGET_FILE_DIR:scan_demo>" "$<CONFIG>")
```
`copy_dlls.bat` 路径已对齐本机（见 `环境配置汇总.md`），按 Debug/Release 拷贝：
- **Qt5**：`C:\devlibs\Qt-5.15.2-msvc2019_64\...` → Core/Gui/Widgets/OpenGL/Svg/SerialPort + `platforms/qwindows[d].dll`
- **OSG**：`C:\devlibs\osg-install\bin` → osg161 系列 + ot21-OpenThreads
- **OpenCV**：按配置分支 → Debug `C:\opencv-cuda-4.13.0-debug\...` / Release `C:\opencv-cuda-4.13.0\...` → core/calib3d/imgproc/imgcodecs/features2d/flann + CUDA 系列（cudaarithm/cudawarping/cudaimgproc/cudev）
- 脚本末尾 `exit /b 0`，保证 POST_BUILD 不因个别 copy 静默失败而中断构建。

注意：大恒 Galaxy SDK DLL、CUDA runtime、VC++ redist **未** 由该脚本处理（见 [模块11](../模块功能/11-安装部署.md) 待实现）。脚本内 Qt/OSG/OpenCV 仍为绝对路径（相对化见待改进）。

## 依赖小结
- **构建期**：Qt 5.15.2、OSG 3.6.5、OpenCV 4.13（含 CUDA）、Eigen 3.4.1、spdlog、大恒 Galaxy SDK；基础库 `base` + 6 个 `mod_*` 模块库。
- **运行期**：上述全部的 DLL + Qt 平台插件。
- **缺失**：统一安装包（NSIS/Inno）、依赖完整打包、首运行配置（均属模块11 待建）。
